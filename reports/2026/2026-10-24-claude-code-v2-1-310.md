## 概要

Claude Code v2.1.310 が公開された。最大の注目点は、Monitor ツールとプラグインモニターが Amazon Bedrock、Google Vertex AI、Microsoft Foundry、およびテレメトリーや非必須トラフィックが無効化された環境でも利用可能になったことである。これにより、エンタープライズ向けのクラウドプロバイダー経由でも監視機能が使えるようになった。

このほか、一部のゲートウェイでリクエストが失敗する問題へのリトライ対応、「Prompt is too long」エラー後の圧縮 (コンパクション) の修正、シンボリックリンクの参照先を表示しない権限プロンプトの修正、auto mode のプロンプト改善、非対話セッションのメモリ使用量改善など、信頼性とユーザビリティに関わる修正・改善が幅広く含まれる。VSCode 拡張、Cloud sessions、Claude Tag (Slack 連携)、Code Review の各プラットフォームにも修正が及んでいる。

## 詳細

### 背景

Claude Code は、Anthropic API 直接接続だけでなく、Amazon Bedrock、Google Vertex AI、Microsoft Foundry といったクラウドプロバイダー経由でも利用できる。これまで Monitor ツールとプラグインモニターはこれらの環境では利用できなかったが、v2.1.310 で解消された。あわせて、ゲートウェイ互換性、圧縮 (コンパクション)、サンドボックス、フックなど、運用上の信頼性に関わる修正が多数行われている。

### 主な変更点

#### 追加機能

- **Monitor ツールとプラグインモニターの対応拡大**: Bedrock、Vertex、Foundry 上、およびテレメトリーや非必須トラフィックが無効化された環境でも Monitor ツールとプラグインモニターが利用可能になった。これらの環境では、長いフォアグラウンドの sleep もブロックされるようになった

#### 修正

- **ゲートウェイ互換性**: `effort-2025-11-24` ベータ値や会話途中のシステムメッセージを拒否する一部のゲートウェイ・互換サーバーの背後でリクエストが失敗する問題を修正。Claude Code はこれらを除いてリトライするようになった
- **バックグラウンドクリーンアップ**: `cleanupPeriodDays` を非常に大きな値に設定した場合に、貼り付けた画像などの最近のファイルがバックグラウンドクリーンアップで削除される問題を修正
- **圧縮 (コンパクション)**: 「Prompt is too long」エラー後の圧縮が、base64 や SVG などの高密度なテキストを含む会話を残しすぎて、次のリクエストが再び失敗し得る問題を修正
- **権限プロンプト**: ファイル読み取りの権限プロンプトがシンボリックリンクの参照先を表示しない問題を修正
- **auto-continue タイムアウト**: 長い編集の後に外部エディターを閉じた瞬間に、質問の auto-continue タイムアウトが発火する問題を修正
- **Windows のフック**: Git Bash がない環境で、フックのコマンドが引用符付き文字列のみ (引用符付きパスなど) の場合に、PreToolUse と PermissionRequest フックがツール呼び出しを通過させてしまう問題を修正

#### 改善

- **auto mode のプロンプト**: 作業ディレクトリ外の最初の読み取り前のプロンプトが、読み取りをブロックするとシェルコマンドが権限を求めるようになる旨を伝えるようになった
- **メモリ使用量**: トランスクリプトファイルが非常に大きい場合の、非対話セッション (`-p`、Agent SDK) の圧縮時のメモリ使用量を改善
- **mod の `Image` 描画**: `allow-passthrough` と `focus-events` が有効な tmux 内で、kitty、Ghostty、iTerm2 3.5 以降 (フルスクリーンレンダリング) において、`alt` テキストのみが表示されていた問題を改善し、画像が描画されるようになった
- **Linux のサンドボックス診断**: `/sandbox` とサンドボックス起動時の警告が、bubblewrap によるサンドボックス起動を妨げる Ubuntu の AppArmor によるユーザー名前空間の制限と、その解除方法を示すようになった

#### 動作変更

- **MCP ツール呼び出しのタイムアウトエラー**: 非対話セッションで、サーバーの elicitation が未回答のまま MCP ツール呼び出しがタイムアウトした場合のエラーが変更された。回答が得られなかったこと、および呼び出しを繰り返さないことを Claude に伝えるようになった

#### プラットフォーム別の修正・改善

**VSCode 拡張:**

- プランレビューカードの「Send feedback and keep planning」ボタンで Enter を押すと、コメントを返す代わりにプランを承認してしまう問題を修正
- Session history の Web タブから開いたクラウドセッションで「Switch branch & continue」の後、パネルに「Something went wrong」と表示される問題を修正

**Cloud sessions:**

- Enterprise のカスタムロールに Claude Code クラウドセッションと Remote Control の権限が追加され、Owner がロールごとにアクセスを制御できるようになった
- クラウド環境のセットアップスクリプトをファイルから読み込む Choose file ボタンが追加された
- クラウド環境の編集ダイアログで、保存やアーカイブの失敗時にダイアログ内にエラーが表示されない問題を修正
- ルーティンの API トークン操作の失敗がトーストのみで通知される問題を修正。エラーがルーティン編集ダイアログ内に表示されるようになった
- セッション開始チェックリストが、クラウド環境のセットアップスクリプトの出力をスクロールボックスで表示するよう改善された
- 管理設定で Cloud sessions または Remote Control を有効化する際に確認を求め、その権限を持つカスタムロールを一覧表示するよう変更された
- クラウド環境ダイアログが、すべてのエディターを一度に表示する代わりに、ネットワークアクセス、セットアップスクリプト、環境変数を行から開くよう変更された

**Claude Tag (Slack 連携):**

- `!restart` や `!help` などの `!` コマンドが、太字・斜体・取り消し線で送信されると通常のメッセージとして扱われる問題を修正
- バンドルリストのバックグラウンド更新が失敗した際に、管理者のチャンネルページとワークスペースページがロードエラーに置き換えられる問題を修正
- 管理設定の支出上限ページが、チャンネル名の読み込み中に「フィルターに一致するチャンネルなし」と報告する問題を修正

**Code Review:**

- リポジトリリストの更新に失敗した後、Code Review 管理セクションがリポジトリとスイッチを非表示にする問題を修正
- Code Review 管理セクションが初回ロードをリトライし、それでも失敗した場合に 1 つの Try again バナーを表示するよう改善された

## 開発者への影響

### 対象

- Amazon Bedrock / Google Vertex AI / Microsoft Foundry 経由で Claude Code を利用しているエンタープライズユーザー
- テレメトリーや非必須トラフィックを無効化して運用している組織
- ゲートウェイや互換サーバーの背後で Claude Code を利用しているチーム
- `-p` や Agent SDK による非対話セッションを大規模トランスクリプトで実行しているユーザー
- Cloud sessions、Claude Tag (Slack 連携)、Code Review を利用している組織の管理者

### 必要なアクション

- **アップデートの適用**: `claude update` または npm 経由で v2.1.310 に更新する
- **Bedrock / Vertex / Foundry 環境での Monitor 利用**: これまで利用できなかった Monitor ツールとプラグインモニターが使えるようになったため、監視を前提としたワークフローの導入を検討できる。あわせて、長いフォアグラウンドの sleep がブロックされるようになった点に注意する
- **`cleanupPeriodDays` の設定確認**: 非常に大きな値を設定していた環境では、最近のファイルが誤削除される問題が修正されたため、意図どおりの保持期間になっているか確認する
- **Enterprise 管理者**: カスタムロールで Cloud sessions と Remote Control のアクセスをロール単位で制御できるようになったため、権限設計の見直しを検討する

### 移行ガイド (該当する場合)

破壊的変更はない。ただし、Bedrock / Vertex / Foundry およびテレメトリー無効環境では、Monitor 関連機能の有効化と長いフォアグラウンド sleep のブロックという動作の変化がある。
