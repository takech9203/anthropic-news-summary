## 概要

Claude Code v2.1.308 と v2.1.309 が公開された。v2.1.308 は「Bug fixes and reliability improvements」のみの保守リリースであり、v2.1.309 が約 50 項目の変更を含む実質的な本体である。

v2.1.309 の中心は、サンドボックスと権限チェックまわりのセキュリティ強化である。macOS / Linux のサンドボックス化された Bash コマンドがシェルの起動ファイルをサンドボックス外で実行していた問題、シンボリックリンク経由で `denyWrite` パターンや設定保護を回避できていた問題、権限チェックをすり抜ける複合コマンドやリダイレクトの問題など、権限境界に関わる修正が多数含まれる。このほか、`sed -i` の扱いの変更、`claude ultrareview` のワークスペーストラスト必須化などの動作変更、VSCode 拡張、Cloud sessions、Slack 連携 (Claude Tag)、Code Review にも広く修正が及んでいる。

## 詳細

### 背景

Claude Code は、サンドボックスと権限ルールによってツール実行の安全性を担保している。v2.1.309 では、シンボリックリンク、複合コマンド、サブシェル、リダイレクトといった経路を突いて権限境界を越えられるケースが多数修正され、ガードの網羅性が高められた。あわせて、セッション管理、スキル・プラグイン、各プラットフォーム (VSCode、Cloud sessions、Slack、Code Review) の信頼性向上も行われている。

### 主な変更点

#### サンドボックス・権限チェックの修正

- macOS と Linux で、サンドボックス化された Bash コマンドが各コマンドの前にシェルの起動ファイルをサンドボックス外で実行していた問題を修正
- macOS サンドボックスの `denyWrite` glob パターンが、パターンのフォルダーにシンボリックリンク経由で到達した場合に実際のパスへ適用されない問題を修正
- サンドボックス化されたコマンドと自動承認された編集が、`--mcp-config` で渡された MCP 設定ファイルを変更できてしまう問題を修正
- 失敗し得るリダイレクトを持つコマンドが設定した変数を、Bash 権限チェックが信頼してしまう問題を修正
- `cd` がラップまたはプレフィックスされた複合コマンドで、git 実行前のディレクトリ変更に対して権限チェックがプロンプトを出さない問題を修正 (素の `cd` と同様に扱われる)
- `Edit(path)` の deny ルールが、サブシェルを含む一部のコマンドで同パスへの Bash リダイレクトをブロックしない問題を修正
- ワークツリー分離セッションで、分離ガードが拒否すべきロケールプレフィックス付きコマンドや、zsh の算術コマンドの一部を受け入れていた問題を修正
- Claude Code が作成するワークツリーとブランチチェックアウトが git replace refs を無視するよう修正 (他の git 操作と同様)
- 設定ディレクトリにシンボリックリンク経由で到達した場合に、プロファイルストアの書き込み保護が適用されない問題を修正
- 無効化された MCP サーバーが、print / SDK セッションで後続の権限プロンプトによって再接続されてしまう問題を修正
- **Linux**: バックグラウンドコマンドがセッションより長く生存した場合に、サンドボックスの書き込み拒否が解除されてしまう問題を修正
- **Windows**: 現在のディレクトリを対象とし追加の引数を持つ一部の `Set-Location` / `cd` コマンドを、PowerShell 権限チェックが自動承認していた問題を修正 (承認プロンプトが表示されるようになった)

#### セッション・UI の修正

- 非常に大きなネストされた CLAUDE.md の配下でファイルを読んだ後、セッションが繰り返しコンパクトされる問題を修正。サイズ上限を超えるネストされた CLAUDE.md は先頭のみ読み込まれる
- ctrl+enter (send now) が、応答開始前に押すとメッセージをキューに入れるだけになり、フック実行中に押すとメッセージを残したままフックを再起動していた問題を修正
- キーバインドされたスラッシュコマンドが `!` モードからシェルで実行されていた問題を修正
- ctrl+o で、配信待ちの他のエージェント・セッションからのメッセージが表示されない問題を修正。トランスクリプトの下に「waiting」として全文表示される
- 長いツール出力のプレビューが絵文字の途中で切断され、`jq` で解析できないセッショントランスクリプトが残る問題を修正
- 親の `/proc` を共有する Linux サンドボックスで、PDF のページ範囲指定の Read が「File does not exist」と報告する問題を修正
- Claude Desktop ホストのセッションで、接続のリフレッシュ時にメッセージが失われることがある問題を修正
- 同じコンピューターのターミナルが別のアカウント・組織にサインインしている場合、Claude デスクトップアプリ内の Claude Code セッションで機能が欠ける問題を修正
- `claude remote-control` のステータスラインが、git リポジトリでないフォルダーでブランチとして `HEAD` を表示する問題を修正
- 分割ペインのエージェントチームメイトが、リーダーのコマンドラインで指定されたツール deny ルールと `--tools` ルールを継承しない問題を修正
- `/rename` で名前を変更したセッションが、VS Code ウィンドウのリロードや非対話の `--resume` 後、他のセッションからは生成された名前で見える問題を修正
- `/rewind` のリストが、`/code-review --fix`、サブエージェント、シェルコマンドでチェックポイント対象のファイルを変更したターンに対して「No code changes」と表示する問題を修正
- `/privacy-settings` が古い「Help improve our AI models」の値を表示していた問題を修正。設定を取得できない場合はその旨も表示される
- 組織がフィードバックを受け付けていない場合に「try again later」と表示される問題を修正 (サーバー側の理由とバグ報告先が表示される)。また、サイズ超過の `/feedback` レポートが失敗せず、トランスクリプトなしで再送されるようになった

#### スキル・プラグイン・フックの修正

- `--add-dir` フォルダー内のスキルが、同名のスキルが既に存在すると到達不能になる問題を修正。`<folder>:<name>` として提供される
- `/verify` と `/code-review` が、シェルからファイルを変更した場合にネストされたパッケージ自身のスキルを見つけられない問題を修正
- PowerShell で実行されるフックが終了コード 2 でブロックしない問題と、Windows で Git for Windows 未インストール時に `"shell": "powershell"` の `PreToolUse` / `PermissionRequest` フックがフェイルオープンする問題を修正
- mod の `turn.step` フックが `haiku` などのモデルエイリアスを指定するとすべてのリクエストがモデルエラーで失敗する問題を修正 (エイリアスが解決されるようになった)
- claude.ai から同期されたプラグインとスキルが、ディスク読み取りエラー後に (ときにはセッション途中で) 削除される問題を修正
- `/claude-api` スキルのドキュメント修正 (ワーカーのトレースコンテキスト、C# トレーシングのスパン欠落、AWS 上の Claude Platform へのリクエストのトレース結合に関する記述)

#### API・その他の修正

- 一部の通常のページ (特定のミニファイされたスクリプトを含むページや、Claude が先に読み取れなかったアーティファクト) で、アーティファクトの公開・更新が拒否される問題を修正
- ターン中に会話がコンパクトされた後、そのターンの残りでアーティファクト更新のたびに権限を求める問題を修正
- `ANTHROPIC_BEDROCK_BASE_URL` がデフォルトの `bedrock-runtime.<region>.amazonaws.com` エンドポイントに設定されている場合、Amazon Bedrock で fine-grained tool streaming が無効のままになる問題を修正
- キープアライブの ping のみを送るゲートウェイの背後で「Waiting for API response」のヒントがちらつく問題を修正。Anthropic バックエンド以外のルートは 45 秒待機する
- Claude が PR、Issue、コメントにロール名やプレースホルダーをメンションとして書き込み、無関係の GitHub ユーザーに通知してしまう問題を修正
- **macOS**: Xcode や Command Line Tools がない Mac で、起動のたびに「Install Command Line Developer Tools」ダイアログが開く問題を修正
- **自己ホスト型ランナー**: 最初のプロンプト (`/code-review` など) がまだサブエージェントで動作中のセッションを `--startup-timeout-min` が停止してしまう問題を修正 (フリーズしたプロセスは引き続き停止される)

#### 改善

- **git コマンドの高速化**: Claude Code が自身のために実行する多くの git コマンドが Windows で高速化された。全プラットフォームで、これらのコマンドのエラーは git が他言語に設定されていても英語で表示される
- **エラーメッセージの改善**: ネストが深すぎて読み込めないフックモジュールのエラーがファイル名を表示するようになった。ディスクフルで中断された Bash コマンドはその旨と空き容量を確保すべきフォルダーを示し、一時ボリュームが満杯の状態での起動も明確なメッセージを表示する
- **`/claude-api` スキル**: OpenTelemetry の追加を求められた際に SDK トレーシングと並んで API トレーシングを提案し、機能を未サポートと答える前にライブドキュメントを確認するようになった。サービスアカウントキーと Workload Identity Federation トークンで OpenTelemetry の送信先を管理できることも反映された
- **自己ホスト型ランナー**: 新しいランナーへ移動したセッションで、中断されたツール呼び出しが「結果不明」として Claude に見えるようになった
- **dataviz スキル**: テキストコントラストの指標として APCA を受け付けるようになり (AA 準拠が必要な箇所では WCAG 2 の比率を維持)、パレット検証スクリプトに `apca(text, background)` 関数が追加された

#### 動作変更

- **`sed -i`**: シミュレートされたファイル編集プレビューではなく、標準の Bash プロンプトを受けて書かれたとおりに実行されるようになった。他の Bash 編集と同様、`/rewind` では復元されない
- **`claude ultrareview`**: ワークスペーストラストが必須になった。ターミナルでは確認を求め、それ以外では拒否される。スクリプトでは `--trust-workspace` フラグ (値を取らない。PR 番号やベースブランチはその前に置く) を渡すか、`CLAUDE_CODE_DISABLE_ULTRAREVIEW_TRUST_CHECK=1` を設定する
- **bypass permissions モードでの `rm` / `rmdir`**: デスクトップアプリと VS Code では、危険な `rm` / `rmdir` のプロンプトが即座に拒否され、書き換えのヒントが示されるようになった。無人セッションが停止しなくなる
- **サンドボックス除外コマンド**: サンドボックスが有効だが実行できない場合、設定でサンドボックスから除外されたコマンドは write-list パスへの書き込み前に確認を求め、サンドボックスなしのフォールバックは拒否される
- **ワークツリーの作成と再利用**: git がオンデマンドでオブジェクトをフェッチしなくなった。Bash サンドボックスが設定された partial clone では、先にオブジェクトをフェッチする
- **`/claude-api` スキル**: Managed Agents のサブエージェントチームを、`coordinator` ではなくダイナミックワークフローがデフォルトで有効な `multiagent_20261001` で構築するようになった

#### プラットフォーム別の修正・改善

**VSCode 拡張:**

- TLS 検査プロキシの背後などで証明書検証に失敗した場合の対処方法を示すログ警告を追加
- エディターが不完全なファイルのコピーをキャッシュした後、Claude パネルが空白のままになる問題を修正 (自動回復、または原因と対処の表示)
- メッセージを送信せずに新しいセッションを開始するたびに、空の「Untitled」セッションがセッション履歴に溜まる問題を修正
- `/goal` などの長いスラッシュコマンドメッセージや、パネルを狭めた後の長いメッセージが「Show more」の背後に折りたたまれない問題を修正
- `~/.claude/keybindings.json` の Chat コンテキストで "ctrl+j" を null に設定した場合、Ctrl+J の動作が VS Code と OS に委ねられるようになった
- mod の「From the … plugin」ラベルがスラッシュコマンドや @ メンションメニューに重なって描画される問題を修正
- コピーした LaTeX 数式の貼り付けで空のリスト項目・段落・コードブロックが生じ、リスト項目が 1 から振り直される問題を修正
- チャットパネルでの Edit / Write が高速化された。各編集後の新しい problems の待機時間が、ほとんどの場合 1〜1.5 秒から 0.75 秒に短縮された

**Cloud sessions:**

- ルーティンフォームの Add connector リストが、読み込み中に「コネクタなし」と表示する問題を修正
- クラウド環境エディターが環境変数を並べ替え、両方の種類の引用符を含む値にバックスラッシュを追加する問題を修正
- 管理設定の自己ホスト環境詳細ダイアログで、タイトル・タブ・ボタンが固定され、コンテンツのみスクロールするようになった
- 「read documentation」ツールの行が、読みやすいページではなくエスケープされた JSON を表示する問題を修正
- Changes ペインが、プッシュ済みコミットのみ、または Claude の編集のみを表示している場合にその旨を示すようになった

**Claude Tag (Slack 連携):**

- 承認済みのチャンネル向けドラフトを誤って DM に投稿する問題を修正。チャンネル指定のない投稿は拒否される
- セッション停止後に承認カードの Allow / Deny が機能しない問題を修正 (回答によりセッションが再起動される)
- ワークスペースが別の Claude 組織へ移動した後、チャンネルのタグなしメッセージを無視する問題を修正 (Enterprise Grid の非共有チャンネルを含む)
- スレッドに追加された新しいメッセージを読む前に、スレッド返信を投稿してしまう問題を修正
- 管理設定の Slack ページで、リストの読み込み失敗時に「ワークスペース未接続」と表示される問題を修正 (Retry ボタン付きのエラーが表示される)

**Code Review:**

- チェックの作成が失敗した後、完了したレビューがプルリクエストにチェックを表示しない問題を修正 (最終試行で完了チェックが追加される)
- `@claude review stop` の後、実行中のレビューの背後でキューされたプッシュがレビューを開始してしまう問題を修正 (チェックが閉じられ、理由が表示される)

### v2.1.308 について

v2.1.308 の変更内容は「Bug fixes and reliability improvements」のみであり、個別の変更点は公表されていない。

## 開発者への影響

### 対象

- Claude Code CLI / VSCode 拡張 / Cloud sessions / 自己ホスト型ランナーのすべてのユーザー
- サンドボックスや権限ルール (`denyWrite`、`Edit(path)` deny、ワークツリー分離など) でツール実行を制限しているエンタープライズ管理者・開発者
- `claude ultrareview` を CI スクリプトから実行しているチーム
- フック・プラグイン・スキルを開発しているユーザー (特に Windows / PowerShell 環境)
- Slack 連携 (Claude Tag) や Code Review を利用している組織

### 必要なアクション

- **アップデートの適用**: `claude update` または npm 経由で v2.1.309 に更新する。権限境界のバイパスに関わる修正が多数含まれるため、サンドボックスや deny ルールに依存して運用している環境では早期の適用を推奨する
- **`claude ultrareview` を使うスクリプトの更新**: ワークスペーストラストが必須になったため、非対話実行では `--trust-workspace` フラグの追加、または `CLAUDE_CODE_DISABLE_ULTRAREVIEW_TRUST_CHECK=1` の設定が必要になる
- **`sed -i` を含むワークフローの確認**: `sed -i` はファイル編集プレビューではなく通常の Bash コマンドとして実行され、`/rewind` で復元されなくなった。編集の巻き戻しに依存している場合は Edit ツールの利用を検討する
- **Windows / PowerShell フックの確認**: 終了コード 2 でのブロックが正しく機能するようになったため、フェイルオープンを前提としていたフックの挙動を確認する
- **bypass permissions モードの無人運用**: デスクトップアプリと VS Code では危険な `rm` / `rmdir` が即時拒否されるようになったため、削除を伴う自動化タスクは挙動の変化に注意する

### 移行ガイド (該当する場合)

破壊的変更は少ないが、以下の動作変更に注意が必要である。

- `claude ultrareview` は、ターミナル以外ではワークスペーストラストなしに実行できなくなった
- `sed -i` は書かれたとおりに実行され、`/rewind` の対象外になった
- サンドボックスが有効だが実行できない環境では、サンドボックス除外コマンドの write-list パスへの書き込みに確認が入り、サンドボックスなしのフォールバックは拒否される

## まとめ

v2.1.309 は、シンボリックリンク、サブシェル、複合コマンドなどを経由した権限境界のバイパスを塞ぐセキュリティ強化が中心の大型保守リリースである。サンドボックスや deny ルールを前提に Claude Code を運用している組織にとって重要度が高く、早期のアップデートが望ましい。あわせて、`claude ultrareview` のトラスト必須化や `sed -i` の扱いの変更など、スクリプトや自動化に影響する動作変更が含まれるため、CI などの非対話実行環境では事前の確認が必要である。v2.1.308 は詳細非公表の保守リリースである。
