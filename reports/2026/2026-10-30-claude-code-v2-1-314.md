## 概要

Claude Code v2.1.314 がリリースされた。本バージョンは 119 項目に及ぶ大型アップデートで、新しい権限設定 `permissions.blockWritesOutsideWorkingDirectories` の追加により、すべての権限モードで作業ディレクトリ外への書き込みを拒否できるようになった。また、VS Code と Claude Desktop の Code タブにアイドルコンパクションが追加され、200K トークンを超えて放置された会話が自動的に要約されるようになった。

エンタープライズ向けでは、Claude apps gateway に IdP グループ単位でアップストリームを割り当てる `groups` リストと、Amazon Bedrock ガードレールの発動を記録する `guardrail_trace` が追加された。修正面では、組織管理者による effort 上限設定時の「Invalid effort level」失敗、`claude -p` の起動失敗時に終了コード 0 で出力なしになる問題、Bedrock で画像が多いセッションが「400 Input is too long.」で失敗し続ける問題など、多数の不具合が解消されている。

## 詳細

### 主な変更点

#### ハイライト

- **`permissions.blockWritesOutsideWorkingDirectories` の追加**: この設定を有効にすると、Write、Edit、NotebookEdit の各ツールが、どの権限モードでも作業ディレクトリ外のパスへの書き込みを拒否するようになる。意図しないファイル変更を防ぐガードレールとして機能する
- **アイドルコンパクション**: VS Code と Claude Desktop の Code タブに追加された。200K トークンを超える会話が放置されると要約が作成され、プロンプトキャッシュの期限が切れていた場合は次のメッセージでその要約が使用される。長時間の会話を再開する際の待ち時間とコストの削減につながる
- **Claude apps gateway の `groups` リスト**: アップストリームにオプションの `groups` リストを指定すると、リストにある IdP グループに所属する開発者のみがそのアップストリームへ送られる。フェイルオーバー時にも適用される
- **Claude apps gateway の `guardrail_trace`**: Bedrock アップストリームに追加され、リクエストで発動した Amazon Bedrock ガードレールフィルターを、マッチしたテキストを含めずにログに記録できる
- **「Invalid effort level」失敗の修正**: 組織の管理者がモデルの effort に上限を設定している場合に、セッションがターンごとに「Invalid effort level」で失敗し続ける問題を修正。Claude Code は effort を下げてリトライし、使用するレベルを表示するようになった
- **`claude -p` の終了コード修正**: 起動に失敗した際に終了コード 0 かつ出力なしで終了していた問題を修正。エラーを表示し、終了コード 1 で終了するようになった。CI などで失敗を検知できなかったケースが解消される
- **Bedrock の画像多数セッションの修正**: 画像が多い Bedrock セッションで、古い画像を削除してコンパクトする代わりに、毎ターンおよび `/compact` が「400 Input is too long.」で失敗していた問題を修正

#### Added (新機能)

- Enterprise 組織向けに、Slack 接続時の管理設定 Bundles / Channels タブに Claude Tag API ドキュメントへのリンクを追加 (非表示化可能)
- Cloud sessions の Scheduled tasks ページに、完了した一回限りのタスクのみが非表示の場合に Include completed ボタンを追加

#### Fixed (修正)

接続・プラットフォーム関連の修正。

- Microsoft Foundry で、デフォルトの Sonnet / Opus / Haiku モデルのデプロイがないリソースでセッションが失敗する問題を修正。同系統の旧モデルにフォールバックするようになった
- ツール検索の `tool_reference` ブロックを受け付けないゲートウェイ経由でリクエストが拒否され続ける問題を修正。ツール検索なしで一度再送し、セッションがそれを記憶する
- ゲートウェイやクラウドプロバイダーが Claude Code の beta ヘッダーを名指しで拒否した場合に、該当ヘッダーなしで再送するようになった
- LLM ゲートウェイ経由でドット付きのモデル ID (`claude-opus-4.8` など) が旧モデルとして扱われ、コンテキストウィンドウ、出力上限、effort、思考モード、コストが誤っていた問題を修正
- システム証明書ストアに前任証明書とクロス署名された更新済みルート証明書がある場合に、TLS 接続が `UNABLE_TO_GET_ISSUER_CERT` で失敗する問題を修正
- Claude apps gateway の Vertex アップストリームが、Google のトークンエンドポイントが接続を受け付けたまま応答しない場合に数分間ハングする問題を修正

権限・設定・セキュリティ関連の修正。

- `claude -p --resume` または `--continue` で入った worktree にサンドボックス保護が適用されない問題を修正
- `--setting-sources` で除外した設定ファイルが、auto モードのルールや保存済みの許可など一部の設定を供給し続ける問題を修正
- Bash にマッチするフックが Monitor ツールの開始するシェルコマンドで実行されない問題を修正 (ブロックと確認は可能、承認と書き換えは不可)
- auto モード、deny ルール、PreToolUse フックがブロックしたシェル / MCP 呼び出しが、折りたたまれたツールグループ内で実行済みのように見える問題を修正
- 管理者の TLS 信頼設定が Claude Desktop セッションに適用されない問題を修正
- リモート managed settings のみで設定された `forceRemoteSettingsRefresh` が、保存済みコピーの期限切れ後に適用されなくなり、サーバー到達不能時にポリシーなしでセッションが開始できていた問題を修正

セッション・動作関連の修正。

- 「使用量制限で自動継続」が、タスクが待機の合間に自己再起動した場合 (/goal のチェックイン、バックグラウンドタスク、スケジュールタスク) に、確認なしで 3 回を超えて継続する問題を修正
- 出力が非常に大きい PreCompact フックがコンパクションを失敗・反復させる問題を修正。各フックの出力は 10,000 文字で切り詰められる
- バックグラウンドの diff 更新がリポジトリの index ロックを一時的に取得し、同時に実行した git コマンドが「Unable to create '.git/index.lock': File exists」で失敗することがある問題を修正
- MCP サーバーのサインインが無効になった後、サインインなしでも動作するサーバーが「needs authentication」と表示される問題を修正 (サインアウト状態で使用される)
- `claude mcp logout` が、macOS キーチェーンが SSH 越しにロックされている場合など、サインインを削除できていないのに成功と報告する問題を修正
- `--resume` や、拒否後のモデル切り替えをまたいだ巻き戻しが、Claude Code の認識しないモデル名のセッションを別モデルへ移動させる問題を修正
- vim モードの `dw` / `dW` / `yw` / `yW` が行末を越える問題、`aw` / `iw` が行末の改行を取り込む問題など、複数の vim モードの挙動を修正
- このほか、ターミナル UI (マークダウンテーブルの表示、エージェントパネルの操作対象、ペースト時のテキスト消失など) とセッション管理 (セッションタイトル、/resume ピッカーの表示など) に関する多数の修正が含まれる

#### Changed (動作変更)

- アイドルコンパクションが、テレメトリをオフにしている Subscriber にも実行されるよう変更。また、1 時間プロンプトキャッシュが有効な場合は Bedrock / Vertex / Foundry / LLM ゲートウェイでも実行される
- Claude のファイルツールが、組織のサーバー管理設定のローカルコピーを編集する前に、ユーザーの設定ファイルと同様に確認を求めるよう変更
- `ANTHROPIC_DEFAULT_OPUS_MODEL`、`availableModels`、`deniedModels` により旧 Opus モデルのみ、またはモデルが残らない場合、フラグされたリクエストが拒否で終わらず別モデルでリトライするよう変更
- Bash ツールのシェルが、継承された `which` のエイリアスや関数をクリアし、エクスポートされた `which` / `unsetenv` 関数をコマンドへ渡さないよう変更。`which` はシステムコマンドまたは zsh ビルトインになる
- フックの `if` 条件 (`Monitor(tail *)` など) が、`Bash(tail *)` が Bash にマッチするのと同様に、Monitor ツールのシェルコマンドにマッチするよう変更
- `/permissions` のレビュータブは Recently blocked に名称変更され、全文を読めない呼び出し (ターミナルが短すぎて表示できないものを含む) の承認を拒否するよう変更
- auto モードのブロック時メッセージを改善。コマンド名を示し、Claude がリトライする可能性と auto モードが再チェックすることを伝え、`/permissions` でのレビューを案内する
- `FORCE_HYPERLINK=false` (`no`、`off` も同様) が、ハイパーリンクをオンではなくオフにするよう変更
- macOS で、Claude が実行するほとんどのコマンド内の `git grep` が C ロケールを使用するよう変更 (UTF-8 として不正なファイルで報告された macOS の正規表現ライブラリのメモリリークを回避)
- 多数のサブエージェントを実行する長い headless / SDK ターンのメモリ使用量を改善。親セッションが各サブエージェントのツール結果をターン終了まで保持しなくなった
- プロンプト履歴の Ctrl+R が、折りたたまれた `[Pasted text]` ピル内のテキストにもマッチするよう改善
- スキルや `/security-review` などのプロンプトベースコマンドで始まるセッションが、無題のままではなくそこからタイトルを取得するよう改善
- `--resume` の速度と破損トランスクリプトでのメモリ使用量、1 万以上の MCP ツールを持つセッションでの `/context` の速度を改善

#### コンポーネント別の変更

**VSCode:**

- MCP サーバーの「Clear authentication」が、保存済みサインインを削除できていないのに成功と報告する問題を修正
- キュー済みメッセージのフック実行中にスピナーと Stop ボタンが表示されない問題を修正
- 保存できないセッショングループの変更 (削除など) が静かに失敗する問題を修正。エラー通知が表示されるようになった
- プランプレビュータブで Cmd+F / Ctrl+F が検索ウィジェットを開かない問題を修正
- ロシア語、ギリシャ語、ヘブライ語など非ラテン系キーボードレイアウトで音声入力ショートカット (Ctrl+D) が動作しない問題を修正
- `CLAUDE_CODE_DISABLE_CFC_PROMPT` が、拡張機能によるセッションへの Claude in Chrome 指示の追加も停止するよう変更 (ブラウザーツールは引き続き利用可能)

**Cloud sessions:**

- 最近使用したセルフホスト環境が、新規セッションカードの最近の環境に表示されない問題を修正
- Claude が別の worktree からプッシュ済みのコミットへブランチを移動した後、クラウドセッションが毎ターン未コミットの変更を報告する問題を修正
- 実行中のクラウド / Remote Control セッションが切り替えを拒否した後も、権限モードピッカーが Auto のままになる問題を修正。実際に使用中のモードを表示し、通知するようになった
- Anthropic のクラウドで実行されるスケジュールタスクが、claude.ai アカウントで有効なプラグインを読み込むよう改善
- 管理設定の GitHub Enterprise の Test connection が、クラウドセッションと同じ方法でも接続テストを行い、失敗時に警告するよう改善
- Web / デスクトップ / モバイルアプリからのクラウドセッションが、セットアップスクリプトがエラー終了しても開始失敗せずに起動するよう変更

**Remote Control:**

- Remote Control セッションの権限モードボタンが、入力するまで誤ったモードを表示する問題を修正。コンピューターがオンラインの間は、開いた時点で実際のモードを表示する
- 8 秒を超えるモデル切り替えが最終結果の代わりに「still pending」エラーになる問題、/compact 後に不要な「Compacted」行が表示される問題を修正
- セッションサービスが一時的に遅い場合に `claude remote-control` セッションが開始に失敗する問題を修正。ワーカーの登録が待機時間を増やしながらリトライされる

**Claude Tag:**

- Enterprise Grid の共有チャンネルで `@Claude !restart` がワークスペースチェック 1 回の失敗で諦める問題を修正。リトライした後、再実行を依頼するようになった
- 両組織が Claude をインストールした Slack Connect チャンネルで、自身のスレッド内のタグに応答しないことがある問題を修正
- セルフホストランナーを待機中のセッションで、Slack のフォローアップメッセージに進捗が表示されない問題を修正。スレッドに待機通知が投稿される
- 管理設定のプラグイン / スキルページで、読み込み失敗後の Retry が未保存のアクセス変更を破棄する問題を修正

### 技術的な詳細

- **作業ディレクトリ外書き込みの拒否**: `permissions.blockWritesOutsideWorkingDirectories` は権限モードに関わらず適用されるため、`bypassPermissions` のような緩いモードでもファイル書き込みの範囲を作業ディレクトリに限定できる
- **アイドルコンパクションの仕組み**: 200K トークンを超えた会話が放置されるとバックグラウンドで要約が作成される。プロンプトキャッシュが有効なうちは元の会話が使われ、期限切れの場合のみ要約が使用されるため、通常の応答品質に影響しにくい設計になっている
- **effort 上限への自動適応**: 組織ポリシーで effort が制限された場合、従来はリクエストが失敗し続けていたが、クライアント側で自動的に許容レベルまで下げてリトライするようになった

## 開発者への影響

### 対象

- Claude Code CLI / VS Code 拡張機能 / Claude Desktop のユーザー
- `claude -p` を CI やスクリプトに組み込んでいるユーザー
- Claude apps gateway を運用する管理者 (特に IdP グループでのルーティングや Bedrock ガードレールの監査が必要な組織)
- Bedrock、Vertex、Foundry、LLM ゲートウェイ経由で Claude Code を利用するユーザー
- effort 上限などの組織ポリシーを設定している管理者
- Cloud sessions、Remote Control、Slack の Claude Tag の利用者

### 必要なアクション

- 通常のアップデートで新機能と修正が適用される。特別な移行作業は不要
- 作業ディレクトリ外への書き込みを禁止したい場合は、`permissions.blockWritesOutsideWorkingDirectories` を設定に追加する
- `claude -p` の終了コードを監視しているスクリプトは、起動失敗が終了コード 1 として正しく報告されるようになったため、エラーハンドリングが期待どおり動作することを確認する
- Claude apps gateway の管理者は、アップストリームの `groups` リストと Bedrock アップストリームの `guardrail_trace` の活用を検討する
- `FORCE_HYPERLINK=false` を設定している環境では、ハイパーリンクがオフになる動作変更に注意する

## まとめ

Claude Code v2.1.314 は 119 項目の変更を含む大型リリース。`permissions.blockWritesOutsideWorkingDirectories` による作業ディレクトリ外書き込みの拒否と、VS Code / Claude Desktop の Code タブへのアイドルコンパクション追加が新機能の柱となる。エンタープライズ向けには Claude apps gateway の `groups` リストと `guardrail_trace` が追加され、組織の effort 上限による「Invalid effort level」失敗、`claude -p` の終了コード、Bedrock の画像多数セッションなど運用上影響の大きい不具合も修正された。CI で `claude -p` を利用している場合や、ゲートウェイ / クラウドプロバイダー経由で運用している場合は、本バージョンへの更新を推奨する。
