## 概要

Claude Code v2.1.270 がリリースされた。今回のリリースは修正 1 件のみの小規模なホットフィックスで、**セッションが長時間実行された後に、Bash の読み取り専用 git コマンドが予期せずパーミッション確認を求める問題**を修正している。これは前バージョン v2.1.269 で発生したリグレッションであり、大型リリース直後の迅速な追従修正という位置づけである。

`git status` や `git log` のような読み取り専用 git コマンドは、本来リポジトリの状態を変更しないため権限確認なしで実行できる。v2.1.269 ではセッションが一定時間経過した後にこの判定が機能しなくなり、これらのコマンドに対して不要な確認プロンプトが表示されるケースがあった。v2.1.270 により、長時間セッションでも従来どおり確認なしで実行される動作に戻っている。

## 詳細

### 背景

前バージョンの v2.1.269 (2026 年 9 月 11 日リリース) は、`claude plugin eval` の導入、プロンプトキャッシュの安定性改善、権限ルールの修正強化など約 98 件の変更を含む大型リリースだった。その中には読み取り専用 git コマンドに関連する変更 (コンパクション後の git ステータス修正など) や権限システムの複数の修正が含まれており、この過程で読み取り専用 git コマンドの権限判定にリグレッションが混入した。

Claude Code は、リポジトリの状態を変更しない読み取り専用の git コマンドを権限確認なしで実行できるよう扱っている。この動作はコードベースの探索や状態確認を頻繁に行うワークフローの快適さを支える基盤であり、リグレッションの影響は日常的な操作に直結するため、翌日に単独の修正としてリリースされた。

### 主な変更点

#### 修正 (Fixed)

- **読み取り専用 git コマンドの権限確認**: セッションが長時間実行された後、Bash の読み取り専用 git コマンドが予期せずパーミッション確認を求める問題を修正 (v2.1.269 のリグレッション)

### 技術的な詳細

この問題の特徴は、**セッション開始直後には発生せず、セッションが一定時間実行された後に顕在化する**点である。セッション開始直後は読み取り専用 git コマンドが期待どおり確認なしで実行されるため、短時間の利用では気付きにくい。一方、長時間の作業セッションや、自動化されたヘッドレスセッションでは、途中から `git status` や `git diff` のようなコマンドに確認プロンプトが挟まるようになり、作業の中断や自動化フローの停止を引き起こし得る。

v2.1.270 ではこの時間経過による判定の劣化が解消され、セッションの実行時間にかかわらず読み取り専用 git コマンドが一貫して確認なしで実行されるようになった。

## 開発者への影響

### 対象

- **v2.1.269 を利用しているすべてのユーザー**: 長時間セッションで読み取り専用 git コマンドに不要な確認プロンプトが表示される問題が解消される
- **長時間セッションで作業する利用者**: セッションの経過時間にかかわらず、`git status` や `git log` などが確認なしで実行される動作に戻る
- **ヘッドレス・自動化環境の利用者**: 予期しない権限確認による自動化フローの停止リスクが解消される

### 必要なアクション

v2.1.269 を利用している場合は、以下のいずれかの方法で v2.1.270 に更新することを推奨する。

```bash
# Claude Code 組み込みコマンド
claude update

# npm でのアップデート
npm update -g @anthropic-ai/claude-code

# バージョンを指定してインストールする場合
npm install -g @anthropic-ai/claude-code@2.1.270

# 現在のバージョン確認
claude --version
```

### 移行ガイド (該当する場合)

破壊的変更はない。設定の変更やワークフローの調整は不要で、更新のみで修正が適用される。
