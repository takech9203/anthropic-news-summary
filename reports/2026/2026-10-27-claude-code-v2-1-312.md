## 概要

Claude Code v2.1.312 がリリースされた。本バージョンでは、Claude apps gateway に `oidc.user_id_claim` が追加され、Microsoft Entra ID の `oid` など `sub` 以外の id_token クレームでユーザーを識別できるようになった。また、フルスクリーン表示でキュー済みメッセージをクリックで即時送信できる「クリックで送信」機能が追加された。

修正面では、巨大な CLAUDE.md などの上書き防止、VS Code 拡張機能からのサインイン後に managed settings が取得されない問題、vim モードの挙動など多数の不具合が解消された。さらに、Bedrock / Vertex / Foundry / Mantle における未認識モデル名への短縮システムプロンプト適用や、プロンプト / エージェントフックの同時実行数制限 (セッションあたり最大 24) などの動作変更も含まれる。VSCode、Cloud sessions、Remote Control、Claude Tag、Code Review の各領域でも改善が行われている。

## 詳細

### 主な変更点

#### Added (新機能)

- **`oidc.user_id_claim` の追加**: Claude apps gateway に `oidc.user_id_claim` が追加された。Microsoft Entra ID の `oid` のように、`sub` 以外の id_token クレームでユーザーを識別できる
- **クリックで送信**: フルスクリーン表示で、キュー済みメッセージの下に表示される「to send now」ヒントをクリックすると、対応するキーと同様にそのメッセージを即時送信できる

#### Fixed (修正)

- VS Code 拡張機能からサインインした後、そのセッションの残りの間 managed settings と組織ポリシーが取得されない問題を修正
- 非常に大きな CLAUDE.md、rules ファイル、サブディレクトリの @-included ファイルを、Claude が冒頭部分しか読んでいない状態で上書きしてしまう問題を修正。Write ツールが全体を読むか、その場で編集するよう Claude に求めるようになった
- git リポジトリ内で Bash の `cd` により深い階層へ移動した後、ディレクトリ単位および `paths:` 指定のスキルが見つからない問題を修正
- ターミナルでセッションを再開した後の最初の返信が、次回の再開時に欠落することがあるまれな問題を修正
- 無効な名前のコマンドがすべてのコマンドの読み込みを停止させ、`claude -p` が出力なしになることがある問題を修正
- 古いセッションファイルのクリーンアップが同時に実行された際、Read ツールが PDF ページで「pdftoppm failed: Could not write image」エラーになることがある問題を修正
- スピナー、OpenTelemetry の `effort` 値、トランスクリプトが、タスク中に新しく選択された effort レベルをモデル適用前に表示していた問題を修正。現在は実際に有効なレベルを表示する
- `/model` と `/effort` のキャッシュ警告が「再読み込みは次のメッセージまで待つ」と表示していた問題を修正。Claude の作業中に行われた変更はより早く反映されることがある
- 最後のメッセージが文中でユーザー待ちの項目に触れただけのセッションが、ユーザー待ちとして表示される問題を修正
- 終了直前に Ctrl+C でクリアした入力テキストが、次回起動時にエージェントビューで復元される問題を修正
- 空の `!` 入力から Ctrl+D で終了した後、エージェントビューがシェルモードで再度開く問題を修正
- vim モードで `d`、`c`、`y` に残り行数より大きいカウント付きの `gj` / `gk` を組み合わせるとテキストを削除またはコピーしてしまう問題を修正。Vim と同様、カーソル移動のみになった
- `/verify` が `/help` と `/` コマンドメニューで、短い説明ではなく Claude 向けの長い説明を表示していた問題を修正

#### Improved (改善)

- プロンプトの effort インジケーターを改善。タスク中の変更は次のメッセージまで待つ可能性があると表示し、不要になると注記が消える
- クラウドセッションにおける WebFetch エラーを改善。ホストが解決できない場合、許可されたネットワークドメイン外の可能性があると説明され、Claude が許可すべきホスト名を提示する

#### Changed (動作変更)

- Bedrock、Vertex、Foundry、Mantle で、カスタムデプロイ名や推論プロファイル ARN など Claude Code が認識しないモデル名に対して、Sonnet や Haiku をフロントしている場合でも短いシステムプロンプトを使用するよう変更。`CLAUDE_CODE_SIMPLE_SYSTEM_PROMPT=0` で従来のフルプロンプトを維持できる
- フラグされたメッセージ後の自動モデル切り替えが、カスタムデプロイ名など Claude Code が認識しないモデル名もカバーするよう変更。`CLAUDE_CODE_DISABLE_REFUSAL_FALLBACK=1` で無効化できる
- 使用量制限メッセージで、5 時間ウィンドウを「session limit」ではなく「5-hour limit」と呼ぶよう変更
- CLI から開始したクラウドセッションは、セッション名とブランチ名をサーバーから取得するよう変更
- プロンプトフックとエージェントフックの同時実行数を、サブエージェントを含めセッションあたり最大 24 に制限。さらに、イベントのタイムアウトより長く待機したものは最大 12 に制限。1 秒未満の `timeout` は 1 秒として扱われる
- サブエージェントの `autoCompactWindow` が、従来は効果のなかった `CLAUDE_CODE_AUTO_COMPACT_WINDOW` によるウィンドウの引き下げに対応。引き上げは引き続き行われない
- OpenTelemetry の `mcp_server.name` が、公式 Anthropic マーケットプレイスのプラグインが宣言する固定 URL リモート MCP サーバーについて、`custom` ではなく実際の名前を報告するよう変更
- OpenTelemetry の `claude_code.safety_event` イベントの送信を停止

#### コンポーネント別の変更

**VSCode:**

- 組織設定が読み込めない、または起動時に拒否された場合に、セッションが終了コードのみで終了する問題を修正。タブに理由が表示され、Retry または再サインインを選択できる
- 使用量制限のリセット表示を時刻表示 ("Resets at 3:10 PM") に変更し、「5-hour limit」と表記するよう変更

**Cloud sessions:**

- クラウドで実行するルーティンの作成・編集時に、モデルピッカーに effort レベルを追加
- クラウド環境設定のセットアップスクリプト欄に、カラー表示・行番号・Copy ボタン付きの Bash エディターを追加
- Claude がクラウドセッションにリポジトリを追加した際のステップ表示を改善。生の JSON ではなく、実行内容の短いテーブルが表示される
- 送信失敗後に未変更のメッセージを再送信すると、まれに 2 回実行される問題を修正
- クラウド環境の作成失敗時、エラーが開いているダイアログの外にトーストとしてのみ表示される問題を修正。ダイアログ内に表示されるようになった
- Routines ページのルーティンメニューにある Edit が、編集ダイアログを開かずにルーティンのページへ遷移する問題を修正

**Remote Control:**

- アーカイブ解除した Remote Control セッションが、コンピューターが再接続するまで作業中として表示される問題を修正。アイドルとして表示されるようになった

**Claude Tag:**

- Slack での Claude Tag のリトライ通知を改善。汎用的な API エラーではなく、使用中のモデル名やレート制限到達を表示する
- 古いプライベート Slack チャンネルがパブリックになり新しい ID を取得した際、チャンネルのオン / オフスイッチとエージェント設定がワークスペースのデフォルトに戻る問題を修正
- ネットワークアクセスが None に設定された環境のチャンネルで、Slack の Claude が返信しない問題を修正
- 同じチャンネルの別スレッドで回答中に、誤ったスレッドにファイルを投稿することがある問題を修正

**Code Review:**

- GitHub が push イベントを遅れて配信した場合に、古いコミットをレビューする、または何もレビューしない問題を修正。プルリクエストの現在のコミットをレビューするようになった

### 技術的な詳細

本バージョンでは、エンタープライズ環境やサードパーティプラットフォーム利用者に関わる変更が複数含まれる。

- **OIDC 認証の柔軟化**: `oidc.user_id_claim` により、Microsoft Entra ID など `sub` 以外のクレームを使う IdP との統合が容易になる
- **システムプロンプトの最適化**: Bedrock / Vertex / Foundry / Mantle で未認識のモデル名 (カスタムデプロイ名、推論プロファイル ARN など) に短いシステムプロンプトを使用。従来の動作は `CLAUDE_CODE_SIMPLE_SYSTEM_PROMPT=0` で維持可能
- **フックの同時実行制限**: プロンプト / エージェントフックはセッションあたり最大 24 並列 (サブエージェント含む)、タイムアウト超過待機分は最大 12 に制限される

## 開発者への影響

### 対象

- Claude Code CLI / VS Code 拡張機能のユーザー
- Claude apps gateway を OIDC (特に Microsoft Entra ID) と組み合わせて利用する管理者
- Bedrock、Vertex、Foundry、Mantle 経由でカスタムデプロイ名や推論プロファイル ARN を使用するユーザー
- プロンプトフック / エージェントフックを多数利用するユーザー
- Cloud sessions、Remote Control、Slack の Claude Tag、Code Review の利用者

### 必要なアクション

- 通常のアップデートで新機能と修正が適用される。特別な移行作業は不要
- Bedrock / Vertex / Foundry / Mantle で未認識モデル名に対し従来のフルシステムプロンプトを維持したい場合は、`CLAUDE_CODE_SIMPLE_SYSTEM_PROMPT=0` を設定する
- フラグされたメッセージ後の自動モデル切り替えを無効化したい場合は、`CLAUDE_CODE_DISABLE_REFUSAL_FALLBACK=1` を設定する
- 多数のフックを並列実行する構成では、セッションあたり最大 24 の同時実行制限の影響を確認する

## まとめ

Claude Code v2.1.312 は、`oidc.user_id_claim` の追加による認証連携の柔軟化と、クリックで送信機能の追加に加え、大きな CLAUDE.md の上書き防止や VS Code サインイン後の managed settings 取得など多数の修正を含むリリース。Bedrock / Vertex / Foundry / Mantle での未認識モデル名への短縮システムプロンプト適用や、フックの同時実行数制限 (セッションあたり最大 24) といった動作変更もあり、サードパーティプラットフォームや大規模なフック構成を利用するユーザーは関連する環境変数と制限値の確認を推奨する。
