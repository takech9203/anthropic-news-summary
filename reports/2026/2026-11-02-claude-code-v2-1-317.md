## 概要

Claude Code v2.1.317 がリリースされた。合計 87 件の変更を含む大規模なアップデートで、セキュリティ、エンタープライズ管理、可観測性 (Observability) の強化が目立つ。新機能では、Web / シェルツールがアカウントのメールアドレスをネットワークへ送信する前に確認を求めるチェック、Agent SDK フックコールバックの `onFailure: "block"` オプション、OTel テレメトリへの `anthropic.plan` などの属性追加、Claude apps gateway の管理 API に過去の支出を集計するコストレポート `GET /v1/organizations/analytics/cost` が追加された。

修正面では、Claude Desktop セッションでプロジェクト / ローカル MCP サーバーが最初のターン後に切断される問題、LLM ゲートウェイ利用時に auto モードが毎ターン失敗する問題、セッション復元時の会話消失、プロキシ環境での OpenTelemetry エクスポートの停止など、47 件の不具合が解消された。このほか、VSCode 拡張、クラウドセッション、Remote Control、セルフホストランナーなどコンポーネント別の改善も多数含まれる。

## 詳細

### 主な変更点

#### ハイライト

- **アカウントメール送信前の確認チェック**: Web ツールまたはシェルツールの呼び出しがアカウントのメールアドレスをネットワークへ送信しようとする際、事前に確認を求めるようになった。プロンプトインジェクションなどによる意図しない個人情報の流出を防ぐセキュリティ強化
- **`/schedule` のコネクタ警告**: 新しいクラウドスケジュールタスクに、ユーザーが要求していないコネクタが付与された場合に警告を表示し、削除方法を案内する
- **Agent SDK フックの `onFailure: "block"`**: フックコールバックが失敗した場合に、アクションを実行させるのではなくブロックできるようになった。フックをセキュリティゲートとして利用する場合のフェイルセーフ (fail-closed) 動作を実現できる
- **OTel テレメトリの属性追加**: `anthropic.plan`、`anthropic.seat_type`、`anthropic.provider`、`anthropic.custom_base_url` がメトリクス、イベント、スパンに追加された。プランやプロバイダー別の利用分析が可能になる
- **Claude apps gateway のコストレポート API**: 管理 API に `GET /v1/organizations/analytics/cost` が追加され、期間を指定して過去の支出を合計、開発者別、日別、IdP グループ別に取得できる。あわせて、`admin:` を設定したゲートウェイでは各開発者の IdP グループが日次で記録され (`admin.identity_retention_days` の期間保持)、コストレポートのグループ集計に利用される
- **`CLAUDE_CODE_DISABLE_NESTED_SESSION_ID` の追加**: セルフホストランナーで `1` に設定すると、セッション内で実行した `claude -p` が以前のバージョンと同様にそのセッションの ID とトランスクリプトを使用する。既定ではネストした `claude -p` が独自のセッション ID を持つ新動作となる (後述の修正を参照)

#### Added (新機能)

ハイライトのほか、以下が追加された。

- Claude Desktop の Code タブに、組織のリモート管理設定がセッションに読み込まれていない間は通知を表示し、読み込み完了後にも通知を表示する機能を追加
- auto モードのチェックがサブエージェントのツール呼び出しに回答を返せなかった場合に通知を追加。従来はメインビューに何も表示されなかった

#### Fixed (修正)

接続・ゲートウェイ・ネットワーク関連の修正。

- 一部の Claude Desktop セッションで、プロジェクトおよびローカルの MCP サーバーが最初のターン後に切断される問題を修正
- ベース URL に設定した LLM ゲートウェイがサーバーサイドの安全性チェックに 403 または 422 を返す場合に、auto モードが毎ターン失敗する問題を修正 (apiKeyHelper がある 403 の動作は従来どおり)
- TLS 検査を行う一部のプロキシの背後で、ルート証明書の更新後に API リクエストが「unable to get local issuer certificate」で失敗する問題を修正
- リージョンまたはネットワークによるブロック (HTTP 403) がサインイン失敗として表示されていた問題を修正。エラーがブロックの内容を説明するようになった
- Claude apps gateway が Amazon Bedrock の「Input is too long.」エラーを隠し、セッションがコンパクトされずに「upstream rejected the request」で毎ターン失敗する問題を修正
- stdio MCP サーバーの env 設定で `AWS_BEARER_TOKEN_BEDROCK` を空に設定した場合、空文字列ではなく未設定として扱い、サーバーがマシン自身の AWS 認証情報を使用できるように修正

OpenTelemetry 関連の修正。

- プロキシ経由の `https://` エンドポイントへのエクスポートが、別のエクスポートの実行中に開始されると送信されない問題を修正
- `http://` エンドポイントへのエクスポートをブロック (HTTP 403) するプロキシに対して、接続試行が大量に発生する問題を修正
- 応答しないプロキシの背後でエクスポートが無期限にハングする問題を修正。10 秒 (または `OTEL_EXPORTER_OTLP_TIMEOUT`、最大 30 秒) でタイムアウトする

セッション・会話管理関連の修正。

- セルフホストランナーのセッションが、プランの承認待ち中に再起動されると直近のターンや会話全体を失う問題を修正
- 非常に長い会話で、コンパクションが自身のリクエストを短縮する必要がある場合に以前の要約が失われる問題を修正
- 前回の送信以降に非常に大きな CLAUDE.md が変更されたセッションで、自動コンパクション後に「Prompt is too long」が発生する問題を修正
- クラウド / SDK セッションで、タイトル生成中に新しいメッセージや Stop が届くとセッションタイトルが失われる問題を修正
- クラウドまたはセルフホストランナーのセッション内で実行した `claude -p` がそのセッションの ID を共有し、セッションのトランスクリプトに書き込み、再起動時に誤った会話を再開することがある問題を修正。あわせて、独自に生成したタイトルを親セッションに送信する問題も修正
- 再開したセッションが、すでに把握済みのファイル変更を Claude に再度通知する問題と、以前にツールが無効でツール呼び出しが失敗していた場合に組み込みツールを使用しないことがある問題を修正
- フルディスクやクォータ超過でトランスクリプトや ~/.claude.json の書き込みが失われた場合に `claude -p` が終了コード 0 で終了する問題を修正。エラーを表示し、text / json 出力では終了コード 1 を返す
- `claude --from-pr` が、リンクされたセッションが最初のページより古い場合に「No conversations found」と報告する問題を修正
- `claude auth status` が遅いトークンリフレッシュの保存前に終了し、次回実行時にサインアウトされることがある問題を修正

auto モード・権限関連の修正。

- クラウドセッションの auto モードが、Artifact ツールのアップロード、データベース書き込み、outputs フォルダー経由のファイル保存で承認待ちになる問題を修正
- claude.ai とモバイルアプリで、同時に表示された 2 つの権限プロンプトのうち 2 つ目にファイルパスやコマンドが表示されない問題を修正
- Remote Control と SDK ホストが、mod のツール呼び出しに対して「don't ask again」を提示していた問題を修正
- tmux や iTerm2 のペインで動作するエージェントチームのメンバーが、リードセッションが手動モードであるにもかかわらず auto モードで開始される問題を修正
- バックグラウンドセッションが、アップグレードまたはリタイア時に直前の権限モード変更を失うことがある問題を修正

エージェントチーム・スケジュールタスク関連の修正。

- 削除されたエージェントチームの受信箱が、チームメイトの遅延メッセージによって再作成される問題と、再作成されたチームメイトが以前のシャットダウン承認によってチームから削除される問題を修正
- スケジュールタスクを無効化した後、保存済みのタスクを一覧表示・削除できなくなる問題を修正
- `/schedule` がクラウドスケジュールタスクの作成・更新後に、次回実行時刻とリンクを結果に含めない問題を修正
- `/team-onboarding` ガイドの削除指示で対象を指定しなかった場合に、最後に更新したガイドが削除される問題と、サーバーが削除を拒否した場合にも削除済みと報告する問題を修正

そのほかの修正。

- 設定ファイルへの編集が、起動後約 1 秒以内に行われると別の設定変更があるまで反映されない問題を修正
- claude.ai から同期したスキルがディスクに書き込めない場合に、失われたり 10 分ごとに再ダウンロードされたりする問題を修正
- `DISABLE_PROMPT_CACHING_OPUS` と `DISABLE_PROMPT_CACHING_SONNET` が、デフォルトモデルの `[1m]`、他リージョン、日付なしの表記に対して効果がない問題を修正
- Grep と Glob が時間制限に達した際、部分的な結果を完全な結果として扱う問題を修正
- 停止したシェルコマンドの子プロセスに SIGTERM が 2 回送信され、一部のプログラムがクリーンアップをスキップすることがある問題を修正
- Ctrl+C がプロンプトの入力テキストをクリアする際に、実行中のすべてのバックグラウンドエージェントを停止させる問題を修正
- このほか、PDF のメタデータによるページ数の過少カウント、200 件以上のアーティファクト所有時に共有リストが空になる問題、スクリーンリーダーモードでのサブエージェント経過時間の読み上げ、`/loop` の自己ペースウェイクアップ、`/feedback` の表示、ヘッドレスセッションの高メモリ使用と起動遅延などの修正が含まれる

#### Improved (改善)

- Microsoft Foundry で Azure 認証情報を読み込めない場合のエラーを改善。確認または更新を促し、`cloud_credential_error` として報告される
- 必須の Claude apps gateway に到達できない場合の起動エラーを改善。サインインではなくネットワークの問題を指摘し、ゲートウェイの TLS 証明書を検証できない場合はその旨を表示する
- セルフホストランナーのサーバーエラーからの回復を改善。501 / 529 以外の 5xx の後、ランナーの次回ポーリングとセッションは失敗した接続を再利用せず新しい接続を開く。ハートビートに応答がない場合も、アイドル接続を順に試すのではなく新しい接続を開く
- 終了時に表示される「Resume this session with」のヒントが、`--resume` の前に起動時のフラグ (例: `--chrome --debug`) を繰り返すようになった
- `/design-sync` が、デザインシステムが Claude へ移行済みであることを冒頭で伝え、アップロードで失敗する前に停止するようになった

#### Changed (動作変更)

- SendMessage で、実行中のバックグラウンドエージェントへのメッセージが早く届くように変更。実行中のコマンドは停止されずにバックグラウンドへ移動する
- メイン会話と異なるモデルを使用するサブエージェントとチームメイトが、セッションの effort レベルではなく、そのモデルの保存済み effort レベルまたはデフォルトを使用するように変更
- プラグインモニターの実行中は、終了時の「Background work is running」プロンプトをスキップするように変更
- 組み込みの `plugin-authoring` スキルが、作成した mod が動作した後に一度だけ、mod の共有を支援することを提案するように変更

#### Removed (削除)

- Read ツールの「file unchanged since your last Read」スタブを削除。変更のないファイルを再度読み込むと内容が返されるようになった

#### コンポーネント別の変更

**Windows:**

- ネイティブのパス検索が失敗する一部のボリュームで、すべてのツール呼び出しが拒否される問題を修正。作業ディレクトリのチェックがフォルダーの同一性を比較するようになった
- Claude Desktop 以外で開始したセッションで、セッションスクラッチパッドなどの一時パスがプロジェクトのパス長に応じて長くなり、クローンしたリポジトリが 260 文字のパス制限に達する問題を修正

**Gateway:**

- グループのプール予算が尽きた後、ステータスラインと `/usage` が開発者自身の支出上限を 100% 使用済みと表示する問題を修正

**セルフホストランナー:**

- セッションが新しいランナーへ移動し、ターンが `CLAUDE_CODE_RESUME_INTERRUPTED_TURN_MAX_AGE_MS` より古い場合に、Claude が中断されたツール呼び出しを認識しない問題を修正
- オフに切り替えた MCP サーバーが、セッションサービスが切り替えの保存を拒否していた場合に、別マシンへの移動後に再び有効になる問題を修正

**VSCode:**

- フォークした会話でメッセージが失われる問題を修正。並列実行されたツール呼び出しの 1 つしか保持されず、コンパクションが保持した最後のメッセージも失われていた
- Claude の起動が時間内に完了せずメッセージが失われる場合に、エラー表示の前にもう一度起動を試みるようになった
- リージョンまたはネットワークによるブロック時にサインイン画面が開く問題を修正
- Claude タブ内のファイルリンクが、チャットの上ではなく別のエディターグループで開くようになった
- `chat.fontSize` を上げても Claude パネルの添付チップ、メニュー、バナー、ダイアログが小さいままの問題を修正
- テレメトリ無効時に `ultrathink` がターンの effort を上げず、レインボー表示もされない問題を修正
- Account パネルでプラン名の 2 語目が小文字で表示される問題を修正

**Cloud sessions:**

- MCP サーバーが訪問を求めるリンクを開くか拒否できるリンクカードを追加。従来はリクエストがユーザーに見えないまま処理されていた
- 管理設定の組織環境ダイアログを個人用ダイアログと同じ短いレイアウトに変更。各セクションは行から開き、未保存の入力があれば閉じる前に確認する
- すでにシークレットを持つホストへのネットワークシークレット追加が、既存のものを黙って置き換える問題を修正。Add secret フォームは拒否し、既存のシークレットを案内する
- 新しいスケジュールタスクが組織のデフォルト環境を無視する問題を修正。フォームは Anthropic ホストのデフォルトではなく、管理者が選択した環境で開始される

**Remote Control:**

- `/remote-control` が、`disableRemoteControl` 設定で無効化されている場合に「Unknown command」と答える問題を修正
- `claude remote-control` の再起動後、直前のメッセージから 1 分以内に送信した場合に、アイドルセッションへの次のメッセージが応答されない問題を修正
- アプリがフォーク名を設定しない場合の命名を改善。長い名前は「(fork)」の語尾を保持し、`claude remote-control` で開始したセッションでは「Name (fork)」のフォークが「Name (fork 2)」になる

**Claude Tag:**

- Slack に新しく貼り付けたアーティファクトリンクが、Slack のサイドパネルではなく、Claude でアーティファクトを開く Open ボタン付きのシンプルなカードを表示するように変更

### 技術的な詳細

- **メールアドレス送信チェック**: アカウントのメールアドレスという識別子がネットワーク経由で外部に送信される前にユーザー確認を挟むことで、悪意あるプロンプトや誤操作によるデータ流出のリスクを低減する。Web ツールとシェルツールの両方が対象
- **`onFailure: "block"` のセマンティクス**: 従来、Agent SDK のフックコールバックが失敗 (例外やタイムアウトなど) した場合、対象のアクションはそのまま実行されていた (fail-open)。`onFailure: "block"` を指定すると、コールバックの失敗時にアクションがブロックされる (fail-closed)。権限チェックや監査をフックで実装している場合に重要な選択肢となる
- **コストレポート API と IdP グループ記録**: `GET /v1/organizations/analytics/cost` は日付範囲を指定して支出を取得でき、集計軸は合計、開発者別、日別、IdP グループ別の 4 種類。IdP グループ別の集計は、`admin:` を設定したゲートウェイが日次で記録する各開発者の IdP グループ情報に基づき、保持期間は `admin.identity_retention_days` で制御する
- **ネストした `claude -p` のセッション分離**: セッション内で実行された `claude -p` は独自のセッション ID とトランスクリプトを持つようになり、親セッションのトランスクリプト汚染や誤った会話の再開を防ぐ。旧動作が必要な場合は `CLAUDE_CODE_DISABLE_NESTED_SESSION_ID=1` を設定する
- **Read ツールのスタブ削除**: 変更のないファイルの再読み込みで「file unchanged」のスタブではなく実際の内容が返るようになったため、長い会話でコンテキストから内容が失われた場合でも再読み込みで確実に取得できる

## 開発者への影響

### 対象

- Claude Code CLI / VS Code 拡張機能 / Claude Desktop のユーザー
- Agent SDK でフックを実装している開発者 (特にフックをセキュリティゲートとして利用する場合)
- OpenTelemetry で Claude Code の利用状況を監視している組織 (特にプロキシ環境)
- Claude apps gateway を運用する管理者 (コスト分析、IdP グループ管理)
- セルフホストランナー、クラウドセッション、Remote Control、エージェントチームの利用者
- LLM ゲートウェイや TLS 検査プロキシの背後で Claude Code を利用するユーザー
- CI などでセッション内から `claude -p` をネストして実行しているユーザー

### 必要なアクション

- 通常のアップデートで新機能と修正が適用される。特別な移行作業は原則不要
- Agent SDK のフックで失敗時にアクションを確実にブロックしたい場合は、`onFailure: "block"` の設定を検討する
- セッション内の `claude -p` が親セッションの ID とトランスクリプトを共有する旧動作に依存しているセルフホストランナー環境では、`CLAUDE_CODE_DISABLE_NESTED_SESSION_ID=1` を設定する
- OTel でプランやプロバイダー別の分析を行いたい場合は、追加された `anthropic.plan` などの属性をダッシュボードやアラートに取り込む
- Claude apps gateway の管理者は、コストレポート API による支出分析と、IdP グループ記録の保持期間 (`admin.identity_retention_days`) の設定を確認する
- Read ツールの「file unchanged」スタブ削除により、ファイル再読み込みの挙動が変わる点に注意する (自動化やフックでスタブ文字列に依存している場合は見直しが必要)

## まとめ

Claude Code v2.1.317 は 87 件の変更を含む大規模リリース。アカウントメール送信前の確認チェックや Agent SDK フックの `onFailure: "block"` といったセキュリティ強化、OTel 属性の拡充と Claude apps gateway のコストレポート API によるエンタープライズ可観測性の向上が柱となる。MCP サーバーの切断、auto モードの失敗、セッション復元時の会話消失、プロキシ環境での OpenTelemetry エクスポート停止など、運用に影響する不具合も幅広く修正されており、特にゲートウェイやプロキシ環境、セルフホストランナーを利用する組織にとって安定性が大きく向上するアップデートである。
