## 概要

Claude Code v2.1.316 がリリースされた。本バージョンでは、`ultrathink` キーワードを無効化する `CLAUDE_CODE_DISABLE_ULTRATHINK` や、サブエージェントの effort レベルを指定する `CLAUDE_CODE_SUBAGENT_EFFORT` など、複数の環境変数が追加された。エンタープライズ向けでは、Claude apps gateway にグループ単位の月次共有予算 `pooled_budget`、複数ポリシーをマージして適用する `managed.policy_mode: layered`、Amazon Bedrock ガードレールのプロンプト攻撃フィルター向けに入力タグを付与する `guardrail.input_tagging` が追加されている。

修正面では、Claude Code の自己終了時にシェルコマンドが残留する問題、改行を含む bash エイリアスの破損、PowerShell フックが終了コード 2 でブロックしない問題など、多数の不具合が解消された。また、SSL 証明書エラーが原因と対処法を示すようになるなど、エラーメッセージの改善も含まれる。なお、Opus 4.8 の fast mode が 2026 年 10 月 30 日付で非推奨となり、2026 年 11 月 30 日に削除されることが告知された (詳細は別レポートを参照)。

## 詳細

### 主な変更点

#### ハイライト

- **`CLAUDE_CODE_DISABLE_ULTRATHINK` の追加**: `ultrathink` キーワードを無効化できる。キーワードの誤発動による高 effort 実行を避けたい環境で有用
- **`CLAUDE_CODE_SUBAGENT_EFFORT` の追加**: 他に指定がない場合にサブエージェントが実行される effort レベルを設定できる。従来はセッションの effort を継承していたため、サブエージェントのコストと速度を独立して制御できるようになった
- **Claude apps gateway のプールドグループ予算**: 支出上限の管理 API の `pooled_budget` で、グループのメンバーが共有する月次予算を、各メンバー個別の上限に加えて設定できる
- **`managed.policy_mode: layered` の追加**: Claude apps gateway で、開発者にマッチするすべてのポリシーが適用されるようになるモード。各ポリシーは下に列挙されたものの上にマージされる。従来は最初にマッチしたポリシーのみが適用されていた
- **`guardrail.input_tagging` の追加**: Claude apps gateway の Bedrock アップストリームで、Amazon Bedrock ガードレールのプロンプト攻撃フィルターが必要とする入力タグでプロンプトをラップする。`all_messages_and_system` を指定するとシステムプロンプトにもタグが付与される
- **Opus 4.8 fast mode の非推奨化**: 2026 年 10 月 30 日付で非推奨となり、2026 年 11 月 30 日に削除される。削除後、Opus 4.8 への fast mode リクエストはエラーを返し、標準の Opus 4.8 にはフォールバックしない。速度向上を維持するには Opus 5.5 への移行が必要

#### Added (新機能)

- `CLAUDE_CODE_DISABLE_LOOPED_CROSS_CERT_DROP` を追加。ループ状に相互認証するシステムクロス証明書を保持する。プライベート CA がそれを必要とするサーバー向け

#### Fixed (修正)

シェル・プロセス関連の修正。

- macOS と Linux で、Claude Code が自己終了した際 (認証情報の拒否やクラウドセッションのアーカイブなど) にシェルコマンドが実行されたまま残る問題を修正
- 値に改行を含む bash エイリアス (Git Bash を除く) と、名前がダッシュで始まる関数が、Bash ツールのシェルで破損または消失する問題を修正
- `SHELLOPTS` がエクスポートされている場合に、Bash ツールから起動した bash スクリプトが最初のコマンドで停止する問題を修正
- PowerShell フックが、コマンドが型キャスト、`param`、`using`、または属性で始まる場合に終了コード 2 でブロックしない問題を修正
- Windows: rc ファイルで errexit と pipefail を設定し、winpty エイリアスのみ (またはエイリアスなし) が定義されている場合に、Git Bash の Bash ツールでエイリアスと関数が失われる問題を修正

ネットワーク・プラットフォーム関連の修正。

- 圧縮レスポンスが途中で切れた場合や破損した場合に、一部のネットワークリクエストがハングする問題を修正
- Vertex AI と Amazon Bedrock で、最新モデルがアカウントやリージョンでまだ利用できない場合に、`sonnet` / `opus` / `haiku` が旧モデルへ切り替わらずセッション途中でエラーを表示する問題を修正
- Claude apps gateway が、リクエストに含まれるすべてのモデルを `availableModels`、`deniedModels`、`models` に対してチェックしていなかった問題を修正。ブロックされたモデルを含むリクエストは、該当フィールドを示す 400 エラーを返すようになった
- managed settings が Claude apps gateway を必須とする環境で `claude auth login` が実行を拒否する問題を修正。ターミナルではゲートウェイのサインインを表示するようになった

権限・セキュリティ・設定関連の修正。

- `--restricted` セッションが、Read の許可ルールの対象であれば作業ディレクトリ外のファイルをアップロードしていた問題を修正
- `"$defaults"` を含まない managed の `autoMode.allow` リストに、ホストアプリの `--settings`、`/permissions` での最初のルール追加、または `/auto-mode-setup` によって組み込み例外が復活する問題を修正
- auto モードがサーバーの安全性判定を得られずにターンを停止した際、クラウドセッションとクラウドスケジュールタスクが失敗としてマークされない問題を修正
- バックグラウンドエージェントの実行中に、`claude -p` のテキスト出力が auto モードのターン停止理由を表示しないことがある問題を修正
- プロキシまたは LLM ゲートウェイの背後でホストアプリ (Claude Desktop など) から開始したセッションで、experimental betas 無効時に `CLAUDE_CODE_AUTO_MODE_SERVER=1` が無視される問題を修正

セッション・UI 関連の修正。

- 不可視文字を含むプロンプトの送信に Enter が 2 回必要だった問題を修正。プレーンなプロンプトはクリーニング後 1 回の Enter で送信され、コマンドは引き続きレビューを待つ
- 親サブエージェントのモデルを継承したサブエージェントが、バックグラウンドジョブやメッセージで再開した際にメインモデルへ移動する問題を修正
- `/model <id>` が、このバージョンで認識されないモデルを指定した際に、auto-compact が 200K コンテキストウィンドウを前提とすることを警告しない問題を修正
- 検索プロセスがタイムアウトで強制終了されても終了しない場合に、Grep と Glob が応答を返さない問題を修正 (Windows で確認)
- 会話の一部が保存中に `/clear` や `/resume` を実行していた場合、まれに会話の再開時にプランが復元されない問題を修正
- プラグイン MCP の `headersHelper` スクリプトが、認証情報系の名前の環境変数に `1` などのスイッチ値が設定されている場合に、破損した `CLAUDE_PLUGIN_ROOT` とサーバー URL を受け取る問題を修正
- SDK の `register_repo_root` コントロールリクエストが、作業ディレクトリ外のディレクトリの CLAUDE.md を読み込まない問題を修正 (`CLAUDE_CODE_ADDITIONAL_DIRECTORIES_CLAUDE_MD=1` 使用時)
- Artifact ツールが `self` レベルのアーティファクトデータベースアクセスルールを `?` と表示し、それらのルールが失われる再公開を拒否する際にルール内容を提示しない問題を修正
- このほか、ターミナル UI (「hold space to speak」ヒントの表示回数、初回セットアップの文字欠け、Enterprise アンケートカードの入力確定など) に関する修正が含まれる
- セルフホストランナー: Claude の作業中に送信されたメッセージが、セッションのプロセス差し替え後、Stop の後に応答される問題と、セッションのマシン移動時に MCP サーバーのオン / オフ設定が失われることがある問題を修正

#### Improved (改善)

- Claude Desktop や Web の Code タブから開始した `/code-review` で、クラウドセッションと `claude remote-control` セッションがプレーンテキストのリストではなく findings カードを表示するようになった
- 大規模リポジトリでの `/diff` を改善。リフレッシュごとのリポジトリ全体に対する git コマンドが通常 1 回減り、git が遅い場合はリフレッシュの間隔が空けられる
- `/ultrareview`、クラウドセッション、クラウドエージェントが GitHub リモートを見つけられない場合のメッセージを改善。https://github.com/new でのリポジトリ作成を案内し、`/ultrareview` は `gh` が拒否する `gh` コマンドを提案しなくなった
- SSL 証明書エラーが、中間証明書を省略しているサーバーなどの考えられる原因と、それぞれの対処法を示すようになった

#### Changed (動作変更)

- `"$defaults"` を含まない `autoMode.allow` リストが、スケジュールタスクのプロンプトに関する組み込みルールを削除しないように変更
- Team / Enterprise ログインのサーバー管理設定を変更。Anthropic の API から取得した設定は承認プロンプトなしで適用され、検証に失敗した保存済みコピーは拒否される

#### コンポーネント別の変更

**VSCode:**

- チャットパネルから Claude apps gateway へサインインできるようになった。ターミナルは不要
- `ultrathink` がターミナルと同様に、ターンを `xhigh` effort で実行し、チャットボックスでレインボー表示されるよう変更
- モデル設定に `[1m]` タグ (`opus[1m]` など) がある場合に、Effort スライダー、Ultracode スイッチ、モデル名が表示されない問題を修正
- 設定ファイルにエラーがある間に、保存済みの `/btw` サイド質問履歴が早く削除されすぎる問題を修正
- プランが「Yes, and manually approve edits」で承認された会話が、リロードや再起動後に Auto モードで復帰する問題を修正

**Cloud sessions:**

- MCP サーバーが要求するフォームに入力または拒否できるフォームカードを追加。従来はユーザーが見ることなくリクエストがキャンセルされていた
- 切り替えて戻ったクラウド / Remote Control セッションがメッセージを最新化している間、「Catching up…」の行が表示されるようになった
- Enterprise メンバーが自身のクラウド環境でネットワークシークレットを追加・削除できるよう変更 (従来は閲覧のみ)
- Changes ペインを改善。リストが省略している内容についての注記が、diff の上の行ではなくブランチ名の横のバッジになった
- Claude がディレクトリを変更した後、Files ペインのファイル検索がフォルダーを ../.. パスで表示する問題を修正。結果はプロジェクトルートからのパスで表示される

**Claude Tag:**

- Slack チャンネルで作成した canvas が別のチャンネルや DM にも共有されると、そのチャンネルから編集や追記を拒否する問題を修正
- 両組織が Claude をインストールした Slack Connect スレッドで、Slack がもう一方の組織のアプリに返信を配送した場合に、タグなしの返信が応答されない問題を修正
- クラウドスケジュールタスクの Slack 上のライブステータスチェックリストが途中のまま止まる問題を修正。実行中に投稿したトップレベルメッセージをその実行が編集できるようになった
- Slack チャンネルの「Respond automatically」スイッチが、チャンネルの Configure ページと Claude Tag 管理設定で「How Claude participates」の選択に変更された

**Code Review:**

- Code Review 分析ページに重要度別の findings カードを追加。期間内の合計 findings 数、重要度別に積み上げた日次チャート、各重要度の件数を表示する

### 技術的な詳細

- **サブエージェントの effort 制御**: `CLAUDE_CODE_SUBAGENT_EFFORT` は、エージェント定義などで effort が明示されていない場合にのみ適用される。多数のサブエージェントを起動するワークフローで、セッション全体を高 effort にしたままサブエージェントのコストを抑える、といった使い分けが可能になる
- **layered policy mode**: 従来の Claude apps gateway は開発者にマッチした最初のポリシーのみを適用していた。`managed.policy_mode: layered` では、マッチしたすべてのポリシーが下位のものの上にマージされるため、組織全体の基本ポリシーにチーム固有の設定を重ねる運用ができる
- **Bedrock ガードレールの入力タグ**: Amazon Bedrock ガードレールのプロンプト攻撃フィルターは、評価対象の入力を特定のタグで囲む必要がある。`guardrail.input_tagging` はこのタグ付けをゲートウェイ側で行い、`all_messages_and_system` ではシステムプロンプトも対象に含める
- **モデルフォールバックの改善**: Vertex AI / Bedrock でエイリアス (`sonnet` など) が指す最新モデルが未提供のリージョンやアカウントでも、セッションがエラーで中断せず旧モデルへ切り替わるようになった

## 開発者への影響

### 対象

- Claude Code CLI / VS Code 拡張機能 / Claude Desktop のユーザー
- Bash ツールでエイリアス、関数、`SHELLOPTS` を利用するユーザー、PowerShell フックを利用する Windows ユーザー
- Claude apps gateway を運用する管理者 (特に予算管理、ポリシー設計、Bedrock ガードレールの利用が必要な組織)
- Vertex AI / Amazon Bedrock / LLM ゲートウェイ経由で Claude Code を利用するユーザー
- **Opus 4.8 の fast mode を利用しているユーザー (移行が必要)**
- Cloud sessions、Remote Control、Slack の Claude Tag、Code Review の利用者

### 必要なアクション

- 通常のアップデートで新機能と修正が適用される。特別な移行作業は原則不要
- **Opus 4.8 の fast mode を利用している場合は、2026 年 11 月 30 日の削除までに Opus 5.5 へ移行する**。削除後はリクエストがエラーになり、標準の Opus 4.8 へのフォールバックは行われない
- サブエージェントのコストを制御したい場合は、`CLAUDE_CODE_SUBAGENT_EFFORT` の設定を検討する
- `ultrathink` キーワードを無効化したい環境では `CLAUDE_CODE_DISABLE_ULTRATHINK` を設定する
- Claude apps gateway の管理者は、`pooled_budget` によるグループ共有予算、`managed.policy_mode: layered`、Bedrock アップストリームの `guardrail.input_tagging` の活用を検討する
- Team / Enterprise のサーバー管理設定が承認プロンプトなしで適用されるようになった動作変更に注意する

## まとめ

Claude Code v2.1.316 は、`CLAUDE_CODE_DISABLE_ULTRATHINK` や `CLAUDE_CODE_SUBAGENT_EFFORT` などの環境変数追加と、Claude apps gateway の `pooled_budget` / `managed.policy_mode: layered` / `guardrail.input_tagging` といったエンタープライズ機能の拡充が柱のリリース。シェルコマンドの残留プロセス、bash エイリアスの破損、PowerShell フックのブロック不全など運用上影響のある不具合も多数修正された。Opus 4.8 fast mode の非推奨化 (2026-11-30 削除予定) が告知されているため、該当ユーザーは期限までに Opus 5.5 への移行を計画することを推奨する。
