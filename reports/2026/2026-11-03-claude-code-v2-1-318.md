## 概要

Claude Code v2.1.318 がリリースされた。合計 84 件の変更を含むアップデートで、認証・設定ファイルの信頼性向上が最大のテーマとなっている。新機能では、Claude apps gateway の `mantle` アップストリームに別 AWS アカウントのロールを引き受ける `assume_role` が追加され、開発者ごとの AWS コスト配分が可能になった。また、claude.ai サインインの有効期限が `claude auth status` (`loginExpiresAt`) と `claude -p` の JSON 結果 (`credential_expires_at`) で確認できるようになり、期限の 10 日前から stderr に警告が表示される。

修正面では、`--continue` で以前の会話が失われる v2.1.314 のリグレッション、macOS で多数の Bash コマンド実行中にセッションが停止する問題、共有ネットワークホームディレクトリで `~/.claude.json` や保存済みログインが破損・消失する一連の問題など、41 件の不具合が解消された。動作変更では、IDE ターミナル内での起動時に IDE 拡張機能を自動インストールしなくなった点や、`deniedMcpServers` の URL エントリが Anthropic 提供サーバーやコネクタもブロックするようになった点が重要である。

## 詳細

### 主な変更点

#### ハイライト

- **Claude apps gateway の `assume_role`**: `mantle` アップストリームに `assume_role` を設定できるようになり、別の AWS アカウントのロールを利用可能になった。開発者ごとの AWS コスト配分 (cost attribution) にも対応し、エンタープライズでのマルチアカウント運用とコスト管理を強化する
- **認証有効期限の可視化**: 保存済み claude.ai サインインの終了日が `claude auth status` の `loginExpiresAt` と `claude -p` JSON 結果の `credential_expires_at` に追加された。さらに、期限の 10 日前から `claude -p` のテキスト出力で stderr に 1 行の警告が表示されるため、CI や自動化環境で認証切れを事前に検知できる
- **共有ネットワークホームディレクトリの堅牢化**: `~/.claude.json`、設定ファイル、保存済みログインが保存時に削除・空ファイル化・古いコピーへの置き換えをされにくくなった。あわせて、設定ファイルが誤って「存在しない」と報告された場合に再確認する処理が追加され、MCP サーバーや信頼済みフォルダーなしでセッションが開始されるケースが減少した
- **mod の `$.model.fork` に `effort` オプション**: セッションの effort 設定にかかわらず、簡単なサイドジョブを `low` などの指定した effort で実行できるようになった。結果には送信された effort が報告される
- **mod 有効化の回答記録**: Claude Code がセッション内で作成した mod の有効化を尋ねた際の回答が記録されるようになった

#### Added (新機能)

ハイライトのほか、上記 5 件が今回の新機能のすべてである (mod 有効化の回答記録、gateway の `assume_role`、`$.model.fork` の `effort` オプション、認証有効期限の表示、期限前の stderr 警告)。

#### Fixed (修正)

セッション・会話管理関連の修正。

- `--continue` が、不正な形式のツール呼び出しのリトライが尽きた後に以前の会話を失うことがある問題を修正 (v2.1.314 のリグレッション)
- macOS で多数の Bash コマンドを実行中のセッションが、メモリ増加とともに停止する問題を修正
- アイドルコンパクションが、会話を要約ではない応答で置き換える問題を修正
- 再起動したセッションが、API エラーで失敗したメッセージを、待機中の新しいメッセージより先に再送する問題を修正
- 大きな画像の読み込みやツール呼び出しのリトライ直後に再起動が起きた場合に、中断されたターンが失われる問題を修正
- 削除されたセッショントランスクリプトが、アイドル状態の非対話セッション終了時に最後のプロンプト付きで再作成される問題を修正
- ヘッドレスセッションで、モデル変更直後に送信したメッセージが Stop 後も実行され続ける問題を修正。Stop がキュー内メッセージと同様にキャンセル・停止するようになった

認証・設定ファイル関連の修正。

- `/logout`、`claude auth logout`、`claude mcp remove` が、共有ネットワークホームで設定ファイルを更新できない場合でも成功と報告し、信頼・同意・MCP 設定の変更が無言で失われる問題を修正
- 別のターミナルやホストが同じアカウント・組織に再サインインした際に、ジョブが `Not logged in` で終了する問題を修正
- `claude mcp add` / `remove` がロックなしで設定を書き込む問題を修正。ロックを待つか終了コード 1 で終了するようになった
- `claude plugin` コマンドが遅いトークンリフレッシュの保存前に終了し、次回実行時にサインアウトされることがある問題を修正
- ネットワークホームの空き容量が尽きた際に、保存済みログインが空ファイルで置き換えられる問題を修正
- `forceLoginOrgUUID` が設定されたマシンで、許可された組織の `setup-token` トークンが起動時に拒否される問題を修正
- 非対話起動が、有効な JSON でない `~/.claude.json` をデフォルト値で置き換える問題を修正。起動は失敗し、復元方法を表示してファイルをそのまま残す (anthropics/claude-code#87551)
- バックアップのない空の `~/.claude.json` が破損として報告される問題を修正。ファイルがない場合と同様に起動するようになった
- 保持期間クリーンアップが、`claude -p` のみ実行するホームから `~/.claude.json` のバックアップをすべて失わせる問題を修正。最後の正常なバックアップを削除する前に新しいバックアップを取得する
- 保存済み claude.ai ログインの期限切れ時のサインイン失敗が、原因を説明し、`claude -p` では `claude auth login` と `claude setup-token` を案内するようになった
- 同じマシンの別ログインが保存した `allowedProviders` リストにより、セッションが起動時に拒否される問題を修正

UI・権限・ヘッドレス関連の修正。

- メッセージ送信直後や遅いプロンプト表示前に入力したキーが、権限プロンプトに回答してしまう問題を修正
- 失敗したカスタムスラッシュコマンドや、Claude のみ呼び出せるコマンドが、`claude -p` と SDK セッションで何も出力しない問題を修正
- `claude -p` と Agent SDK セッションが、mod が `turn.step` をフックしている間に API エラーで応答が途切れても成功と報告する問題を修正。あわせて、mod の `turn.step` フックが停止された応答をヘッドレス実行で成功として終わらせる問題も修正
- 「Now using usage credits」の通知が、バックグラウンドサブエージェント実行中に約 30 秒ごとに再表示される問題を修正
- 20 枚を超える画像を含むリクエストで、大きすぎる画像のエラーが常に 2000px と表示される問題を修正。API の制限値を表示するようになった
- バックグラウンドシェルの詳細ダイアログを開いている間、実行時間が更新されない問題を修正

ネットワーク・インフラ関連の修正。

- `NODE_EXTRA_CA_CERTS` ファイルが空、PEM 形式でない、または先頭の証明書が破損している場合に、すべての接続が失敗する問題を修正。読み取り可能な証明書は使用され、stderr に警告が表示される
- バージョン probe で終了する stdio MCP サーバーが、起動のたびに再 probe される問題を修正。独自の理由で 3 秒未満に終了するサーバーも、7 日間レガシーハンドシェイクに固定される
- `claude remote-control` ホスト、バックグラウンドデーモン、セルフホストランナーが、アップデートやバージョンクリーンアップによる実行中プロセスのバイナリ削除後に、新しいセッションを開始できない (`spawn ENOENT`) 問題を修正。あわせて、別ユーザー所有の実行中プロセス (例: `sudo claude` の残り) がクリーンアップで死んでいると判定され、バイナリが削除され得る問題も修正
- セルフホストランナーまたはクラウドセッションの再起動後に承認されたシェルコマンドが、依頼されたフォルダーではなくセッションの開始フォルダーで実行される問題を修正
- 使用量上限後に再開したワークフローが、完了済みエージェントを再実行する問題を修正

このほか、クラウドセッション再起動後にコネクタツールが利用不可であることを Claude に伝えない問題、アップロード拒否時にクラウドセッションがターン途中で停止する問題、`Setup` フックが `CLAUDE_ENV_FILE` に書いた変数が一部のクラウドセッションで Bash ツールに届かない問題、iPhone アプリでクラウドセッションのターンが実行中にもかかわらず完了と表示される問題、`/remote-control` が接続失敗後もセッションを利用可能と表示する問題、`/design revoke` が 404 でも成功と報告する問題、`/mcp` がクラウドセッションでモデルが使用できないツールまで数える問題、PushNotification の重複通知などが修正された。

#### Improved (改善)

- 共有ネットワークホームでの保存時の `~/.claude.json`、設定ファイル、保存済みログインの生存性を改善 (前述のハイライト参照)
- MCP ツールのエラーを改善。ツールのロード前に行われた呼び出しが、入力スキーマを返すようになった
- macOS 組み込みの `/bin/bash` を Bash ツールが使用する場合の、git コミットとプルリクエスト作成の信頼性を改善
- 使用量上限メニューの「Ask your admin for more usage」が、1 ステップでリクエストを送信するようになった
- 一時停止やスリープ後のリモートセッションの再接続速度を改善
- 自動アップデートの信頼性を改善。リリース検証中の一時的なネットワーク障害は、次回チェックを待たずに即座にリトライされる
- 無人実行 (`claude -p`、SDK アプリ) が、変更がない場合に実行ごとの `~/.claude.json` 書き換えを行わなくなった
- You should know トーストが、ターミナルでしか機能しない「press 2」ではなく「try again」と案内するようになった

#### Changed (動作変更)

- IDE ターミナル内で起動した場合に、IDE 拡張機能のインストール・更新を行わなくなった。外部ターミナルからの `/ide` またはエディターの拡張機能ビューを使用する
- `deniedMcpServers` の URL エントリが、アップストリーム URL が一致する Anthropic 提供サーバーと、クラウドセッションおよびセルフホストランナーのコネクタもブロックするようになった。それ以外の場合はコネクタを名前で拒否する
- 「Switch models when a message is flagged」が「Ask each time」の場合、サブエージェントはモデルを切り替えるのではなく停止するようになった
- バックグラウンドサブエージェントが、すべてのプロバイダーで 3 分後にシェルコマンドをバックグラウンドへ移動するようになった。実行中にプロンプトキャッシュが期限切れになるのを防ぐ
- Bedrock、Vertex、Foundry、またはテレメトリ無効時のサブエージェント進捗サマリーは、コールドプロンプトキャッシュの場合にサブエージェントの応答を最大 5 分待つことがある
- mod が `prompt.submit` で添付する内容が、システムメッセージではなくユーザーのターンに残るようになった
- `/permissions` のルール詳細、組み込みルール、削除確認ビューが標準ダイアログを使用するようになった。Ctrl+C を 2 回押すと終了ではなく戻る・キャンセルになる
- `/claude-api managed-agents-onboard` が、新しいエージェントの組み込みツールとクイックスタートテンプレートの MCP ツールに、デフォルトで `auto` 権限ポリシー (「Judge risky actions」) を付与するようになった (Claude Console と同一)。オプトアウトするには「run without asking」と指定する

#### Removed (削除)

- v2.1.286 以前に開始した会話の再開時にモデルの以前の thinking を保持する v2.1.288 の修正を削除。該当の thinking は破棄されるようになった

#### コンポーネント別の変更

**Gateway:**

- フェデレーション (`external_account`) 認証情報ファイルの Google アクセストークンが期限切れ間近の場合のログ警告を追加
- `listen.trusted_proxies` のログヒントを改善。`X-Forwarded-For` に接続元アドレスを自身で追加するプロキシのみを列挙するよう案内する
- Amazon Bedrock で AWS CountTokens が失敗した場合の警告を改善。501 の後はゲートウェイではなく Claude Code がカウントすることを伝え、AWS がアクセスを拒否した場合のみ IAM を指摘する

**セルフホストランナー:**

- オーケストレーターの spawn-runner フック環境に `CLAUDE_RUNNER_SPAWN_REASON` を追加。Anthropic がリクエストを送信した理由 (例: `runner_lost`、`resumed`) が設定される
- `--release-idle-session-min` が値なしの最終引数、または空白のみの値の場合に起動時警告を追加
- オーケストレーターのログ行を変更。`ok session=…` がすべてのログレベルで stdout に出力され (従来は debug のみ、stderr)、`nack session=…` のフィールド順も変更された。`retryable=true:` / `retryable=false:` にマッチするスクリプトは更新が必要

**Cloud sessions:**

- No repository オプションを追加。Anthropic ホスト環境のクラウドセッションがリポジトリを選択せずに開始できるようになった
- 標準的な Chrome の名前が追加され、Playwright 以外のツールも `google-chrome` と `CHROME_PATH` で組み込み Chromium を利用できるようになった
- 環境が削除されたクラウドセッションのカードに New session ボタンを追加
- `gh run view --log` と `gh api` による GitHub Actions ログの読み取りを修正。ほとんどの環境でログを取得できるようになった
- Create PR 失敗時のメッセージを改善。「Try again」ではなく理由または GitHub へのリンクを表示する
- コネクタ検索の結果が、コネクタディレクトリの一部のみを対象としていることを Claude に伝えるようになった

**VSCode:**

- 組織の設定によりサインインが拒否されたウィンドウが、毎分新しい Claude Code プロセスをバックグラウンドで起動する問題を修正
- チャットパネルのエラーバナーで、長い単語が閉じるボタンを押し出す問題を修正
- サインイン画面が、ステータスチェック失敗時に Claude Code の出力内容を表示するようになった

**Remote Control / Claude Tag / Code Review:**

- 作業フォルダーが存在しないセッションの誤解を招く「spawn error: ENOENT」を修正。エラーがフォルダー名を示すようになった
- 同一リポジトリの並列チェックアウトが環境メニューで同一に見える問題を修正。各行が自身のフォルダー名を表示する
- Claude Tag 管理セットアップのキーボードフォーカスとスクリーンリーダーの読み上げを修正
- Code Review 分析ページが、サーバーまたはネットワーク障害後に 1 回リトライし、空のカードではなく Try again バナーを表示するようになった

### 技術的な詳細

- **`assume_role` の構成**: Claude apps gateway の `mantle` アップストリームに `assume_role` を設定すると、ゲートウェイが別の AWS アカウントのロールを引き受けて Bedrock などへアクセスできる。開発者ごとの AWS コスト配分にも利用でき、アカウント分離とコスト管理を両立できる
- **認証有効期限の確認方法**: 対話環境では `claude auth status` の `loginExpiresAt`、自動化環境では `claude -p` の JSON 出力に含まれる `credential_expires_at` を参照する。テキスト出力では期限の 10 日前から stderr に警告が 1 行出力されるため、CI のログ監視で検知できる
- **設定ファイル保護の多層化**: 共有ネットワークホームでの保存耐性の改善に加え、破損した `~/.claude.json` をデフォルトで上書きせず復元方法を案内して停止する動作、バックアップ削除前の新規バックアップ取得、ロックを尊重した `claude mcp add` / `remove` など、設定喪失を防ぐ修正が多層的に導入された
- **`deniedMcpServers` の適用範囲拡大**: URL エントリによる拒否が Anthropic 提供サーバーとコネクタにも適用されるため、組織ポリシーで特定のアップストリームを一括ブロックできる。クラウドセッションとセルフホストランナーではセッションにコネクタ自身の URL が渡されるため URL で一致する。それ以外の環境ではコネクタを名前で拒否する必要がある
- **プロンプトキャッシュを考慮したサブエージェント動作**: 長時間のシェルコマンドを 3 分でバックグラウンドへ移動することで、サブエージェントのプロンプトキャッシュの期限切れを防ぐ。Bedrock / Vertex / Foundry またはテレメトリ無効時は、コールドキャッシュで進捗サマリーが最大 5 分待機する場合がある

## 開発者への影響

### 対象

- Claude Code CLI / VS Code 拡張機能のユーザー
- 共有ネットワークホームディレクトリ (NFS など) で Claude Code を運用する組織
- `claude -p` や Agent SDK で無人実行・CI 連携を行う開発者
- Claude apps gateway を運用する管理者 (特にマルチアカウント AWS 環境)
- セルフホストランナー、クラウドセッション、Remote Control の利用者
- mod (プラグイン) を開発している開発者

### 必要なアクション

- 通常のアップデートで新機能と修正が適用される。特別な移行作業は原則不要
- CI や自動化環境では、`claude -p` JSON 出力の `credential_expires_at` または stderr の期限警告を監視に組み込み、認証切れを事前に検知する運用を検討する
- マルチアカウント AWS 環境でゲートウェイを運用する管理者は、`mantle` アップストリームの `assume_role` 設定と開発者別コスト配分の利用を検討する
- セルフホストランナーのオーケストレーターログを解析するスクリプトは、`ok session=…` / `nack session=…` のフィールド順変更 (特に `retryable=true:` / `retryable=false:` へのマッチ) に合わせて更新する
- IDE 拡張機能は IDE ターミナル内の起動では自動インストールされなくなったため、必要な場合は外部ターミナルから `/ide` を実行するか、エディターの拡張機能ビューからインストールする
- v2.1.286 以前に開始した会話の thinking 保持が削除されたため、古い会話の再開時に以前の thinking が破棄される点に留意する

## まとめ

Claude Code v2.1.318 は 84 件の変更を含むリリースで、認証と設定ファイルの信頼性向上が中心となっている。共有ネットワークホームディレクトリでの `~/.claude.json` や保存済みログインの破損・消失対策が多層的に導入され、認証有効期限の可視化と事前警告により無人実行環境の運用性も向上した。Claude apps gateway の `assume_role` によるクロスアカウント AWS 対応と開発者別コスト配分はエンタープライズ利用者にとって重要な追加機能である。`--continue` のリグレッションや macOS でのセッション停止など日常利用に影響する不具合も修正されており、特にネットワークホームや CI 環境で Claude Code を運用する組織に恩恵の大きいアップデートである。
