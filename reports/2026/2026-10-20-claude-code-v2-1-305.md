## 概要

Claude Code v2.1.305 は、約 40 項目の変更を含むメンテナンスリリースである。Linux サンドボックス内でユーザー名前空間の作成を許可する `sandbox.allowNestedUserNamespaces` 設定と、無人リトライモード向け環境変数 `CLAUDE_CODE_RETRY_WATCHDOG_USAGE_LIMIT_RECHECK_MS` が追加された。

特に重要なのは、v2.1.304 のリグレッションにより、Vertex AI や Bedrock などのプロバイダーやゲートウェイがツール検索 (ToolSearch) を拒否した場合に、すべてのリクエストが失敗していた問題の修正である。該当環境のユーザーは早期のアップデートが推奨される。

## 詳細

### 背景

v2.1.304 では、カスタム `ANTHROPIC_BASE_URL` 使用時にツール検索がデフォルトで有効化された。しかし、エンドポイントやゲートウェイがツール検索をサポートしない構成では、全リクエストが失敗するリグレッションが発生していた。v2.1.305 はこの修正を中心に、worktree、MCP、Workflow、スクリーンリーダー対応、Self-hosted runner など幅広い領域の不具合を解消している。

### 新機能

- **`sandbox.allowNestedUserNamespaces` の追加**: Linux でサンドボックス化されたコマンドがユーザー名前空間を作成できるようになる設定。Chromium や rootless podman の実行に必要となる。ただし、この設定を有効にするとサンドボックスのファイル保護を回避できるようになる点に注意が必要である
- **`CLAUDE_CODE_RETRY_WATCHDOG_USAGE_LIMIT_RECHECK_MS` の追加**: 無人リトライモード (`CLAUDE_CODE_RETRY_WATCHDOG`) が、リセット時刻より前に解除された使用量制限を検知できるようになる環境変数

### 主なバグ修正

- **ツール検索拒否時の全リクエスト失敗 (v2.1.304 リグレッション)**: Vertex AI、Bedrock などのプロバイダーで、エンドポイントまたはゲートウェイがツール検索を拒否した場合、および ToolSearch が許可されていない、または `--tools` に含まれていないゲートウェイ配下で、すべてのリクエストが失敗していた問題を修正。Claude Code はツール検索なしで再試行するようになった
- **`/effort` と `/autocompact` の設定不適用**: モデル名が `modelOverrides` の値と大文字小文字や `[1m]` タグの有無で異なる場合に、設定が適用されなかった問題を修正
- **ベアリポジトリの worktree**: 新しい worktree がデフォルトブランチではなくローカル HEAD から開始されることがある問題と、変更のないサブエージェント worktree がクリーンアップされないことがある問題を修正
- **ディスク満杯時のエラー表示**: ディスクが満杯の状態で Bash コマンドが生の `ENOSPC` ファイルパスとともに失敗していた問題を修正。エラーメッセージでディスクが満杯であることと、コマンドが実行されなかったことを明示するようになった
- **MCP サーバーの置き換え**: クラウドセッションまたは SDK の `setMcpServers` で渡された MCP サーバーが、セッションの途中でユーザー設定内の同名サーバーに置き換えられてしまう問題を修正
- **サブエージェントのモデル名誤表示**: サブエージェントがフォールバックモデルに切り替わった後、Claude がサブエージェントの作業に対して誤ったモデル名を報告する問題を修正
- **コンパクション要約の欠落通知**: クラウドセッションとチームメイトで、コンパクションが要約に収めるために最も古いメッセージを除外した際、それが Claude に伝わっていなかった問題を修正
- **Cowork クラウドセッションの待機**: スケジュールされた Cowork クラウドセッションで、WebFetch の URL 承認を誰も行えない状況のサブエージェントごとに 5 分間待機するケースをさらに修正
- **Workflow の再開**: Workflow の resume が、完了済みの `pipeline()` および `parallel()` エージェントを実行ジャーナルから復元せず、再実行してしまう問題を修正
- **Remote Control の `/resume` 表示**: `/resume` で会話を切り替えた後、空の「(session)」エントリが `/resume` に残る問題を修正
- **`/usage` の表示崩れ**: 幅の狭いターミナルで `/usage` の行が切れてしまう問題を修正
- **起動時警告の表示**: 起動時の警告がロゴの上に生テキストとして表示されていた問題を修正。警告はデバッグログに出力され、何も制限していない権限ルールはバナー下に警告行として表示される
- **スクリーンリーダーモード**: 検索ボックスが VoiceOver で「telephone recorder」と読まれる記号の代わりに「Search:」と読み上げるようになり、Ctrl+R の検索一致や「ultrathink」などのハイライトされたプロンプトテキストで単語内にスペースが入らなくなった

#### Self-hosted runner の修正

- stdout のみを runner や orchestrator と共有する start スクリプトが、`TERM` 設定時に `Resource temporarily unavailable` で失敗する問題を修正 (v2.1.300 リグレッション)
- git の credential helper や askpass プログラムが `GIT_CONFIG` 経由で設定を読む場合に、v2.1.296 以降リポジトリアクセスが失敗していた問題を修正
- orchestrator が、バックグラウンドで起動した runner が出力を開いたままにしていると、spawn-runner フックをタイムアウトとして報告する問題を修正

### 改善

- **`/usage` の警告表示**: 各警告が原因を示す 1 行の修正案として表示され、`f` キーで修正を適用できるようになった。同じ修正案は VS Code と `/doctor` にも表示される
- **MCP 同意ダイアログ**: プロンプト入力のつもりで押した Enter が Accept として扱われにくくなった
- **Mod の `Image` 描画**: iTerm2 3.5 以降のフルスクリーンレンダリングで `alt` テキストのみが表示されていた問題が改善され、画像が描画されるようになった
- **Remote Control の spawn モードメッセージ**: `w` キーを押すと新しいモードがフォルダに保存されたことを表示し、保存されたモードを使用して `claude remote-control` を起動した際はその出所を表示するようになった

### 動作変更

- **`allowedMcpServers` のフィルタリング**: `env` 内でのみ `${VAR}` を使用する `managed-mcp.json` の stdio サーバーをフィルタリングしなくなった。許可リストに含まれていなかったサーバーがアップグレード後に読み込まれるようになるため、無効のままにしたい場合は `deniedMcpServers` を使用する
- **Claude Desktop マウントプラグインの権限**: 組織の管理設定で `allowManagedPermissionRulesOnly` が設定されている場合、Claude Desktop がパス指定でマウントするプラグインは `allowed-tools` を保持しなくなった
- **`/artifacts` の削除確認**: 1 または Enter で保持、2 で削除、Esc でキャンセルに変更され、`y` と `n` では応答できなくなった
- **Mod のドックペイン幅**: ターミナル幅の 45% 以内に収まるようになった。より広いターミナルから引き継いだ幅にも適用される

### 周辺機能の変更

- **[VSCode]**: SessionStart や Setup フックの実行中に「Running start-up hooks」スピナーステータスとスクリーンリーダー向けアナウンスを追加。`spinnerVerbs` 設定で短い動詞に置き換えた際に「Compacting...」が途切れる問題を修正。セッションが時間内に開始せずフックも実行されていない場合のメッセージが、サインインやネットワークではなく出力ログと原因一覧を先に示すよう変更された
- **[Cloud sessions]**: Cloud environments 管理ページが既存環境の保存を「installs packages」エラーで誤って拒否する問題を修正。セルフホスト環境の削除時に、削除を妨げている要因と影響範囲をダイアログとエラーメッセージで表示するよう改善された
- **[Claude Tag]**: 管理画面の Add place 検索に Claude が未参加のパブリック Slack チャンネルを追加。別の GitHub アカウントに移動したリポジトリをアクセスバンドルに再追加できるよう修正。Slack DM スレッドやスレッド内のルーチンが投稿されなくなる問題を 2 件修正。大規模組織でチャンネルリストの読み込み中でもプラグイン、スキル、バンドルの編集が機能するよう改善された
- **[Code Review]**: レビュー中に複数のプッシュがプルリクエストに着弾した際、最新コミットがレビューされないことがある問題を修正。再レビューが、以前のブロッキング指摘が未解決のまま LGTM で始まらないよう変更された

## 開発者への影響

### 対象

- Claude Code CLI / VSCode 拡張 / Cloud sessions のすべてのユーザー
- Bedrock / Vertex AI や LLM ゲートウェイ経由で利用するエンタープライズユーザー (特に v2.1.304 でリクエスト失敗が発生していた環境)
- Linux サンドボックスで Chromium や rootless podman を実行したいユーザー
- Self-hosted runner / Remote Control / Workflow の利用者

### 必要なアクション

- **アップデートの適用**: `claude update` または npm 経由で v2.1.305 に更新する。Vertex AI、Bedrock、ゲートウェイ環境で v2.1.304 のリクエスト失敗が発生している場合は、即時の適用を推奨する
- **サンドボックス利用者**: Chromium や rootless podman をサンドボックス内で実行する必要がある場合のみ `sandbox.allowNestedUserNamespaces` を有効にする。ファイル保護を回避できるようになるため、影響を理解した上で設定する
- **管理者**: `allowedMcpServers` の動作変更により、`env` 内でのみ `${VAR}` を使用する `managed-mcp.json` の stdio サーバーがアップグレード後に読み込まれるようになる。意図しないサーバーが有効化されないか確認し、必要に応じて `deniedMcpServers` で明示的に無効化する
- **無人実行の利用者**: `CLAUDE_CODE_RETRY_WATCHDOG` を使用している場合、`CLAUDE_CODE_RETRY_WATCHDOG_USAGE_LIMIT_RECHECK_MS` の設定により、使用量制限の早期解除を検知できる

### 移行ガイド (該当する場合)

破壊的変更はないが、以下の動作変更に注意が必要である。

- `allowedMcpServers` が、`env` 内でのみ `${VAR}` を使用する `managed-mcp.json` の stdio サーバーをフィルタリングしなくなった
- `allowManagedPermissionRulesOnly` 設定下では、Claude Desktop がパス指定でマウントするプラグインの `allowed-tools` が無効になった
- `/artifacts` の削除確認で `y` / `n` キーが使用できなくなった

## まとめ

v2.1.305 は、v2.1.304 で発生した Vertex AI / Bedrock / ゲートウェイ環境での全リクエスト失敗という重大なリグレッションを修正する重要なリリースである。あわせて、Linux サンドボックスの柔軟性を高める `sandbox.allowNestedUserNamespaces` の追加や、`/usage` 警告のワンキー修正、worktree、MCP、Workflow、アクセシビリティに関する多数の修正が含まれる。エンタープライズ環境のユーザーを中心に、早めのアップデートが望ましい。
