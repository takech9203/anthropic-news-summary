## 概要

Claude Code v2.1.245 および v2.1.246 (いずれも 2026 年 8 月 25 日、npm レジストリ基準) がリリースされた。

v2.1.245 は、glibc 2.44 を搭載した Linux ディストリビューション (Arch Linux、CachyOS、Fedora Rawhide など) で発生していた起動時クラッシュを修正する単一項目のパッチである。該当環境では Claude Code が起動できない状態だったため、影響を受けていたユーザーには重要な修正となる。

v2.1.246 は約 60 項目におよぶリリースで、Bash allow ルールのワイルドカードに関する起動時警告、`/permissions` への Auto mode タブの追加、ターン完了時刻の表示という新機能に加え、フルスクリーンモードやトランスクリプト表示、バックグラウンドセッション、プラグイン、MCP、テーマ、サードパーティエンドポイント利用時の問題など、広範囲のバグ修正が含まれる。特に、サードパーティゲートウェイ (`ANTHROPIC_BASE_URL`) 用の API キーが Anthropic へのテレメトリリクエストに付与されていた問題の修正は、認証情報の取り扱いに関わる重要な修正である。

## 詳細

### 背景

同日の v2.1.243 は、プロンプトキャッシュ TTL 設定やモデルピッカーのカスタマイズ、起動・メモリの大幅な改善を含む大規模リリースであった。v2.1.245 はその後に発生が確認された glibc 2.44 環境での起動クラッシュに対応する緊急パッチであり、v2.1.246 は権限管理の強化と広範なバグ修正をまとめたフォローアップリリースという位置付けになる。

### 主な変更点

#### v2.1.245: glibc 2.44 での起動クラッシュ修正

- glibc 2.44 を搭載した Linux ディストリビューション (例: Arch Linux、CachyOS、Fedora Rawhide) での起動時クラッシュを修正

#### v2.1.246: 新機能 (Added)

- **Bash allow ルールの起動時警告**: サブコマンドの前にワイルドカードを含む Bash allow ルール (例: `Bash(git * main)`) に対して起動時に警告を表示する。このようなルールはサブコマンドの前に挿入されたオプションにもマッチしてしまうため、意図しない許可を防ぐための注意喚起となる
- **`/permissions` に Auto mode タブを追加**: auto モードの分類器ルールを表示・編集できる
- **ターン完了時刻の表示**: ターン終了時の所要時間表示に完了時刻が追加された (例: `✻ Sautéed for 23s · done 6:05 PM`)

#### v2.1.246: 修正 (Fixed)

**フルスクリーン・トランスクリプト表示:**

- ターミナルのリサイズ後に最下部へジャンプすると、次のキー入力までトランスクリプトが空白になる問題を修正
- diff に非常に長い 1 行 (例: base64 文字列) が含まれると深刻な表示の遅延が発生する問題を修正。該当行はマーカー付きで切り詰めて表示される
- 過去のメッセージ位置でのフルスクリーンスクロールの乱れ (最下部へのジャンプが途中で止まる問題を含む) を修正
- メッセージの最初の 500 文字に markdown が含まれない場合にメッセージ全体の markdown レンダリングが無効になる問題、および `+` / `N)` 形式のリストと setext 見出しの問題を修正
- フルスクリーンおよび Ctrl+O のトランスクリプトビューで、セッションが長くなるほどメモリが増加する問題を修正。各メッセージ行がトランスクリプト全体のツール参照テーブルのコピーを保持しなくなった
- 実行中に中断されたコマンドが、中断された形跡なしに「Ran 1 shell command」と表示される問題を修正
- ウィンドウをフォーカスするためにクリックしただけで、フルスクリーンモードがポインター下のコントロールへキーボードフォーカスを移動する問題を修正

**バックグラウンドセッション・エージェント:**

- 起動ディレクトリが削除されている、マシンがスリープしていた、またはホストのプロセス起動が遅い場合に、バックグラウンドセッションが 45 秒後に開けなくなる問題を修正
- 別の Claude Code プロセスが npm パッケージを再インストール中に、バックグラウンドセッションが「Couldn't start the background service … EACCES」で開けなくなる問題を修正
- 動的ワークフロー中に ← キーや `/background` を実行すると完了済みサブエージェントが再起動される問題を修正。事前に確認を求め、再起動されるサブエージェント数を表示する
- 起動直後のセッションを `claude agents` で開くと、ワーカーの起動中 (Windows で多発) に「was stopped while the respawn was in flight」で停止する問題を修正
- `claude agents` がバックグラウンド化した名前付きセッションを二重に表示する問題を修正。同じ会話を再度バックグラウンド化すると新しい行に番号が付く (例: `my-session (2)`)
- 古いバックグラウンドセッションの記録が指している場合に、ユーザー自身が作成した `.claude/worktrees/` 配下の git worktree が保持期間スイープで削除される問題を修正
- フォーク済みまたはバックグラウンド化済みのセッションからの `/fork` が、空の会話で新セッションを開始する問題を修正
- Windows / macOS: 異常終了したセッションが `~/.claude/sessions` に残した古いエントリを、ヘッドレスセッションがクリーンアップしない問題を修正

**MCP・プラグイン:**

- ヘッドレス / リモートセッションで、着信メッセージにより中断された MCP ツール呼び出しが「completed with no output」としてモデルに報告される問題を修正。明示的な中断エラーが返るようになった
- パラメーターのスキーマが空 (`{}`) の場合に、MCP ツールの引数が本来の型ではなく JSON 文字列として送信される問題を修正
- プラグインキャッシュが同一プラグインに対して SHA 名のディレクトリを重複作成する問題を修正
- frontmatter の `name` に `<plugin>:` プレフィックスを含むプラグインスキルが、スラッシュメニューでプレフィックス二重 (例: `/plugin:plugin:skill`) で表示される問題を修正
- インストール済みプラグインの短縮名を指定した `claude plugin update` が失敗する問題を修正 (完全修飾名のみ動作していた)
- `plugin.json` が UTF-8 BOM 付きで保存されているとプラグインのインストールが失敗する問題を修正
- `skills/*/SKILL.md` 配下にスキルを定義するプラグインに対して `/reload-plugins` が 0 skills と報告する問題を修正
- hook のエラーメッセージが、解決済みのプラグインパスではなくリテラルの `${CLAUDE_PLUGIN_ROOT}` を表示する問題を修正
- `~/.claude/plugins/known_marketplaces.json` が空または破損している場合に、`claude plugin install <name>` がエラーを報告せず静かに終了する (またはターミナルでハングする) 問題を修正
- `requiresUserInteraction` が付いた MCP ツールの権限プロンプトに「Yes, and don't ask again」が表示される問題を修正。この選択肢が書き込む allow ルールはツール側で無視されていた
- `--strict-mcp-config` セッションが、読み込まれることのない `.mcp.json` サーバーの承認を求め、バックグラウンドセッションが起動時に待機状態になる問題を修正

**権限・セキュリティ・認証:**

- **サードパーティゲートウェイの API キー送信を修正**: `ANTHROPIC_BASE_URL` に設定したサードパーティゲートウェイ用の API キーが、Anthropic へのテレメトリ・メトリクスリクエストに付与されていた問題を修正。認証情報は自身のホストにのみ送信されるようになった
- 非常に大きなセッションで auto モードのツール呼び出しが「temporarily unavailable」として拒否される問題を、安全性チェックの期限をプロンプトサイズに応じてスケーリングすることで修正
- 末尾に `&&` や `||` が残った不正な形式のコマンドに対して、Bash の権限チェックが必ず承認を要求するように修正
- サンドボックスの「Network request outside of sandbox」権限プロンプトの待機中に `Notification` hook が発火しない問題を修正
- `apiKeyHelper` が短命な JWT を返す場合に、アイドル後の最初のプロンプトで API エラーが表示される問題を修正。期限切れのキャッシュ済みトークンは送信前に更新され、401 / 403 認証エラーは静かにリトライされる
- コマンドサンドボックスのファイルシステム設定が `--setting-sources` を尊重しない問題を修正

**テーマ・キー入力・UI:**

- `/rename` がテーマのプロンプト枠線色 (カスタムテーマの `promptBorder` を含む) をデフォルトのシアンで上書きする問題を修正。`/color` で選択しない限りテーマの色が維持される
- カスタムテーマの diff 色 (`diffAdded` / `diffRemoved` とその dimmed バリアント) が diff と `/theme` プレビューで無視される問題を修正
- `keybindings.json` に未知のアクション名のバインディングがあると、そのキーが無効になる問題を修正。該当バインディングはスキップされてデフォルトの動作が維持され、`--debug` 時に警告がログに出力される
- `/stats` のアクティビティヒートマップが、UTC より東のタイムゾーンで各日のアクティビティを 1 セルずれて表示する (日曜の件数が月曜に表示される) 問題を修正
- `/--` で始まるプロンプト (例: Lean のドキュメントコメント) が、Claude に送信されずに未知のスラッシュコマンドとして拒否される問題を修正
- 入力テキストが実在パスにマッチしなくなった後も `@` ファイルピッカーが開いたままになる問題を修正
- エージェントビューへの移動と復帰後に、ステータスラインのコストと所要時間がゼロにリセットされる問題を修正
- 補完トークンまたは作業ディレクトリに null バイトが含まれる場合にパス補完が失敗する問題を修正

**サードパーティエンドポイント・その他:**

- サードパーティの Anthropic 互換エンドポイント (`ANTHROPIC_BASE_URL`) が `id` なしの `tool_use` ブロックをストリーミングした際に、最初のツール呼び出しでレンダリングエラーにより UI が停止する問題を修正
- 保存された履歴に Anthropic API が受け付けないツールブロック (主にサードパーティ API プロキシが書き込んだもの) が含まれる場合に、再開したセッションが毎ターン 400 エラーで失敗する問題を修正
- 非常に大きな既存ファイルを上書きした後、Write ツールが「Out of memory」を報告したり長時間フリーズしたりする問題を修正 (ファイル自体は書き込み済みだった)
- サーバー管理設定を持つ一部の Team / Enterprise ユーザーで、`curl -fsSL https://claude.ai/install.sh | bash` が「Raw mode is not supported」で失敗する問題を修正
- プランモードで終了したセッションが、VS Code 拡張および権限プロンプトツール付きの `claude -p --continue` / `--resume` でプランモード外で再開される問題を修正 (権限モード未設定の場合)
- 1 つのリポジトリから同時に起動した `/ultrareview` 実行とクラウドセッション (例: 複数の worktree から) が、別の起動のコミットされていない変更を含んだ状態で開始されることがある問題を修正
- `/autofix-pr` などのバックグラウンドクラウドセッションのタスク進捗カウント (例: `3/5`) からタスクが欠落することがある問題を修正
- Remote Control セッションが claude.ai と Claude アプリで 2 回目のプロンプトまでプレースホルダー名のままになる問題を修正。自動生成タイトルが最初のプロンプト後に表示される
- セルフホストランナーが不正な形式のワークポーリング応答 (例: 中間プロキシの HTML ページ) を受け取ると、ライブセッションを終了したりランナー自体が終了したりする問題を修正。ポーリングをリトライするようになった

#### v2.1.246: 改善 (Improved)

- **`/cd` の改善**: 移動先ディレクトリのプロジェクト設定、hook、`.mcp.json` サーバー (通常の承認プロンプトあり)、スキル、エージェントが、`--resume` 時ではなく移動直後に有効になる
- bash シェルでの Bash ツールのレイテンシを改善。スナップショット関数の再生で、関数ごとの base64 サブシェルを使用しなくなった
- `maxTurns` 制限で停止したサブエージェントの結果が、完了済みとして表示されるのではなく部分的 (partial) とマークされ、`SendMessage` で継続するためのヒントが付くようになった
- 非対話セッション (`-p`、SDK、クラウドセッション) が、サーバーエラー・接続断・ストールでストリーム途中に切断された応答を、エラー終了せず自動的に継続するようになった
- ワークロードアイデンティティフェデレーションセッション、起動時の `apiKeyHelper` 実行中に送信されたイベント、アイドル中のログイントークン期限切れ後について、使用状況テレメトリの組織への帰属を改善

#### v2.1.246: 変更 (Changed)

- `/code-review` を、Bedrock、Vertex AI、Foundry、Claude アプリゲートウェイ経由、およびテレメトリや非必須トラフィックが無効な環境でも、Claude が自発的に開始できるように変更
- `/goal`: アイドルセッションが長時間のバックグラウンド作業に対して開始するチェックインを、ゴールごとに最大 3 回に変更。次のメッセージを送るとさらに 3 回許可される
- `claude install` と `claude update` が、保留中の managed-settings 同意プロンプトをコマンド実行中に表示せず、次の対話セッションに延期するように変更
- claude.ai から同期されたプラグインの OpenTelemetry イベントを変更。`plugin_id_hash` がプラグインの実際のマーケットプレイスを反映し、管理者インストールのプラグインでは `enabled_via` が `admin-install` になる

### 技術的な詳細

権限管理まわりでは、ワイルドカードを含む Bash allow ルールの挙動に注意が必要である。`Bash(git * main)` のようなルールは、`git` と `main` の間に任意のオプションが挿入されたコマンドにもマッチするため、想定より広い範囲を許可してしまう可能性がある。v2.1.246 では該当ルールに対して起動時に警告が表示されるため、既存の allow ルールを見直す契機となる。

また、`ANTHROPIC_BASE_URL` でサードパーティゲートウェイを利用している環境では、これまでゲートウェイ用の API キーが Anthropic へのテレメトリ・メトリクスリクエストにも付与されていた。v2.1.246 以降は認証情報が自身のホストにのみ送信されるため、ゲートウェイの認証情報が外部に送信される経路が解消されている。

## 開発者への影響

### 対象

- glibc 2.44 を搭載した Linux ディストリビューション (Arch Linux、CachyOS、Fedora Rawhide など) のユーザー (v2.1.245 で起動可能に)
- ワイルドカードを含む Bash allow ルールを設定しているユーザー (起動時警告の対象)
- `ANTHROPIC_BASE_URL` でサードパーティゲートウェイやプロキシを利用しているユーザー (認証情報送信の修正、`tool_use` レンダリングエラーや 400 エラーの修正)
- バックグラウンドセッション、`claude agents`、動的ワークフローを利用しているユーザー
- プラグインや MCP サーバーを開発・利用しているユーザー
- カスタムテーマや `keybindings.json` を利用しているユーザー

### 必要なアクション

以下のいずれかの方法で最新バージョンに更新できる。

```bash
# Claude Code 組み込みコマンド
claude update

# npm でのアップデート
npm update -g @anthropic-ai/claude-code

# 現在のバージョン確認
claude --version
```

glibc 2.44 環境で v2.1.244 以前が起動できない場合は、npm 経由で直接更新するか、インストールスクリプトで v2.1.245 以降を導入する。

アップデート後に Bash allow ルールの警告が表示された場合は、`/permissions` で該当ルールを確認し、意図しないコマンドまで許可していないか見直すことを推奨する。auto モードを利用している場合は、`/permissions` の新しい Auto mode タブで分類器ルールを確認できる。

### 移行ガイド (該当する場合)

破壊的変更はアナウンスされていないため、移行作業は不要である。

## まとめ
