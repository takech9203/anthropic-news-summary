Messages API と Token Counting API の最大リクエストサイズが 128 MB に拡大

2026-10-28

概要

Anthropic は 2026 年 10 月 28 日、ファーストパーティ Claude API における Messages API と Token Counting API の最大リクエストサイズを、従来の 32 MB から 128 MB に引き上げました。Base64 エンコードされた画像やドキュメントを多数含むリクエストや、大量のメッセージ履歴を含む長いコンテキストのリクエストを、従来の 4 倍のサイズまで単一の API 呼び出しで送信できます。

📦

32 MB から 128 MB へ 4 倍に拡大

Messages API の最大リクエストサイズが 128 MB に引き上げられ、画像や PDF を多数含むマルチモーダルリクエストを分割せずに送信できます。

🔢

Token Counting API も同時に 128 MB に拡大

Token Counting API は Messages API と同じリクエスト形式を受け取るため、両者の制限が揃うことで、送信前のトークン数見積もりというユースケースをそのまま維持できます。

🏢

適用対象はファーストパーティ Claude API のみ

128 MB の上限は https://api.anthropic.com 固有のものです。Amazon Bedrock や Google Cloud などのクラウドプラットフォームには異なる制限 (20〜32 MB) が適用されます。

✅

既存コードへの変更は不要

本変更は上限の引き上げであり、後方互換性に影響はありません。移行作業は不要です。

Before / After

Before

32 MB

  • 32 MB を超えるリクエストは分割して送信が必要
  • 413 request_too_large エラーが発生しやすい

After

128 MB

  • 413 エラーの発生頻度が低下
  • Token Counting API も 128 MB で事前検証がそのまま可能

主な変更点

📨 Messages API

最大リクエストサイズが 32 MB から 128 MB に拡大 (4 倍)。Base64 エンコードされた画像や PDF、長い会話履歴を含む大きなリクエストを単一呼び出しで送信できます。

🔢 Token Counting API

Messages API と同時に 128 MB へ引き上げ。送信予定のリクエストをそのまま事前検証し、トークン数を見積もるワークフローを維持できます。

🏢 適用範囲

ファーストパーティ Claude API (https://api.anthropic.com) のみに適用。パートナー運営のクラウドプラットフォームには独自の制限が適用されます。

⚠️ 制限超過時の動作

制限を超えたリクエストは、従来どおり HTTP ステータスコード 413 の request_too_large エラーで拒否されます。

技術詳細: エンドポイント別のサイズ制限

公式ドキュメントの API overview (Request size limits) によると、変更後のファーストパーティ Claude API のリクエストサイズ制限は以下のとおりです。

エンドポイント 最大リクエストサイズ
Messages API、Token Counting API 128 MB (今回拡大)
Message Batches API 256 MB
Files API 500 MB
Sessions、Agents、Environments 32 MB

クラウドプラットフォームでの制限: パートナー運営プラットフォームには独自のリクエストサイズ制限があります。

プラットフォーム 最大リクエストサイズ
ファーストパーティ Claude API 128 MB
Claude Platform on AWS 32 MB
Claude Models on Google Cloud (Anthropic managed) 32 MB
Microsoft Foundry 32 MB
Claude Models on Google Cloud (Google managed) 30 MB
Amazon Bedrock 20 MB
⚠
メッセージ数の上限: Messages API にはリクエストサイズとは別に、1 リクエストあたり最大 100,000 メッセージという上限も存在します。

コードサンプル

Token Counting API を使用して、大きなリクエストを送信する前にトークン数を確認する例です。リクエストサイズ制限 (128 MB) は Messages API と Token Counting API で共通のため、送信予定のリクエストをそのまま事前検証できます。

Python 送信前のトークン数確認と Messages API 呼び出し 
import anthropic
import base64

client = anthropic.Anthropic()

# 画像を Base64 エンコードしてコンテンツに含める
with open("large_document_page.png", "rb") as f:
    image_data = base64.standard_b64encode(f.read()).decode("utf-8")

messages = [
    {
        "role": "user",
        "content": [
            {
                "type": "image",
                "source": {
                    "type": "base64",
                    "media_type": "image/png",
                    "data": image_data,
                },
            },
            {"type": "text", "text": "この画像の内容を要約してください。"},
        ],
    }
]

# 送信前にトークン数をカウント (最大リクエストサイズ: 128 MB)
count = client.messages.count_tokens(
    model="claude-sonnet-4-5",
    messages=messages,
)
print(f"入力トークン数: {count.input_tokens}")

# Messages API で送信 (最大リクエストサイズ: 128 MB)
response = client.messages.create(
    model="claude-sonnet-4-5",
    max_tokens=1024,
    messages=messages,
)
print(response.content[0].text)

ユースケース

🖼️ 大規模マルチモーダルリクエストの統合

Base64 エンコードされた画像や PDF を多数含むリクエストでは、エンコードによってデータサイズが元のバイナリより増加します。これまで 32 MB の制限を回避するためにリクエストを分割していた場合、単一リクエストへの統合を検討でき、実装を簡素化できます。

📜 長いコンテキストを扱うアプリケーション

長い会話履歴や大量のドキュメントをコンテキストに含むリクエストを 1 回の API 呼び出しで送信できます。413 request_too_large エラーに対するハンドリングやリトライロジックを実装している場合、発生頻度の低下が見込まれます。

🔢 送信前のトークン数見積もりワークフロー

Token Counting API も同じ 128 MB に拡大されたため、大きなリクエストでも送信前にトークン数を正確に見積もれます。複数の API 呼び出しで同じファイルを再利用する場合は、リクエストに直接埋め込む代わりに Files API (最大 500 MB) の利用も引き続き選択肢となります。

⚠
マルチプラットフォーム構成での注意: Amazon Bedrock (20 MB) や Google Cloud の Google managed (30 MB)、Anthropic 運営のクラウドプラットフォーム (32 MB) を併用している場合、ファーストパーティ API 向けの大きなリクエストをそのまま送信するとエラーになる可能性があります。最も小さい上限に合わせた設計か、プラットフォームごとの分岐処理を検討してください。
ℹ️
移行作業は不要: 本変更は上限の引き上げであり、後方互換性に影響はありません。ファーストパーティ Claude API を利用しているすべての開発者が、コード変更なしで恩恵を受けられます。
