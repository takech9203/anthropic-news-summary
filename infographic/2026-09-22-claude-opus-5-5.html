Claude Opus 5.5 発表

Fable 5.1 同等の性能を 40% 低いコストで実現する Claude 5.5 ファミリー初のモデル (モデル ID: claude-opus-5-5)

📅 2026-09-22 ｜ ソース: Anthropic News / Claude API Release Notes

概要

Anthropic は 2026 年 9 月 22 日、Claude 5.5 ファミリー初のモデルとなる Claude Opus 5.5 を発表しました。ほとんどの作業で Claude Fable 5.1 と同等の性能を発揮しながら、実行コストは Opus 5 より 40% 低く、長時間のエージェント的コーディングおよびナレッジワーク向けに設計されています。Claude API、Amazon Bedrock、Claude Platform on AWS、Google Cloud、Microsoft Foundry で即日利用可能です。

💎

Fable 5.1 同等の性能を 40% 低いコストで

ベンチマーク上は Fable 5.1 を上回るスコアを示すものの、実際の差は「スコアが示すよりも小さい」と注記されており、位置付けは Fable 5.1 同等の性能をより低コストで実現するモデルです。METR や Frontier Design による外部評価を経てリリースされました。

💰

価格を 20% 引き下げ、キャッシュ読み取りは 60% 削減

入力 $4 / 出力 $20 (100 万トークンあたり) と Opus 5 ($5/$25) から 20% 引き下げられ、キャッシュ読み取りは $0.20/MTok と 60% 削減されました。

📏

1M トークンコンテキストと 128k 最大出力

1M トークンのコンテキストウィンドウ (デフォルト) と 128k の最大出力トークンを備え、長時間のエージェント的コーディングやナレッジワークに対応します。

🧠

adaptive thinking は常時オン

thinking を無効化できず、effort パラメータ (low から max) で推論の深さを制御します。thinking: disabled / enabled の指定は 400 エラーになります。

🗓️

Sonnet 5.5 と Haiku 5.5 は数週間以内に公開予定

Opus 5.5 は、フロンティアモデルの性能を大幅に低いコストで提供することを目指した Claude 5.5 ファミリーの最初のモデルです。

Before / After: Opus 5 → Opus 5.5

Before (Opus 5)

  • 入力 $5 / 出力 $25 (100 万トークンあたり)
  • キャッシュ読み取り $0.50/MTok
  • 20 万行のコードベース監査に 20 時間超
  • thinking: enabled/disabled で thinking を指定
  • tool_choice は auto / any / tool が利用可能
  • computer use は computer_20251124

After (Opus 5.5)

  • 入力 $4 / 出力 $20 (20% 減)、キャッシュ読み取り $0.20/MTok (60% 減)
  • 20 万行のコードベース監査を 3 時間未満で完了
  • 出力生成は 30% 以上高速
  • thinking フィールドは省略し effort パラメータで制御 (常時オン)
  • tool_choice は auto と strict tool use のみ
  • computer use は computer_toolset_20260801 (Bedrock は旧版も可)
  • 1M トークンコンテキスト (デフォルト)、128k 最大出力

性能面のハイライト

💻 コーディング

20 万行のコードベース監査を 3 時間未満で完了 (Opus 5 は 20 時間超)。HAProxy の C から Rust への移植を 9.5 時間で完了 (Fable 5.1 は 12 時間、コストは 51% 減)。

🔍 調査・分析

収益報告レポートテストで 18 回中 16 回が品質基準をクリア (Fable 5.1 と Opus 5 は 0 回)。

💬 コミュニケーション

重要情報を冒頭に配置し、より自然で明瞭な文章に改善されました。

⚡ 速度

出力生成は Opus 5 より 30% 以上高速です。fast mode (リサーチプレビュー) では最大 2.5 倍の速度を実現します。

🛡️ 安全性

  • 🏆 行動監査で過去最高スコア 約 2,000 シナリオの自動行動監査で過去最高スコアを記録。封じ込め境界の回避試行は Opus 5 / Mythos 5.1 比で約 85% 減少しました。
  • 🛡️ プロンプトインジェクション耐性 Gray Swan のテストで Fable 5.1 と同率最低の攻撃成功率を記録しました。
  • 🔬 生物学・サイバーセキュリティ分野のセーフガード Fable 5.1 と同等のセーフガードを適用 (Life Sciences Verification Program、Cyber Verification Program 経由でアクセス可能)。
  • 📜 コンプライアンス対応 蒸留対策の preserved thinking、EU AI Act 準拠のウォーターマーク、ゼロデータ保持に対応しています。

技術的な詳細

  • 🧠 adaptive thinking は常時オン Opus 5.5 では thinking を無効化できません。thinking: disabled および thinking: enabled を指定すると 400 エラーが返ります。thinking フィールドを省略し、effort パラメータ (low から max) で推論の深さを制御します。
  • 🔧 tool_choice の制約 tool_choice の any と tool は 400 エラーとなります。auto と strict tool use を使用します。
  • 🖥️ computer use のツールセット変更 Claude API と Google Cloud では computer_toolset_20260801 が必須となり、旧来の computer_20251124 は 400 エラーとなります (Bedrock では引き続き動作)。
  • ⚡ fast mode (リサーチプレビュー) Claude API 上で利用可能。入力 $8 / 出力 $40 (100 万トークンあたり) で、最大 2.5 倍の速度を実現します。Claude Code と Claude Platform でも利用できます。
  • 📈 利用上限の拡大 Pro / Max / Team / Enterprise プランで 5 時間の利用上限が引き上げられ、レート制限リセットの保存機能も追加されました。

💻 コード例

Python Opus 5.5 の呼び出し例 (effort パラメータで推論の深さを制御) 
import anthropic

client = anthropic.Anthropic()

# thinking フィールドは省略し、effort パラメータで推論の深さを制御する
message = client.messages.create(
    model="claude-opus-5-5",
    max_tokens=128000,
    effort="high",  # low / medium / high / max
    tool_choice={"type": "auto"},  # any と tool は 400 エラー
    messages=[
        {
            "role": "user",
            "content": "リポジトリ全体を監査し、セキュリティ上の問題を報告してください。",
        }
    ],
)

print(message.content)

開発者への影響

🎯 対象

  • Claude API、Amazon Bedrock、Claude Platform on AWS、Google Cloud、Microsoft Foundry で Opus 系モデルを利用している開発者
  • 長時間のエージェント的コーディングやナレッジワークの自動化に取り組むチーム
  • Opus 5 のコストがボトルネックとなっていたユースケース

✅ 必要なアクション

  1. モデル ID を claude-opus-5-5 に更新する
  2. thinking フィールドを削除し、effort パラメータでの制御に切り替える
  3. tool_choice に any または tool を指定している場合は auto と strict tool use に移行する
  4. computer use を利用している場合、Claude API / Google Cloud では computer_toolset_20260801 に更新する

🔀 移行ガイド

項目 Opus 5 Opus 5.5
thinking の指定 thinking: enabled/disabled フィールドを省略し effort で制御
tool_choice auto / any / tool auto と strict tool use のみ
computer use computer_20251124 computer_toolset_20260801 (Bedrock は旧版も可)
コンテキストウィンドウ — 1M トークン (デフォルト)
最大出力トークン — 128k
⚠️ API 仕様変更に注意

thinking: enabled/disabled の指定、tool_choice の any / tool、旧 computer use ツールセット (computer_20251124、Claude API / Google Cloud の場合) はいずれも 400 エラーとなります。Opus 5 からの移行時には上記の必要なアクションを確認してください。

ユースケース

💻 長時間のエージェント的コーディング

20 万行のコードベース監査を 3 時間未満で完了するなど、大規模なコードベースの監査や言語間の移植 (例: HAProxy の C から Rust への移植を 9.5 時間、コスト 51% 減) といった長時間タスクを、Opus 5 より大幅に低いコストと時間で実行できます。

📊 ナレッジワークの自動化

収益報告レポートテストで 18 回中 16 回が品質基準をクリア (Fable 5.1 と Opus 5 は 0 回) しており、調査・分析やレポート作成などのナレッジワーク自動化に適しています。1M トークンコンテキストにより大量の資料を一度に扱えます。

💰 コスト最適化が必要な既存 Opus ワークロード

Opus 5 のコストがボトルネックとなっていたユースケースでは、価格 20% 減、キャッシュ読み取り 60% 減、30% 以上の高速化により、実運用コストを大幅に削減できます。応答速度が重要な場面では fast mode (入力 $8 / 出力 $40) も選択できます。

まとめ

Claude Opus 5.5 は、Claude Fable 5.1 と同等の性能を Opus 5 比 40% 低いコストで提供する、コスト効率を重視したフロンティアモデルです。価格の引き下げ (入力 $4 / 出力 $20)、キャッシュ読み取り 60% 減、30% 以上の高速化により、長時間のエージェント的コーディングやナレッジワークの実運用コストを大幅に削減できます。一方で、thinking の常時オン化、tool_choice の制約、computer use ツールセットの更新など API 仕様の変更があるため、Opus 5 からの移行時には必要なアクションの確認を推奨します。Sonnet 5.5 と Haiku 5.5 は数週間以内に公開予定です。
