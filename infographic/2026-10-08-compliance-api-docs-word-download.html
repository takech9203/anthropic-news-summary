Claude API エンタープライズ コンプライアンス ベータ

Compliance API が Claude Docs ドキュメントの
Word ファイルダウンロードに対応

📅 2026-10-08 | Claude Developer Platform Release Notes

概要

📝

Claude Docs ドキュメントを Word 形式で取得可能に

Compliance API が Claude Docs ドキュメントを Word ファイルとしてダウンロードできるようになった。Claude Enterprise 組織向けのベータ提供である。

📋

一覧は List code artifacts で行う

Claude Docs ドキュメントは GET /v1/compliance/apps/code/artifacts で、artifact_type が claude_docs のエントリとして返る。ファイルとアーティファクトが独立に一覧されないという従来の原則の例外となる。

🗜️

ダウンロードは ZIP 形式

コンテンツエンドポイントを multi_file_format=zip 付きで呼び出すと、テキストを持つタブごとに 1 つの Word (.docx) ファイルを含む ZIP アーカイブが返る。

🚫

取得できるのは現在のテキストのみ

versions リストは空、published_version_id は null であり、コメント、アップロードされたファイル、編集履歴は ZIP に含まれない。

🔄

既存インテグレーションへの破壊的変更なし

本機能は新しい取得経路の追加であり、既存のチャット、ファイル、プロジェクト系エンドポイントの仕様に変更はない。既存の Compliance Access Key でそのまま利用できる。

主な機能

📋 claude_docs としての一覧

List code artifacts エンドポイントが、Claude Docs ドキュメントを artifact_type が claude_docs のアーティファクトとして返す。所有者情報、公開範囲 (read_mode)、更新日時 (updated_at) も含まれる。

📦 タブごとの .docx を含む ZIP

GET .../artifacts/{artifact_id}/content?multi_file_format=zip が、テキストを持つタブごとに 1 つの Word (.docx) ファイルを含む ZIP アーカイブを返す。

📄 現在のテキストのみを取得

Claude Docs ドキュメントの versions リストは空で、published_version_id は null。バージョン単位ではなく、現在のテキストのみをダウンロードする。

🔑 既存のキーとスコープで利用可能

claude.ai で作成した Compliance Access Key の read:compliance_user_data スコープで取得できる。新しいキーやスコープの追加は不要。

🏢 Claude Enterprise 組織限定

本機能を含むページのエンドポイントは Claude Enterprise 組織のみが利用できる。Admin API キーでは 403 Forbidden が返る。

技術詳細

🔌 対象エンドポイント

エンドポイント 役割
GET /v1/compliance/apps/code/artifacts コードアーティファクトの一覧 (claude_docs を含む)
GET /v1/compliance/apps/code/artifacts/{artifact_id}/content?multi_file_format=zip Claude Docs ドキュメントの現在のテキストを ZIP で取得 (ベータ)

🔐 認証とスコープ

🔑 read:compliance_user_data — 取得に必要

取得には claude.ai で作成した Compliance Access Key (sk-ant-api01-...) が必要。チャット、ファイル、プロジェクト系のエンドポイントは Admin API キー (sk-ant-admin01-...) では利用できず、403 Forbidden が返る。

📋 List code artifacts の主なパラメータ

項目 内容
limit 最大件数 (デフォルト 20、最大 100)
organization_ids 組織 ID フィルター (最大 500 件)
user_ids 所有者ユーザー ID フィルター (最大 200 件)
updated_at.gt/gte/lt/lte 更新日時フィルター (RFC 3339 形式)
page 前のレスポンスの next_page トークンによるページネーション

レスポンスの artifact_type は claude_docs のほか、claude_slides、claude_design、claude_design_systems、claude_motion、code、other を取り得る。結果はアーティファクト ID 順にソートされる。

⚖️ Claude Docs ドキュメントと他のアーティファクトの違い

項目 一般のコードアーティファクト Claude Docs ドキュメント
artifact_type code など claude_docs
versions 直近約 20 バージョンのメタデータ 空
published_version_id 公開バージョンの ID null
コンテンツ取得 バージョン単位でダウンロード content?multi_file_format=zip で現在のテキストを取得
取得形式 バージョンのコンテンツ タブごとの Word (.docx) を含む ZIP

コードサンプル

Bash Claude Docs ドキュメントの一覧 
# コードアーティファクトを一覧し、artifact_type が claude_docs の
# エントリを抽出する。next_page が無くなるまでページングする
curl --fail-with-body -sS -G \
  "https://api.anthropic.com/v1/compliance/apps/code/artifacts" \
  --header "x-api-key: $ANTHROPIC_COMPLIANCE_ACCESS_KEY" \
  --header "anthropic-version: 2023-06-01" \
  --data-urlencode "limit=100" \
  | jq '[.data[] | select(.artifact_type == "claude_docs")]'
Bash Claude Docs ドキュメントの Word ダウンロード 
# 現在のテキストを、テキストを持つタブごとに 1 つの Word (.docx)
# ファイルを含む ZIP アーカイブとしてダウンロードする (ベータ)。
# コメント、アップロードされたファイル、編集履歴は含まれない
artifact_id="cart_01Tu9VwXyZaBcDeFgHiJkLmN"

curl --fail-with-body -sS -G \
  "https://api.anthropic.com/v1/compliance/apps/code/artifacts/$artifact_id/content" \
  --header "x-api-key: $ANTHROPIC_COMPLIANCE_ACCESS_KEY" \
  --header "anthropic-version: 2023-06-01" \
  --data-urlencode "multi_file_format=zip" \
  --output "${artifact_id}.zip"

注意点

⚠️ 取得できる内容には限界がある

Compliance API 経由で取得できるのは Claude Docs ドキュメントの現在のテキストのみである。監査要件に対して何が証跡として残るかを関係者と確認する必要がある。

  • コメント、アップロードされたファイル、編集履歴は ZIP に含まれない
  • versions リストは空で、published_version_id は null。過去バージョンは取得できない
  • Compliance API 経由の Claude Docs ダウンロードはベータであり、仕様が変わる可能性がある

🔁 完全な列挙にはページネーションと時間フィルターの注意点がある

ページネーションは next_page トークン方式で、has_more が true でも次ページが空の場合があるため、next_page が無くなるまで続ける必要がある。また、updated_at の時間フィルターは結果整合性のあるインデックスに対して照合されるため、コンプライアンス上完全な列挙には時間フィルターを省略し、増分エクスポートではウィンドウ間に十分な重なりを設けて id で重複排除することが推奨されている。

❓ コンテンツエンドポイント単体のリファレンスは未確認

コンテンツエンドポイント (.../content) 単体の API リファレンスページの URL は、調査時点では特定できていない。エンドポイントの仕様は Retrieve files and artifacts セクションの記述に基づく。multi_file_format に zip 以外の値が指定できるかどうかも、ドキュメント上では確認できていない。

ユースケース

⚖️ eDiscovery (電子証拠開示)

コンプライアンス / eDiscovery 担当者は、Claude Docs で作成されたドキュメントを証跡としてエクスポートできる。List code artifacts で claude_docs のエントリを一覧し、タブごとの Word ファイルを含む ZIP として取得する。

🔐 DLP (データ損失防止)

セキュリティチームは、組織内で作成された Claude Docs ドキュメントの内容を Word 形式で取り出し、DLP で機微情報の検査にかけられる。ZIP を展開してタブ単位の .docx を検査パイプラインに流し込める。

🛡️ 監査カバレッジの整理

Claude Enterprise 管理者は、Claude Docs の組織展開に際して監査カバレッジを整理できる。取得できるのは現在のテキストのみという限界を踏まえ、何が証跡として残るかを監査要件に反映する。

必要なアクション

エクスポート対象への追加

アーティファクトのエクスポートを実装している場合、List code artifacts の結果から artifact_type が claude_docs のエントリを選別し、ZIP ダウンロード経路を追加する。

カバレッジの限界を把握する

取得できるのは現在のテキストのみで、コメント、アップロードされたファイル、編集履歴は含まれない。監査要件に対して何が証跡として残るかを関係者と確認する。

ZIP 展開処理の実装

レスポンスは単一の Word ファイルではなく、テキストを持つタブごとに .docx を含む ZIP アーカイブである。展開とタブ単位の保存に対応する。

完全列挙の設計

updated_at フィルターには結果整合性の注意点があるため、完全なエクスポートでは時間フィルターを省略し、増分エクスポートでは重なりを設けて id で重複排除する。

ベータであることの考慮

本番の監査要件に組み込む場合は、ベータ提供であり仕様が変わる可能性があるという前提を明示する。
