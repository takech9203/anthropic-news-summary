Claude Code v2.1.314

119 項目の大型リリース。作業ディレクトリ外への書き込み拒否設定とアイドルコンパクションが追加

📅 2026-10-30 | ソース: Claude Code Changelog

概要

📦

119 項目の大型リリース

新しい権限設定とアイドルコンパクションを柱に、接続・権限・セッション・各コンポーネントにわたる多数の新機能、修正、動作変更を含む。

🛡️

permissions.blockWritesOutsideWorkingDirectories の追加

有効にすると、Write、Edit、NotebookEdit の各ツールが、どの権限モードでも作業ディレクトリ外への書き込みを拒否する。意図しないファイル変更を防ぐガードレールとして機能する。

🗜️

アイドルコンパクション

VS Code と Claude Desktop の Code タブに追加。200K トークンを超えて放置された会話はバックグラウンドで要約され、プロンプトキャッシュが期限切れの場合は次のメッセージでその要約が使用される。

🔌

Claude apps gateway の機能強化

IdP グループ単位でアップストリームを割り当てる groups リストと、Amazon Bedrock ガードレールの発動を記録する guardrail_trace が追加された。

🔧

運用上影響の大きい不具合を修正

組織の effort 上限による「Invalid effort level」失敗、claude -p の起動失敗が終了コード 0 になる問題、Bedrock で画像が多いセッションが「400 Input is too long.」で失敗し続ける問題などを解消。

主要変更

✨ Added (新機能)

🛡️ 作業ディレクトリ外書き込みの拒否

permissions.blockWritesOutsideWorkingDirectories を有効にすると、Write / Edit / NotebookEdit がどの権限モードでも作業ディレクトリ外への書き込みを拒否する。

🗜️ アイドルコンパクション

VS Code と Claude Desktop の Code タブで、200K トークン超の放置された会話を自動要約。長時間の会話を再開する際の待ち時間とコストを削減する。

👥 gateway の groups リスト

アップストリームに groups リストを指定すると、リストにある IdP グループに所属する開発者のみがそのアップストリームへ送られる。フェイルオーバー時にも適用される。

📋 gateway の guardrail_trace

Bedrock アップストリームに追加。リクエストで発動した Amazon Bedrock ガードレールフィルターを、マッチしたテキストを含めずにログに記録できる。

🔗 Claude Tag API ドキュメントリンク

Enterprise 組織向けに、Slack 接続時の管理設定 Bundles / Channels タブに Claude Tag API ドキュメントへのリンクを追加 (非表示化可能)。

✅ Include completed ボタン

Cloud sessions の Scheduled tasks ページに、完了した一回限りのタスクのみが非表示の場合に Include completed ボタンを追加。

🔧 Fixed (修正)

🌐 接続・プラットフォーム関連

🖼️ Bedrock の画像多数セッション

古い画像を削除してコンパクトする代わりに、毎ターンおよび /compact が「400 Input is too long.」で失敗していた問題を修正。

🏭 Microsoft Foundry のフォールバック

デフォルトの Sonnet / Opus / Haiku モデルのデプロイがないリソースでセッションが失敗する問題を修正。同系統の旧モデルにフォールバックする。

🔌 ゲートウェイの互換性

ツール検索の tool_reference ブロックや beta ヘッダーを拒否するゲートウェイに対し、該当機能なしで再送するようになった。ドット付きモデル ID (claude-opus-4.8 など) が旧モデルとして扱われる問題も修正。

🔐 TLS / Vertex のハング

クロス署名された更新済みルート証明書での UNABLE_TO_GET_ISSUER_CERT 失敗と、gateway の Vertex アップストリームが Google のトークンエンドポイント無応答時に数分間ハングする問題を修正。

🔒 権限・設定・セキュリティ関連

⚡ 「Invalid effort level」失敗

組織の管理者が effort に上限を設定している場合に、セッションがターンごとに失敗し続ける問題を修正。effort を下げてリトライし、使用するレベルを表示する。

🖥️ claude -p の終了コード

起動に失敗した際に終了コード 0 かつ出力なしで終了していた問題を修正。エラーを表示し、終了コード 1 で終了する。CI で失敗を検知できなかったケースが解消される。

🏖️ worktree のサンドボックス保護

claude -p --resume または --continue で入った worktree にサンドボックス保護が適用されない問題を修正。

⚙️ 設定ソースの除外

--setting-sources で除外した設定ファイルが、auto モードのルールや保存済みの許可など一部の設定を供給し続ける問題を修正。

📡 リモート managed settings

forceRemoteSettingsRefresh が保存済みコピーの期限切れ後に適用されず、サーバー到達不能時にポリシーなしでセッションが開始できていた問題を修正。管理者の TLS 信頼設定が Claude Desktop に適用されない問題も修正。

🪝 Monitor ツールへのフック適用

Bash にマッチするフックが Monitor ツールの開始するシェルコマンドで実行されない問題を修正 (ブロックと確認は可能、承認と書き換えは不可)。

💬 セッション・動作関連

🔁 使用量制限での自動継続

タスクが待機の合間に自己再起動した場合に、確認なしで 3 回を超えて継続する問題を修正。

🗜️ PreCompact フックの反復失敗

出力が非常に大きい PreCompact フックがコンパクションを失敗・反復させる問題を修正。各フックの出力は 10,000 文字で切り詰められる。

🔀 git index ロックの競合

バックグラウンドの diff 更新が index ロックを一時取得し、同時実行した git コマンドが「index.lock: File exists」で失敗することがある問題を修正。

⌨️ vim モードの挙動

dw / dW / yw / yW が行末を越える問題、aw / iw が行末の改行を取り込む問題など、複数の挙動を修正。

ほか、MCP サインイン表示、claude mcp logout、モデル切り替えをまたいだ巻き戻し、ターミナル UI、セッション管理など多数の修正あり

🔄 Changed (動作変更)

🗜️ アイドルコンパクションの対象拡大

テレメトリをオフにしている Subscriber にも実行される。1 時間プロンプトキャッシュが有効な場合は Bedrock / Vertex / Foundry / LLM ゲートウェイでも実行される。

🏢 管理設定ローカルコピーの保護

Claude のファイルツールが、組織のサーバー管理設定のローカルコピーを編集する前に、ユーザーの設定ファイルと同様に確認を求める。

🔁 旧 Opus のみの場合のリトライ

ANTHROPIC_DEFAULT_OPUS_MODEL、availableModels、deniedModels により旧 Opus モデルのみ、またはモデルが残らない場合、フラグされたリクエストが拒否で終わらず別モデルでリトライする。

🐚 Bash ツールの which 保護

継承された which のエイリアスや関数をクリアし、エクスポートされた which / unsetenv 関数をコマンドへ渡さない。which はシステムコマンドまたは zsh ビルトインになる。

🚫 Recently blocked タブ

/permissions のレビュータブを Recently blocked に名称変更。全文を読めない呼び出しの承認を拒否する。auto モードのブロック時メッセージも改善された。

⚡ パフォーマンス改善

多数のサブエージェントを実行する長い headless / SDK ターンのメモリ使用量、--resume の速度、1 万以上の MCP ツールを持つセッションでの /context の速度を改善。

ほか、フックの if 条件の Monitor 対応、FORCE_HYPERLINK=false の動作修正、macOS の git grep C ロケール化、Ctrl+R 検索の改善など

コンポーネント別の改善

💻 VSCode

MCP サーバーの「Clear authentication」の誤報告、フック実行中のスピナー非表示、セッショングループ変更の静かな失敗、プランプレビューの検索ウィジェット、非ラテン系キーボードでの音声入力ショートカット (Ctrl+D) を修正。CLAUDE_CODE_DISABLE_CFC_PROMPT が Claude in Chrome 指示の追加も停止するよう変更。

☁️ Cloud sessions

セルフホスト環境が最近の環境に表示されない問題、別 worktree からのブランチ移動後の未コミット変更誤報告、権限モードピッカーの表示を修正。スケジュールタスクのプラグイン読み込み、GitHub Enterprise の Test connection を改善。セットアップスクリプトがエラー終了してもセッションが起動するよう変更。

🎮 Remote Control

権限モードボタンが入力するまで誤ったモードを表示する問題、8 秒を超えるモデル切り替えの「still pending」エラー、/compact 後の不要な「Compacted」行を修正。セッションサービスが一時的に遅い場合、ワーカーの登録が待機時間を増やしながらリトライされる。

🏷️ Claude Tag

Enterprise Grid 共有チャンネルでの @Claude !restart のリトライ、Slack Connect チャンネルでの自スレッド内タグへの無応答、セルフホストランナー待機中の進捗非表示、管理設定プラグインページの Retry による未保存変更の破棄を修正。

技術詳細

🛡️ 作業ディレクトリ外書き込みの拒否

permissions.blockWritesOutsideWorkingDirectories は権限モードに関わらず適用されるため、bypassPermissions のような緩いモードでもファイル書き込みの範囲を作業ディレクトリに限定できる。

JSON settings.json の設定例 
{
  "permissions": {
    "blockWritesOutsideWorkingDirectories": true
  }
}

🗜️ アイドルコンパクションの仕組み

200K トークンを超えた会話が放置されるとバックグラウンドで要約が作成される。プロンプトキャッシュが有効なうちは元の会話が使われ、期限切れの場合のみ要約が使用されるため、通常の応答品質に影響しにくい設計になっている。

⚡ effort 上限への自動適応

組織ポリシーで effort が制限された場合、従来はリクエストが失敗し続けていたが、クライアント側で自動的に許容レベルまで下げてリトライするようになった。使用するレベルも表示される。

👥 gateway の groups によるルーティング

アップストリームにオプションの groups リストを指定すると、リストにある IdP グループに所属する開発者のみがそのアップストリームへ送られる。フェイルオーバー時にも適用されるため、グループ単位の経路制御を維持できる。

ユースケース

🛡️ ファイル変更の範囲を制限したいユーザー / 管理者

permissions.blockWritesOutsideWorkingDirectories を設定に追加することで、どの権限モードでも作業ディレクトリ外への書き込みを拒否できる。bypassPermissions を使う自動化環境でも、意図しないファイル変更を防ぐガードレールとして機能する。

🖥️ claude -p を CI やスクリプトに組み込んでいるユーザー

起動失敗が終了コード 1 として正しく報告されるようになったため、エラーハンドリングが期待どおり動作することを確認する。従来は終了コード 0 かつ出力なしで、失敗を検知できないケースがあった。

🏢 Claude apps gateway を運用するエンタープライズ管理者

IdP グループ単位のルーティングが必要な組織は groups リストを、Bedrock ガードレールの監査が必要な組織は guardrail_trace の活用を検討する。effort 上限を設定している組織では「Invalid effort level」失敗が解消される。
