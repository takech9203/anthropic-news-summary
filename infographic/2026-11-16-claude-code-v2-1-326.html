Before / After - Code Mode とエージェントチーム

Before (〜 v2.1.325)

Code Mode とエージェントチームは同時に有効化できなかった。どちらか一方を選ぶ必要があり、チームセッションでは Code Mode のメリットを活用できなかった

After (v2.1.326 〜)

エージェントチームを有効にしたまま Code Mode をオンにできる。Code Mode 有効化済みのユーザーは、チーム有効のセッションも Code Mode で開始される

関連する修正も多数: auto モード下の Code Mode でインライン ! コマンドが承認を要する場合のスキルロード失敗、バックグラウンドサブエージェントのスキルプリロード失敗、mod が $.tool.call / $.tool.check 経由でツールを使えない問題などを修正。Code Mode の権限チェックも強化され、$ シェルヘルパーは一部の値をエラーで拒否するようになった

主要な変更点

🤝 Code Mode とエージェントチームの併用

  • 両機能を同時に有効化できるようになった
  • チーム有効のセッションも Code Mode で開始
  • Code Mode の権限チェックを強化。確認・拒否されるサンドボックスコマンドが増加
  • 有効化できない場合のメッセージが対処方法を提示

🩺 起動時・診断の新機能

  • --allowedTools / --disallowedTools / --tools の不完全なルール値に起動時警告
  • /status に機能無効化の理由を表示する行を追加
  • Ctrl+O で非表示の起動通知を表示
  • managed-mcp.json 追加時の説明メッセージ
  • /doctor が作業しながら所見を逐次報告

🏖️ サンドボックスと権限の強化

  • macOS / Linux / WSL の Bash サンドボックス保護を改善
  • 機密性の高いホームフォルダへは既定で書き込み不可 (sandbox.filesystem.allowWrite で許可可能)
  • .credentials.json などサインインファイルへの書き込みを拒否
  • bypass permissions モードでも一部は承認を要求または拒否
  • プログラム名を含まない、または $HOME で始まるワイルドカード allow ルールは auto モードで無視

⚙️ auto モードの既定値変更

  • HIPAA 構成の組織はターミナルと VS Code のセッションが既定で auto モード (disableAutoMode でオフ)
  • 組織ポリシー未ロードでモード未設定のセッションは Manual ではなく auto モードで開始
  • 設定ロード後はサーバー管理の defaultMode に従う

📡 OpenTelemetry と mod の拡張

  • OTEL_RESOURCE_INCLUDE_HOST で host.name と host.id をリソース属性に追加 (既定はオフ)
  • mod の Box に overflowX="scroll"、Text に maxLines と wrap="clip" を追加
  • PreToolUse フック拒否時に tool_decision イベントが残らない問題を修正

👀 Monitor とバックグラウンド実行の改善

  • 監視がイベントなしで期限切れの際、stderr 出力の有無と保持ファイルを Claude に通知
  • バックグラウンドセッションが LLM ゲートウェイを失う問題を修正
  • プロセス番号再利用で自身のプロセスを誤終了する問題を修正
  • 20 超のサブエージェント実行時の CPU 使用率を改善

技術詳細 - Code Mode とエージェントチームの併用

🏖️ サンドボックスの書き込み許可設定

サンドボックス化されたコマンドは一部の機密性の高いホームフォルダへ既定で書き込めなくなった。必要なフォルダはユーザー設定または管理対象設定の sandbox.filesystem.allowWrite で許可できる。

JSON settings.json - サンドボックスの書き込み許可 
{
  "sandbox": {
    "filesystem": {
      "allowWrite": [
        "~/.cache/my-tool"
      ]
    }
  }
}

📡 OpenTelemetry のホスト属性

複数マシンでのテレメトリー集計時にホストを識別したい場合、以下の環境変数を設定する。これにより host.name と host.id がリソース属性に含まれる (既定はオフ)。

Bash OpenTelemetry ホスト属性の有効化 
export OTEL_RESOURCE_INCLUDE_HOST=1

カテゴリ別の修正の要約 (約 220 項目)

🛡️ 権限・ルール関連

  • Edit の deny ルールがソース側のみをカバーする場合に cp が拒否される問題を修正
  • 削除・上書きコマンド (find -delete、cat a > b、sort -o) が検索・読み取りとして要約される問題を修正
  • 設定ファイルへ書き込めない場合、警告とファイル名を表示するようになった

🔑 サインイン・認証

  • /login で Console サインインがサブスクリプションのログインを置き換える問題を修正
  • 承認済み ANTHROPIC_API_KEY 使用中に「Login successful」で終わる問題を修正
  • サインイン画面全体を大幅改善 (コード入力フィールド、拒否理由の表示など)

🔌 MCP 関連

  • 同一ミリ秒着信時に並列 MCP ツール呼び出しが別の呼び出しの結果を読む競合を修正
  • 類似名サーバーが 2 つあると MCP プロンプトが消える問題、stdio サーバーの起動失敗理由が /mcp に表示されない問題を修正

💾 セッション・会話の復元

  • クラッシュ後の再開で直近ターンが失われる問題、メモリ不足時の履歴喪失を修正
  • Bedrock / Vertex / Foundry のコンパクションが要約の代わりに返信する問題を修正
  • Vertex AI の 30 MB 制限エラーでのスタックはコンパクションして再試行するようになった

📱 Remote Control・クラウドセッション

  • サーバー一時利用不能時の応答途中の切断、短いターミナルでの QR コード切れを修正
  • プロキシ独自の HTTP 502 / 504 / 520 - 524 でのファイルアップロード失敗は再試行するようになった
  • claude remote-control などの応答はスマートフォンやブラウザへリアルタイムでストリーミング

🖥️ ターミナル UI・描画 / プラットフォーム固有

  • ストリーミング中の行落ちや画面ジャンプ、フルスクリーンの空白化・フリーズを修正
  • 日本語・中国語・韓国語の返信で句読点に接する太字が生の ** で表示される問題を修正
  • Linux のシンボリックリンク経由ホーム、Windows パスのバックスラッシュ喪失、tmux 3.7 の再描画などを修正

🚀 パフォーマンス改善

  • 長いセッションでの入力・ストリーミング・リサイズの応答性を改善
  • ファイル読み取り・編集後の応答時間を改善 (特に Windows で顕著)
  • アイドル時の CPU 使用率改善、git リポジトリでの /compact 後の初回応答を高速化

💻 VS Code 拡張の更新

  • プロンプトサジェストをオフにする claudeCode.promptSuggestions 設定を追加
  • フォーク会話での「Rewind code to here」が 1 ターン余分に取り消す問題を修正
  • 一部ネットワークでの保存済みサインイン喪失を修正、Edit / Write の速度を改善

ユースケース - 開発者への影響

🤝 Code Mode とエージェントチームの利用者

両機能の併用が可能になり、複数エージェントの協調作業でもツール呼び出しをスクリプトとして効率的に実行できる。Code Mode 有効化済みの場合はチームセッションの動作が変わるため、権限チェック強化による確認・拒否の増加に注意する

🏢 サンドボックス・権限設定を運用する組織や無人実行環境

書き込み可能フォルダの縮小、bypass permissions モードでの確認追加、環境変数設定行の確認など、無人実行に影響し得る変更が多数ある。スケジュールタスクや CI の動作を確認し、必要なフォルダは sandbox.filesystem.allowWrite で許可する。HIPAA 構成の組織は auto モード既定化に注意し、不要なら disableAutoMode を設定する

📡 OpenTelemetry でモニタリングしている組織・mod 開発者

OTEL_RESOURCE_INCLUDE_HOST でホスト識別が可能になった。Cowork クラウドセッションのエクスポート保留により claude_code.session.count が減少し得る点に注意。mod 開発者は Box / Text の新プロパティで表示制御の幅が広がる

必要なアクション

  1. アップデートの適用: 安定性・セキュリティに関わる修正が多数含まれるため、早期の更新を推奨
  2. 無人実行・CI の確認: bypass permissions モードや auto モードでも確認・拒否されるコマンドが増えたため、自動化ワークフローの動作を確認する
  3. サンドボックスの書き込み先の確認: 書き込みに失敗する場合は sandbox.filesystem.allowWrite で必要なフォルダを許可する
  4. auto モード既定化の確認: HIPAA 構成の組織は、auto モードを望まない場合 disableAutoMode を設定する
  5. ワイルドカード allow ルールの見直し: プログラム名を含まない、または $HOME で始まるルールは auto モードで無視されるため、明示的なルールへ書き換える
  6. ツールルールの書式確認: --allowedTools などで起動時警告が出た場合は書式を修正する
移行ガイド (該当する場合): 管理対象設定の autoMode.environment で "$defaults" を含まないリストは Claude Desktop と Agent SDK アプリでも組み込みエントリを置き換えるようになった。セルフホストランナーは --trust-workspace false 下でより多くのリポジトリ設定が無視される (Linux / macOS で gh がない場合は組み込み gh api が既定で提供、--use-anthropic-gh false でオフ)。plan モードの自動コンパクションは応答中のモデル (opusplan なら Opus) を使うためコスト増の可能性がある。worktree 作成・/teleport・IDE チェックアウトはより厳格な PATH で git を実行するため、git フィルターやヘルパーにフルパス指定が必要になる場合がある

まとめ

Claude Code v2.1.326 は、Code Mode とエージェントチームの併用解禁という機能面の前進と、v2.1.325 から続くサンドボックス・権限の堅牢化を両立させた約 370 項目の大規模リリースである。修正の大半はサインイン、MCP、バックグラウンドセッション、ターミナル描画といった日常的な利用品質に関わるもので、入力応答性や CPU 使用率などのパフォーマンス改善も幅広い。一方で、auto モードの既定化、bypass permissions モードでの確認追加、サンドボックスの書き込み範囲縮小など無人実行に影響する挙動変更も多いため、自動化ワークフローを運用している環境では更新後の動作確認と設定の見直しを推奨する
