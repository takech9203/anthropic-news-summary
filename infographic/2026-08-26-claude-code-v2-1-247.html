主要機能 — 新機能 Added

💬 SendFeedback ツール

セッション中に問題が発生した場合、Claude がフィードバック報告の下書きを作成し、ユーザーは内容を確認したうえで /feedback から送信できる。feedbackDrafts 設定でオフにできる。

💡 spinnerTipsOverride の拡張

{id, text, cooldownSessions, priority} 形式のエントリ、tipsFile、label が追加され、組織が独自のヒントを組み込みのヒントと一緒にローテーション表示できるようになった。

⚡ Bash 権限プロンプトに auto mode への案内

auto mode を紹介するヒントが表示され、「Yes, and switch to auto mode」をワンキーで選択できるようになった。

💰 /claude-api cost-optimize

既存プロジェクトの Claude API 支出をプロファイリングし、コスト削減策 (キャッシング、トークンハイジーン、バッチ処理、effort、モデル選択) を計測しながら 1 つずつ適用していくコマンド。

🏢 /claude-api スキルの Admin API 対応

組織メンバー、招待、ワークスペース、API キー、レート制限レポート、ワークロードアイデンティティフェデレーション、CMEK をカバーするようになった。

修正のハイライト Fixed

⌨️ 入力・キーボード・UI

  • 履歴検索、/config、/mcp、/skills、バックグラウンドタスク、/model で、矢印キーと Enter の素早い連続入力により移動先の 1 つ上の行へ操作が実行される問題を修正
  • kitty プロトコル対応ターミナルで、非ラテン系 (例: キリル文字) キーボードレイアウト使用時に Ctrl ショートカットが発火しない問題を修正
  • エスケーププレフィックス直後にマウスレポートが分割されて届いた場合に、<35;150;7M のようなテキストがプロンプトに挿入される問題を修正

🤖 サブエージェント・フック・バックグラウンド

  • サブエージェントが初回呼び出しのモデル 404 で停止する問題を修正。セッションのフォールバックモデルチェーンを使用し、親へのエラーにはエラー種別、ステータス、リクエスト ID、モデルが含まれる
  • フックやバックグラウンドエージェントの数メガバイトのエラー出力で会話がオーバーフローし「Prompt is too long」で動かなくなる問題を修正
  • フックやバックグラウンドタスクの出力ファイルが書き込めない場合にメモリが際限なく増加する問題を修正。出力が失われた箇所はファイルに記録される
  • フォアグラウンドから引き継がれたシェルコマンドがバックグラウンドで完了した際の内部エラー記録や、誤解を招く [exited with code -1] 表示を修正
  • ターミナルのホストプロセス終了後、バックグラウンドセッションが claude agents で「opening…」のまま表示され続ける問題を修正。数秒以内に理由付きで失敗と表示され、Enter で再起動できる

🗂️ セッション・設定・ツール連携

  • Bash サンドボックスのコマンド後クリーンアップが、dotfile 管理 (nix / home-manager、stow) の ~/.claude/settings.json シンボリックリンクを削除する問題を修正
  • /terminal-setup が Zed の keymap.json 全体を上書きする問題を修正。キーバインディングをマージするようになった
  • セッションレジストリを更新できなかった場合に /rename が静かに完了扱いになる問題を修正。他セッションで古い名前が表示される可能性を通知する
  • --agent セッションの /compact と「Summarize from here」が、会話自身のシステムプロンプトではなくデフォルトのシステムプロンプトで要約する問題を修正
  • SSH 経由の /install-github-app を修正。サインイン URL のコピー結果を正しく表示し、ブラウザを開けない場合は URL を即座に表示する
  • バージョン指定のないマーケットプレイスプラグインのライブキャッシュディレクトリが、2 つ目のスコープへのインストール時に削除・再作成され、使用中のセッションに影響する問題を修正

☁️ クラウド・リモートセッション

  • /remote-control で開始した Remote Control セッションが、接続クライアントに作業ツリーの diff を報告しない問題を修正
  • セルフホストランナーのセッションが起動前に running を報告し、Claude デスクトップアプリから早すぎる「Claude is waiting for your input」通知が発生する問題を修正
  • managed settings で Claude アプリゲートウェイサインインが構成され Anthropic エンドポイントに到達できない場合に、初回セットアップが「Unable to connect to Anthropic services」で終了する問題を修正
  • クラウドセッション (Claude Code on the web、デスクトップ、モバイルアプリ) で、メッセージ送信直後のモード切り替え時に以前の権限モードが表示される問題を修正
  • バックグラウンドエージェント、シェル、モニターの実行中にターン間でコンテナが再起動するとクラウドセッションが無応答になる問題を修正。再開したセッションが失われた作業を報告する

改善と変更

📈 改善 Improved

  • プラグインマーケットプレイスのハードニング: 制御文字や不可視文字を含む名前は拒否され、/plugin と claude plugin の出力に含まれるマーケットプレイス提供のテキストはエスケープ処理される
  • Bedrock、Vertex、Foundry のセッション (およびテレメトリが無効なセッション) で、構成済みの MCP サーバーが接続に失敗した場合に、Claude がツールが存在しないと結論づけるのではなく、接続失敗を通知されるようになった

🔀 変更 Changed

  • Sonnet 5 のデフォルト auto-compact ウィンドウをフル 1M コンテキストに変更: 1M ウィンドウのセッションは約 934K トークンではなく約 967K トークンで auto-compact されるようになった
  • クロスセッションのピアメッセージがデフォルトで Message from @<sender>: <first line> の 1 行プレビューに折りたたまれるようになった。Ctrl+O で全文を展開できる
  • レンダリングされた markdown 内のターミナルハイパーリンクについて、ネットワークパスや自動マウントパスを指すもの、制御文字を含むもの、不可視文字で始まるものはプレーンテキストとして表示されるようになった
  • プロンプトフッターの PR バッジが、直前のチェックから 1 分未満の場合はターミナルの再フォーカス時に GitHub への再チェックをスキップするようになった
  • managed settings がゲートウェイログインを強制する場合、またはカスタム OAuth デプロイメントが構成されている場合に、アナリティクスがログイン後だけでなく起動時から無効になるようになった
  • Claude アプリゲートウェイのサインインリクエストが Claude Code を識別するようになった (surface=claude_code デバイス認可パラメーターと claude-code/<version> User-Agent)
  • 組織のサインイン強制が、ホスト提供またはユーザーごとの Windows レジストリ設定が存在する場合でも、管理者の managed settings を読み取れないときは起動時に終了するように変更

技術的な詳細

💬 SendFeedback ツールの仕組み

セッション中の不具合をその場で報告可能にする仕組み。Claude が問題の内容をフィードバック報告として下書きし、ユーザーは /feedback で内容をレビューしてから送信する。自動送信ではなくユーザーの確認を挟む設計で、不要であれば feedbackDrafts 設定で無効化できる。

💰 /claude-api cost-optimize のワークフロー

Claude API を利用する既存プロジェクトのコスト構造を分析し、プロンプトキャッシング、トークンハイジーン、Batch API、effort パラメーター、モデル選択といったコスト削減レバーを、効果を計測しながら 1 つずつ適用していくワークフローを提供する。同時に /claude-api スキルは Admin API (組織メンバー管理、ワークスペース、API キー、レート制限レポート、CMEK など) にも対応し、組織管理系のタスクにも利用できるようになった。

🧠 コンテキスト管理: auto-compact 発動点の拡大

Sonnet 5 の 1M コンテキストウィンドウを使用するセッションのデフォルト auto-compact 発動点が約 934K トークンから約 967K トークンに変更され、コンパクト化までに利用できるコンテキストが約 33K トークン拡大した。

🛡️ セキュリティ面のハードニング

プラグインマーケットプレイスのハードニング (制御文字・不可視文字を含む名前の拒否、出力のエスケープ処理) と、ターミナルハイパーリンクの安全化 (ネットワークパスや制御文字を含むリンク先のプレーンテキスト化) により、悪意あるマーケットプレイスやドキュメントを経由した攻撃面が縮小されている。

開発者への影響

🎯 対象

  • Claude API を利用するプロジェクトのコストを最適化したい開発者 (/claude-api cost-optimize)
  • 組織で Claude Code を展開し、独自のヒントを表示したい管理者 (spinnerTipsOverride)
  • Admin API を利用する組織管理者 (/claude-api スキルの対応拡大)
  • Sonnet 5 の 1M コンテキストウィンドウを利用しているユーザー (auto-compact 発動点の変更)
  • サブエージェント、フック、バックグラウンドセッション、クラウドセッションを利用しているユーザー
  • nix / home-manager や stow で ~/.claude/settings.json を管理しているユーザー
  • Bedrock、Vertex AI、Foundry 経由で MCP サーバーを利用しているユーザー

  • API コストの削減に取り組む場合は、対象プロジェクトで /claude-api cost-optimize を実行し、提示されるコスト削減策を計測しながら適用していくことを検討するとよい

ユースケース

💰 既存プロジェクトの API コスト削減

Claude API を利用するプロジェクトで /claude-api cost-optimize を実行すると、支出のプロファイリングに基づき、キャッシング、トークンハイジーン、バッチ処理、effort、モデル選択といった削減策を効果を計測しながら 1 つずつ適用できる。

🏢 組織向けカスタマイズと管理タスクの自動化

管理者は spinnerTipsOverride で組織独自のヒントをローテーション表示できる。さらに /claude-api スキルが Admin API (組織メンバー、招待、ワークスペース、API キー、レート制限レポート、ワークロードアイデンティティフェデレーション、CMEK) に対応したため、組織管理系のタスクにも利用できる。

🧠 Sonnet 5 での長時間セッション

1M コンテキストウィンドウのセッションでは auto-compact の発動点が約 967K トークンに引き上げられたため、大規模なコードベースの調査や長時間の作業でコンパクト化までに使えるコンテキストが実質的に増加する。
