Usage and Cost Analytics API がベータ版でリリース - 使用量とコストの分析が大幅に強化

Claude Console と Claude Enterprise の両組織を単一の API でカバーする統合分析 API — actor ディメンション、最大 5 ディメンションのグループ化、ランキングに対応

📅 2026-10-29 | ソース: Claude Developer Platform Release Notes | カテゴリ: API アップデート

概要

Anthropic は 2026 年 10 月 29 日、組織のトークン使用量とコストを詳細に分析できる Usage and Cost Analytics API をベータ版としてリリースしました。

🧩

2 つのエンドポイントで構成

GET /v1/organizations/analytics/usage はトークン数とリクエスト数を、GET /v1/organizations/analytics/cost は USD 建てのコストを返します。

🤝

Console と Enterprise を統合する単一 API

同一のエンドポイント、パラメータ、レスポンスフィールドで Claude Console と Claude Enterprise の両方の組織に対応し、1 つのインテグレーションで両組織タイプをカバーできます。Claude Platform on AWS や Claude Models on Google Cloud (Anthropic managed) にも対応します。

🔍

豊富なディメンションで分析

model、workspace_id、api_key_id、actor、service_tier、context_window、inference_geo、speed、product などで最大 5 つまでグループ化できます。actor ディメンションでユーザー / サービスアカウント単位の帰属も把握できます。

🏷️

ベータヘッダーが必要

すべてのリクエストに anthropic-beta: analytics-usage-cost-2026-08-24 と anthropic-version ヘッダーが必要です (SDK と ant CLI は自動で付与)。

📦

既存 API はレガシーに位置付け

従来の Usage and Cost API (usage_report/messages、cost_report) と Claude Enterprise Analytics API のレポートエンドポイントはレガシー化されました。引き続きサポートされますが、新規のインテグレーションには新 API の利用が推奨されます。

背景

これまで、組織の使用量とコストをプログラムから取得する手段は、組織の種類によって分かれていました。Claude Console (Claude Platform) の組織は Admin API の Usage and Cost API を、Claude Enterprise (claude.ai) の組織は Claude Enterprise Analytics API のレポートエンドポイントを使用する必要があり、それぞれレスポンス形式やグループ化の機能が異なっていました。

新しい Usage and Cost Analytics API は、同一のエンドポイント、パラメータ、レスポンスフィールドで両方の組織タイプに対応する統合 API として設計されており、1 つのインテグレーションで両方をカバーできます。

主要機能

📊 Usage エンドポイント

ベータ

/v1/organizations/analytics/usage がトークン数とリクエスト数を返します。uncached_input_tokens、キャッシュ作成 / 読み取りトークン、output_tokens、total_tokens、server_tool_use (web_search_requests など)、requests を含みます。

💰 Cost エンドポイント

ベータ

/v1/organizations/analytics/cost が USD 建てコストを返します。amount (割引適用後・クレジット適用前) と list_amount (定価ベース) を、セント単位・小数点以下 6 桁の 10 進文字列で表現します (例: "41280.000000" は 412.80 米ドル)。

👤 actor ディメンション

新機能

リクエストの帰属先 (ユーザー、サービスアカウント、フェデレーションされたクラウド ID、または API キー自体) を識別できます。ユーザー単位のコスト配賦やチャージバックに活用できます。

🎛️ 柔軟なフィルタリング

新機能

ブラケット記法 (models[]=... など) で各フィルタに最大 100 個の値を指定できます。同一フィルタ内は OR、異なるフィルタ間は AND で結合されます。

📈 ランキングとタイムシリーズ

新機能

order_by でトークン数、リクエスト数、コストなどのメトリクスによるランキングを取得できます。time_bucket_width (1m、1h、1d) と order_by=time の組み合わせで時系列データを構築できます。

📦 レガシー API のサポート継続

レガシー

Usage and Cost API (usage_report/messages、cost_report) と Claude Enterprise Analytics API の usage_report、cost_report、user_usage_report、user_cost_report はレガシーとなりましたが、引き続きサポートされます。

Before / After: レガシー API との比較

Before: レガシー Usage and Cost API

  • 組織タイプごとに別々の API (Console は Admin API、Enterprise は Analytics API)
  • ベータヘッダー不要
  • データは通常 5 分以内に反映
  • data は時間バケットのリスト (空バケットを含む)
  • bucket_width (デフォルト 1d)、任意の日付範囲
  • account_ids[] や group_by[]=description によるグループ化
  • デフォルトワークスペースは workspace_id: null

After: Usage and Cost Analytics API

  • Console と Enterprise の両組織を単一 API で統合
  • analytics-usage-cost-2026-08-24 ベータヘッダーが必須
  • data は order_by でランク付けされた行のリスト (使用量のない組み合わせは行なし)
  • time_bucket_width (省略時は全期間の合計)
  • actor、product、cost_type、token_type など構造化ディメンションでグループ化 (最大 5 つ)
  • デフォルトワークスペースも実際の workspace_id を持つ

🧭

Claude Enterprise のレポートエンドポイントからの移行では、キー、フィルタ / ディメンション名、メトリクスフィールド、カーソルのルールなどがそのまま引き継がれ、新たに必要なのはベータヘッダーのみです。user_usage_report / user_cost_report の代替は group_by[]=actor&actor_types[]=user_actor となります。

技術詳細

🔌 エンドポイントとベータヘッダー

  • Usage: GET /v1/organizations/analytics/usage — トークン数とリクエスト数を返します
  • Cost: GET /v1/organizations/analytics/cost — USD 建てのコストを返します
  • 必須ヘッダー: anthropic-beta: analytics-usage-cost-2026-08-24 と anthropic-version (SDK と ant CLI は自動で付与)

🔐 認証

組織タイプ 認証方法
Claude Console Admin API キー (sk-ant-admin01-...)、または org:admin スコープの OAuth トークン
Claude Enterprise read:analytics スコープのキー (Analytics API キー)
Claude Platform on AWS AWS IAM (ListAccountUsage / ListAccountCost アクション)
Claude Models on Google Cloud Google Cloud 認証情報 (usageAnalytics.list / costAnalytics.list 権限)

🔍 グループ化ディメンション

  • 共通ディメンション: model、workspace_id、api_key_id、actor、actor_type、service_tier、context_window、inference_geo、speed、product などで最大 5 つまでグループ化可能
  • Cost 限定ディメンション: cost_type (トークン、Web 検索、コード実行、セッション使用量) と token_type があり、5 ディメンション制限の対象外
  • フィルタリング: ブラケット記法で各フィルタに最大 100 個の値を指定可能。同一フィルタ内は OR、異なるフィルタ間は AND で結合

📊 レスポンスの構成

  • 共通構造: 各行は starting_at / ending_at (期間)、group (ディメンション)、メトリクスで構成
  • Usage メトリクス: uncached_input_tokens、cache_creation (ephemeral_1h_input_tokens、ephemeral_5m_input_tokens)、cache_read_input_tokens、output_tokens、total_tokens、server_tool_use、requests
  • Cost メトリクス: amount (割引適用後・クレジット適用前)、list_amount (定価ベース)、currency (常に "USD")、requests。金額はセント単位の小数点以下 6 桁の 10 進文字列

📅 日付範囲と時間バケット

  • タイムスタンプは RFC 3339 形式 (UTC)。starting_at は含み、ending_at は含まない
  • starting_at は 2026 年 1 月 1 日以降かつ過去 365 日以内である必要がある
  • 1 リクエストの範囲は最大 31 日間。time_bucket_width=1m の場合は最大 24 時間
  • time_bucket_width を指定する場合は ending_at が必須

🕒 データ鮮度とページネーション

  • データ鮮度: レスポンスの data_refreshed_at タイムスタンプで確認可能。データは通常 4 時間以内に更新され、最大 24 時間かかる場合がある。遅延イベントの到着と照合処理により、暦月終了の約 7 日後まで値が修正される可能性がある
  • ページネーション: limit は 1 ページあたりの行数 (1〜1,000、デフォルト 20)。has_more が true の場合、next_page の値で次のページを取得。全ページは同一のデータスナップショットを読み取る
⚠️

レガシー API (通常 5 分以内にデータ反映) と比較すると、新 API のデータ反映は遅くなる点に注意が必要です (通常 4 時間以内、最大 24 時間)。

コード例

モデル別の日次トークン使用量を取得する例です。

Bash モデル別の日次トークン使用量 
curl --globoff "https://api.anthropic.com/v1/organizations/analytics/usage?\
starting_at=2026-09-01T00:00:00Z&\
ending_at=2026-09-08T00:00:00Z&\
time_bucket_width=1d&\
group_by[]=model&\
limit=10" \
  -H "anthropic-version: 2023-06-01" \
  -H "anthropic-beta: analytics-usage-cost-2026-08-24" \
  -H "x-api-key: $ANTHROPIC_API_KEY"

Python SDK を使用した例です。

Python Python SDK での使用量取得 
client = anthropic.Anthropic()

rows = client.beta.organization.analytics.usage.list(
    starting_at="2026-09-01T00:00:00Z",
    ending_at="2026-09-08T00:00:00Z",
    time_bucket_width="1d",
    group_by=["model"],
    limit=10,
)

for row in rows:
    print(f"{row.starting_at} {row.group.model}: {row.usage.total_tokens}")

モデル、コストタイプ、トークンタイプ別のコストを取得する例です。

Bash ディメンション別のコスト取得 
curl --globoff "https://api.anthropic.com/v1/organizations/analytics/cost?\
starting_at=2026-09-01T00:00:00Z&\
ending_at=2026-10-01T00:00:00Z&\
group_by[]=model&\
group_by[]=cost_type&\
group_by[]=token_type" \

  -H "anthropic-beta: analytics-usage-cost-2026-08-24" \
  -H "x-api-key: $ANTHROPIC_API_KEY"

ユースケース / 開発者への影響

💸 コスト配賦・チャージバック

actor ディメンションにより、ユーザー、サービスアカウント、フェデレーションされたクラウド ID 単位でコストの帰属先を特定できます。部門やチームごとのコスト配賦、チャージバックの仕組みをより細かい粒度で構築できます。

📊 予算モニタリング・ダッシュボード構築

time_bucket_width と order_by=time の組み合わせで時系列データを構築し、使用量やコストの推移を可視化できます。Datadog、Grafana Cloud などのオブザーバビリティプラットフォームとの連携を管理する運用チームにも有用です。

🧩 組織タイプをまたぐ統合インテグレーション

Claude Console と Claude Enterprise の両組織を 1 つのインテグレーションでカバーできるため、複数の組織タイプを運用する企業や、マルチテナント向けの分析ツールを提供する開発者のメンテナンスコストを削減できます。

✅ 必要なアクション

  • 新規インテグレーション: Usage and Cost Analytics API (/v1/organizations/analytics/usage と /v1/organizations/analytics/cost) を使用する
  • 既存インテグレーション: レガシー API は引き続きサポートされるため、即時の移行は不要。ただし、より多くのグループ化 / フィルタリングディメンション (actor、product、cost_type、token_type など) が必要な場合は移行を検討する
  • ベータヘッダーの付与: 直接 HTTP で呼び出す場合は anthropic-beta: analytics-usage-cost-2026-08-24 ヘッダーを忘れずに付与する

まとめ

Usage and Cost Analytics API のベータリリースにより、Claude Console と Claude Enterprise の両組織が単一の API で使用量とコストを詳細に分析できるようになりました。actor ディメンションによるユーザー / サービスアカウント単位の帰属、最大 5 ディメンションのグループ化、メトリクスによるランキングなど、従来の API より大幅に強化された分析機能を提供します。

レガシー API は引き続きサポートされるため既存インテグレーションへの即時の影響はありませんが、新規開発では新 API の採用が推奨されます。コスト配賦やチャージバック、ダッシュボード構築に取り組む組織にとって重要なアップデートです。
