Claude API Managed Agents

Dreams (research preview) が Claude Opus 5 をサポート

2026-08-01

エージェントのメモリストアと過去セッションを Claude に読み込ませ、重複統合・更新・インサイト抽出を行う非同期ジョブ「Dreams」で、最上位モデル Claude Opus 5 が選択可能になりました。

概要

⭐

Claude Opus 5 が Dreams のサポートモデルに追加

Dreams のパイプラインを実行するモデルとして最上位モデル Claude Opus 5 を選択可能になり、より高品質なメモリのキュレーションを実現できます。

💤

Dreams はメモリを再編成する非同期ジョブ

既存のメモリストアと過去のセッショントランスクリプトを読み込み、重複の統合、古い情報の更新、新しいインサイトの抽出を行った新しいメモリストアを生成します。

🛡️

入力ストアは一切変更されない安全設計

出力は入力とは別の新しいメモリストアとして生成されるため、結果をレビューし、不要であれば破棄できます。

🔧

移行は model パラメータの変更のみ

既存コードの model パラメータに claude-opus-5 を指定するだけで移行でき、API の呼び出し方法やその他のパラメータに変更はありません。

💰

課金は選択したモデルの標準 API トークンレート

コストは入力セッションの数と長さにほぼ比例するため、まず少数のセッションで試し、品質を確認してから規模を拡大することが推奨されます。

背景: なぜ Dreams が必要か

Managed Agents のエージェントは動作中にメモリストアへ書き込みを行いますが、書き込みはローカルかつ増分的です。多数のセッションを重ねるうちに、メモリストアには問題が蓄積していきます。Dreams は以下の 3 つの処理でこれを解決します。

🔗

重複エントリの統合

セッションを重ねて蓄積した重複エントリをまとめ、メモリストアをコンパクトに保ちます。

🔄

古い情報の置き換え

古い情報や矛盾するエントリを最新の値で置き換え、メモリの一貫性を維持します。

💡

新しいインサイトの抽出

過去のセッショントランスクリプトからパターンと新しいインサイトを抽出し、メモリに反映します。

技術詳細

📥

入力と出力

入力は既存のメモリストア 1 つとセッション 1 ~ 100 件。出力は別の新しいメモリストアで、その ID は Dream が running 状態になって間もなく outputs[] に現れます。

🔑

ベータヘッダー

Dream のエンドポイントは dreaming-2026-04-21 でゲートされています。managed-agents-2026-04-01 と両方のヘッダーの送信が必要です (SDK は自動的に設定)。

📝

instructions によるステアリング

オプションの instructions フィールド (最大 4,096 文字) で合成処理の方針を指示できます。パイプラインはテキストエディタではないため、特定行への命令的な編集指示は効果がなく、個別編集には Memory Stores API を使用します。

📡

実行時間と監視

非同期実行で、入力トランスクリプト数に応じて数分から数時間かかります。running 状態で session_id が設定され、セッションイベントをストリーミングしてリアルタイムに観察できます。

💴

料金とレート制限

選択したモデルの標準 API トークンレートで課金され、usage フィールドで正確な合計を確認できます。Dream の作成にはデフォルトのレート制限が適用され、引き上げにはサポートへの問い合わせが必要です。

Dream のライフサイクル

pending

Dream が作成され、キューに登録された状態

running

パイプラインが処理中。usage は進行に応じて更新

completed

正常終了。outputs[] に新しいメモリストアが含まれる

failed

エラーで終了。出力ストアは失敗前までの内容で残る

canceled

キャンセルされた状態。出力ストアはそのまま残る

コードサンプル

Claude Opus 5 を指定して Dream を作成する例 (Python) です。

Python Claude Opus 5 で Dream を作成 
dream = client.beta.dreams.create(
    inputs=[
        {"type": "memory_store", "memory_store_id": store_id},
        {"type": "sessions", "session_ids": [session_a, session_b]},
    ],
    model="claude-opus-5",
    instructions="Focus on coding-style preferences; ignore one-off debugging notes.",
)
print(dream.id)  # drm_01...

# ステータスをポーリング
while dream.status in ("pending", "running"):
    time.sleep(10)
    dream = client.beta.dreams.retrieve(dream.id)
    print(f"status={dream.status} input_tokens={dream.usage.input_tokens}")

# 完了後、出力ストアを新しいセッションで利用
output_store_id = next(
    output.memory_store_id for output in dream.outputs if output.type == "memory_store"
)
session = client.beta.sessions.create(
    agent=agent_id,
    environment_id=environment_id,
    resources=[
        {"type": "memory_store", "memory_store_id": output_store_id},
    ],
)

ユースケース / 開発者への影響

長期運用エージェントのメモリ品質維持

Managed Agents でエージェントを構築し、メモリストアの重複・矛盾・古いエントリの蓄積に課題を抱えているチームは、Opus 5 による高品質なキュレーションでメモリの一貫性を回復できます。入力ストアは変更されないため、安全に試すことができます。

既存 Dreams 利用者のモデルアップグレード

model パラメータに claude-opus-5 を指定するだけで、最上位モデルによるメモリキュレーションを利用できます。標準 API トークンレートで課金されるため、コストとキュレーション品質のバランスの検討が必要です。

スモールスタートによる段階的な導入

コストは入力セッションの数と長さにほぼ比例します。まず少数のセッションで試し、キュレーション品質に満足してから規模を拡大する運用が推奨されます。まだ Dreams を利用していない場合は、リサーチプレビューへのアクセスリクエストが必要です。
