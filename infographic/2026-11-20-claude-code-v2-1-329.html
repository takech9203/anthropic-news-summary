Claude Code v2.1.329

/code-review のブランチ全体レビュー化と Code Mode の安定化を中心とした 130 項目のアップデート

📅 2026-11-20 | ソース: Claude Code Changelog

概要 - キーポイント

🌿

/code-review の動作変更 (重要)

ターゲット未指定時はブランチ全体をデフォルトブランチと比較してレビューするようになり、PR 番号指定時は gh pr diff で確実に対象の pull request を読むようになった。失敗時はレビューせず安全に停止する

⚙️

Code Mode の 20 項目超の修正・変更 (重要)

スクリプトの暴走ループや長大ファイル保持によるメモリ問題を解消。テレメトリ・機能フラグが無効な環境でも起動するようになり、フックはフェイルオープン化された (拒否が必要なら "onFailure": "block" を設定)

🔑

macOS Keychain 起因の繰り返しサインアウトを修正

Keychain の読み取りはできるが保存ができない場合の繰り返しサインアウトを修正。ログイン更新時は Claude Code-write-check アイテムで書き込み可否をテストする

🧠

長時間セッションのメモリ使用量を大幅に改善

status line スクリプトのメモリ暴走、バックグラウンドシェルや Remote Control による以前の会話のメモリ保持、大きな MCP ツール結果を持つ長時間セッションのメモリ使用量などを広範に改善

📋

/tasks の統合表示とスケジュールタスクの強化

スケジュールタスク、/loop のウェイクアップ、ゴール、この会話のフォークが /tasks に統合表示され、x キーで個別に停止できる。以前のバージョンで保存したタスクの多くは再スケジュールが必要になる点に注意

主要な変更点

🌿 /code-review のブランチ全体レビュー化

  • ターゲット未指定時は現在のブランチ全体をデフォルトブランチと比較してレビュー。複数コミットのブランチで diff を見失う問題も修正
  • PR 番号指定時は gh pr diff で取得し、読めない場合はその旨を report
  • --fix や PR URL 指定時は、gh pr diff が拒否・失敗したらレビューせず停止
  • 存在しない ~/.claude/CLAUDE.md による権限プロンプトと、medium レビューの findings カードが "high" と表示される問題を修正

⚙️ Code Mode の大規模修正

  • スクリプトの暴走ループがメモリを使い尽くす問題を修正 (上限で停止)
  • 大きなテキストファイルの保持、サブエージェント起床ごとのメモリ増加を修正
  • MCP フォームの回答待ち中に 10 分制限で停止する問題、2 分超の MCP 呼び出しが "moved to the background" を受け取る問題を修正
  • 256 MiB を超える行範囲の読み取りを拒否するようになった
  • テレメトリ・機能フラグが無効でも起動するように変更 (無効化は managed settings で)

📋 /tasks とスケジュールタスクの強化

  • スケジュールタスク・/loop・ゴール・フォークを /tasks に統合表示し、x キーで個別停止
  • ヘッダー・フッターのバックグラウンドカウントを 1 つの数字に一本化
  • 'Exit and stop tasks' がこのセッションのスケジュールタスクも終了
  • 注意: 以前のバージョンで保存したタスクの多くは新しいセッションで再スケジュールが必要

🔑 macOS Keychain 関連の修正

  • 読み取り可・保存不可の Keychain による繰り返しサインアウトを修正
  • ログイン更新時に Claude Code-write-check アイテムで書き込み可否をテスト
  • claude doctor がサンドボックス内でロック解除を勧める問題を修正
  • /tui などのインプレース再起動がログイン更新を短時間待つように

🧠 メモリ使用量の改善

  • 終端なく出力する status line スクリプトによるフリーズとギガバイト単位のメモリ使用を修正
  • バックグラウンドシェルや Remote Control が以前の会話のメモリを保持する問題を修正
  • 多数のファイル編集・大きな MCP ツール結果を持つ長時間セッションのメモリを改善
  • --resume / --continue 後のメモリ使用量と、メモリ逼迫時の画面更新スキップを改善

🏃 Self-hosted runner の修正と変更

  • Git LFS リポジトリでセットアップが失敗する問題を修正 (ポインターで開始し git lfs pull で取得)
  • SSH ホストエイリアス・GitHub SSH 証明書・GHE.com の SSH ユーザーの git remote に対応
  • --push-outcome-on-release がブランチを削除してしまう問題を修正
  • 2 つ目のホスト名のクローンは _repos/clones/<host>/ 配下に作成
  • --repository-folder が --capacity 1 のとき base フォルダー内のほとんどのフォルダーを指定可能に

💻 VS Code 拡張の更新 (17 項目)

  • trust プロンプト辞退後に Review trust から再読み込みなしで再表示可能に
  • トークン更新に 10〜30 秒かかると全ウィンドウでサインアウトされる問題を修正
  • IME 変換中のキー入力が権限プロンプトの操作やダイアログ操作を引き起こす問題を修正
  • 組み込みツールの安全性チェックが確認を求める理由を表示
  • 切れたツール入出力のエディタータブ表示、diff タブの Accept ボタン残留などを修正

✨ そのほかの新機能

  • trust ダイアログにフックの宣言元を示す警告を追加。非対話ホストでは managed settings のフック読み込み失敗を会話内で警告
  • /mcp に "Server message" 行: 接続拒否するリモート HTTP MCP サーバーの JSON-RPC エラーを表示
  • /status に "Marketplace auto-update" 行: 自動更新されない managed マーケットプレイスと理由を表示
  • OpenTelemetry のイベント・メトリクス有効時も Code Mode を有効化可能に

🪝 Code Mode のフックのフェイルオープン化 - Before / After

Before (〜 v2.1.328)

エラーになった PreToolUse フックが、Code Mode のスクリプトのツール呼び出しを拒否していた (Code Mode 外と挙動が異なっていた)

After (v2.1.329 〜)

エラーになった PreToolUse フックは、Code Mode 外と同様にツール呼び出しを拒否しない (フェイルオープン)。失敗時に必ず拒否すべきフックには "onFailure": "block" を設定する

フックの失敗時に必ずブロックすべきセキュリティ用途のフックには、"onFailure": "block" を明示する。

JSON settings.json - フェイルクローズドなフック定義 
{
  "hooks": {
    "PreToolUse": [
      {
        "matcher": "Bash",
        "hooks": [
          {
            "type": "command",
            "command": "/usr/local/bin/security-check.sh",
            "onFailure": "block"
          }
        ]
      }
    ]
  }
}

🔄 max_tokens エラーの自動リトライ削除への対応

v2.1.326 で導入された、max_tokens エラーに記載された上限での自動リトライが削除された。出力トークン上限が小さいモデルをゲートウェイ経由で使っている場合は、環境変数で上限を明示する。

Bash ゲートウェイのモデルの出力上限に合わせて設定 
# ゲートウェイのモデルの出力上限に合わせて設定
export CLAUDE_CODE_MAX_OUTPUT_TOKENS=8192

カテゴリ別の修正・変更の要約

⚙️ Code Mode のスクリプト実行の修正

  • Esc 後にスクリプトの完了済み編集と停止したコマンドが隠れ、終了時に失われる問題を修正
  • 数千回のツール呼び出し後にターミナルがフリーズする時間を大幅に短縮
  • let x; が前のスクリプトで x に与えた値を保持してしまう問題を修正
  • 引数不要のツールを引数なしで呼ぶとパラメータ不足エラーになる問題を修正
  • 4,096 を超えるツールがあるセッションで tools 経由のアクセスを失う問題を修正
  • 一部のツールのみを列挙する mod が Code Mode を黙って無効化する問題を修正 (無効化は managed settings で)
  • 自前の log、preview、sleep を宣言するスクリプトを拒否せず実行。MCP ツールのターン終了要求を待機スクリプトからの呼び出しでも尊重

🐛 注目のバグ修正 (抜粋)

  • ~/.claude.json の保全: 読み取れない状態のまま保存が走ると設定がデフォルトにリセットされることがある問題を修正
  • /terminal-setup の安全化: VS Code の settings / keybindings ファイルを破損する問題と、Shift+Enter バインドを失いながら成功と報告する問題を修正
  • IDE diff の保全: 編集受け入れ時に末尾の改行や BOM が失われる問題を修正
  • /teleport: クラウドセッション選択時に開いている会話が置き換えられる問題を修正 (新しいセッションを開始し /resume で戻れる)
  • 使用状況まわり: /usage の「オフ」誤表示、/usage-credits の再ログイン要求、/model が上限ブロックを伝えない問題を修正
  • MCP のファイル種別: application/octet-stream で送られる PDF・画像・Office ファイルが .bin として保存され読めなくなる問題を修正
  • auto mode: 作業ディレクトリ外や自分自身を指すシンボリックリンクの rm に手動承認を求める問題を修正
  • Opus 4.8 / Opus 5: ファイル送信が初回に失敗することがある問題を修正

🔄 そのほかの挙動変更と削除

  • auto mode の git status 削減: 実行頻度を下げ、大規模リポジトリの待ち時間を短縮。変更を破棄する git コマンドはワーキングツリーの確認までブロックされることがある
  • チームメイトペイン: 一部が /bin/sh 経由で起動し、シェルのスタートアップファイルを読まないことがある
  • macOS の computer use: 新しい安全ルールに更新され、一部のアクション拒否・アプリ制限・30 秒超のアプリ起動の打ち切りが適用される
  • Gateway の警告強化: access_control.allow_cidrs が空の間は毎回起動時に通知される
  • max_tokens エラーの自動リトライ削除: 必要に応じて CLAUDE_CODE_MAX_OUTPUT_TOKENS を設定する
  • VS Code のコマンド出力: 隠し文字と制御シーケンスを記号として表示するため、一部言語のテキストが崩れて見えることがある
  • Stop / SubagentStop フックの background_tasks で Monitor のスクリプトが monitor として列挙される

ユースケース - 開発者への影響

🌿 /code-review を CI やレビューフローで使う開発者

ターゲット未指定時の対象が「現在の diff」から「ブランチ全体とデフォルトブランチの比較」に変わった。PR レビューは gh pr diff 経由となるため、gh CLI が利用できない環境では停止する点を確認する

🛡️ Code Mode とフックでポリシーを適用する組織

フックがフェイルオープン化されたため、失敗時に必ず拒否すべき command / HTTP / MCP ツールフックには "onFailure": "block" を設定する。また「テレメトリ無効」などに依存して Code Mode を無効化していた場合は、managed settings での明示的な無効化に切り替える

🍎 macOS ユーザー・長時間セッションの利用者

Keychain への書き込み不可による繰り返しサインアウトが解消され、Claude Code-write-check という Keychain アイテムが作られるようになる。長時間セッションやバックグラウンド処理のメモリ使用量も大幅に改善されるため、早期の更新が有効

🏃 Self-hosted runner の運用者・スケジュールタスクの利用者

Git LFS・SSH エイリアス・ブランチ削除など運用に関わる修正が多い。複数ホストのクローン配置と --repository-folder の挙動変更にも注意する。以前のバージョンで保存したスケジュールタスクの多くは、新しいセッションで再スケジュールが必要になる

必要なアクション

  1. アップデートの適用: メモリ使用量・認証・Code Mode の安定性に関わる修正が多いため、早期の更新を推奨する
  2. スケジュールタスクの再登録: 以前のバージョンで保存したスケジュールタスクが新しいセッションで動かない場合は、再スケジュールする
  3. Code Mode のフック構成の確認: フック失敗時に拒否が必要な command / HTTP / MCP ツールフックには "onFailure": "block" を設定する。Code Mode の無効化が「テレメトリ無効」などに依存していた場合は managed settings での明示的な無効化に切り替える
  4. /code-review の運用確認: レビュー対象がブランチ全体に変わったことと、gh pr diff が失敗すると停止することを確認する
  5. ゲートウェイ利用者の設定確認: max_tokens エラーの自動リトライが削除されたため、必要に応じて CLAUDE_CODE_MAX_OUTPUT_TOKENS を設定する。access_control.allow_cidrs が空のゲートウェイは毎回起動時に通知が出る
移行ガイド (該当する場合): 一部のツールのみを列挙する mod で Code Mode を無効化していた場合、この方法では無効にならなくなったため managed settings で無効化する。チームメイトペインでシェルのスタートアップファイルに依存していた場合は、一部のペインが /bin/sh 経由で起動して環境変数や PATH の設定が読まれないことがあるため、必要な設定をセッション側で明示する

まとめ

Claude Code v2.1.329 は、/code-review をブランチ全体レビューと gh pr diff による確実な PR 取得へと刷新し、Code Mode のメモリ暴走・実行制御の問題を集中的に解消したリリースである。macOS Keychain 起因の繰り返しサインアウトの修正、status line スクリプトやバックグラウンド処理によるメモリ肥大の解消、/tasks へのスケジュールタスク・/loop・フォークの統合など、日常利用の信頼性を底上げする修正が 130 項目にわたって含まれる。Code Mode の起動条件緩和とフックのフェイルオープン化は組織のポリシー運用に影響するため、managed settings と "onFailure": "block" による明示的な制御への移行を推奨する
