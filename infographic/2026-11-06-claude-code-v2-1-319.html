auto mode と MCP タスク

概要 - キーポイント

☁️

auto mode のサーバーサイドチェック挙動変更

テレメトリまたはフィーチャーフラグが無効な環境 (LLM ゲートウェイ配下を含む) では、サーバーが確認できない呼び出しは確認または拒否され、組み込み分類器へのフォールバックは行われない。従来の動作は CLAUDE_CODE_AUTO_MODE_SERVER=0 で維持できる (Bedrock、Vertex、Foundry は変更なし)

🔌

MCP タスクのバックグラウンド実行

MCP サーバーがツール呼び出しをタスクとして実行する場合、Claude Code は即座にバックグラウンドへ移動し、完了時に結果を Claude に伝える。長時間実行の MCP ツールでターンがブロックされなくなった。フィーチャーフラグのフェッチなしでも動作する

🚦

permissions.denyInsteadOfPrompting 設定

権限プロンプトで待機することになるツール呼び出しを拒否してターンを継続する新設定。ターミナルセッション、サブエージェント、teammates で有効で、無人実行や長時間の自律タスクでのプロンプト待ちによる停止を回避できる

⚡

/claude-api latency-optimize コマンド

Claude API を利用するコードのどこでユーザーを待たせているかを特定し、より高速な設定を eval に対して試行する新コマンドが追加された

🛡️

複数のセキュリティ修正

細工された環境変数プレフィックスによる Bash 権限バイパス、accept-edits / auto mode で sed が権限チェックをすり抜けるケース、worktree 作成時のサンドボックスエスケープなどを修正

主要機能 (Added)

🔌 MCP タスクのバックグラウンド化

タスクとして実行される MCP ツール呼び出しを即座にバックグラウンドへ移動。従来どおり待機させるには CLAUDE_CODE_DISABLE_MCP_TASK_BACKGROUND、機能自体の無効化は CLAUDE_CODE_DISABLE_MCP_TASKS=1 を設定する

🚦 denyInsteadOfPrompting

permissions.denyInsteadOfPrompting により、権限プロンプトで待機する代わりにツール呼び出しを拒否してターンを継続。無人実行での停止を防げる

⚡ /claude-api latency-optimize

Claude API コードの待ち時間の発生箇所を特定し、より高速な設定を eval に対して試行するコマンド

🏳️ フィーチャーフラグのみ停止

CLAUDE_CODE_DISABLE_FEATURE_FLAGS で、テレメトリを無効化せずにフラグのフェッチだけを停止。すべてのフラグは組み込みデフォルト値を使用する

💰 /usage に支出額を表示

本日・今週・今月の支出額を表示 (支出上限のない Claude apps gateway 配下の開発者向け、ゲートウェイが本バージョン以降の場合)

📋 /tasks に履歴行を追加

「Earlier in this session」行で終了したサブエージェントが一覧され、リストから消えた後やセッション再起動後でも再度開いてメッセージを送れる

➕ その他の追加

  • Claude apps gateway に admin.pooled_conflict_rule と admin.pooled_priority_order を追加。複数グループに属する開発者のプールグループ予算の支払い順を設定できる
  • Claude apps gateway にオプションの login_notice 設定を追加。ブラウザ検証ページとサインイン画面に運用者定義のメッセージを表示できる
  • CLAUDE_GATEWAY_LOG_FORMAT=json を追加。運用ログ行が severity、time、message を持つ JSON になる
  • あるポリシーが名前で列挙するカスタムモデル ID を別ポリシーの availableModels も許可している場合の起動時警告を追加
  • Claude Desktop の 11 月 10 日の変更に先立ち、desktopHome がないまま coworkTabEnabled: false や chatSessionRetentionDays に依存するポリシーへの起動時警告を追加
  • claude.ai ログイン終了後に ant auth login で継続し使用量が Claude Console 組織に課金される場合の警告と、課金先組織名の起動時表示を追加
  • クラウドセッションの /loop 確認に、タイマーはコンテナとともに停止する旨の注記と存続するループの提案を追加

🔌 MCP タスクの仕組み

MCP サーバーがツール呼び出しをタスクとして実行すると、Claude Code は呼び出しを待たずに即座にバックグラウンドへ移動し、完了時に結果を Claude に通知する。MCP タスクはフィーチャーフラグのフェッチなしでも動作する (Bedrock、Vertex、Foundry、LLM ゲートウェイ、DISABLE_TELEMETRY 環境を含む)。同期的な動作が必要な場合は CLAUDE_CODE_DISABLE_MCP_TASK_BACKGROUND を、機能自体の無効化は CLAUDE_CODE_DISABLE_MCP_TASKS=1 を設定する

🚦 denyInsteadOfPrompting の適用範囲

ターミナルセッション、サブエージェント、teammates に適用される。権限プロンプトで停止する代わりにツール呼び出しが拒否され、Claude は別のアプローチでターンを継続できるため、無人実行での停止を防げる

🏳️ フィーチャーフラグとテレメトリの分離

従来はテレメトリを無効化するとフィーチャーフラグのフェッチも止まっていたが、CLAUDE_CODE_DISABLE_FEATURE_FLAGS によりフラグのフェッチのみを停止できる。すべてのフラグは組み込みデフォルト値で動作する

👁️ Monitor ツールの権限整合性

WebSocket 監視を含む Monitor の動作が Bash コマンドの権限ルールと一貫するようになり、ask ルールの対象コマンドは bypass mode や auto mode でもプロンプトが省略されない。監視経由での権限ルール迂回ができなくなった

  • Claude in Chrome を改善。短時間の切断後は復帰を最大 6 秒待機し、javascript_tool の結果は 60,000 文字まで会話に残る
  • claude purge と古いセッションのクリーンアップを改善。削除できなかったフォルダーをリトライし、残る場合はエラーとして報告

動作変更 (Changed) と削除 (Removed)

  • Monitor ツールの権限ルール適用: WebSocket 監視がすべての Bash コマンドのルールに従う。deny ルールは監視を拒否し、ask ルール下では Monitor への allow、bypass mode、auto mode のいずれもプロンプトをスキップしない
  • auto mode 設定の保護: プロジェクト外でサーバーサイドチェックを無効化した場合、プロジェクトの設定ファイルやプラグインがそれを再有効化できなくなった
  • CLAUDE_CODE_PROXY_RESOLVES_HOSTS は、ホストがネットワークを管理する環境では設定ファイルから設定できなくなった。プロセス環境で設定する
  • セッションの Bash / PowerShell の完全一致 ask ルールは、より広い deny ルールがコマンドをカバーする場合、確認ではなく拒否される
  • Bash ツールが、参照・表示系以外のフラグ付き which の実行前に権限を求める
  • --add-dir のディレクトリは、信頼ダイアログの承認後に初めてプラグインマーケットプレイスを登録する
  • ネストされたスキルのロードを変更。Bash サンドボックス有効時、開始フォルダーより下の .claude/skills のスキルは、そこで開始するか /cd した場合のみロードされる
  • 自己ペースの /loop は、再スケジュールなしにターンが終了した時点で終了する。従来の動作は CLAUDE_CODE_LOOP_KEEPALIVE=1 で維持できる
  • PostToolUse フックが、ターン中断後に完了したツール呼び出しでも実行される (最大 10 秒)
  • セーフガードがサブエージェントを停止した後、Claude は自分で作業する代わりに、より狭いプロンプトでのリトライまたはユーザーへの報告を指示される
  • クラウドセッションは、deny / ask ルールをすべて維持できないワーカー移動時に、セッションスコープの allow ルールを破棄する
  • TLS 検査プロキシ配下の自動証明書修復は、ALL_PROXY が唯一のプロキシ変数の場合は実行されない。HTTPS_PROXY に http:// URL を設定する
  • アーティファクトデータベースの保存を変更。他者が書き込んだ可能性のある行の保存では各ファイルに隠しマーカーファイルが付与される
  • /claude-api managed-agents-onboard のテンプレートを Claude Console に合わせて更新。Performance tuner を削除し、2 つを改名、5 つで web 検索とフェッチを無効化

  • サインインやコネクタ、API アドレスを指すリンクは、ブラウザで開く代わりにアドレス付きテキストとして表示される

☁️ Cloud sessions / Code Review / Claude Tag

  • スケジュールされたタスクが memory という名前のコネクタを静かに除外する問題を修正
  • クラウドセッションで待機中メッセージの Send now が実行中のバックグラウンドエージェントを終了させる問題を修正

ユースケース - 開発者への影響

🏢 LLM ゲートウェイ配下やテレメトリ無効環境で auto mode を利用する組織

サーバーが確認できない呼び出しがフォールバックなしで確認・拒否されるようになったため、挙動の変化を確認する。従来の組み込み分類器を使い続ける場合は CLAUDE_CODE_AUTO_MODE_SERVER=0 を、managed settings で CLAUDE_CODE_DISABLE_EXPERIMENTAL_BETAS を設定している場合は CLAUDE_CODE_AUTO_MODE_SERVER=1 も併せて設定する

🤖 CI / 無人実行環境 (claude -p、Agent SDK) の開発者

claude -p が auto mode で安全性チェック不能により拒否された場合、終了コード 1 を返すようになったため、終了コードを監視するスクリプトは変化を考慮する。権限プロンプトによる停止を避けたい場合は permissions.denyInsteadOfPrompting の利用を検討する

🔌 長時間実行の MCP ツールを持つ MCP サーバー開発者

タスクとして実行される呼び出しが即座にバックグラウンドへ移動するようになった。同期動作が前提のクライアント統合は CLAUDE_CODE_DISABLE_MCP_TASK_BACKGROUND でオプトアウトできる

✅ 必要なアクション

  • 自己ペースの /loop を利用するユーザー: 従来のフォールバック起床を維持するには CLAUDE_CODE_LOOP_KEEPALIVE=1 を設定する
  • Claude API のレイテンシに課題がある開発者: /claude-api latency-optimize を実行し、待ち時間の発生箇所の特定と高速な設定の検証を行う
  • セルフホストランナーの運用者: 失敗セッションのログはランナーホスト上で確認する。CLAUDE_RUNNER_CHECKOUT_PATH のフォルダー命名変更 (重複時の -2、-3 サフィックス) に依存するスクリプトがあれば更新する

まとめ

Claude Code v2.1.319 は 146 件の変更を含む大型リリースで、auto mode のサーバーサイドチェックの厳格化と MCP タスクのバックグラウンド実行対応が中心。サーバーが確認できない呼び出しのフォールバック廃止は LLM ゲートウェイ配下やテレメトリ無効環境の組織に直接影響するため、CLAUDE_CODE_AUTO_MODE_SERVER の設定方針を決めておく必要がある。permissions.denyInsteadOfPrompting や claude -p の終了コード修正は無人実行の制御性を高め、Bash 権限バイパスやサンドボックスエスケープなどのセキュリティ修正、Monitor ツールの権限ルール適用により権限モデルの一貫性も強化された。/claude-api latency-optimize や /tasks の履歴行など日常の開発体験の改善も幅広く、ほぼすべての利用者に関係するアップデートである
