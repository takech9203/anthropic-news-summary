Claude API 観測性 Managed Agents

OpenTelemetry エクスポート (ベータ) と Claude Managed Agents スケジュールデプロイメントの AWS 対応

📅 2026-10-14 | ソース: Claude Developer Platform Release Notes

Messages API と Managed Agents セッションを既存の観測バックエンドでトレース可能に。さらに cron 式によるエージェントの定期実行が Claude Platform on AWS でも利用可能になりました。

概要

📡

OpenTelemetry エクスポートがベータ版で登場

Messages API リクエストと Claude Managed Agents セッションを、お客様が利用中の観測バックエンド (Datadog、Grafana Cloud、Langfuse など) でトレースできるようになりました。

🧰

7 言語の SDK がスパン出力に対応

Claude SDK は Python、TypeScript、C#、Go、Java、PHP、Ruby の 7 言語でクライアント側のスパンを出力します。コードでトレーサープロバイダーを登録して設定します。

🎯

Claude Console から API 側スパンを取得

Claude Console で OpenTelemetry destination を追加すると、API 側 (サーバー側) のスパンを取得できます。設定には Admin 権限が必要です。

⏰

スケジュールデプロイメントが Claude Platform on AWS に対応

cron 式で指定したスケジュールに従い、エージェントが自律的にセッションを開始できます。各実行はお客様の AWS アカウント内の IAM ロールとしてセッションを作成します。

📏

GenAI セマンティック規約に準拠

API と SDK は GenAI セマンティック規約の属性を使用するため、同規約をサポートするプラットフォームは追加設定なしでスパンを認識できます。

背景

OpenTelemetry はベンダー中立の観測性標準であり、多くの観測プラットフォームがサポートしています。トレースは 1 つのリクエストがシステムを通過する完全な記録、スパンはトレース内の 1 ステップ (モデルリクエストやツール使用など) を表します。

これまで Claude API のリクエスト内部の挙動 (各モデル実行、サーバーツールの実行、エージェントのターンなど) を既存の観測基盤で可視化する公式な仕組みはありませんでした。今回のベータリリースにより、以下が可能になります。

🔍 デバッグ

失敗したリクエストや遅いリクエストの原因を、トレースで詳細に調査できます。

💰 コスト・性能追跡

トークン消費とレイテンシーを継続的に追跡できます。

🧪 評価構築

実トラフィックから評価 (eval) を構築できます。

主な変更点 1: OpenTelemetry エクスポート (ベータ)

🧰 SDK トレーシング

Claude SDK (Python、TypeScript、C#、Go、Java、PHP、Ruby) がクライアント側のスパンを出力。コードでトレーサープロバイダーを登録して設定します。権限は不要です。

🎯 API トレーシング

Claude Console で OpenTelemetry destination を追加すると、API 側 (サーバー側) のスパンを取得できます。設定には Admin 権限が必要です。

🔗 両方の併用

SDK と API の両方を設定すると、1 つのリクエストの SDK スパンと API スパンを 1 つのトレースで確認できます。なお Claude Platform on AWS へのリクエストでは、API スパンは独立したトレースになります。

主な変更点 2: スケジュールデプロイメントの AWS 対応

スケジュールデプロイメントは、エージェントが自律的にセッションを開始し、予測可能なサイクルでタスクを完了できるようにする機能です。Deployments API で作成・管理します。今回のアップデートで、この機能が Claude Platform on AWS でも利用可能になりました。

🗓️ スケジュール定義

標準 POSIX cron 式 (分 時 日 月 曜日) と IANA タイムゾーン識別子で定義。粒度は分単位までです。

🔐 AWS 固有の要件

各実行はお客様の AWS アカウント内の IAM ロールとしてセッションを作成します。デプロイメント作成前に、エージェントの execution_identity に aws_role タイプと role_arn の設定が必要です (未設定の場合は 400 エラー)。

📜 実行履歴

各実行は deployment run レコードとして記録され、成功時はセッション ID、失敗時はエラー種別 (environment_archived_error、session_rate_limited_error など) を確認できます。

🔄 ライフサイクル管理

pause / unpause / archive の操作が可能です。ライフサイクル変更は Webhook イベントとして配信されます。

💵 予算管理

budget オブジェクトで実行ごとのコスト上限を設定可能です。累積ではなく各実行に個別に適用されます。

📈 上限

組織あたり最大 1,000 件のスケジュールデプロイメントを作成できます。

技術的な詳細

🎚️ コンテンツモード

OpenTelemetry エクスポートでは、スパンにモデルのプロンプトとレスポンスを含めるかどうかをコンテンツモードで制御します。

Metadata only (デフォルト)

識別子、タイミング、ステータス、トークン数と、エージェントやツールの名前・説明などお客様が選択したテキストのみを含みます。

Full content

Metadata only の内容に加えてモデルのプロンプトとレスポンスを含みます。失敗や遅延の原因分析、会話全文の確認、実トレースからの評価構築に利用できます。

⚠️ 注意: Full content では各スパンのコンテンツはデフォルトで最大 0.75 MB です。上限を超えると SDK または API がコンテンツを短縮し、anthropic.content.truncated を true に設定します。HIPAA、FERPA、K-12 のデータ取り扱い制限がある組織では、destination はコンテンツモードに関係なくメタデータのみをエクスポートします (SDK スパンは影響を受けません)。

🔢 トークンのカウント

トークンを重複なくカウントするには、リクエストごとに 1 つのソースのスパンだけを合計します。Messages API リクエストに SDK スパンと API スパンの両方がある場合は API スパンを合計します。両者は同じ anthropic.messages.create という名前のため、kind (SDK 側は CLIENT、API 側は SERVER) で区別します。

ℹ️ 補足: エクスポートされたスパンの配信はベストエフォートであり、API 使用量の完全な記録が保証されるわけではありません。使用量の正確な追跡には Usage API を使用します。

🕰️ スケジュールデプロイメントの DST (夏時間) の扱い

cron スケジュールはウォールクロック (現地時刻の文字どおりの一致) で動作します。春の時間送りで存在しない時刻はトリガーされず、秋の時間戻しで 2 回発生する時刻は 2 回実行されます。実行の欠落や重複が許容できない場合は、現地時間 1 時から 3 時の時間帯を避けるか、UTC を使用します。

また、負荷分散のため、実際の実行には実行間隔の最大 15% (最小 5 秒、最大 9 分) のジッターが適用されます。

コード例

スケジュールデプロイメントの作成例 (Python)。毎週金曜日の 20 時 (America/New_York) にコンプライアンススキャンを実行します。

Python スケジュールデプロイメントの作成 
deployment = client.beta.deployments.create(
    name="Weekly compliance scan",
    agent=agent.id,
    environment_id=environment.id,
    initial_events=[
        {
            "type": "user.message",
            "content": [{"type": "text", "text": "Run the weekly compliance scan."}],
        },
    ],
    schedule={
        "type": "cron",
        "expression": "0 20 * * 5",
        "timezone": "America/New_York",
    },
)

レスポンスには schedule.upcoming_runs_at に次回以降の実行予定時刻が含まれ、スケジュールが正しく設定されたことを確認できます。

開発者への影響

🎯 対象

観測性を強化したい開発者・SRE チーム

Claude API (Messages API) を本番環境で運用し、観測性を強化したい開発者・SRE チーム。

Managed Agents のデバッグ・監視

Claude Managed Agents のセッションをデバッグ・監視したいお客様。

AWS 環境での定期実行

AWS 環境で Claude Managed Agents を定期実行したいお客様。

✅ 必要なアクション: OpenTelemetry エクスポートを利用する場合

  1. SDK トレーシング: アプリケーションでトレーサープロバイダーを登録する (権限は不要)
  2. API トレーシング: Claude Console で OpenTelemetry destination を追加する (Admin 権限が必要)
  3. コンテンツモード (Metadata only / Full content) を要件に合わせて選択する。観測プラットフォーム側のアクセス制御と保持設定が組織の要件を満たすか確認する

✅ 必要なアクション: スケジュールデプロイメントを Claude Platform on AWS で利用する場合

  1. IAM ロールを用意する。信頼ポリシーで aws-external-anthropic.amazonaws.com サービスプリンシパルに sts:AssumeRole と sts:SetSourceIdentity を許可する
  2. ロールに aws-external-anthropic:CreateSession、sts:GetWebIdentityToken、sts:TagGetWebIdentityToken の権限を付与する
  3. エージェントの execution_identity に {"type": "aws_role", "role_arn": "..."} を設定する (設定する IAM プリンシパルには対象ロールへの iam:PassRole が必要)
  4. Deployments API または ant apply でデプロイメントを作成する

🔀 移行ガイド

既存機能の破壊的変更はありません。いずれも追加機能のため、移行作業は不要です。

⚠️ ベータに関する注意: OpenTelemetry エクスポートはベータ版であり、Anthropic との契約の Beta Services 条項の下で提供されます。スケジュールデプロイメントの利用にはベータヘッダー managed-agents-2026-04-01 が必要です。

まとめ

今回のアップデートは、Claude API を本番運用する組織にとって運用面の強化が中心です。OpenTelemetry エクスポート (ベータ) により、既存の観測基盤 (Datadog、Grafana Cloud、Langfuse など) で Messages API リクエストと Managed Agents セッションを他のアプリケーショントレースと同じ場所で可視化でき、デバッグ、コスト追跡、評価構築のワークフローが大きく改善されます。7 言語の SDK がスパン出力に対応し、GenAI セマンティック規約に準拠している点も、既存ツールとの統合を容易にします。

また、スケジュールデプロイメントの Claude Platform on AWS 対応により、AWS 環境のお客様も IAM ロールベースのアクセス制御を維持したまま、エージェントの定期実行 (週次スキャン、定期レポート作成など) を構築できるようになりました。両機能ともベータ段階のため、本番導入時はベータ条項とデータ保持要件の確認を推奨します。
