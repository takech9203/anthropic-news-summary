概要 — キーポイント

🚀

Fable 5 の後継となる 2 つの新モデル

2026 年 9 月 1 日、長時間実行のエージェント型コーディング、ナレッジワーク、研究用途に最適化された claude-fable-5-1 と claude-mythos-5-1 がリリースされた。Mythos 5.1 は Project Glasswing 参加者向けに提供される。

🧠

1M コンテキスト + 128k 出力 + 常時オンのアダプティブ思考

1M トークンのコンテキストウィンドウ (デフォルト)、128k の最大出力トークン、常時オンのアダプティブ思考 (adaptive thinking) をサポートする。

💰

基本価格は据え置き、キャッシュ読み取りは大幅引き下げ

価格は $10/$50 per MTok と Fable 5 から据え置き。プロンプトキャッシュ読み取りは $0.25 per MTok (基本入力価格の 0.025 倍) に引き下げられ、他モデルの 0.1 倍と比較して大幅に低い比率となった。

⚠️

開発者が対応すべき API 挙動の変更

tool_choice の any / tool が非サポート化 (400 エラー)、思考ブロックの互換性ポリシー導入、テキスト透かしと C2PA Content Credentials の付与、30 日間のデータ保持必須化が含まれる。

🖥️

マルチプラットフォーム対応と Claude Code 統合

Claude API、Amazon Bedrock / Claude Platform on AWS、Google Cloud、Microsoft Foundry で利用可能。Claude Code v2.1.257 では claude-fable-5-1 がデフォルトの Fable モデルとなった。

主要機能

📚 1M トークンコンテキスト

1M トークンのコンテキストウィンドウがデフォルトで有効。大規模コードベースの解析や長時間実行のエージェントタスク、大量のドキュメントを扱う研究ワークフローに対応する。

📝 128k 最大出力トークン

最大 128k トークンの出力に対応。大規模なコード生成や長文レポートの作成を 1 回のリクエストで完結できる。

🧠 常時オンのアダプティブ思考

アダプティブ思考 (adaptive thinking) が常時オンで動作。タスクの難易度に応じて思考量を調整し、エージェント型コーディングと研究ワークフローの性能を強化する。

⚡ キャッシュ読み取り $0.25 per MTok

プロンプトキャッシュ読み取りが基本入力価格の 0.025 倍に引き下げ。他モデルの 0.1 倍と比較して大幅に低く、長いコンテキストを繰り返し利用するエージェントワークロードのコスト効率が大きく向上する。キャッシュ書き込みは変更なし。

🔏 コンテンツの来歴表示

生成テキストに Anthropic のテキスト透かしを付与。コード実行ツール経由で生成された画像・動画ファイルには C2PA Content Credentials を付与する (リクエスト側の変更は不要)。

API 変更点 — 開発者が対応すべき挙動変更

🚫 tool_choice の制限 — any / tool が 400 エラーに

tool_choice の any と tool タイプが非サポートとなり、指定すると 400 エラーを返す。auto と none は変更なし。スキーマ準拠のツール入力を保証したい場合は、strict tool use または structured outputs の使用が推奨される。

🧩 思考ブロックの互換性ポリシー

Fable 5.1 / Mythos 5.1 が生成した思考ブロックは、生成したモデル自身またはそれより新しいモデルのみが読み取り可能。古いモデルに再送すると API がブロックを破棄する。Fable 5.1 は Claude Opus 5、Fable 5、Mythos 5 および以前のモデルの思考ブロックを受け入れ可能。

🔒 思考ブロック再送時の履歴検証 (thinking-binding)

Fable 5.1 では思考ブロック以前の履歴が変更されていないかを API が検証する。2026 年 8 月 31 日以降に作成されたアカウントでは、system プロンプト、tools、以前のメッセージが変更された後にブロックを再送すると 400 エラーとなる。thinking-binding-controls-2026-08-01 ベータヘッダーにより、破棄されたブロックを input_transformations フィールドで報告させたり、prefix_mismatch_behavior で拒否 / 破棄を選択したりできる。

💧 コンテンツの来歴表示

生成テキストに Anthropic のテキスト透かしを付与。コード実行ツール経由で生成された画像・動画ファイルに C2PA Content Credentials を付与する (リクエスト側の変更は不要)。

🗄️ 30 日間のデータ保持が必須

両モデルとも 30 日間のデータ保持が必須。ゼロデータ保持は Anthropic の明示的な許可がない限り原則利用不可となる。

🔄 tool_choice の Before / After

Before — Fable 5 まで

tool_choice で auto / none / any / tool の 4 タイプを指定可能。ツールの強制呼び出しに any / tool を利用できた。

After — Fable 5.1 / Mythos 5.1

auto / none のみサポート。any / tool は 400 エラー。スキーマ準拠を保証したい場合は strict tool use または structured outputs へ移行する。

🧪 あわせて案内されたベータ機能

⚙️ ターン途中の effort 変更

mid-conversation-output-config-2026-07-01 ヘッダー。messages 内の role: "system" メッセージに output_config.effort を追加し、プロンプトキャッシュを維持したまま effort を変更可能。対象は Fable 5.1、Mythos 5.1、Opus 5。

💬 ターンスコープのシステムメッセージ

mid-conversation-system-clear-at-2026-08-21 ヘッダー。clear_at: "next_user_message" を設定すると現在のターンのみ有効となる。

📊 思考の進捗表示

thinking-display-updates-2026-08-18 ヘッダー。thinking.display: "updates" を指定すると、思考内容は空のまま、ツール呼び出し間の短い進捗更新をテキストで返す。

🖥️ Claude Code への統合

Claude Code v2.1.257 では claude-fable-5-1 がデフォルトの Fable モデルとなった。

💻 コードサンプル

Python Fable 5.1 での strict tool use の使用例 
import anthropic

client = anthropic.Anthropic()

message = client.messages.create(
    model="claude-fable-5-1",
    max_tokens=128000,
    tools=[
        {
            "name": "get_weather",
            "description": "指定した都市の天気を取得する",
            "input_schema": {
                "type": "object",
                "properties": {
                    "city": {"type": "string"},
                },
                "required": ["city"],
            },
            # tool_choice の any / tool は非サポートのため、
            # スキーマ準拠を保証したい場合は strict tool use を使用する
            "strict": True,
        }
    ],
    messages=[
        {"role": "user", "content": "東京の天気を教えてください。"}
    ],
)

print(message.content)

開発者への影響

🎯 対象

  • Claude API で tool_choice の any または tool を使用している開発者
  • 複数モデル間で会話履歴 (思考ブロックを含む) を共有しているアプリケーションの開発者
  • プロンプトキャッシュを多用する長時間実行エージェントの開発者
  • ゼロデータ保持契約を利用している組織

🛠️ 必要なアクション

1

tool_choice の見直し

any / tool を使用しているコードは 400 エラーとなるため、strict tool use または structured outputs へ移行する。

2

思考ブロックの取り扱い確認

会話履歴を古いモデルに再送するフローがある場合、ブロックが破棄されることを前提に設計を見直す。挙動を制御したい場合は thinking-binding-controls-2026-08-01 ベータヘッダーを検討する。

3

履歴の不変性確認

2026 年 8 月 31 日以降に作成されたアカウントでは、思考ブロック再送時に履歴改変が 400 エラーとなるため、履歴を書き換えるロジックがないか確認する。

4

データ保持ポリシーの確認

ゼロデータ保持を利用している場合は、両モデルの利用可否を Anthropic に確認する。

🔀 移行ガイド

Fable 5 から Fable 5.1 への移行では、モデル ID を claude-fable-5-1 に変更するだけで基本的な動作は維持される。ただし、tool_choice 制限と思考ブロックの互換性ポリシーに該当する実装は事前に修正が必要である。

ユースケース

🤖 長時間実行のエージェント型コーディング

1M トークンコンテキストと 128k 出力トークン、常時オンのアダプティブ思考により、大規模コードベースを対象とした長時間のエージェントタスクを安定して実行できる。Claude Code v2.1.257 ではデフォルトの Fable モデルとして利用可能。

⚡ プロンプトキャッシュを多用するエージェントワークロード

キャッシュ読み取りが $0.25 per MTok (基本入力価格の 0.025 倍) に引き下げられたことで、長いコンテキストを繰り返し参照するエージェントワークロードのコスト効率が大きく向上する。

📖 ナレッジワークと研究ワークフロー

大量のドキュメントを扱うナレッジワークや研究用途に最適化されており、Mythos 5.1 は Project Glasswing 参加者向けの研究ワークフローに提供される。

まとめ

⭐

エージェント型コーディングとナレッジワーク向けの最先端モデル

Claude Fable 5.1 と Claude Mythos 5.1 は、1M トークンコンテキスト、128k 出力トークン、常時オンのアダプティブ思考を備え、Fable 5 の後継として性能をさらに強化した。

💰

コスト効率の大幅な向上

基本価格は据え置きのまま、プロンプトキャッシュ読み取りが基本入力価格の 0.025 倍まで引き下げられ、長いコンテキストを繰り返し利用するエージェントワークロードのコスト効率が大きく向上する。

⚠️

移行前の確認を推奨

tool_choice の any / tool の廃止、思考ブロックの互換性ポリシー、30 日間のデータ保持必須化など、既存アプリケーションに影響する変更が含まれるため、移行前に該当箇所の確認と修正を推奨する。
