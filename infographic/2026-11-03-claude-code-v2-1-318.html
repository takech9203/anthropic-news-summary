概要 - キーポイント

🛡️

共有ネットワークホームでの設定破損を防止

~/.claude.json、設定ファイル、保存済みログインが保存時に削除・空ファイル化・古いコピーへの置き換えをされにくくなった。設定ファイルが誤って「存在しない」と報告された場合の再確認処理も追加され、MCP サーバーや信頼済みフォルダーなしでセッションが開始されるケースが減少

⏰

認証有効期限の可視化と事前警告

claude.ai サインインの有効期限が claude auth status の loginExpiresAt と claude -p の JSON 結果の credential_expires_at で確認可能に。期限の 10 日前から stderr に警告が 1 行表示され、CI や自動化環境で認証切れを事前に検知できる

🔑

Claude apps gateway の assume_role 対応

mantle アップストリームに assume_role を設定し、別の AWS アカウントのロールを引き受け可能に。開発者ごとの AWS コスト配分にも対応し、エンタープライズのマルチアカウント運用とコスト管理を強化

🔁

日常利用に影響する重要なリグレッション修正

--continue で以前の会話が失われる v2.1.314 のリグレッション、macOS で多数の Bash コマンド実行中にセッションが停止する問題などを解消

🧩

mod 開発者向けの新オプション

$.model.fork に effort オプションが追加され、セッションの effort 設定にかかわらず low などの指定した effort でサイドジョブを実行可能に。mod 有効化を尋ねた際の回答も記録されるようになった

主要機能 (Added)

🔑 gateway の assume_role

Claude apps gateway の mantle アップストリームで別 AWS アカウントのロールを利用可能に。アカウント分離と開発者別のコスト配分を両立できる

📆 認証有効期限の表示

保存済み claude.ai サインインの終了日を claude auth status の loginExpiresAt と claude -p JSON 結果の credential_expires_at で確認できる

⚠️ 期限前の stderr 警告

期限の 10 日前から claude -p のテキスト出力で stderr に 1 行の警告を表示。CI のログ監視で認証切れを事前に検知できる

🎚️ $.model.fork の effort オプション

mod がセッションの effort 設定にかかわらず、簡単なサイドジョブを指定した effort で実行可能に。結果には送信された effort が報告される

📝 mod 有効化の回答記録

Claude Code がセッション内で作成した mod の有効化を尋ねた際の回答が記録されるようになった

🛡️ 設定ファイル保護の多層化

共有ネットワークホームでの保存耐性の改善に加え、破損した ~/.claude.json をデフォルトで上書きせず復元方法を案内して停止する動作、バックアップ削除前の新規バックアップ取得、ロックを尊重した claude mcp add / remove など、設定喪失を防ぐ修正が多層的に導入された

🚫 deniedMcpServers の適用範囲拡大

URL エントリによる拒否が Anthropic 提供サーバーとコネクタにも適用され、組織ポリシーで特定のアップストリームを一括ブロック可能に。クラウドセッションとセルフホストランナーではコネクタ自身の URL で一致し、それ以外の環境ではコネクタを名前で拒否する必要がある

⚡ プロンプトキャッシュを考慮したサブエージェント動作

長時間のシェルコマンドを 3 分でバックグラウンドへ移動し、サブエージェントのプロンプトキャッシュの期限切れを防ぐ。Bedrock / Vertex / Foundry またはテレメトリ無効時は、コールドキャッシュで進捗サマリーが最大 5 分待機する場合がある

重要な修正 (Fixed) - 41 件

💬 セッション・会話管理

  • --continue が、不正な形式のツール呼び出しのリトライが尽きた後に以前の会話を失う問題 (v2.1.314 のリグレッション) を修正
  • macOS で多数の Bash コマンドを実行中のセッションが、メモリ増加とともに停止する問題を修正
  • アイドルコンパクションが、会話を要約ではない応答で置き換える問題を修正
  • 再起動したセッションが、API エラーで失敗したメッセージを、待機中の新しいメッセージより先に再送する問題を修正
  • 大きな画像の読み込みやツール呼び出しのリトライ直後の再起動で、中断されたターンが失われる問題を修正
  • ヘッドレスセッションで、モデル変更直後のメッセージが Stop 後も実行され続ける問題を修正

🔐 認証・設定ファイル

  • /logout や claude mcp remove が、共有ネットワークホームで設定を更新できない場合でも成功と報告し、変更が無言で失われる問題を修正
  • 別のターミナルやホストが同じアカウントに再サインインした際に、ジョブが Not logged in で終了する問題を修正
  • claude mcp add / remove がロックなしで設定を書き込む問題を修正。ロックを待つか終了コード 1 で終了する
  • ネットワークホームの空き容量が尽きた際に、保存済みログインが空ファイルで置き換えられる問題を修正
  • 非対話起動が、有効な JSON でない ~/.claude.json をデフォルト値で置き換える問題を修正。起動は失敗し、復元方法を表示してファイルをそのまま残す
  • 保持期間クリーンアップが ~/.claude.json のバックアップをすべて失わせる問題を修正。最後の正常なバックアップを削除する前に新しいバックアップを取得する

🖥️ UI・権限・ヘッドレス

  • メッセージ送信直後に入力したキーが、権限プロンプトに回答してしまう問題を修正
  • 失敗したカスタムスラッシュコマンドが claude -p と SDK セッションで何も出力しない問題を修正
  • mod の turn.step フック中の API エラーや停止された応答が、ヘッドレス実行で成功と報告される問題を修正
  • 20 枚を超える画像を含むリクエストのエラーが常に 2000px と表示される問題を修正。API の制限値を表示する

🌐 ネットワーク・インフラ

  • NODE_EXTRA_CA_CERTS ファイルの不備ですべての接続が失敗する問題を修正。読み取り可能な証明書は使用され、stderr に警告を表示
  • アップデートによるバイナリ削除後に claude remote-control ホストやセルフホストランナーが新しいセッションを開始できない問題 (spawn ENOENT) を修正
  • セルフホストランナーやクラウドセッションの再起動後に、承認済みシェルコマンドが依頼されたフォルダーではなく開始フォルダーで実行される問題を修正
  • 使用量上限後に再開したワークフローが、完了済みエージェントを再実行する問題を修正
このほかの修正: クラウドセッション再起動後のコネクタツール利用不可の通知、アップロード拒否時のターン途中停止、Setup フックの CLAUDE_ENV_FILE 変数が Bash ツールに届かない問題、iPhone アプリの誤ったターン完了表示、PushNotification の重複通知など多数の修正が含まれる

改善 (Improved)

  • 共有ネットワークホームでの保存時の ~/.claude.json、設定ファイル、保存済みログインの生存性を改善
  • MCP ツールのエラーを改善。ツールのロード前に行われた呼び出しが入力スキーマを返す
  • macOS 組み込みの /bin/bash 使用時の git コミットとプルリクエスト作成の信頼性を改善
  • 使用量上限メニューの「Ask your admin for more usage」が 1 ステップでリクエストを送信
  • 一時停止やスリープ後のリモートセッションの再接続速度を改善
  • 自動アップデートの信頼性を改善。一時的なネットワーク障害は即座にリトライされる
  • 無人実行 (claude -p、SDK アプリ) が、変更がない場合に実行ごとの ~/.claude.json 書き換えを行わない

動作変更 (Changed) と削除 (Removed)

  • IDE ターミナル内での起動時に、IDE 拡張機能のインストール・更新を行わなくなった。外部ターミナルからの /ide またはエディターの拡張機能ビューを使用する
  • deniedMcpServers の URL エントリが、Anthropic 提供サーバーとクラウドセッション・セルフホストランナーのコネクタもブロックするようになった
  • 「Switch models when a message is flagged」が「Ask each time」の場合、サブエージェントはモデル切り替えではなく停止する
  • バックグラウンドサブエージェントが、すべてのプロバイダーで 3 分後にシェルコマンドをバックグラウンドへ移動する
  • mod が prompt.submit で添付する内容が、システムメッセージではなくユーザーのターンに残る
  • /permissions の詳細・削除確認ビューが標準ダイアログに。Ctrl+C を 2 回押すと終了ではなく戻る・キャンセルになる
  • /claude-api managed-agents-onboard が、新しいエージェントのツールにデフォルトで auto 権限ポリシーを付与する

ユースケース - 開発者への影響

🏢 共有ネットワークホーム (NFS など) で Claude Code を運用する組織

~/.claude.json や保存済みログインの破損・消失対策が多層的に導入され、MCP サーバーや信頼済みフォルダーの設定が無言で失われるリスクが大幅に低減。通常のアップデートで適用され、特別な移行作業は原則不要

🤖 CI / 無人実行環境 (claude -p、Agent SDK) の開発者

claude -p JSON 出力の credential_expires_at または stderr の期限警告を監視に組み込むことで、認証切れによるジョブ失敗を事前に検知できる。変更がない場合の実行ごとの ~/.claude.json 書き換えも廃止された

🔐 マルチアカウント AWS 環境のゲートウェイ管理者

mantle アップストリームの assume_role 設定により、別アカウントのロール経由で Bedrock などへアクセスでき、開発者別のコスト配分でアカウント分離とコスト管理を両立できる

その他の留意点: セルフホストランナーのオーケストレーターログを解析するスクリプトはフィールド順変更に合わせた更新が必要。IDE 拡張機能は IDE ターミナル内の起動では自動インストールされないため、外部ターミナルから /ide を実行するか拡張機能ビューからインストールする。v2.1.286 以前に開始した会話の再開では以前の thinking が破棄される

まとめ

Claude Code v2.1.318 は 84 件の変更を含むリリースで、認証と設定ファイルの信頼性向上が中心。共有ネットワークホームディレクトリでの設定破損・消失対策が多層的に導入され、認証有効期限の可視化と事前警告により無人実行環境の運用性も向上した。gateway の assume_role によるクロスアカウント AWS 対応と開発者別コスト配分はエンタープライズ利用者にとって重要な追加機能であり、--continue のリグレッションや macOS でのセッション停止など日常利用に影響する不具合も修正された。特にネットワークホームや CI 環境で Claude Code を運用する組織に恩恵の大きいアップデートである
