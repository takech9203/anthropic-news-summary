Claude Enterprise Analytics API のカウント修正 3 件: Web 検索数、コネクタ利用ユーザー数、プロジェクト活動

📅 2026-11-23 | ソース: Claude API Release Notes

概要

📊

Enterprise Analytics API の過少カウント修正 3 件を発表

2026 年 11 月 23 日の Claude API リリースノートで、Claude Enterprise Analytics API のカウント修正 3 件が発表された。いずれも実際の利用より少なく集計される過少カウント (undercount) の是正で、値が大きくなる方向の修正。

🔍

List User Activity の web_search_count を修正 (適用済み)

チャットで Claude が使用する一部の検索ツールがカウントされていなかった問題を解消。追加される検索の多くは Chat and Cowork unified に由来する。2026 年 11 月 17 日 (UTC) 以降のデータに適用。

🔌

Get Connector Usage のコネクタ利用ユーザー数を修正 (適用済み)

individual_auth_distinct_user_count と managed_auth_distinct_user_count から一部のユーザーが漏れていた問題を解消。従来 null だった箇所に数値が表示される場合もある。2026 年 11 月 19 日 (UTC) 以降のデータに適用。

📁

プロジェクト活動の修正は 2026-11-24 適用予定

Get Chat Project Usage と、project_id でフィルタした List User Activity が対象。Cowork クラウドセッションへの移行後に送信されたメッセージなどの漏れを是正する。2026 年 11 月 20 日 (UTC) 以降のデータが対象。

⚠️

適用開始日より前のデータは再集計されない

各修正はそれぞれの適用開始日以降のデータにのみ適用される。適用開始日をまたぐ期間の時系列比較では、集計方法の違いによる不連続が生じる点に注意が必要。

背景: Chat and Cowork unified との関係

Claude Enterprise Analytics API は、Claude Enterprise 組織向けに組織全体のエンゲージメント・導入状況・コストデータ (ユーザー活動、プロジェクト・スキル・コネクタの利用状況など) を提供する API。claude.ai で作成する read:analytics スコープ付きの Analytics API キーを使用し、エンドポイントは https://api.anthropic.com/v1/organizations/analytics/ 配下に提供される。

  • 🔄今回の修正の背景には、2026 年 11 月 20 日に発表された「Chat and Cowork unified」(Cowork の機能を claude.ai のチャットに統合) のセッションカウント新ルールがある。新ルールでは、UTC 日の中で Claude が Bash コマンドの実行、ファイルの作成、ファイルの編集のいずれかに最初に成功した時点でセッションが開始し、その日の終わりに終了するとカウントされる
  • 🔌コネクタ利用ユーザー数の修正は、このセッションカウント変更が到達したチャットで発生していたカウント漏れを是正するものであると明記されている
  • 🔍Web 検索数の修正で追加される検索の多くは Chat and Cowork unified に由来し、プロジェクト活動の修正もチャットが Cowork クラウドセッションへ移行した後のメッセージの漏れを例に挙げており、いずれも Chat and Cowork unified への移行に関連している

3 件の修正内容

🔍 web_search_count の修正

✅ 適用済み | 2026-11-17 以降のデータ

List User Activity エンドポイントのトップレベル web_search_count が、チャットで Claude が使用するすべての検索ツールをカウントしていなかった。修正により漏れていた検索が含まれるようになり、値は従来より大きくなる可能性がある。追加される検索の多くは Chat and Cowork unified に由来する。

🔌 コネクタ利用ユーザー数の修正

✅ 適用済み | 2026-11-19 以降のデータ

Get Connector Usage エンドポイントで、セッションカウント変更が到達したチャットにおいて individual_auth_distinct_user_count と managed_auth_distinct_user_count が一部のユーザーを漏らしていた。ほとんどの組織ではこれらのユーザーの大部分がカウントに含まれるようになり、従来 null だった箇所に数値が表示される場合もある。

📁 プロジェクト活動の修正

🗓️ 2026-11-24 適用予定 | 2026-11-20 以降のデータ

Get Chat Project Usage と project_id フィルタ時の List User Activity が対象。Cowork クラウドセッション移行後のメッセージなどの漏れを是正し、message_count、distinct_conversation_count、distinct_user_count が大きくなり、last_activity_date がより新しくなる可能性がある。結果に表示されるプロジェクトやユーザーが増える場合もある。

💡 project_id フィルタを使用しない場合、プロジェクト活動の対象メッセージの一部は chat_cowork_unified_metrics.sessions.message_count にカウントされる。そのため、同じユーザーのチャットの message_count が、フィルタありの場合にフィルタなしの場合より大きくなることがある。

3 件に共通する性質

  • 🚫再集計なし: いずれの修正も、適用開始日より前のデータは再集計しない。適用開始日をまたぐ期間の時系列比較では、集計方法の違いによる不連続が生じる
  • 🔁取得済みデータの変化: 適用開始日以降の日付について、修正前に取得したカウントは修正後の再取得で値が変わる可能性がある
  • 📈過少カウントの是正: いずれも値が大きくなる方向の修正
  • ⏱️List User Activity の API リファレンスによると、データは通常 1 日遅れで利用可能になり、その後数日間は数パーセント程度改定される場合がある。project_id フィルタを使用した行では、chat_cowork_unified_metrics.sessions のカウントはすべて 0 になる (セッションはプロジェクト単位で計測されないため)

コードサンプル

Bash List User Activity で指定日のユーザー活動を取得 (curl) 
# 指定日のユーザー活動を取得 (web_search_count は 2026-11-17 以降の日付で修正後の値になる)
curl "https://api.anthropic.com/v1/organizations/analytics/users?date=2026-11-21" \
  -H "anthropic-version: 2026-10-21" \
  -H "x-api-key: $ANTHROPIC_ANALYTICS_KEY"
Bash project_id フィルタで特定プロジェクトの活動を取得 (curl) 
# 特定プロジェクトに絞ったユーザー活動を取得
# (project_id フィルタ時の行は 2026-11-24 のプロジェクト活動修正の対象)
curl "https://api.anthropic.com/v1/organizations/analytics/users?date=2026-11-21&filter[]=project_id:claude_proj_XXXX" \
  -H "anthropic-version: 2026-10-21" \
  -H "x-api-key: $ANTHROPIC_ANALYTICS_KEY"
🔑 Analytics API キー (read:analytics スコープ) は claude.ai で作成し、x-api-key ヘッダーで渡す。トップレベルの web_search_count が今回の修正対象。

開発者への影響と必要なアクション

対象: Claude Enterprise Analytics API の List User Activity、Get Connector Usage、Get Chat Project Usage エンドポイントを利用している Claude Enterprise 組織と、これらのデータを BI ツールやダッシュボードに取り込んで利用状況レポートを作成している管理者・分析チーム。

1

取得済みデータの再取得

適用開始日以降の日付 (Web 検索数は 2026-11-17 以降、コネクタは 2026-11-19 以降、プロジェクト活動は 2026-11-20 以降) について修正前に取得したデータは、過少カウントの可能性がある。正確な値が必要な場合は再取得する。

2

時系列比較の注意

適用開始日より前のデータは再集計されないため、適用開始日をまたぐ期間の推移分析では、カウント方法の違いによる見かけ上の増加が起こり得る。レポートに注記を加えることを検討する。

3

null ハンドリングの確認

Get Connector Usage の individual_auth_distinct_user_count と managed_auth_distinct_user_count は、従来 null だった箇所に数値が表示されるようになる場合がある。null を前提とした処理がある場合は動作を確認する。

4

2026-11-24 の適用に備える

プロジェクト活動の修正適用後は、Get Chat Project Usage の結果に表示されるプロジェクトや、project_id フィルタ時の List User Activity に表示されるユーザーが増える可能性がある。また、フィルタありの message_count がフィルタなしより大きくなるケースがある点に留意する。

ユースケース

📊 利用分析ダッシュボードのデータ再取得

Analytics API のデータを BI ツールに取り込んでいる分析チームは、適用開始日以降の日付のデータを再取得することで、Web 検索数・コネクタ利用ユーザー数・プロジェクト活動を修正後の正確な値でダッシュボードに反映できる。修正前に取得してキャッシュした値は過少カウントの可能性があるため、対象期間の洗い替えを計画する。

📈 適用開始日をまたぐ時系列比較での注記運用

週次・月次の利用状況レポートを作成している管理者は、適用開始日 (2026-11-17 / 11-19 / 11-20) をまたぐ期間の推移グラフに「集計方法の変更による見かけ上の増加」の注記を加えることで、誤った増加トレンドの解釈を防げる。いずれも値が大きくなる方向の修正である点を関係者に共有しておく。

🔧 コネクタ利用レポートの null 処理見直し

Get Connector Usage の distinct_user_count 系フィールドを集計パイプラインで処理している組織は、従来 null だった箇所に数値が入るようになるため、null を「利用なし」として扱うロジックや型変換処理の動作確認を行い、集計の欠落やエラーを未然に防げる。

まとめ

2026 年 11 月 23 日の Claude API リリースノートでは、Claude Enterprise Analytics API の過少カウント修正 3 件が発表された。List User Activity の web_search_count (2026-11-17 以降のデータに適用済み)、Get Connector Usage のコネクタ利用ユーザー数 (2026-11-19 以降のデータに適用済み)、そして Get Chat Project Usage と project_id フィルタ時の List User Activity におけるプロジェクト活動 (2026-11-20 以降のデータを対象に 2026-11-24 適用予定) である。これらの修正は、2026 年 11 月 20 日に発表された Chat and Cowork unified のセッションカウント新ルールの展開に関連しており、いずれも値が大きくなる方向の是正。適用開始日より前のデータは再集計されないため、分析チームは対象期間のデータ再取得と、適用開始日をまたぐ時系列比較における不連続への注意が必要になる。
