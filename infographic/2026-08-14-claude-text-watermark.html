透明性 責任ある AI 規制対応

Claude のテキスト透かしの仕組み: 鍵付き擬似乱数サンプリングによる生成テキストの識別

📅 2026-08-14 | ソース: Anthropic News

今後の Claude モデルが生成するテキストに透かし (watermark) が入ります。テキストには何も追加されず、品質への影響もありません。鍵を持つ者だけが「Claude が生成した確率」を統計的に算出できます。

概要 / キーポイント

Anthropic は 2026 年 8 月 14 日、今後の Claude モデルが生成するテキストに透かしを含める仕組みを解説する記事を公開しました。EU AI 法への準拠を目的とした対応であり、Anthropic は 2026 年 7 月に「EU Code of Practice on Transparency of AI-Generated Content」に約 190 の署名者とともに署名しています。他の主要 AI 開発企業も同様に、それぞれ独自の透かしを実装する予定です。

💧

乱数の「源」を置き換える透かし

単語選択に使う乱数を、鍵と直前の数語に基づく擬似乱数に置き換えます。Google DeepMind が 2024 年に Nature 誌で発表した SynthID-Text の一種であり、テキストに文字やトークンを追加するものではありません。

✨

品質への影響なし

読者には透かしの有無を区別できず、内部テストでは品質、創造性、可読性への影響がないことが確認されています。追加トークンも不要なため、速度とコストへの影響はごく僅かです。

🗝️

検出には鍵が必要

鍵を持つ者だけが、単語の並びが Claude の選択パターンと一致するかを統計的に検証し、Claude が生成した確率を算出できます。透かし検出 API は近日提供予定です。

🇪🇺

EU AI 法への準拠が背景

EU AI 法の透明性要件への対応として実装されます。地域を限定した実装方法が未確立のため、当面はグローバルに適用されます。

🖼️

画像などのファイルは C2PA で対応

.png、.jpg、.svg などのファイルには透かしではなく、オープン標準 C2PA による暗号署名付きメタデータ (コンテンツクレデンシャル) を付与します。

背景

  • EU AI 法の透明性要件: EU AI 法は、AI が生成したコンテンツの透明性を求めており、Anthropic は 2026 年 7 月に「EU Code of Practice on Transparency of AI-Generated Content」に署名しました。今回の透かしはこの準拠のための実装です。
  • 当面はグローバルに適用: 地域を限定した実装方法が未確立のため、特定地域だけでなくグローバルに適用されます。
  • 手法の系譜: 採用された手法は、2022 年の Scott Aaronson の提案に遡る手法群に属し、直接的には DeepMind の SynthID-Text (Nature、2024 年) の一種です。
  • Gemini での実績: DeepMind の論文では Gemini の一部トラフィックで検証が行われ、評価において「統計的有意差なし」と報告されています。

主な変更点

💧 将来のモデルに透かしが入る

将来の Claude モデルが生成するテキストに透かしが入ります。テキスト自体には何も追加されず、隠し文字も存在しません。追加トークンも不要で、速度とコストへの影響はごく僅かです。

⏳ 旧モデルには移行期間

2026 年 8 月 2 日以前のモデルには移行期間が設けられ、今後数か月で順次対応します。

🖼️ ファイルは別の仕組み

.png、.jpg、.svg などのファイルには透かしではなく、オープン標準 C2PA による暗号署名付きメタデータ (コンテンツクレデンシャル) を付与します。

🔍 検出 API を近日提供予定

透かし検出 API は近日提供予定であり、詳細は検討中とされています。

技術的な詳細: 動作原理

LLM は 1 語ずつテキストを生成し、次の単語を確率付きの候補リストから選択します。「overcast」と「grey」のように意味がほぼ変わらない低リスクな選択では、通常は乱数によって単語が決定されます。

透かしは、この乱数の「源」を変える手法です。任意の乱数生成器の代わりに、鍵と直前の数語から導出した擬似乱数で単語を決定します。単語選択は依然としてランダムに見えますが、鍵を持つ者は単語の並びが Claude の選択パターンと一致するかを確認でき、そのテキストを Claude が生成した確率を算出できます。モデルが本来選ばない単語 (例: 「nubilous」のような難解語) を選ばせることはないため、出力の自然さは保たれます。

🎲

モノポリーの比喩: 記事はこの仕組みを、モノポリーでサイコロの代わりに円周率の桁を使ってコマを進める比喩で説明しています。プレイヤーにとってはランダムであることに変わりありませんが、後から手順を確認すれば円周率が使われたかを判定できます。

出力への影響とプライバシー

✅ 出力への影響

🎨 品質への影響なし

内部テストで品質、創造性、可読性への影響がないことを確認済みです。読者には透かしの有無を区別できません。

📝 テキストへの追加なし

隠し文字や特殊なトークンは一切挿入されません。

⚡ 速度とコスト

追加トークンが不要なため、影響はごく僅かです。

🔒 プライバシー

  • 透かしから個人、組織、チャットを特定することはできません
  • 鍵にもユーザー情報を復元できる要素は含まれていません

⚠️ 制限事項

検出結果の解釈には以下の制限事項の理解が不可欠です。

  • 判定できるのは「Claude が関与した可能性」のみ: 人間が書いたことや、他の AI が書いたことは確認できません。他社は別の鍵と手法を使用します。
  • 短いテキストでは検出精度が低い: 長文ほど信頼度が上がります。
  • 事実記述では透かしが疎になる: 例えば「Principia」の次は「Mathematica」しかないような箇所では単語の選択肢がなく、透かしを埋め込む余地がありません。
  • 校正や軽微な編集にはほとんど付かない: 大半が人間の言葉のままであるため、透かしが入る余地がほとんどありません。
  • コードには少ない: 正確性が要求されるため透かしは少ないですが、コメントなど任意選択がある部分には適用できます。
  • 編集への耐性: 軽い編集では透かしは完全には消えませんが、全面的な書き直しでは消えます。
  • 「書いた」と「大幅に編集した」の区別は不可: どちらも Claude の関与として検出されます。

既存の AI 検出ツールとの違い

既存の AI 検出ソフトウェア

  • Pangram などが該当し、鍵を持たない
  • AI 特有の言い回し (「quietly」の多用など) を統計的に分析する
  • 文体の特徴に基づく推定

Claude の透かし

  • 鍵に基づく擬似乱数パターンの照合
  • 鍵の保有者だけが検証できる
  • 原理が根本的に異なる検証手段

開発者への影響

🎯 対象

  • Claude API を利用する開発者: 将来のモデルが生成するテキストに透かしが含まれるようになりますが、出力形式や品質に変化はありません。
  • コンテンツプラットフォームの運営者: 近日提供予定の透かし検出 API により、Claude 生成テキストの識別が可能になる見込みです。
  • EU AI 法への対応を進める企業: AI 生成コンテンツの透明性要件への準拠状況を把握する担当者。
  • 教育機関や出版などで AI 検出を行う組織: 既存の統計的 AI 検出ツールとは異なる、鍵に基づく検証手段が加わります。

🛠️ 必要なアクション

1

アプリケーションへの影響確認: 透かしはテキストに文字を追加せず、品質にも影響しないため、既存のアプリケーションで対応が必要な変更はありません。

2

検出 API の続報の確認: 透かし検出 API は近日提供予定であり、詳細は検討中とされているため、公式発表を待つ必要があります。

3

検出結果の解釈の整理: 検出できるのは「Claude が関与した可能性」であり、人間が書いたことの証明や他の AI の識別はできません。短文や事実記述、コードでは信頼度が下がる点を運用ポリシーに織り込みます。

4

法的位置づけの理解: 透かしは所有権、著作権、法的責任に影響しません。

🔄 移行ガイド

📅

2026 年 8 月 2 日以前のモデルには移行期間が設けられ、今後数か月で順次透かしが適用されます。開発者側での移行作業は不要です。

ユースケース

🔍 コンテンツの出所確認

近日提供予定の透かし検出 API により、コンテンツプラットフォームは投稿されたテキストを Claude が生成した確率を算出し、コンテンツの出所確認という新しいユースケースが開ける可能性があります。

🇪🇺 EU AI 法への準拠状況の把握

AI 生成コンテンツの透明性要件への対応を進める企業は、Claude の透かしが EU Code of Practice への署名に基づく準拠実装であることを把握し、自社の対応方針に反映できます。

🎓 教育機関や出版での AI 検出

既存の統計的 AI 検出ツール (文体分析) とは原理が異なる、鍵に基づく検証手段が加わります。ただし短文、事実記述、コード、軽微な編集では検出力が下がる制限を運用に織り込む必要があります。
