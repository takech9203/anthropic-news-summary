Claude API Console 開発者ツール

Claude Console の Workbench が Playground に刷新、Messages API 全パラメータ対応と SDK リクエスト / レスポンスの完全表示を実現

📅 2026-08-18 | ソース: Claude Developer Platform Release Notes

Playground は Messages API のすべてのパラメータをサポートし、コード実行や Web 検索などの API 機能を示すテンプレートを収録。実行のたびに完全な SDK リクエストと API レスポンスを表示し、API の構造の理解とアプリケーション開発を支援します。https://platform.claude.com/playground から利用できます。

概要 / キーポイント

Anthropic は 2026 年 8 月 18 日、Claude Console の Workbench を Playground として刷新したことをリリースノートで発表しました。公式ヘルプセンターによると、Playground は公開されている Messages API の上に直接構築されており、Playground で組み立てたリクエストはコードから送信するものと同一です。

🧪

Workbench が Playground へ世代交代

ツールの位置づけが「プロンプト管理ツール」から「API の学習と実験のための実行環境」へ転換されました。Playground は https://platform.claude.com/playground から利用できます。

🎛️

Messages API の全パラメータをサポート

モデルセレクターでの Claude モデル切り替えに加え、temperature や最大出力トークン数などのパラメータをモデル設定から調整できます。コード実行や Web 検索などの API 機能を示すテンプレートも収録されています。

📨

完全な SDK リクエストと API レスポンスを表示

実行ごとに、完全なメッセージ構造、stop reason、usage を含む生の API リクエストとレスポンスを表示します。画面上の表示とコードの挙動が一致することが保証されます。

🔒

ステートレスな設計へ転換

プロンプトや会話は Anthropic のサーバーに保存されず、下書きはブラウザ内に留まります。一方で、旧 Workbench のプロンプト履歴の保存やプロンプト評価 (evals) はサポートされません。

⏰

旧 Workbench データのエクスポート期限は 2026 年 9 月 1 日

旧 Workbench (legacy) に保存されていたデータは 2026 年 9 月 1 日まで Console の設定からエクスポート可能で、それ以降は復元できなくなります。利用者は期限までにエクスポートを完了する必要があります。

背景

Workbench は Claude Console 内でプロンプトを作成、テスト、保存できるツールとして提供されてきました。プロンプトの保存、バージョン管理、評価 (evals)、共有といった機能を持つ一方、Console 上の表示と実際の API リクエストの対応関係が必ずしも明確ではありませんでした。

今回の刷新は、ツールの位置づけを「プロンプト管理ツール」から「API の学習と実験のための実行環境」へと転換するものです。ヘルプセンターは Playground の用途を以下のように整理しています。

  • コードを書く前にモデルや新しい API 機能を試す
  • プロンプトを反復改善し、完全なレスポンスを確認する
  • API リクエスト / レスポンスの構造を学ぶ
  • 作業内容を自分のアプリケーションで実行できるコードスニペットとしてエクスポートする

Before / After: Workbench → Playground

Before: Workbench (legacy)

  • プロンプト、履歴をサーバーに保存
  • Messages API パラメータは一部のみ対応
  • リクエスト / レスポンス表示は限定的
  • API 機能を示すテンプレートはなし
  • Console 上の表示と実際の API リクエストの対応関係が不明確
  • 位置づけは「プロンプト管理ツール」

After: Playground (2026-08-18 以降)

  • サーバーに保存しないステートレス設計。下書きはブラウザ内のみ
  • Messages API のすべてのパラメータをサポート
  • 完全な SDK リクエストと API レスポンスを表示
  • コード実行、Web 検索などのテンプレートを収録
  • 公開 Messages API 上に直接構築され、画面とコードが同一
  • 位置づけは「API の学習と実験のための実行環境」
💡

Playground で組み立てたリクエストはコードから送信するものと同一であり、「Console では動くがコードでは動かない」という乖離が起きにくくなりました。一方、旧 Workbench の保存プロンプト、バージョン管理、evals、共有は Playground には含まれません。

⚠️ 最重要: 旧 Workbench データのエクスポート期限

2026 年 9 月 1 日

旧 Workbench (legacy) に保存されていたデータのエクスポート期限。それ以降はアクセスできなくなり、復元できません。

旧 Workbench に保存されていたデータは、Console の設定 (https://platform.claude.com/settings/privacy) から JSON 形式でエクスポートできます。手順は以下の通りです。

1

Console のプライバシー設定にアクセスする。

2

[Export Workbench data] ダイアログで、プロンプトに加えて含める内容を選択する。Model completions (過去の実行で保存されたレスポンス) と Uploaded files (プロンプトに添付した画像や PDF) を選択でき、いずれを含めてもエクスポートサイズが大幅に増加する可能性がある。

3

[Export] を選択する。データは JSON 形式でパッケージ化され、準備完了後にダウンロードリンクがメールで届く。

👥

組織全体のエクスポート: Primary Owner または Admin は、組織全体のデータをエクスポートするオプションも利用できます。

🚫

Playground へのインポートは不可: エクスポートした Workbench データを Playground にインポートすることはできません。Playground はプロンプトや会話を保存しないため、インポート先が存在しません。エクスポートはデータのコピーを保持したり、自社のツールへ移行したりするためのものです。

主な変更点

🎛️ 1. Messages API の全パラメータをサポート

Playground は Messages API のすべてのパラメータをサポートします。モデルセレクターで Claude モデルを切り替えられるほか、temperature や最大出力トークン数などをモデル設定から調整できます。同一のプロンプトを異なるモデルや設定で実行し、レスポンスの変化を比較する用途に適しています。

📚 2. API 機能を示すテンプレートを収録

コード実行や Web 検索などの API 機能の使い方を示すテンプレートを、読み込んで編集した上で実行できます。ツール定義を追加してツール使用 (tool use) をテストしたり、構造化出力 (structured outputs) で定義した形式のデータを返させたりすることも可能です。レスポンス内のツール呼び出しとツール結果も表示され、API 上での表現方法を正確に確認できます。

📨 3. 完全な SDK リクエストと API レスポンスの表示

実行ごとに、完全なメッセージ構造、stop reason、usage を含む生の API リクエストとレスポンスを表示します。アプリケーションが実際に送受信するものと同じ形式であり、画面上の表示とコードの挙動が一致します。トークン数と使用量も実行ごとに確認できます。

💻 4. コード生成と「Open in Playground」

「code」トグルをクリックすると、現在のリクエストをコードスニペットとしてエクスポートできます。スニペットは Playground でテストした内容を正確に反映し、自分の API キーでそのまま実行できます。公式ドキュメント内のコード例には「Open in Playground」オプションが追加され、例を Playground に読み込んで実行、編集できます。

🔒 5. ステートレスな設計への転換

Playground はプロンプトや会話を Anthropic のサーバーに保存しません。下書きはブラウザ内に留まり、リクエストのコピーは「code」タブから保持できます。旧 Workbench の保存プロンプト、プロンプトのバージョン管理、プロンプト評価 (evals)、プロンプト共有は Playground には含まれません。

技術詳細: Playground の利用手順

ヘルプセンターに記載されている利用手順は以下の通りです。

1

Claude Console (https://platform.claude.com/) にログインする。

2

ナビゲーションから [Playground] を選択する。

3

組織がワークスペースを使用している場合は、作業するワークスペースを選択する。

4

プロンプト欄にユーザーメッセージを入力する。システムプロンプトの追加も可能。

5

[Run] をクリックしてリクエストを送信する。

6

Claude のレスポンスと、そのリクエストのトークン数、使用量を確認する。

7

プロンプトを編集して再実行し、反復改善する。

コード例

Playground の「code」トグルからエクスポートされるコードスニペットは、画面上で実行したリクエストと同一の内容になります。以下は Web 検索ツールを有効にしたリクエストの例です。

Python code トグルからエクスポートされるスニペットの例 (Web 検索ツール有効) 
# Playground でテストしたリクエストは、code トグルから
# そのまま実行可能なスニペットとしてエクスポートできる
import anthropic

client = anthropic.Anthropic()

response = client.messages.create(
    model="claude-sonnet-4-5",
    max_tokens=1024,
    temperature=1.0,
    system="お客様の質問に日本語で簡潔に回答してください。",
    messages=[
        {
            "role": "user",
            "content": "Anthropic の最新の発表を教えてください。",
        }
    ],
    tools=[
        {
            "type": "web_search_20250305",
            "name": "web_search",
            "max_uses": 3,
        }
    ],
)

# Playground と同様に stop_reason と usage を確認できる
print(f"Stop reason: {response.stop_reason}")
print(f"Usage: {response.usage}")
for block in response.content:
    if block.type == "text":
        print(block.text)

開発者への影響

🎯 対象

  • Claude API を学習中の開発者: 実行ごとに完全な SDK リクエストと API レスポンスが表示されるため、コードを書く前に API の構造を正確に把握できます。
  • 新機能を検証したい開発者: コード実行や Web 検索などのテンプレートから、新しい API 機能を実装前に試せます。
  • プロンプトを反復改善する開発者: モデルやパラメータを切り替えながら同一プロンプトの挙動を比較できます。
  • 旧 Workbench の利用者: 保存プロンプト、履歴、evals が利用できなくなるため、データのエクスポートとワークフローの見直しが必要になります。

🛠️ 必要なアクション

1

旧 Workbench データのエクスポート: 2026 年 9 月 1 日の期限までに、Console のプライバシー設定から保存プロンプト、Model completions、Uploaded files をエクスポートする。期限を過ぎるとデータは復元できない。

2

組織全体のエクスポートの検討: Primary Owner または Admin は、個々のメンバーに任せず組織全体のデータを一括エクスポートすることを検討する。

3

evals ワークフローの代替手段の検討: Playground はプロンプト評価をサポートしないため、旧 Workbench の evals に依存していた場合は代替の評価基盤を用意する。

4

プロンプト管理の移行: サーバー側にプロンプトが保存されなくなるため、プロンプトのバージョン管理はリポジトリなど自社の管理基盤へ移行する。「code」タブからエクスポートしたスニペットをコードとして管理する運用が推奨される。

5

Playground の試用: https://platform.claude.com/playground にアクセスし、テンプレートや SDK リクエスト表示を確認する。

🔄 移行ガイド: Workbench からの運用差分

旧 Workbench から Playground への移行では、以下の差分を前提に運用を組み立てる必要があります。

💾 保存の概念がない

プロンプトの永続化はブラウザ内の下書きとコードエクスポートのみ。継続的に使うプロンプトは、エクスポートしたコードスニペットとしてバージョン管理システムで管理します。

📊 evals の移行

評価が必要な場合は、エクスポートしたプロンプトを自社の評価パイプラインやサードパーティの評価ツールに移します。

🤝 共有の移行

プロンプト共有機能がないため、チーム内の共有はコードリポジトリやドキュメントで行います。

📖 ドキュメントとの連携

公式ドキュメントの「Open in Playground」から例を読み込めるため、学習フローはドキュメント起点に切り替えると効率的です。

ユースケース

🎓 API 構造の学習

コードを書く前にモデルや新しい API 機能を試し、実行ごとに表示される完全な SDK リクエストと API レスポンス (メッセージ構造、stop reason、usage) から、API リクエスト / レスポンスの構造を正確に学べます。

🧪 新機能の実装前検証

コード実行や Web 検索などのテンプレートを読み込んで編集し、ツール定義の追加によるツール使用 (tool use) のテストや、構造化出力 (structured outputs) の形式確認を実装前に行えます。

🔁 プロンプトの反復改善とモデル比較

モデルセレクターと Messages API 全パラメータの調整により、同一のプロンプトを異なるモデルや設定で実行してレスポンスの変化を比較できます。仕上がったリクエストは「code」トグルからスニペットとしてエクスポートし、自分の API キーでそのまま実行できます。

まとめ

2026 年 8 月 18 日の発表により、Claude Console の実験環境は Workbench から Playground へと世代交代しました。

🎯

API との一致性が中心的な価値

Playground は公開 Messages API の上に直接構築されており、画面で組み立てたリクエストとコードから送信するリクエストが同一になります。実行ごとに完全な SDK リクエストと API レスポンスが表示されるため、「Console では動くがコードでは動かない」という乖離が起きにくくなります。

🛤️

学習から実装への導線が整備された

コード実行や Web 検索などのテンプレート、ドキュメントからの「Open in Playground」、code タブからのスニペットエクスポートにより、API 機能の学習、検証、実装コードへの反映が一続きのフローになりました。

⚖️

ステートレス化はトレードオフを伴う

プロンプトや会話がサーバーに保存されないためプライバシー面の懸念は減る一方、保存プロンプト、バージョン管理、evals、共有は失われました。これらに依存していたチームは、コードリポジトリや外部の評価基盤への移行が必要になります。

⏰

最重要の期限は 2026 年 9 月 1 日

旧 Workbench のデータはこの日までしかエクスポートできず、以降は復元不可となります。旧 Workbench を利用していた組織は、期限前に Model completions と Uploaded files を含めたエクスポートの要否を判断し、実行しておくべきです。
