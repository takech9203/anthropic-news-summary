Claude Code v2.1.310 リリース

Monitor ツールの Bedrock / Vertex / Foundry 対応でエンタープライズ環境の機能ギャップを解消

📅 2026-10-24 (CHANGELOG.md 更新日) | ソース: Claude Code Changelog

概要

📡

Monitor ツールがクラウドプロバイダー経由でも利用可能に

Monitor ツールとプラグインモニターが Amazon Bedrock、Google Vertex AI、Microsoft Foundry、およびテレメトリーや非必須トラフィックが無効化された環境でも利用可能になった。

🔁

ゲートウェイ互換性のリトライ対応

effort-2025-11-24 ベータ値や会話途中のシステムメッセージを拒否する一部のゲートウェイ・互換サーバーの背後でリクエストが失敗する問題を修正。これらを除いてリトライするようになった。

🗜️

圧縮とメモリ使用量の信頼性向上

「Prompt is too long」エラー後の圧縮が高密度テキストを残しすぎる問題の修正や、大規模トランスクリプトでの非対話セッションのメモリ使用量改善が含まれる。

🔐

Enterprise カスタムロールで Cloud sessions を制御可能に

Enterprise のカスタムロールに Claude Code クラウドセッションと Remote Control の権限が追加され、Owner がロールごとにアクセスを制御できるようになった。

🌐

各プラットフォームにも広く修正

VSCode 拡張、Cloud sessions、Claude Tag (Slack 連携)、Code Review の各プラットフォームにも修正・改善が及んでいる。

背景: Monitor ツールの対応拡大

Claude Code は、Anthropic API 直接接続だけでなく、Amazon Bedrock、Google Vertex AI、Microsoft Foundry といったクラウドプロバイダー経由でも利用できる。これまで Monitor ツールとプラグインモニターはこれらの環境では利用できなかったが、v2.1.310 で解消された。あわせて、これらの環境では長いフォアグラウンドの sleep もブロックされるようになった。

主要機能・修正

📡 Monitor ツールの対応拡大

Bedrock、Vertex、Foundry 上、およびテレメトリーや非必須トラフィックが無効化された環境でも Monitor ツールとプラグインモニターが利用可能になった。これらの環境では長いフォアグラウンドの sleep もブロックされる。

🔁 ゲートウェイ互換性

effort-2025-11-24 ベータ値や会話途中のシステムメッセージを拒否するゲートウェイ・互換サーバーの背後でリクエストが失敗する問題を修正。これらを除いてリトライするようになった。

🗜️ 圧縮の修正

「Prompt is too long」エラー後の圧縮が、base64 や SVG などの高密度なテキストを含む会話を残しすぎて、次のリクエストが再び失敗し得る問題を修正した。

🧭 auto mode のプロンプト改善

作業ディレクトリ外の最初の読み取り前のプロンプトが、読み取りをブロックするとシェルコマンドが権限を求めるようになる旨を伝えるようになった。

🔐 Enterprise カスタムロール対応

Cloud sessions で、Enterprise のカスタムロールに Claude Code クラウドセッションと Remote Control の権限が追加され、Owner がロールごとにアクセスを制御できるようになった。

技術詳細: 修正

🔧

信頼性に関わる修正

6 件
  • ゲートウェイ互換性: effort-2025-11-24 ベータ値や会話途中のシステムメッセージを拒否する一部のゲートウェイ・互換サーバーの背後でリクエストが失敗する問題を修正。これらを除いてリトライするようになった
  • バックグラウンドクリーンアップ: cleanupPeriodDays を非常に大きな値に設定した場合に、貼り付けた画像などの最近のファイルがバックグラウンドクリーンアップで削除される問題を修正
  • 圧縮: 「Prompt is too long」エラー後の圧縮が、base64 や SVG などの高密度なテキストを含む会話を残しすぎて、次のリクエストが再び失敗し得る問題を修正
  • 権限プロンプト: ファイル読み取りの権限プロンプトがシンボリックリンクの参照先を表示しない問題を修正
  • auto-continue タイムアウト: 長い編集の後に外部エディターを閉じた瞬間に、質問の auto-continue タイムアウトが発火する問題を修正
  • Windowsフック: Git Bash がない環境で、フックのコマンドが引用符付き文字列のみの場合に、PreToolUse と PermissionRequest フックがツール呼び出しを通過させてしまう問題を修正

技術詳細: 改善と動作変更

📈

改善

4 件
  • auto mode のプロンプト: 作業ディレクトリ外の最初の読み取り前のプロンプトが、読み取りをブロックするとシェルコマンドが権限を求めるようになる旨を伝えるようになった
  • メモリ使用量: トランスクリプトファイルが非常に大きい場合の、非対話セッション (-p、Agent SDK) の圧縮時のメモリ使用量を改善
  • mod の Image 描画: allow-passthrough と focus-events が有効な tmux 内で、kitty、Ghostty、iTerm2 3.5 以降において、alt テキストのみが表示されていた問題を改善し、画像が描画されるようになった
  • Linuxサンドボックス診断: /sandbox とサンドボックス起動時の警告が、bubblewrap によるサンドボックス起動を妨げる Ubuntu の AppArmor によるユーザー名前空間の制限と、その解除方法を示すようになった
⚡

動作変更

1 件
  • MCP ツール呼び出しのタイムアウトエラー: 非対話セッションで、サーバーの elicitation が未回答のまま MCP ツール呼び出しがタイムアウトした場合のエラーが変更された。回答が得られなかったこと、および呼び出しを繰り返さないことを Claude に伝えるようになった

プラットフォーム別の修正・改善

💻 VSCode 拡張 2 件

  • プランレビューカードの「Send feedback and keep planning」ボタンで Enter を押すと、コメントを返す代わりにプランを承認してしまう問題を修正
  • Session history の Web タブから開いたクラウドセッションで「Switch branch & continue」の後、パネルに「Something went wrong」と表示される問題を修正

☁️ Cloud sessions 7 件

  • Enterprise のカスタムロールにクラウドセッションと Remote Control の権限が追加され、Owner がロールごとにアクセスを制御できるようになった
  • クラウド環境のセットアップスクリプトをファイルから読み込む Choose file ボタンが追加された
  • クラウド環境の編集ダイアログで、保存やアーカイブの失敗時にダイアログ内にエラーが表示されない問題を修正
  • ルーティンの API トークン操作の失敗がトーストのみで通知される問題を修正。エラーがルーティン編集ダイアログ内に表示されるようになった
  • セッション開始チェックリストが、セットアップスクリプトの出力をスクロールボックスで表示するよう改善された
  • 管理設定で Cloud sessions または Remote Control を有効化する際に確認を求め、その権限を持つカスタムロールを一覧表示するよう変更された
  • クラウド環境ダイアログが、ネットワークアクセス、セットアップスクリプト、環境変数を行から開くよう変更された

💬 Claude Tag (Slack 連携) 3 件

  • !restart や !help などの ! コマンドが、太字・斜体・取り消し線で送信されると通常のメッセージとして扱われる問題を修正
  • バンドルリストのバックグラウンド更新が失敗した際に、管理者のチャンネルページとワークスペースページがロードエラーに置き換えられる問題を修正
  • 管理設定の支出上限ページが、チャンネル名の読み込み中に「フィルターに一致するチャンネルなし」と報告する問題を修正

🔍 Code Review 2 件

  • リポジトリリストの更新に失敗した後、Code Review 管理セクションがリポジトリとスイッチを非表示にする問題を修正
  • Code Review 管理セクションが初回ロードをリトライし、それでも失敗した場合に 1 つの Try again バナーを表示するよう改善された

開発者への影響と必要なアクション

対象: Amazon Bedrock / Google Vertex AI / Microsoft Foundry 経由で Claude Code を利用しているエンタープライズユーザー、テレメトリーや非必須トラフィックを無効化して運用している組織、ゲートウェイや互換サーバーの背後で利用しているチーム、-p や Agent SDK による非対話セッションを大規模トランスクリプトで実行しているユーザー、Cloud sessions / Claude Tag / Code Review を利用している組織の管理者。

1

アップデートの適用

claude update または npm 経由で v2.1.310 に更新する。

2

Bedrock / Vertex / Foundry 環境での Monitor 利用

これまで利用できなかった Monitor ツールとプラグインモニターが使えるようになったため、監視を前提としたワークフローの導入を検討できる。あわせて、長いフォアグラウンドの sleep がブロックされるようになった点に注意する。

3

cleanupPeriodDays の設定確認

非常に大きな値を設定していた環境では、最近のファイルが誤削除される問題が修正されたため、意図どおりの保持期間になっているか確認する。

4

Enterprise 管理者: 権限設計の見直し

カスタムロールで Cloud sessions と Remote Control のアクセスをロール単位で制御できるようになったため、権限設計の見直しを検討する。

移行ガイド: 注意すべき動作の変化

  • 破壊的変更はない
  • Bedrock / Vertex / Foundry およびテレメトリー無効環境では、Monitor 関連機能の有効化と長いフォアグラウンド sleep のブロックという動作の変化がある

ユースケース

🏢 クラウドプロバイダー経由のエンタープライズ運用

Amazon Bedrock、Google Vertex AI、Microsoft Foundry 経由で Claude Code を利用している組織では、これまで使えなかった Monitor ツールとプラグインモニターが利用可能になる。テレメトリーを無効化した環境でも同様に使えるため、監視を前提としたワークフローをエンタープライズ環境に導入できる。

🔀 ゲートウェイの背後での安定運用

effort-2025-11-24 ベータ値や会話途中のシステムメッセージを拒否するゲートウェイ・互換サーバーの背後で運用しているチームでは、これまで失敗していたリクエストが自動的にリトライされるようになり、ゲートウェイ起因の失敗が減少する。

🤖 Agent SDK による大規模な非対話実行

-p や Agent SDK で大規模トランスクリプトの非対話セッションを実行しているユーザーは、圧縮時のメモリ使用量改善と「Prompt is too long」エラー後の圧縮修正により、長時間のバッチ処理やエージェント実行の安定性が向上する。

まとめ

v2.1.310 は、Monitor ツールとプラグインモニターの Bedrock / Vertex / Foundry 対応を中心に、エンタープライズ環境での機能ギャップを埋めるリリースである。

ゲートウェイ互換性のリトライ対応、圧縮の修正、Windows フックのフェイルオープン修正など、運用の信頼性に関わる修正も多い。クラウドプロバイダー経由で Claude Code を利用している組織や、ゲートウェイの背後で運用しているチームには特に有益なアップデートである。
