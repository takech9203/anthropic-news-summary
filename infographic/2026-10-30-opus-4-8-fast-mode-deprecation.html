Claude API 廃止予定

Claude Opus 4.8 のファストモード非推奨化

2026 年 11 月 30 日に削除、Claude Opus 5.5 への移行が必要

📅 発表日: 2026-10-30 | ソース: Claude API Release Notes

⏰

移行期限: 2026 年 11 月 30 日 (残り約 1 か月)

削除後、claude-opus-4-8 への speed: "fast" リクエストはエラーを返します。標準速度へのフォールバックは行われません。

概要

🚫

Opus 4.8 のファストモードが非推奨に

2026 年 10 月 30 日、Claude Opus 4.8 (claude-opus-4-8) の speed: "fast" パラメータが非推奨 (deprecated) となりました。リサーチプレビューのまま GA には至りませんでした。

📅

削除予定日は 2026 年 11 月 30 日

約 1 か月の移行期間中は引き続き動作しますが、削除日以降は該当リクエストがエラーになります。早期の移行が推奨されます。

⚠️

フォールバックなしでエラーを返す

Claude Opus 4.6 のときのような標準速度へのフォールバックは行われません。エラーハンドリングのないアプリケーションは、削除日以降にリクエストが失敗するリスクがあります。

✅

推奨移行先は Claude Opus 5.5

Opus 5.5 のファストモードは 2026 年 10 月 15 日に GA 済み。ベータヘッダー不要で、Start / Build / Scale ティアにデフォルトのレート制限が付与されます。

💰

移行で 20% のコスト削減

Opus 5.5 のファストモード価格は入力 $8 / 出力 $40 (MTok あたり) で、Opus 4.8 の $10 / $50 より 20% 安価です。

Before / After 比較

Before: Opus 4.8 ファストモード

  • ❌ リサーチプレビュー (非推奨、2026-11-30 削除)
  • ❌ ベータヘッダー fast-mode-2026-02-01 が必要
  • ❌ レート制限はアクセス申請が必要
  • ❌ 入力 $10 / 出力 $50 (MTok あたり)
  • ❌ Claude API のみ対応

After: Opus 5.5 ファストモード

  • ✅ GA (一般提供、2026-10-15 から)
  • ✅ ベータヘッダー不要 (送信しても影響なし)
  • ✅ Start / Build / Scale ティアにデフォルト付与
  • ✅ 入力 $8 / 出力 $40 (20% 安価)
  • ✅ Claude API、Google Cloud、Microsoft Foundry 対応

主な変更点

🚫 ファストモード非推奨化

claude-opus-4-8 に対する speed: "fast" パラメータ (ベータヘッダー fast-mode-2026-02-01 付き) が非推奨となりました。エイリアスとスナップショット版の両方が対象です。

⏳ 約 1 か月の移行期間

2026 年 11 月 30 日までは引き続き動作します。該当アプリケーションを運用している開発者は、期限までに計画的な移行が必要です。

❌ 削除後はエラーを返す

削除日以降、該当リクエストはエラーになります。Opus 4.6 のような標準速度へのフォールバック (usage.speed が "standard" で成功) は行われません。

🎯 推奨移行先は Opus 5.5

Opus 5.5 のファストモードは GA 済みで、ベータヘッダーなしで利用可能。約 3 週間のリサーチプレビューを経て 2026 年 10 月 15 日に GA に到達しました。

削除後の挙動に関する注意

  • ファストモード非対応モデルへの speed: "fast" リクエストは、原則としてエラーを返します
  • Claude Opus 4.6 のみ例外的に標準速度で成功 (usage.speed は "standard") しますが、Opus 4.8 は削除後この例外に該当しません
  • ファストモードは Batch API および Priority Tier では利用できません
  • 速度設定が異なるリクエスト間ではプロンプトキャッシュが共有されない点に注意が必要です

移行手順 (2026 年 11 月 30 日まで)

1

影響範囲の特定

コードベース内で claude-opus-4-8 と speed: "fast" の組み合わせを使用している箇所を洗い出す

2

モデル ID の更新

claude-opus-4-8 を claude-opus-5-5 に変更する

3

ベータヘッダーの削除

fast-mode-2026-02-01 ヘッダーは Opus 5.5 では不要 (残しても動作はする)

4

動作確認

Opus 5.5 のファストモードで期待通りの動作と出力品質を確認する

5

レート制限の確認

Start / Build / Scale ティアのデフォルトのファストモードレート制限が要件を満たすか、Claude Console の Rate limits ページで確認する

6

コストの再見積もり

ファストモード価格が $10 / $50 から $8 / $40 (入力 / 出力、MTok あたり) に下がるため、予算を再計算する

移行時の注意事項

  • Opus 5.5 のファストモードは GA 済みのため、リサーチプレビュー時のようなアクセス申請は不要です
  • Evaluation ティアの組織は Start / Build / Scale ティアへの移行後に利用可能になります
  • speed: "fast" パラメータ自体の仕様変更はありません
  • ファストモードから標準速度へフォールバックする実装では、プロンプトキャッシュがヒットしなくなる点に注意してください

コードサンプル: 移行例

Python 変更前 (2026 年 11 月 30 日以降エラーが発生) 
import anthropic

client = anthropic.Anthropic()

# 2026 年 11 月 30 日以降、このリクエストはエラーを返します
response = client.messages.create(
    model="claude-opus-4-8",
    speed="fast",
    max_tokens=4096,
    extra_headers={"anthropic-beta": "fast-mode-2026-02-01"},
    messages=[
        {
            "role": "user",
            "content": "このモジュールを依存性注入を使うようにリファクタリングしてください。"
        }
    ]
)
Python 変更後 (推奨) 
import anthropic

client = anthropic.Anthropic()

# ベータヘッダーは不要になりました
response = client.messages.create(
    model="claude-opus-5-5",
    speed="fast",
    max_tokens=4096,
    messages=[
        {
            "role": "user",
            "content": "このモジュールを依存性注入を使うようにリファクタリングしてください。"
        }
    ]
)

# 実際に使用された速度を確認できます ("fast" または "standard")
print(response.usage.speed)

開発者への影響 / 対象ユースケース

🖥️ Opus 4.8 ファストモードを利用中のアプリケーション

claude-opus-4-8 に対して speed: "fast" を指定しているすべてのアプリケーションが直接影響を受けます。コードベース内の該当箇所を洗い出し、2026 年 11 月 30 日までにモデル ID を claude-opus-5-5 に変更してください。

⚡ 高い OTPS に依存するストリーミング / リアルタイムシステム

ファストモードの最大 2.5 倍の出力トークン毎秒 (OTPS) に依存するシステムは、削除後にエラーが発生するとサービス停止につながります。エラーハンドリングの実装と Opus 5.5 への早期移行が重要です。

🧪 リサーチプレビュー参加者

ベータヘッダー fast-mode-2026-02-01 を付与して Opus 4.8 のリサーチプレビューに参加していた開発者は、Opus 5.5 ではヘッダーなしで GA 版を利用できます。アクセス申請も不要になり、運用が簡素化されます。

まとめ

📌

残り約 1 か月の移行期間

Opus 4.8 のファストモードは 2026 年 11 月 30 日に削除され、以降はエラーを返します。移行はモデル ID の変更とベータヘッダーの削除のみで完了するため、負担は小さいと言えます。該当するアプリケーションを運用している開発者は、早急に移行計画を策定し、テスト環境での動作確認を開始してください。
