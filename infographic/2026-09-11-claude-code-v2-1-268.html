v2.1.268 90 件超の変更 ゲートウェイ管理 + セキュリティ強化

概要 — キーポイント

💰

Claude apps gateway の pricing 対応

gateway.yaml に pricing: を設定すると、サインイン済みの Claude Code クライアントが管理対象設定経由で同じレートを受け取り、/cost とテレメトリの表示がゲートウェイの支出メーターと一致するようになった。allow_cidrs 未設定時の起動時警告や gatewayInternalNetworks 管理対象設定も追加された。

🔒

権限チェックとセキュリティの集中修正

シンボリックリンクされたディレクトリ (macOS の /etc、/tmp、/var、Linux の /bin) に対する deny / ask ルールのバイパス、env -C や eval 同居時の deny ルールバイパス、エラー表示へのトークン・パスワード露出などが修正された。

🛠️

サードパーティ互換エンドポイントの HTTP 400 リグレッション修正

v2.1.265 以降、ANTHROPIC_BASE_URL で指定したサードパーティの Anthropic 互換エンドポイントで全ターンが HTTP 400 で失敗していた問題を修正。互換エンドポイント経由の利用者には必須のアップデート。

⏱️

WebFetch に 300 秒デッドラインを導入

応答を返さないサーバーで WebFetch が無限にハングする問題を修正。フェッチは 300 秒で失敗するようになり、CLAUDE_CODE_WEBFETCH_DEADLINE_MS で上書き可能 (0 で無効化)。

⚡

CPU 使用率と安定性の改善

長時間のアイドルセッションでビジーループが CPU コアを占有し続ける問題を修正。フルスクリーンモードの描画高速化、--continue / --resume の高速化など、90 件超の変更を含む大型リリース。

背景 — リリースの位置づけ

前バージョンは 2026 年 9 月 9 日リリースの v2.1.267 で、プロンプトキャッシュ安定性の大幅改善と maxEffortLevel 設定の追加を中心としたリリースだった。v2.1.268 はその流れを引き継ぎつつ、エンタープライズ向けのゲートウェイ管理機能と、権限システムの抜け穴をふさぐセキュリティ修正に重点を置いている。

また、v2.1.265 以降、Artifact ツールの入力スキーマに含まれる正規表現をサードパーティの Anthropic 互換エンドポイント (ANTHROPIC_BASE_URL) が拒否し、すべてのターンが HTTP 400 で失敗するリグレッションが発生していた。v2.1.268 ではこの問題が修正されており、互換エンドポイント経由の利用者にとっては必須のアップデートとなる。

主要変更

💰 gateway pricing 対応 New

gateway.yaml の pricing: 設定がサインイン済みクライアントに管理対象設定経由で伝搬し、/cost とテレメトリの金額がゲートウェイの支出メーターと一致する。コスト管理の一貫性が向上する。

🔒 権限ルールバイパスの修正 Security

シンボリックリンクディレクトリの実パス経由アクセスや、env -C / eval を同一行に含むコマンドで deny / ask ルールが適用されない問題を修正。防御が意図どおり機能するようになる。

🙈 シークレットの露出防止 Security

プラグイン / マーケットプレイスのエラーが git ソース URL 内のトークンやパスワードを表示する問題と、/mcp や claude mcp list などが ${VAR} から解決されたシークレットを表示する問題を修正。

⏱️ WebFetch デッドライン Fixed

応答を開いたまま完了しないサーバーでの無限ハングを解消。300 秒 (5 分) で失敗するようになり、CLAUDE_CODE_WEBFETCH_DEADLINE_MS でミリ秒単位の上書きが可能 (0 で無効化)。

⚡ CPU 使用率の修正 Fixed

長時間のアイドルセッションでビジーループが CPU コアを占有し続ける問題と、セッションリキャップ中の高頻度なターミナルフォーカス通知が CPU 使用率を高止まりさせる問題を修正。

🛠️ 互換エンドポイントの HTTP 400 修正 Fixed

v2.1.265 以降のリグレッションを修正。原因は Artifact ツールの入力スキーマ内の正規表現をサードパーティエンドポイントが拒否していたこと。ANTHROPIC_BASE_URL 利用者には必須の更新。

🔒 権限ルールバイパスの修正

今回修正された権限まわりの問題は、いずれも「ルールの記述と実際のパス・コマンドの解釈のずれ」に起因する。(1) シンボリックリンクの二重経路: macOS では /etc、/tmp、/var が、Linux では /bin がシンボリックリンクである。deny / ask ルールをリンク側のパスで書いても実パス (例: /private/etc) でアクセスされると適用されず、逆に Bash コマンドがリンク側の表記で書かれた deny ルールを無視するケースがあった。v2.1.268 では双方向で一致が取られる。(2) 解析不能コマンドの同居: env -C や eval のように権限チェッカーが静的に解析できないコマンドが同一行にあると、Read / Edit の deny ルールが適用されないケースがあった。deny ルールで機密ファイルへのアクセスを制限している環境では、これらの修正によって想定どおりの防御が機能するようになるため、早期の更新が推奨される。

❌ v2.1.268 以前

シンボリックリンク側のパスで書いた deny ルールが実パス (例: /private/etc) 経由のアクセスに適用されない。env -C や eval を同一行に含むコマンドで Read / Edit の deny ルールがバイパスされる。エラー表示にトークンやパスワードが露出する。

✅ v2.1.268 以降

シンボリックリンクと実パスの双方向で一致が取られ、deny / ask ルールが意図どおり適用される。解析不能コマンド同居時のバイパスも修正され、シークレットはエラー表示から除去される。防御が想定どおり機能する。

⏱️ WebFetch のデッドライン

応答を開いたまま完了しないサーバーに対して WebFetch が無限に待ち続ける問題への対策として、300 秒 (5 分) のデッドラインが導入された。環境変数 CLAUDE_CODE_WEBFETCH_DEADLINE_MS でミリ秒単位の上書きが可能で、0 を設定するとデッドラインを無効化できる。あわせて、localhost などドットを含まないホスト名に対するエラーメッセージも、拒否の理由と curl の利用を提案する内容に改善された。

📋 タスク管理ツールのモデル限定

TaskCreate / TaskGet / TaskUpdate / TaskList および TodoWrite は、Claude 3.x、Opus 4.0–4.7、Sonnet 4.0–4.6、Haiku 4.5 に限定して提供されるようになった。これらより新しいモデルではタスク管理が別の仕組みで扱われるためと考えられる。従来の動作に依存するワークフローがある場合は、環境変数 CLAUDE_CODE_ENABLE_TODO_TOOLS=1 で対象外のモデルでも有効化できる。

コード例

Claude apps gateway で pricing を設定し、クライアントの /cost と一致させる例。

YAML gateway.yaml — pricing の設定 
# gateway.yaml
pricing:
  # モデルごとのレートを定義すると、サインイン済みの
  # Claude Code クライアントに管理対象設定経由で伝搬する
  claude-opus-4-6:
    input_per_mtok: 5.00
    output_per_mtok: 25.00

access_control:
  # 空のままにすると起動時に警告が表示される
  allow_cidrs:
    - 10.0.0.0/8

WebFetch のデッドラインを調整する例。

Bash WebFetch デッドラインの調整 
# デッドラインを 10 分に延長
export CLAUDE_CODE_WEBFETCH_DEADLINE_MS=600000

# デッドラインを無効化 (従来の動作に戻す)
export CLAUDE_CODE_WEBFETCH_DEADLINE_MS=0

タスク管理ツールを対象外のモデルでも有効化する例。

Bash タスク管理ツールの有効化 
export CLAUDE_CODE_ENABLE_TODO_TOOLS=1

💡 具体的なユースケース

🏢 組織のコスト管理を一元化する

Claude apps gateway を運用する組織では、gateway.yaml の pricing: にモデルごとのレートを定義することで、ゲートウェイの支出メーターとクライアントの /cost 表示・テレメトリが同一のレートで計算される。管理者とユーザーの間でコストの認識が一致し、予算管理や配賦がしやすくなる。

🔒 機密ファイルの防御を確実にする

deny ルールで /etc や機密ディレクトリへのアクセスを制限している環境では、シンボリックリンクの実パス経由や env -C / eval 同居によるバイパスが修正されたことで、想定どおりの防御が機能するようになる。セキュリティを重視する組織では早期の更新が推奨される。

🤖 CI / 自動化パイプラインからの CLI 制御

claude plugin install / uninstall / update / enable / disable の --json 対応と、claude auth status --json の configDirectory 追加により、スクリプトからプラグイン管理や認証状態の確認を機械可読な形式で行える。CI 環境のセットアップや自動化が容易になる。

🔀 移行ガイド — 注意すべき動作変更

破壊的変更はアナウンスされていないが、以下の動作変更に注意が必要である。

🌐 WebFetch ルールで Artifact を制御していた場合

プレーンな WebFetch の deny / ask ルールは Artifact ツールの読み取り・更新に適用されなくなった。引き続きブロックやゲートが必要な場合は、Artifact ルールまたは WebFetch(domain:claude.ai) に書き換える。

📋 タスク管理ツールを新しいモデルで使う場合

TaskCreate / TaskGet / TaskUpdate / TaskList と TodoWrite が提供されるモデルが限定された。対象外のモデルで必要な場合は CLAUDE_CODE_ENABLE_TODO_TOOLS=1 を設定する。

⏱️ WebFetch で 5 分を超える取得を行う場合

300 秒のデッドラインが導入されたため、必要に応じて CLAUDE_CODE_WEBFETCH_DEADLINE_MS で延長するか、0 で無効化する。

✅ 承認スキップ設定のローカル Cowork セッション

Artifact ツールがセッションフォルダ外やシンボリックリンク越しのローカルファイルを確認なしに読み取らなくなった。該当ファイルを扱うワークフローは動作を確認する。
