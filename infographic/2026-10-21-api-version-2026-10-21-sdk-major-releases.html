API 更新

API version 2026-10-21 リリースと SDK/CLI メジャーバージョン公開

新 API バージョンをデフォルト送信する全 SDK/CLI のメジャーアップデート — 複数の破壊的変更と Apache 2.0 へのライセンス変更を含む大規模な節目

📅 2026-10-21 | ソース: Claude API Release Notes | カテゴリ: API 更新

概要

Anthropic は 2026 年 10 月 21 日、新しい API バージョン 2026-10-21 をリリースしました。あわせて、この新バージョンをデフォルトで送信するクライアント SDK と ant CLI のメジャーバージョンが公開されました。

🏷️

新 API バージョン 2026-10-21

Messages API のサンプリングパラメータ削除、assistant メッセージ内 document ブロックのエラー化、Admin API のフィールド名整理など、複数の破壊的変更が適用されます。

📦

全 SDK/CLI のメジャーバージョン公開

Python 2.0.0、TypeScript 1.0.0、C# 13.0.0、Go 2.0.0、Java 3.0.0、PHP 1.0.0、Ruby 2.0.0 と ant CLI 2.0.0 が公開され、デフォルトで 2026-10-21 を送信します。

🔑

認証ヘッダーの統一

SDK/CLI は API キーを X-Api-Key ではなく Authorization: Bearer ヘッダーで送信するようになりました。プロキシやゲートウェイの対応が必要です。

📜

ライセンスを Apache 2.0 に変更

新バージョン以降、SDK と CLI のライセンスが MIT License から Apache License, Version 2.0 に変更されました。旧バージョンは MIT のままです。

🛡️

ユーザープロファイルに enforcement フィールド追加

enforcement_status と enforcement_actions フィールドが追加され、Anthropic がエンドカスタマーを制限または BAN したかどうかを確認できるようになりました。

背景

従来の SDK と CLI は、すべてのリクエストで anthropic-version: 2023-06-01 ヘッダーを送信していました。今回のメジャーバージョンアップにより、各言語の SDK と ant CLI は Amazon Bedrock および Google Cloud クライアントを含め、デフォルトで 2026-10-21 を送信するようになります。

Before (旧 SDK/CLI)

  • anthropic-version: 2023-06-01 を送信
  • API キーは X-Api-Key ヘッダー
  • temperature / top_p / top_k を指定可能
  • ライセンスは MIT License

After (新メジャー版)

  • anthropic-version: 2026-10-21 をデフォルト送信
  • API キーは Authorization: Bearer ヘッダー
  • サンプリングパラメータ送信は 400 エラー
  • ライセンスは Apache License 2.0

公式の移行ガイド「Migrating to API version 2026-10-21」でアップグレード手順が案内されています。

主な変更点

🏷️ API バージョン 2026-10-21

破壊的変更

Messages API でのサンプリングパラメータ削除、assistant メッセージ内 document ブロックと user メッセージ内 citations のエラー化、Admin API / Enterprise Analytics API の旧フィールド名削除が適用されます。

📦 SDK/CLI メジャーリリース

新バージョン

7 言語の SDK と ant CLI の新メジャーバージョンが公開されました。新 API バージョンのデフォルト送信に加え、API バージョンに依存しない破壊的変更も含まれます。

🔑 認証方式の変更

破壊的変更

API キーを Authorization: Bearer で送信。クライアントは 1 つの資格情報のみ保持し、CLI の --api-key / --auth-token フラグは削除されました。

📜 ライセンス変更

MIT → Apache 2.0

新バージョン以降の SDK と CLI は Apache License, Version 2.0 になります。コード変更は不要ですが、依存関係のライセンス管理をしている場合は更新が必要です。

🛡️ enforcement フィールド

新機能

ユーザープロファイルに enforcement_status と enforcement_actions が追加され、プロファイル一覧 API の enforcement_status[] フィルタで制限 / BAN 中のプロファイルを検索できます。

詳細 1: API バージョン 2026-10-21 の破壊的変更

移行ガイドによると、Messages API (トークンカウント、Message Batches 内の各リクエストを含む) では以下の変更が適用されます。

  • assistant メッセージ内の document ブロックがエラーに: assistant メッセージに直接 document ブロックを配置したリクエストは 400 エラーを返します。ドキュメントは user メッセージで送信する必要があります。Web フェッチツール結果など、別のブロック内にネストされたドキュメントは引き続き受け付けられます
  • user メッセージ内の citations がエラーに: user メッセージ内の text ブロックに空でない citations 配列を送信すると 400 エラーを返します。assistant メッセージ内の citations や、ドキュメント・検索結果に対する "citations": {"enabled": true} 設定は引き続き有効です
  • サンプリングパラメータの削除: temperature、top_p、top_k を送信すると、デフォルト値であっても 400 エラーを返します。これらを省略した場合はデフォルト値 (temperature は 1.0) でサンプリングされます。非デフォルト値に依存するリクエストは、パラメータの送信を止めるか、2023-06-01 に留まる必要があります

🗂️ Admin API / Claude Enterprise Analytics API のフィールド名変更

リネームされたフィールドの旧名称がレスポンスから削除されます。

詳細 3: API バージョン非依存の SDK/CLI 破壊的変更

移行ガイドの「SDK and CLI changes」セクションによると、以下の変更が含まれます。

  • MessageParam のロール別分割: 従来は全ロール共通だった MessageParam 型が、UserMessageParam、AssistantMessageParam、SystemMessageParam に分割されました。BetaMessageParam も同様に分割されます。送信される JSON のフィールドと値は従来と同じです
  • 単一値 enum の定数化: C#、Go、Java、PHP、Ruby SDK において、1 つの値しか取れない必須フィールドが enum 型から定数に変更されました
  • ツールランナーのクライアント側コンパクション削除: TypeScript と Ruby SDK で、クライアント側コンパクションが削除され、API 内部で会話を要約するサーバー側コンパクションに置き換えられました
  • Text Completions API の削除: レガシーの Text Completions API が TypeScript、Go、Java、Ruby SDK と CLI から削除されました。Messages API を使用します
  • 非ベータ Models メソッドから betas を削除: ベータヘッダーを送信するには client.beta.models 側のメソッド、または CLI の ant beta:models を使用します
  • API キーを Authorization: Bearer ヘッダーで送信: SDK/CLI は API キーを X-Api-Key ヘッダーではなく Authorization: Bearer <key> で送信するようになりました。X-Api-Key を読み取る、または設定するプロキシやゲートウェイは Authorization を使用するよう変更が必要です。Claude API 自体はどちらのヘッダーのキーも受け付けます
  • クライアントは 1 つの資格情報のみ保持: API キーと認証トークンがヘッダーを共有するため、SDK クライアントは 1 つの資格情報のみを保持します。複数を渡すとエラーになります
  • CLI の --api-key / --auth-token フラグ削除: コマンドラインの値はシェル履歴やプロセス一覧に表示されるため削除されました。代わりに環境変数 ANTHROPIC_API_KEY / ANTHROPIC_AUTH_TOKEN、--api-key-stdin / --auth-token-stdin、または ant auth login を使用します
  • CLI の Go モジュールパス変更: go install の場合、モジュールパスが github.com/anthropics/anthropic-cli/v2 になりました

詳細 4: ライセンス変更 (MIT → Apache 2.0)

新バージョン以降、SDK と CLI のライセンスは MIT License から Apache License, Version 2.0 に変更されました。旧バージョンは引き続き MIT License のままです。

📜

コード変更は不要ですが、依存関係のライセンスを追跡している場合はエントリの更新が必要です。TypeScript のプラットフォームパッケージ (@anthropic-ai/bedrock-sdk など) と C# の関連パッケージ (Anthropic.Bedrock など) はそれぞれの 1.0.0 リリースでライセンスが変更されます。

詳細 5: ユーザープロファイルの enforcement フィールド追加

ユーザープロファイルに enforcement_status と enforcement_actions フィールドが追加され、Anthropic がエンドカスタマーを制限または BAN したかどうかを確認できるようになりました。

🔍

制限または BAN が有効なプロファイルを探すには、プロファイル一覧 API で新しい enforcement_status[] フィルタを使用します。

技術詳細

SDK を使用している場合、リクエストにはその SDK のメジャーバージョンがリリースされた時点の API バージョンが使用されます。SDK を使わずに API を直接呼び出す場合は、anthropic-version ヘッダーに 2026-10-21 を設定します。

Bash anthropic-version ヘッダーの指定例 
curl https://api.anthropic.com/v1/messages \
  -H "x-api-key: $ANTHROPIC_API_KEY" \
  -H "anthropic-version: 2026-10-21" \
  -H "content-type: application/json" \
  -d '{
    "model": "claude-opus-5-5",
    "max_tokens": 1024,
    "messages": [{"role": "user", "content": "Hello, Claude"}]
  }'

コード例

CLI の認証フラグは削除されたため、環境変数または標準入力を使用します。

Bash CLI 認証方法の移行 
# Before (v1 まで)
ant --api-key "$KEY" models list

# After: 環境変数から
export ANTHROPIC_API_KEY="$KEY"
ant models list

# After: シークレットマネージャーから
op read op://vault/anthropic/api-key | ant --api-key-stdin models list

Go で CLI をインストールする場合はモジュールパスに /v2 を追加します。

Bash Go モジュールパスの変更 
# Before
go install 'github.com/anthropics/anthropic-cli/cmd/ant@latest'

# After
go install 'github.com/anthropics/anthropic-cli/v2/cmd/ant@latest'

開発者への影響

🎯 対象

📦 SDK / CLI 利用者

Claude API を SDK (Python、TypeScript、C#、Go、Java、PHP、Ruby) または ant CLI 経由で利用しているすべての開発者が対象です。

🎛️ サンプリングパラメータ利用アプリ

temperature、top_p、top_k などのサンプリングパラメータを使用しているアプリケーションは、新バージョンでは 400 エラーになるため影響評価が必要です。

🌐 プロキシ・ゲートウェイ運用者

X-Api-Key ヘッダーを読み取る、または設定するプロキシ・ゲートウェイの運用者は、Authorization: Bearer への対応が必要です。

🗂️ Admin API / Enterprise Analytics API 利用コード

Admin API や Claude Enterprise Analytics API のレスポンスフィールドを読み取るコードは、旧フィールド名の削除に対応する必要があります。

📜 ライセンス管理組織

依存関係のライセンスを管理している組織は、MIT から Apache 2.0 への変更を反映する必要があります。

✅ 必要なアクション

  1. 移行ガイドの確認: Migrating to API version 2026-10-21 で自分のコードに影響する破壊的変更を確認する
  2. サンプリングパラメータの削除: リクエストから temperature、top_p、top_k を削除する。非デフォルト値に依存する場合は影響を評価する
  3. SDK/CLI のアップグレード: 各言語の新メジャーバージョンにアップグレードし、型変更 (MessageParam の分割など) に対応する
  4. プロキシ・ゲートウェイの更新: X-Api-Key ではなく Authorization: Bearer ヘッダーを処理するよう変更する
  5. ライセンス情報の更新: 依存関係のライセンス管理をしている場合、MIT から Apache 2.0 への変更を反映する

まとめ

API version 2026-10-21 のリリースと全 SDK/CLI のメジャーバージョンアップは、Claude API の大規模な節目となる更新です。サンプリングパラメータの削除、認証ヘッダーの Authorization: Bearer への統一、Admin API のフィールド名整理など、複数の破壊的変更が含まれるため、開発者は移行ガイドに沿った計画的なアップグレードが必要となります。

ライセンスの Apache 2.0 への変更はコード変更を伴いませんが、ライセンス管理をしている組織は更新が求められます。また、ユーザープロファイルの enforcement_status フィールドにより、エンドカスタマーに対する Anthropic の制限・BAN 状態をプログラムから確認できるようになり、プラットフォーム運用者の安全管理が強化されました。
