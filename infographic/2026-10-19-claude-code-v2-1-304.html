✨ 新機能

🧭 /auto-mode-setup の追加

プロジェクトと最近のセッションを読み取り、auto モードに利用環境を学習させるガイド付きセットアップ。Amazon Bedrock、Google Vertex AI、Microsoft Foundry、Claude apps gateway、テレメトリ無効のセッションでも利用できる。

🔐 /claude-api managed-agents-secure

Managed Agents のエージェント設定を Anthropic 公開のセキュリティガイドと比較するコマンド。設定の変更は行わず、確認のみを実施する。

⏱️ Pro / Max プランの使用量警告

非アクティブな会話の再開が 5 時間の使用量制限の相当な割合を消費する場合に警告を表示。そのまま再開するか、新しい会話を開始するかを選択でき、新しい会話でも前の会話を参照すれば Claude が内容を調べられる。

🧩 Mod (プラグイン) 向け API の強化

  • tool.check の応答に decider: "person" を追加。許可ダイアログまたはホストのコールバックのみが承認でき、誰にも確認できない場合は Mod の理由とともに拒否される
  • tool.check イベントに、読み取り専用かどうかを示す e.isReadOnly を追加
  • settings.read フックが各設定レイヤーを受け取り、マージ後の設定を書き換え可能に。管理対象の Mod が組織設定を上限として扱える
  • 先行プラグインが自分の Mod のフックをスキップした場合、イベント名とプラグイン名をトランスクリプトに表示

📜 コンパクション要約へのツール名表示

トランスクリプトビュー (Ctrl+O) のコンパクション要約に、それまでに呼び出されたツール名が表示されるようになった。

🔍 Code Review のレビューレベル

Owner が組織に対して Quick / Standard (デフォルト) / Deep の 3 段階を選択でき、リポジトリごとに個別のレベルも設定可能。GitHub 組織の全リポジトリ (後から追加されたものを含む) を個別選択なしでレビュー対象にするオプションも管理設定に追加された。

🖥️ VSCode 拡張の Mod 描画対応

Bedrock、Vertex AI、Foundry 上のセッション、LLM ゲートウェイ経由、テレメトリ無効時でも、チャットパネルで Mod の描画が利用できるようになった。

⚡ 改善

🤖 サブエージェント並列実行時の性能: 多数のサブエージェントが同時に動作する際の応答性とスループットが向上
🧠 メモリ使用量: 長い会話や再開した会話でリクエストを送信する際のメモリ使用量が改善
📉 セッションファイルサイズ: auto モードで安全性分類器のコンテキストをリクエストごとに保存しなくなり、ファイルサイズが削減
🚀 大型セッションの再開: SDK / ヘッドレスモードでコンパクション済みの大きなセッションを再開した際、最初のリクエストがより早く送信される
☁️ Cloud sessions の初回ターン: 最初のターンが claude.ai から同期されたプラグインのローカル (stdio) MCP サーバーを待たなくなった (alwaysLoad: true のサーバーを除く)
🚪 ゲートウェイ互換性: カスタム ANTHROPIC_BASE_URL 使用時にツール検索がデフォルト有効になり、400 / 422 時はツール検索なしで再試行
🪟 Windows の git 起動: cmd ランチャーを経由せず git.exe を直接実行するようになり、起動が高速化
📈 /usage の表示: 使用量データのレート制限時に、制限の終了時刻を表示するようになった

🐛 主なバグ修正 (40 件超)

データ損失、セキュリティ、互換性に関わる主要なものは以下のとおり。

🌳 worktree のコミット消失防止データ損失: claude --worktree が、HEAD がデタッチ状態または別ブランチにある場合でも、終了時に確認なしで worktree とブランチを削除し、コミットを失う可能性があった問題を修正
📝 トランスクリプトのメッセージ欠落データ損失: CLAUDE_CODE_TRANSCRIPT_LOCAL_GC によるファイル整理中にディスクが満杯になると、保存済みトランスクリプトからメッセージが欠落する問題を修正
💾 マウントドライブ削除時の安全確認安全性: /Volumes、/media、WSL の /mnt/c などマウントされたドライブやその直下のフォルダに対する rm -r で、安全確認プロンプトが表示されなかった問題を修正
🏢 組織ポリシーの反映遅延: 起動時に ANTHROPIC_API_KEY を承認した後や /config で「Use custom API key」を切り替えた後、組織ポリシーが毎時チェックまで更新されなかった問題を修正
🛑 ヘッドレス実行の制御: プラグインがサブエージェントの生成や完了済みエージェントの再実行によって、--max-turns、Stop、入力終了を超えてヘッドレス実行を継続させてしまう問題を修正
📦 サンドボックスの起動失敗: sandbox.filesystem.denyRead の glob に文字クラスではないブラケット (ルートフォルダ名の [user-id] など) が含まれると、Linux でサンドボックス化されたコマンドが起動に失敗する問題を修正
🚪 LLM ゲートウェイの互換性: context_management: Extra inputs are not permitted エラーが発生した場合、そのフィールドなしでリクエストを再送するよう修正
📡 OpenTelemetry 設定の無視: 初回セットアップ中や /logout 後の初回起動時にサインインすると、サーバー管理設定で配信された OpenTelemetry 設定がセッション全体で無視される問題を修正
🪝 フック拒否理由の上書き: 同じツール呼び出しに対する Agent SDK のコールバックフックがタイムアウトした際、PreToolUse フックの拒否理由がタイムアウトエラーで置き換えられてしまう問題を修正
🗑️ コマンド出力ファイルの削除: 大きなコマンド出力のファイルがセッションのツール結果フォルダにコピーできなかった場合に、Bash / PowerShell がそのファイルを削除してしまう問題を修正 (ディスク満杯時を除く)
🤖 サブエージェントの作業内容の消失: 完了直後にメッセージ送信や再開を行うと、サブエージェントが直近の作業内容を忘れることがある問題を修正
ℹ️ このほか、Remote Control の起動・履歴取得、コンパクション後の「Context limit reached」エラー、CLAUDE_CODE_AUTO_COMPACT_WINDOW の k / M サフィックス解釈、/effort の表示、agent teams のシャットダウン時の CLI 終了など、30 件以上の修正が行われている。

📦 アップデートの適用

claude update または npm 経由で v2.1.304 に更新する。worktree 削除やトランスクリプト欠落などデータ損失に関わる修正が含まれるため、早期の適用を推奨する。

Bash アップデートコマンド

# auto モードのガイド付きセットアップ
claude
> /auto-mode-setup

# Managed Agents 設定のセキュリティ確認
> /claude-api managed-agents-secure

🧩 Mod 開発者

decider: "person"、e.isReadOnly、レイヤー対応になった settings.read フックを確認し、必要に応じて権限制御ロジックを見直す。1 ソースあたりのスキルフック数は 1,024 件、マッチャー文字数は 16,384 文字に制限された。

⚙️ 環境変数の確認

CLAUDE_CODE_AUTO_COMPACT_WINDOW が k / M サフィックスを正しく解釈するようになったため、200k のような指定が意図どおり動作するか確認する。

🧭 auto モード利用者

/auto-mode-setup を実行すると、プロジェクトに合わせた auto モードの設定を対話的に行える。

🔄 移行ガイド

破壊的変更はなし。ただし以下の動作変更に注意

  • カスタム ANTHROPIC_BASE_URL 使用時、ツール検索がデフォルトで有効になった
  • コンパクション後にスキルリストが再送されるようになり、/reload-skills は新規または変更されたスキルのみを送信する
  • プラグイン以外のフックを禁止するポリシー下では、メイン会話で使用されたスキルのフックが除外される場合、そのスキルの allowed-tools も付与されない

📝 まとめ

v2.1.304 は、/auto-mode-setup や Code Review のレビューレベルなどの新機能に加えて、worktree のコミット消失やトランスクリプト欠落といったデータ損失リスクの修正、エンタープライズ環境での互換性改善を幅広く含む重要なリリースである。特に worktree や LLM ゲートウェイを利用している開発者は、早めのアップデートが望ましい。
