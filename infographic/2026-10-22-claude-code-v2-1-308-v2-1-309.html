サンドボックス・権限チェックの修正

🛡️

権限境界に関わる修正

12 件
  • macOS と Linux で、サンドボックス化された Bash コマンドが各コマンドの前にシェルの起動ファイルをサンドボックス外で実行していた問題を修正
  • macOS サンドボックスの denyWrite glob パターンが、パターンのフォルダーにシンボリックリンク経由で到達した場合に実際のパスへ適用されない問題を修正
  • サンドボックス化されたコマンドと自動承認された編集が、--mcp-config で渡された MCP 設定ファイルを変更できてしまう問題を修正
  • 失敗し得るリダイレクトを持つコマンドが設定した変数を、Bash 権限チェックが信頼してしまう問題を修正
  • cd がラップまたはプレフィックスされた複合コマンドで、git 実行前のディレクトリ変更に対して権限チェックがプロンプトを出さない問題を修正 (素の cd と同様に扱われる)
  • Edit(path) の deny ルールが、サブシェルを含む一部のコマンドで同パスへの Bash リダイレクトをブロックしない問題を修正
  • ワークツリー分離セッションで、分離ガードが拒否すべきロケールプレフィックス付きコマンドや、zsh の算術コマンドの一部を受け入れていた問題を修正
  • Claude Code が作成するワークツリーとブランチチェックアウトが git replace refs を無視するよう修正 (他の git 操作と同様)
  • 設定ディレクトリにシンボリックリンク経由で到達した場合に、プロファイルストアの書き込み保護が適用されない問題を修正
  • 無効化された MCP サーバーが、print / SDK セッションで後続の権限プロンプトによって再接続されてしまう問題を修正
  • Linuxバックグラウンドコマンドがセッションより長く生存した場合に、サンドボックスの書き込み拒否が解除されてしまう問題を修正
  • Windows現在のディレクトリを対象とし追加の引数を持つ一部の Set-Location / cd コマンドを、PowerShell 権限チェックが自動承認していた問題を修正 (承認プロンプトが表示されるようになった)

動作変更

⚡

スクリプト・自動化に影響する変更

6 件
  • sed -i: シミュレートされたファイル編集プレビューではなく、標準の Bash プロンプトを受けて書かれたとおりに実行されるようになった。他の Bash 編集と同様、/rewind では復元されない
  • claude ultrareview: ワークスペーストラストが必須になった。ターミナルでは確認を求め、それ以外では拒否される。スクリプトでは --trust-workspace フラグ (値を取らない。PR 番号やベースブランチはその前に置く) を渡すか、CLAUDE_CODE_DISABLE_ULTRAREVIEW_TRUST_CHECK=1 を設定する
  • bypass permissions モードでの rm / rmdir: デスクトップアプリと VS Code では、危険な rm / rmdir のプロンプトが即座に拒否され、書き換えのヒントが示されるようになった。無人セッションが停止しなくなる
  • サンドボックス除外コマンド: サンドボックスが有効だが実行できない場合、設定でサンドボックスから除外されたコマンドは write-list パスへの書き込み前に確認を求め、サンドボックスなしのフォールバックは拒否される
  • ワークツリーの作成と再利用: git がオンデマンドでオブジェクトをフェッチしなくなった。Bash サンドボックスが設定された partial clone では、先にオブジェクトをフェッチする
  • /claude-api スキル: Managed Agents のサブエージェントチームを、coordinator ではなくダイナミックワークフローがデフォルトで有効な multiagent_20261001 で構築するようになった

開発者への影響と必要なアクション

対象: Claude Code CLI / VSCode 拡張 / Cloud sessions / 自己ホスト型ランナーのすべてのユーザー。特にサンドボックスや権限ルール (denyWrite、Edit(path) deny、ワークツリー分離など) で運用するエンタープライズ管理者、claude ultrareview を CI から実行するチーム、Windows / PowerShell でフック・プラグイン・スキルを開発するユーザー、Slack 連携や Code Review を利用する組織。

1

アップデートの適用

claude update または npm 経由で v2.1.309 に更新する。権限境界のバイパスに関わる修正が多数含まれるため、サンドボックスや deny ルールに依存して運用している環境では早期の適用を推奨する。

2

claude ultrareview を使うスクリプトの更新

ワークスペーストラストが必須になったため、非対話実行では --trust-workspace フラグの追加、または CLAUDE_CODE_DISABLE_ULTRAREVIEW_TRUST_CHECK=1 の設定が必要になる。

3

sed -i を含むワークフローの確認

sed -i はファイル編集プレビューではなく通常の Bash コマンドとして実行され、/rewind で復元されなくなった。編集の巻き戻しに依存している場合は Edit ツールの利用を検討する。

4

Windows / PowerShell フックの確認

終了コード 2 でのブロックが正しく機能するようになったため、フェイルオープンを前提としていたフックの挙動を確認する。

5

bypass permissions モードの無人運用

デスクトップアプリと VS Code では危険な rm / rmdir が即時拒否されるようになったため、削除を伴う自動化タスクは挙動の変化に注意する。

移行ガイド: 注意すべき動作変更

  • claude ultrareview は、ターミナル以外ではワークスペーストラストなしに実行できなくなった
  • sed -i は書かれたとおりに実行され、/rewind の対象外になった
  • サンドボックスが有効だが実行できない環境では、サンドボックス除外コマンドの write-list パスへの書き込みに確認が入り、サンドボックスなしのフォールバックは拒否される

ユースケース

🏢 deny ルールで統制するエンタープライズ環境

機密ディレクトリへの書き込みを denyWrite や Edit(path) の deny ルールで禁止している組織では、シンボリックリンクやサブシェル経由のリダイレクトでルールを回避できていた経路が塞がれる。ガードの網羅性が高まるため、権限境界を前提とした運用の安全性が直接向上する。

🤖 CI での自動コードレビュー運用

claude ultrareview を CI スクリプトから実行しているチームは、ワークスペーストラスト必須化により非対話実行が拒否されるようになる。--trust-workspace フラグの追加または環境変数の設定でパイプラインを更新することで、信頼していないワークスペースでの意図しない実行を防ぎつつ自動レビューを継続できる。

🌙 bypass permissions モードでの無人バッチ処理

夜間バッチなどの無人セッションで bypass permissions モードを使う場合、デスクトップアプリと VS Code では危険な rm / rmdir が即時拒否され、プロンプト待ちでセッションが停止しなくなる。削除を伴うタスクは書き換えのヒントに沿った安全なコマンドへの移行を検討する。

まとめ

v2.1.309 は、シンボリックリンク、サブシェル、複合コマンドなどを経由した権限境界のバイパスを塞ぐセキュリティ強化が中心の大型保守リリースである。サンドボックスや deny ルールを前提に Claude Code を運用している組織にとって重要度が高く、早期のアップデートが望ましい。

あわせて、claude ultrareview のトラスト必須化や sed -i の扱いの変更など、スクリプトや自動化に影響する動作変更が含まれるため、CI などの非対話実行環境では事前の確認が必要である。

v2.1.308 は「Bug fixes and reliability improvements」のみの詳細非公表の保守リリースである。
