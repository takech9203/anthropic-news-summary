概要

Claude Code v2.1.294 と v2.1.295 がリリースされました。v2.1.294 は instructions 形式 (自然言語で書く) の prompt/agent hook の判定を改善する 2 件のみの小規模リリース、v2.1.295 は 143 件 (追加 17 件、修正 97 件、改善 13 件、変更 16 件) を含む大規模リリースです。2 バージョン合計の変更件数は 145 件に上ります。

🚫

hook に onFailure: "block" が追加 (v2.1.295)

command hook と HTTP hook に onFailure: "block" が追加され、hook が起動できない・タイムアウトする・予期しない終了コードで終わる場合に、アクションを素通りさせるのではなくブロックできるようになりました。ガードレールとして hook を使う場合の信頼性が大きく向上します。

🖥️

Program Status Protocol (OSC 7501) 対応 (v2.1.295)

対応するターミナルは、Claude Code が「作業中」「ユーザー待ち」「完了」のいずれの状態かを表示できるようになりました。複数セッションの並行運用で各セッションの状態をターミナル側の UI だけで把握できます。

🏢

Claude apps gateway の大幅強化 (v2.1.295)

timeouts.upstream_ttfb_ms によるストリーム開始時間の制限、upstream ごとの models リストによるモデルの振り分け、監査イベントへの upstream_request_id の追加など、エンタープライズ向けの多数の強化が行われました。

🔧

instructions 形式で書かれた prompt/agent hook が本来ブロックすべきものを許可してしまう問題を修正。Stop / SubagentStop の判定も改善され、Claude が早期に停止しにくくなりました。

1. v2.1.294: instructions 形式 hook の判定改善 (2 件)

  • 🚦 prompt/agent hook のブロック判定の修正 「〜するコマンドをブロックする」のような instructions 形式で書かれた prompt/agent hook が、本来ブロックすべきものを許可してしまう問題を修正しました。
  • 🛑 Stop / SubagentStop での判定改善 「ビルドが壊れていたら続行する」のような instructions 形式で書かれた Stop / SubagentStop の prompt hook の判定が改善され、Claude が早期に停止しにくくなりました。

自然言語で hook を記述するスタイルを使っているチームにとって、ガードレールと停止判定の両面で実効性が高まる修正です。

2. v2.1.295: hook の onFailure: "block" の追加

command hook と HTTP hook に onFailure: "block" オプションが追加されました。これを指定した hook は、以下の場合にアクションを通過させずブロックします。

  • ❌ hook が起動できない場合
  • ⏱️ hook がタイムアウトした場合
  • ⚠️ hook が予期しない終了コードで終わった場合
💡 fail-open から fail-close へ

従来は hook 自体の失敗時にアクションが素通りしていたため、セキュリティやポリシーの強制を hook に依存する構成では「hook が壊れたら無防備になる」という弱点がありました。fail-close な運用が可能になったことで、ガードレール用途での hook の信頼性が大きく向上します。

3. v2.1.295: Program Status Protocol (OSC 7501) 対応

Program Status Protocol (OSC 7501) のサポートが追加されました。このプロトコルを実装するターミナルは、Claude Code が以下のいずれの状態にあるかを表示できます。

⚙️ 作業中

working

⏳ ユーザーの入力待ち

waiting on you

✅ 完了

done

複数のセッションやウィンドウを並行運用する場合に、ターミナル側の UI だけで各セッションの状態を把握できるようになります。

技術的な詳細

🚫 onFailure: "block" による fail-close な hook 運用

従来の command / HTTP hook は、hook 自体が失敗した場合 (起動不能、タイムアウト、予期しない終了コード) にアクションを通過させる fail-open の挙動でした。onFailure: "block" を指定すると、hook の失敗時にアクションがブロックされる fail-close の挙動になります。

    Failure -->|未設定| Pass["⚠️ アクションは通過"]
    Failure -->|block| Block["🚫 アクションをブロック"]

また、inference 監査イベントの upstream_request_id とレスポンスの request-id ヘッダーにより、「Claude Code テレメトリ → ゲートウェイ監査ログ → upstream (Bedrock / Anthropic API) のリクエスト ID」という 3 層のトレーサビリティが揃いました。

コード例

command hook に onFailure: "block" を指定する settings.json の例です。hook が起動できない、タイムアウトする、または予期しない終了コードで終わった場合に、アクションは通過せずブロックされます。

JSON settings.json での onFailure: "block" の指定例 
{
  "hooks": {
    "PreToolUse": [
      {
        "matcher": "Bash",
        "hooks": [
          {
            "type": "command",
            "command": "/path/to/guard-script.sh",
            "onFailure": "block"
          }
        ]
      }
    ]
  }
}

✅ 必要なアクション

  • 🛡️ hook でポリシーを強制しているチーム セキュリティ上重要な command / HTTP hook には onFailure: "block" の指定を検討します。従来は hook の失敗時にアクションが素通りしていました。
  • 🏢 ゲートウェイ管理者 upstream に models リストと timeouts.upstream_ttfb_ms を設定し、モデルルーティングと応答開始時間を明示的に管理できます。Bedrock でのトークンカウント改善を使うには bedrock:CountTokens を付与します。
  • ⏲️ 無人運用の利用者 CLAUDE_CODE_RETRY_WATCHDOG_MAX_WAIT_MS で 429 / 529 エラーの待機時間に上限を設けられます。
  • 🧩 モッド開発者 guard hook が切り詰められた入力を見ていた問題が修正されたため、深くネストした入力を扱う guard の挙動を再確認します。通知には $.ui.notify を利用できます。

🚧 移行ガイド (該当する場合)

⚠️ 注意が必要な挙動変更

破壊的変更はありませんが、以下の挙動変更に注意が必要です。

  • claude.ai コネクタの MCP プロトコル交渉がデフォルトで 2026-07-28 になりました。問題がある場合は MCP_PROTOCOL_NEGOTIATION=legacy で以前の挙動に戻せます
  • サブエージェントのスキルのプリロードが最大 32 個に制限されました。多数のスキルを指定している場合は、Skill ツール経由の呼び出しに切り替わります
  • WebSocket MCP サーバーで 16 MiB 超のメッセージは接続が閉じられるようになりました
  • ゲートウェイ経由のバックグラウンドリクエストが Haiku 4.5 を使うようになったため、ゲートウェイで Haiku 4.5 を提供しているか確認します (未提供の場合はセッションのモデルにフォールバック)

まとめ

Claude Code v2.1.294 と v2.1.295 は、合計 145 件の変更からなるリリース群です。v2.1.294 は instructions 形式の prompt/agent hook の判定を改善する 2 件に絞ったリリースで、自然言語で書いたガードレールの実効性と Stop 判定の精度を高めました。

v2.1.295 は 143 件の大規模リリースで、hook の onFailure: "block" による fail-close なガードレール運用、Program Status Protocol (OSC 7501) によるターミナルでのセッション状態表示、そして timeouts.upstream_ttfb_ms・upstream ごとの models リスト・upstream_request_id を中心とする Claude apps gateway の大幅強化が柱となります。修正面でも、context-1m ベータ拒否時の [1m] モデル全リクエスト失敗、claude -p の出力欠落、リモート MCP の再接続、ターミナルのフリーズといった実運用に効く問題が多数解消されました。hook によるポリシー強制やゲートウェイ運用を行うエンタープライズ環境を中心に、幅広い利用者に更新を推奨できるリリースです。
