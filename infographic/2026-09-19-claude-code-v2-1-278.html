Claude Code v2.1.278

auto mode 分類器がサーバーサイド実行をデフォルト化し、分類器オーバーヘッドが課金対象外に

📅 2026-09-19 (npm 公開日時: 2026-09-19 01:48 UTC) ｜ ソース: Claude Code Changelog

概要

Claude Code v2.1.278 では、auto mode の安全性分類器の実行方法が変更され、サーバーサイド分類器がデフォルトになりました。サーバーが分類チェックを実行する場合、分類器のオーバーヘッドは課金されません。

🖥️

サーバーサイド分類器がデフォルトに

Claude API・Enterprise ユーザー、および Bedrock、Vertex、Foundry、ゲートウェイ上のセッションで、auto mode の安全性分類器がサーバー上で実行されるようになりました。

💰

分類器オーバーヘッドが課金対象外に

サーバーが分類チェックを実行する場合、分類器のオーバーヘッドは課金されません。追加の設定なしで v2.1.278 以降に適用されます。

⚠️

課金されるフォールバック時は警告を表示

サーバーのチェックがセッションに届かず、従来どおり課金されるクライアント側分類器にフォールバックする場合、事前に通知が表示されるため、意図しない課金に気付けます。

🔍

/status に Auto mode server 行を追加

現在のセッションの auto mode 分類器がサーバー上で実行されているかどうかを確認できます。サーバーのチェックが判定している間は Enabled、フォールバック後は Disabled と表示されます。

🔧

環境変数でオプトアウト可能

Bedrock、Vertex、Foundry、ゲートウェイでは CLAUDE_CODE_AUTO_MODE_SERVER=0 を設定することでオプトアウトできます。

Before / After: 分類器の実行場所と課金

auto mode では、シェルコマンドやネットワークリクエストなどのアクションを実行する前に、分類器が安全性チェックを実行します。v2.1.278 でその実行場所と課金の扱いが変わりました。

Before (v2.1.278 より前)

  • 分類器リクエストはクライアント (Claude Code) 側で実行
  • 分類器のオーバーヘッドがトークン使用量として課金される
  • 分類器の実行場所を確認する手段がない

After (v2.1.278 以降)

  • セッション自身のモデルリクエストの一部としてサーバーにチェックを依頼
  • サーバーがチェックを実行した場合は課金されない
  • /status の Auto mode server 行で実行場所を確認できる
  • フォールバック時 (従来どおり課金) は事前に警告を表示

主な変更点

🖥️ サーバーサイド分類器がデフォルトに

Claude API・Enterprise ユーザー、および Bedrock、Vertex、Foundry、ゲートウェイ上の auto mode が、サーバーサイド分類器をデフォルトで使用するように変更されました。サーバーがチェックを実行する場合、分類器オーバーヘッドは課金されません。

🔧 オプトアウト用の環境変数

Bedrock、Vertex、Foundry、ゲートウェイでは CLAUDE_CODE_AUTO_MODE_SERVER=0 を設定することでオプトアウトできます。

⚠️ 課金されるフォールバック時の警告表示

サーバーのチェックがセッションに届かず、従来どおり課金されるクライアント側分類器にフォールバックする場合、警告 (通知) が表示されます。

🔍 /status に Auto mode server 行を追加

セッションの auto mode 分類器がサーバー上で実行されているかどうかを表示します。サーバーのチェックがセッションのアクションを判定している間は Enabled、フォールバック後は Disabled と表示されます。

技術的な詳細

公式ドキュメント (auto mode classifier billing) で確認できた動作の詳細は以下のとおりです。

📢 通知の表示条件

⚠️ フォールバック時に表示される通知

サーバーのチェックがセッションに届かなくなった後、最初にチェック対象となるアクションの実行前にアクションを保留し、次の通知を表示します。

We're changing auto mode to no longer charge for classifier requests in Claude Code. However, this session isn't eligible.

Enter キーで続行: 保留中のアクションとそのセッションの残りは、従来どおり課金される Claude Code 自身の分類器リクエストを使用します。
Esc または Ctrl+C でキャンセル: 保留中のアクションは実行されず現在のターンが停止します (セッションは auto mode のまま)。

  • 👥 通知が表示される対象 サーバーサイドチェックは Enterprise プランと Claude API を使用するアカウント、および Claude Platform on AWS、Amazon Bedrock、Google Cloud の Agent Platform、Microsoft Foundry でデフォルトで要求されます。実際にチェックが実行されるかは、各プラットフォームやリージョンのロールアウト状況に依存します。Pro、Max、Team プランではこの通知は表示されません。
  • 🔀 フォールバックの主な原因 Claude Code と API の間にある LLM ゲートウェイやプロキシが、リクエストヘッダーを削除・書き換えたり、認識しないリクエストフィールド (safeguards など) を破棄したり、レスポンスのキー (safeguard_results など) を削除したりすると、サーバーのチェックがセッションに届かなくなります。ゲートウェイを特定できた場合、通知にはその名前が表示され、確認 (acknowledge) するとそのマシンでは 24 時間再表示されません。
  • 🚪 オプトアウト ゲートウェイがサーバーのチェックを提供できないことが分かっている場合、セッション開始前に CLAUDE_CODE_AUTO_MODE_SERVER=0 を設定すると、分類器リクエストは常に Claude Code 自身のものとなり (従来どおり課金)、通知は表示されません。この変数は Anthropic API への直接接続では読み取られません。また、CLAUDE_CODE_AUTO_MODE_SERVER 未設定時に CLAUDE_CODE_DISABLE_EXPERIMENTAL_BETAS=1 を設定した場合も、サーバーのチェックは無効になります。なお、CLAUDE_CODE_AUTO_MODE_SERVER は一時的な設定であり、将来のリリースで削除される可能性があります。
  • 🤖 非対話モードでの挙動 -p を使用する非対話モードでは通知テキストを stderr に出力し、stream-json 出力では system 警告メッセージとして出力されます。Agent SDK アプリケーションはメッセージストリームからこれを読み取れます。

💻 オプトアウトの設定例

Bash サーバーサイドチェックを利用できない環境でのオプトアウト 
export CLAUDE_CODE_AUTO_MODE_SERVER=0

開発者への影響

🎯 対象

  • Claude API または Enterprise プランで Claude Code の auto mode を使用しているユーザー
  • Amazon Bedrock、Google Cloud の Agent Platform (Vertex)、Microsoft Foundry、LLM ゲートウェイ経由で Claude Code を使用しているユーザー
  • LLM ゲートウェイやプロキシを運用している管理者

💰 コスト面への影響

ケース 影響
課金の削減 サーバーが分類チェックを実行する環境では、auto mode の分類器オーバーヘッドが課金されなくなります。追加の設定なしで v2.1.278 以降に適用されます。
フォールバック時 サーバーのチェックがセッションに届かない場合 (ゲートウェイによるヘッダー・フィールドの改変、プラットフォームやリージョンの未対応など) は、従来どおり Claude Code 自身の分類器リクエストがトークン使用量として課金されます。この場合は事前に通知が表示されるため、意図しない課金に気付けます。
Pro、Max、Team プラン これらのプランでは通知は表示されません。

ユースケース / 必要なアクション

👤 一般ユーザー: 特別な対応は不要

特別な対応は不要です。auto mode 使用中に /status の Auto mode server 行で、分類器がサーバー上で実行されているか確認できます。

🌐 ゲートウェイ運用者: パススルーの確認

サーバーサイドチェックを利用するには、safeguards リクエストフィールドや safeguard_results レスポンスフィールドを含め、リクエスト・レスポンスを改変せずにパススルーする必要があります。詳細はゲートウェイ互換性ガイドを参照してください。

🚪 サーバーサイドチェックを利用できない環境: オプトアウト

ゲートウェイがチェックを提供できないことが分かっている場合は、セッション開始前に export CLAUDE_CODE_AUTO_MODE_SERVER=0 を設定してオプトアウトできます。分類器リクエストは常に Claude Code 自身のものとなり (従来どおり課金)、通知は表示されません。

まとめ

Claude Code v2.1.278 は、auto mode の安全性分類器をサーバーサイド実行にデフォルトで切り替え、分類器オーバーヘッドの課金をなくすコスト面で重要なアップデートです。対象は Claude API・Enterprise ユーザーおよび Bedrock、Vertex、Foundry、ゲートウェイ上のセッションで、サーバーのチェックが届かない場合は通知の上で従来どおり課金されるフォールバックに切り替わります。/status の Auto mode server 行と CLAUDE_CODE_AUTO_MODE_SERVER=0 により、状態の確認とオプトアウトが可能になっています。
