概要: キーポイント

v2.1.301 は、無人運用 (CI やリトライウォッチドッグ) や可観測性 (OpenTelemetry) を重視する組織向けの機能追加と、ターミナル互換性やモデル切り替えまわりの安定性修正が中心の大規模メンテナンスリリースである。

⏱️

新環境変数 CLAUDE_CODE_RETRY_WATCHDOG_MAX_USAGE_LIMIT_WAIT_MS

無人リトライモードで、使用量制限のリセットが遠すぎる場合に待機せずリクエストを終了できるようになった。

⌨️

vim モードの強化

対応する括弧へジャンプする % モーションの追加に加え、Escape 後に INSERT モードに留まる問題や AskUserQuestion の回答が破棄される問題を修正。

📊

OpenTelemetry イベントの拡充

tool_decision イベントに classifier_verdict、permission_mode、classifier_category が追加され、auto モードの分類器判断と権限ルールを区別可能になった。

🛟

モデルエイリアスのフォールバック

fable および best エイリアスが、最新の Fable モデルを利用できない組織でもエラーにならず、前世代の Fable モデルで 1 回リトライするようになった。

📝

コンテキストウィンドウ縮小時の挙動改善

小さいコンテキストウィンドウのモデルへ切り替える際、長すぎる会話は切り替え前のモデルが先に要約するようになった。

主要機能: 新機能 (Added) 6 件

⏱️ リトライ待機の上限設定

CLAUDE_CODE_RETRY_WATCHDOG_MAX_USAGE_LIMIT_WAIT_MS を追加。無人リトライモード (CLAUDE_CODE_RETRY_WATCHDOG) で、リセットが遠すぎる使用量制限に当たった場合、待機せずリクエストを終了する。

📡 OpenTelemetry トレーシングガイド

claude-api スキルに OpenTelemetry トレーシングのガイダンスを追加。ant CLI によるトレース送信先の設定方法を含む。

⌨️ vim モードの % モーション

対応する括弧へのジャンプが可能に。単独でも d/c/y との組み合わせでも使用できる。

📝 mod の複数行入力

mod の Input に rows を追加。ターミナル上で複数行のテキストフィールドを表示でき、Enter で送信、Shift+Enter または Enter 前のバックスラッシュで改行する。

🏷️ tool_decision イベントの属性追加 1

classifier_verdict と permission_mode を追加。auto モードの分類器による判断と権限ルールによる判断を区別できる。

🏷️ tool_decision イベントの属性追加 2

OTEL_LOG_TOOL_DETAILS=1 のとき、分類器ブロックが一致した組み込みルール名を示す classifier_category を追加。

修正: モデル・API まわり (4 件)

  • fable (および best) モデルエイリアスが、組織で最新の Fable モデルを利用できない場合に Anthropic API 上でエラーになる問題を修正。前世代の Fable モデルで 1 回リトライする
  • 小さいコンテキストウィンドウのモデルへ切り替えた際、確認なしに前のモデルによる要約で使用量クレジットを消費することがあるケースを修正

  • モデル名に application-inference-profile を含むモデルへの切り替え時、プロバイダーが Bedrock でないのに awsAuthRefresh コマンドが実行され、モデル切り替えフックが遅延する問題を修正

  • mod の $.env.set: 変数の設定または解除が完了すると {} で解決し、書き込みが行われない場合は理由を示す { deny } で解決するよう変更

技術詳細 1: 無人リトライモードの待機制御

従来、CLAUDE_CODE_RETRY_WATCHDOG による無人リトライモードでは、使用量制限に達するとリセット時刻まで待機し続けていた。新しい環境変数により、待機時間の上限をミリ秒単位で指定できる。CI パイプラインなど時間制約のある環境で、ジョブが長時間ハングすることを防止できる。

Bash リトライ待機の上限設定 
# 使用量制限のリセットまで 30 分を超える場合はリクエストを終了する
export CLAUDE_CODE_RETRY_WATCHDOG=1
export CLAUDE_CODE_RETRY_WATCHDOG_MAX_USAGE_LIMIT_WAIT_MS=1800000

技術詳細 2: OpenTelemetry tool_decision イベントの拡充

ツール実行の許可・拒否イベントに新しい属性が追加され、判断の由来を分析できるようになった。権限ルールによるブロックと auto モード分類器によるブロックを監視基盤上で区別でき、組織のガバナンス運用やルールチューニングに活用できる。

属性 内容 条件
classifier_verdict auto モード分類器の判定結果 常時
permission_mode 判断時の権限モード 常時
classifier_category 分類器ブロックが一致した組み込みルール名 OTEL_LOG_TOOL_DETAILS=1

技術詳細 3: モデル切り替え時のコンテキスト処理フロー

コンテキストウィンドウの小さいモデルへの切り替え時の挙動が改善された。あわせて、確認なしに要約で使用量クレジットが消費されるケースも修正されており、意図しないコスト発生を防ぐ設計になっている。

コード例

無人リトライモードと OpenTelemetry の詳細収集を組み合わせた設定例。

Bash 環境変数の設定と実行例

claude -p "リポジトリのテストを実行して結果を報告してください"

ユースケース

🤖 CI / 無人運用でのリトライ制御

リトライウォッチドッグに待機時間の上限を設定することで、使用量制限のリセットが遠すぎる場合に待機せずリクエストを終了できる。CI パイプラインなど時間制約のある環境で、ジョブが長時間ハングすることを防止できる。

📊 OpenTelemetry によるガバナンス運用

tool_decision イベントの新属性により、権限ルールによるブロックと auto モード分類器によるブロックを監視基盤上で区別できる。組織のガバナンス運用やルールチューニングに活用できる。

🛟 モデル提供状況が異なる組織での継続利用

fable / best エイリアスのフォールバックにより、最新の Fable モデルが組織で未提供でもエラーにならず、前世代の Fable モデルで継続利用できる。

開発者への影響: 対象

  • CI / 無人運用で Claude Code を使用する開発者: リトライウォッチドッグの待機上限設定が利用可能
  • OpenTelemetry で Claude Code を監視する組織: tool_decision イベントの新属性により権限判断の分析が向上
  • vim モードのユーザー: % モーション追加と INSERT モード残留・回答破棄の修正により操作性が向上
  • fable / best エイリアスのユーザー: 最新モデルが組織で未提供でもフォールバックにより継続利用可能
  • mods / スキル / ワークフローの開発者: .catch の挙動変更、$.env.set の戻り値変更、複数行 Input への対応が必要または利用可能
  • 古いターミナル環境 (RHEL 8 など) や iTerm2 のユーザー: 表示崩れの修正
  • VS Code / JetBrains 拡張のユーザー: LaTeX レンダリング、パフォーマンス改善

開発者への影響: 必要なアクション

通常の利用では自動更新により適用されるため、特別な対応は不要。手動更新する場合は claude update を実行する。

  • 無人運用で使用量制限の長時間待機を避けたい場合は、CLAUDE_CODE_RETRY_WATCHDOG_MAX_USAGE_LIMIT_WAIT_MS を設定する
  • OpenTelemetry で classifier_category を収集したい場合は、OTEL_LOG_TOOL_DETAILS=1 を設定する
  • mod 開発者は、フックの .catch ハンドラーがフック自身の throw / タイムアウト時のみ実行される新しい挙動と、$.env.set の戻り値 ({} または { deny }) を前提にコードを確認する
Bash 手動更新コマンド 
claude update

移行ガイド: mod 開発者向けの注意点

破壊的変更は少ないが、mod 開発者は以下の 2 点に注意が必要である。

  • .catch の実行条件の変更: フックの呼び出し配下で発生したイベントでは .catch が呼ばれなくなった。配下イベントのエラー処理に .catch を利用していた場合は、処理の見直しが必要
  • $.env.set の戻り値: 設定・解除の完了時は {}、書き込みが行われない場合は理由付きの { deny } で解決する。戻り値を参照している mod は新形式に対応する

まとめ

Claude Code v2.1.301 は、無人運用の制御性 (リトライ待機上限)、可観測性 (OpenTelemetry イベント拡充)、操作性 (vim モード強化)、安定性 (モデルエイリアスのフォールバック、ターミナル互換性修正) を幅広く強化したリリースである。特に CI や監視基盤と組み合わせて Claude Code を運用する組織にとって有用な改善が多い。

mod 開発者は .catch と $.env.set の挙動変更を確認のうえ、既存 mod の互換性を検証することが推奨される。
