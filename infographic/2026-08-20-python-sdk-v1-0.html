SDK メジャーリリース 破壊的変更

Python SDK v1.0 リリース: httpx2 への移行と非推奨機能の削除を伴うメジャーアップデート

📅 2026-08-20 | ソース: Claude Developer Platform Release Notes

長らく 0.x 系で提供されてきた anthropic Python SDK の初のメジャーバージョン。HTTP レイヤーの httpx2 への移行、Python 3.10+ 必須化、レガシー Text Completions API や旧サンプリングパラメータの削除など、複数の破壊的変更を含む基盤刷新のリリースです。

概要 / キーポイント

2026 年 8 月 20 日、Anthropic は Python SDK (anthropic) の v1.0 をリリースしました。新機能の追加ではなく、基盤の刷新と負債の整理に焦点を当てたメジャーリリースであり、安定した基盤の上でセマンティックバージョニングを開始します。

🔌

HTTP レイヤーが httpx から httpx2 へ移行

最大の変更点。httpx2 は Pydantic チームがメンテナンスする API 互換フォークで、プレーンな値 (timeout=30.0 など) を渡しているユーザーは変更不要です。カスタム http_client やトランスポートを構築している場合は httpx2 からのインポートが必要になります。

🐍

Python 3.10 以降が必須

サポートする Python の最低バージョンが 3.9 から 3.10 に引き上げられました。それ以外のランタイム要件は変わらず、Pydantic は v1 / v2 の両方が引き続きサポートされます。

🗑️

長期間非推奨だった API を削除

レガシーの Text Completions API、Messages メソッドの temperature / top_p / top_k パラメータ、ツールランナーのクライアントサイド compaction_control などが削除されました。

☁️

AnthropicBedrock のリージョン必須化

AWS リージョン未設定時に us-east-1 へ暗黙にフォールバックする挙動が廃止され、構築時に ValueError を送出するようになりました。boto3 プロファイルからのリージョン解決が新たにサポートされます。

🔍

型チェッカーで破壊的変更の大半を検出可能

公式の v1 移行ガイド (MIGRATION.md) にすべての変更点が移行前後のコードスニペット付きで記載されています。アップグレード後に pyright や mypy を実行すると、破壊的変更の大半を検出できます。

背景

Python SDK は 0.x 系のまま長期間運用されてきましたが、その間に非推奨化された API サーフェス (Text Completions API、サンプリングパラメータの直接指定など) が蓄積していました。

また、SDK が依存する HTTP ライブラリ httpx は活発なメンテナンスが行われなくなっており、Pydantic チームが API 互換フォークとして httpx2 (https://httpx2.pydantic.dev) の保守を引き継いでいます。v1.0 は、これらの負債を一括で整理し、安定した基盤の上でセマンティックバージョニングを開始するためのメジャーリリースです。

Before / After: v0.x → v1.0 の破壊的変更

Before: v0.x

  • HTTP レイヤーは httpx (メンテナンス停滞)
  • Python 3.9 をサポート
  • Text Completions API (client.completions.create) が利用可能
  • Messages メソッドで temperature / top_p / top_k を直接指定可能
  • 非同期の with_raw_response は response.parse() を同期呼び出し
  • AnthropicBedrock はリージョン未設定時に警告を出して us-east-1 にフォールバック
  • ツールランナーはクライアントサイドの compaction_control

After: v1.0

  • HTTP レイヤーは httpx2 (Pydantic チームが保守する API 互換フォーク)
  • Python 3.10 以降が必須。Pydantic v1 / v2 は継続サポート
  • Text Completions API は削除。Messages API に一本化
  • temperature / top_p / top_k は削除。旧モデル利用時は extra_body で指定
  • 非同期では await response.parse()。.text / .content はメソッド化
  • リージョン未設定は構築時に ValueError。boto3 プロファイル解決を新サポート
  • サーバーサイドのコンテキスト圧縮 (context_management) に移行
💡

多くのユーザーにとって移行コストは小さい一方、カスタム HTTP クライアント、非同期の .with_raw_response、リージョン未設定の Bedrock クライアントを使っているコードは修正が必須です。旧 httpx.Client を http_client= に渡すと構築時に TypeError が発生する (サイレントに失敗しない) 設計になっています。

主な変更点

🔌 1. httpx から httpx2 への移行

プレーンな値を渡すユーザーは変更不要。カスタムの http_client、Timeout、トランスポートは httpx2 からインポートします。DefaultHttpxClient / DefaultAioHttpClient ヘルパーは変更なしで利用可能。OpenTelemetry、Sentry、respx、pytest-httpx、vcrpy など httpx をパッチするライブラリ併用時は、起動時 (httpx のインポート前) に httpx2.alias_httpx() を呼び出します。

🐍 2. Python 3.10 以降が必須

最低バージョンが 3.9 から 3.10 に引き上げられました。それ以外のランタイム要件は変わらず、Pydantic は v1 / v2 の両方が引き続きサポートされます。

🗑️ 3. レガシー Text Completions API の削除

client.completions.create() (/v1/complete エンドポイント)、Completion / CompletionCreateParams 型、HUMAN_PROMPT / AI_PROMPT 定数が削除されました。Messages API への移行が必要です。

🎛️ 4. temperature / top_p / top_k の削除

messages.create()、stream()、parse()、beta 版の各メソッド、tool_runner()、バッチパラメータから削除され、渡すと TypeError になります。現行モデルはこれらを無視するため実質的な影響はありませんが、解釈する旧モデルでは extra_body 経由で渡せます。

📄 5. 非同期の .with_raw_response の変更

戻り値が LegacyAPIResponse から APIResponse / AsyncAPIResponse に変更。非同期では await response.parse() が必要になり、.text / .content はメソッド化 (response.text() / response.read()) されました。.headers や .status_code などのメタデータは従来どおり属性アクセスのままです。

☁️ 6. AnthropicBedrock のリージョン必須化

リージョン未設定時の us-east-1 フォールバックが廃止され、構築時に ValueError を送出します。aws_region= 引数、AWS_REGION / AWS_DEFAULT_REGION 環境変数、aws_profile の boto3 セッション設定の順で解決されます。Bedrock ストリーミングの未知イベントはスキップされるようになりました。

🧰 7. compaction_control の削除

tool_runner() のクライアントサイド compaction_control が削除され、サーバーサイドのコンテキスト圧縮 (betas=["compact-2026-01-12"] と context_management) に置き換えられました。トリガーのしきい値は 50,000 トークン以上である必要があります。

技術詳細: その他の変更点

主な変更点以外にも、以下の変更が含まれます。

  • messages.parse(stream=True) の削除: 元々機能していなかったパラメータ。構造化出力のストリーミングには messages.stream(..., output_format=Order) ヘルパーを使用します。
  • beta Messages の output_format (スキーマ辞書形式) の削除: beta.messages.create() / count_tokens() / バッチパラメータでは output_config={"format": {...}} を使用。ヘルパーの output_format= は型 (Pydantic モデルなど) のみを受け付け、スキーマ辞書は TypeError になります。
  • 低レベルメソッドの body=: 常に JSON シリアライズされるようになり、生バイト列の送信には content= を使用します (ストリーミングアップロード用のイテレータも受け付けます)。
  • ヘッダー処理: default_headers / extra_headers / with_options() / ANTHROPIC_CUSTOM_HEADERS のエントリは大文字小文字を区別せずに同名ヘッダーを置換。bytes 型のヘッダー値はエラーになるため、事前に .decode() が必要です。
  • 型エイリアスの削除: BetaBase64PDFBlockParam → BetaRequestDocumentBlockParam、agent_toolset.READ_MAX_BYTES → agent_toolset.DEFAULT_MAX_FILE_BYTES など。
  • ストリームの型判定: isinstance(x, Stream) はメッセージストリームにマッチしなくなりました。anthropic.lib.streaming の MessageStream に対して判定します。
  • anthropic.Transport / anthropic.ProxiesTypes などの再エクスポート削除: httpx2.BaseTransport / httpx2.AsyncBaseTransport / httpx2.Proxy を直接使用します。APIStatusError.response などの戻り値は httpx2 の型になるため、isinstance チェックと型注釈の更新が必要になる場合があります。

コード例: 移行前後の比較

📦 アップグレードコマンド

Shell v1.0 へのアップグレード 
pip install --upgrade "anthropic>=1,<2"

🔌 カスタム HTTP クライアントの移行

Python httpx → httpx2: インポートの差し替えだけで残りは同一 
# 移行前 (v0.x)
import httpx
from anthropic import Anthropic, DefaultHttpxClient

client = Anthropic(
    timeout=httpx.Timeout(60.0, connect=5.0),
    http_client=DefaultHttpxClient(
        proxy="http://my.proxy.example",
        transport=httpx.HTTPTransport(local_address="0.0.0.0"),
    ),
)

# 移行後 (v1.0): インポートを差し替えるだけで残りは同一
import httpx2 as httpx
from anthropic import Anthropic, DefaultHttpxClient

client = Anthropic(
    timeout=httpx.Timeout(60.0, connect=5.0),
    http_client=DefaultHttpxClient(
        proxy="http://my.proxy.example",
        transport=httpx.HTTPTransport(local_address="0.0.0.0"),
    ),
)

🔗 パッチ系ライブラリ併用時のエイリアス設定

Python トレーシング / モックライブラリ利用時の alias_httpx 
# アプリケーションの起動時、httpx がインポートされる前に実行する
import httpx2

httpx2.alias_httpx()

import httpx  # 以降、httpx は httpx2 モジュールを指す
assert httpx.Client is httpx2.Client

📄 非同期クライアントの .with_raw_response の移行

Python response.parse() → await response.parse() 
# 移行前 (v0.x)
response = await client.messages.with_raw_response.create(...)
message = response.parse()

# 移行後 (v1.0)
response = await client.messages.with_raw_response.create(...)
print(response.headers["request-id"])  # メタデータは従来どおり属性アクセス
message = await response.parse()

☁️ Bedrock のリージョン指定と旧モデル向け temperature

Python AnthropicBedrock のリージョン明示と extra_body の利用 
from anthropic import AnthropicBedrock

# v1.0 ではリージョンの明示的な設定が必須
client = AnthropicBedrock(aws_region="us-east-1")

# temperature などを解釈する旧モデルでは extra_body で指定
message = client.messages.create(
    model="claude-sonnet-4-6",
    max_tokens=1024,
    messages=[{"role": "user", "content": "こんにちは"}],
    extra_body={"temperature": 0.2},
)

🧰 ツールランナーのコンテキスト圧縮のサーバーサイド移行

Python compaction_control → context_management 
# 移行前 (v0.x): クライアントサイドの compaction_control
runner = client.beta.messages.tool_runner(
    ...,
    compaction_control={"enabled": True, "context_token_threshold": 100_000},
)

# 移行後 (v1.0): サーバーサイドのコンテキスト圧縮
runner = client.beta.messages.tool_runner(
    ...,
    betas=["compact-2026-01-12"],
    context_management={
        "edits": [
            {
                "type": "compact_20260112",
                "trigger": {"type": "input_tokens", "value": 100_000},
            }
        ]
    },
)

開発者への影響

🎯 対象

  • Python SDK (anthropic パッケージ) を利用するすべての開発者
  • カスタム http_client / Timeout / トランスポートを構築している開発者
  • httpx をパッチするトレーシング / モック / テストライブラリを併用している開発者
  • Amazon Bedrock 経由で AnthropicBedrock クライアントを利用する開発者
  • レガシー Text Completions API や temperature などの旧パラメータを使い続けているコードベースの保守者

🛠️ 必要なアクション: 影響度別の整理

変更点 影響を受けるケース 対応
Python 3.10+ 必須 Python 3.9 環境 ランタイムを 3.10 以降に更新
httpx → httpx2 カスタム HTTP クライアント / トランスポート import httpx2 as httpx に置換。パッチ系ライブラリ併用時は起動時に httpx2.alias_httpx() を呼ぶ
Text Completions API 削除 client.completions.create() 利用コード Messages API に移行
temperature / top_p / top_k 削除 Messages メソッドで直接指定しているコード 削除するか、旧モデル利用時は extra_body で指定
.with_raw_response の変更 非同期クライアントで response.parse() を呼ぶコード await response.parse() に変更。.text / .content はメソッド呼び出しに変更
Bedrock リージョン必須化 リージョン未設定で us-east-1 に暗黙依存 aws_region= または環境変数で明示的に設定
compaction_control 削除 ツールランナーでクライアントサイド圧縮を利用 サーバーサイド圧縮 (context_management) に移行

🔄 移行のポイント

1

公式移行ガイドを参照: MIGRATION.md にすべての変更が移行前後のスニペット付きで記載されています。

2

自動移行の活用: Claude Code ユーザーは /claude-api upgrade python で自動移行を実行できます。

3

型チェッカーの実行: アップグレード後に pyright / mypy などの型チェッカーを実行すると、破壊的変更の大半が検出されます。

4

alias_httpx の呼び出し位置に注意: httpx2.alias_httpx() はアプリケーションだけが呼び出すべきで、ライブラリからは呼びません。httpx がすでにインポート済みの場合は RuntimeError になるため、エントリポイントの先頭で呼びます (pytest では早期ロードされるプラグインとして登録します)。

ユースケース

🚀 標準的な利用者: 最小コストでのアップグレード

プレーンな値 (timeout=30.0 など) だけを渡している一般的な利用では、pip install --upgrade "anthropic>=1,<2" の実行と Python 3.10+ の確認だけで移行できます。DefaultHttpxClient / DefaultAioHttpClient ヘルパーも変更なしでそのまま利用できます。

🔍 監視 / テスト基盤を持つチーム: alias_httpx による互換維持

OpenTelemetry や Sentry によるトレーシング、respx / pytest-httpx / vcrpy によるモックなど httpx をパッチするライブラリを併用しているチームは、エントリポイントの先頭で httpx2.alias_httpx() を呼ぶことで既存のトレーシング / テスト基盤を維持したまま v1.0 に移行できます。

☁️ Bedrock 利用の本番環境: リージョン設定の明示化

リージョン未設定で us-east-1 に暗黙依存していた AnthropicBedrock クライアントは構築時に ValueError で即座に検出されるため、意図しないリージョンでの実行を防げます。boto3 プロファイルからのリージョン解決の新サポートにより、既存の AWS 設定との統合も容易になります。

まとめ

Python SDK v1.0 は、新機能の追加ではなく基盤の刷新と負債の整理に焦点を当てたメジャーリリースです。

🔧

HTTP レイヤーの持続性を確保

メンテナンスが継続される httpx2 への移行により、HTTP レイヤーの持続性が確保されました。API 互換フォークのため、多くのユーザーは変更不要です。

🧹

API サーフェスの簡潔化

Text Completions API や旧サンプリングパラメータなどの非推奨サーフェスの削除により、API が簡潔になりました。

⚠️

修正必須のコードを確認

カスタム HTTP クライアント、非同期の .with_raw_response、リージョン未設定の Bedrock クライアントを使っているコードは修正が必須です。

📋

計画的なアップグレードを推奨

型チェッカーで大半の破壊的変更を検出できるため、公式移行ガイドを参照しながら計画的にアップグレードすることが推奨されます。
