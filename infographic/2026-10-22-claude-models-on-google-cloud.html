Claude Models on Google Cloud
(Anthropic managed) ローンチ

Google Cloud プロジェクト経由で Claude API のフル機能にアクセス。IAM で制御、Marketplace で課金

📅 発表日: 2026-10-22 | ソース: Claude Developer Platform Release Notes

概要 — 5 つのキーポイント

☁️

Google Cloud プロジェクト経由で Claude API にアクセス

Anthropic が運営する Claude API に、ユーザー自身の Google Cloud プロジェクトを入り口としてアクセスできる新しい提供形態。ベース URL は https://claude.googleapis.com/v1/projects/{project}/locations/global/workspaces/{workspace}/invoke で、この後ろに通常の Claude API パス (例: /v1/messages) を続けます。

🛡️

Google Cloud IAM によるアクセス制御

API キーは不要。3 つの事前定義ロール (claude.viewer / claude.user / claude.admin) で、既存の Google Cloud の権限管理に Claude API を統合できます。

💳

Google Cloud Marketplace による課金

使用量は Claude Consumption Unit (1 ユニット = 0.01 米ドル) として Google Cloud に報告され、Google Cloud の請求書に表示。Anthropic からの個別請求はなく、Google Cloud の支出コミットメントにもカウントされます。

🔁

Claude API とのリクエスト互換性が高い

差分はベース URL、認証ヘッダー、ワークスペース指定の 3 点のみ。anthropic-version / anthropic-beta ヘッダー、リクエストボディ、ストリーミング、レスポンスは Claude API と同一です。

⚡

Claude Opus 5.5 の Fast mode に対応

Claude API と同様に、本プラットフォーム上でも Claude Opus 5.5 の Fast mode が利用できます。

背景 — Google Cloud 経由の Claude 利用が変わる

Before: Google managed のみ

  • Google が Agent Platform (旧 Vertex AI) の一部として Claude モデルを運営する形態のみ
  • Agent Platform 固有のエンドポイント (:rawPredict / :streamRawPredict) やリクエスト形式が必要
  • Claude API 本体との差分が存在

After: Anthropic managed が追加

  • Claude API そのものを Anthropic が運営したまま、Google Cloud プロジェクトをアクセスと課金の入り口にできる
  • Claude API のエンドポイント・リクエスト形式・機能をそのまま利用可能
  • Google Cloud の IAM と Marketplace 課金を活用

主な変更点

🔌 Claude API へのプロジェクト経由アクセス

ベース URL は claude.googleapis.com のプロジェクトスコープ URL。後ろに通常の Claude API パスを続けるだけで、Claude API のフル機能を利用できます。

🛡️ IAM によるアクセス制御

3 つの事前定義ロールで権限を一元管理。API を呼び出す ID には roles/claude.user を付与します。Claude Console を開けるのは claude.admin のみです。

💳 Marketplace 課金

Anthropic が使用量を計測し、Claude Consumption Unit として Google Cloud に報告。請求は Google Cloud の請求書に統合され、支出コミットメントにもカウントされます。

⚡ Opus 5.5 Fast mode 対応

Claude API と同様に、Claude Opus 5.5 の Fast mode が本プラットフォーム上でも利用可能です。

🛡️ IAM 事前定義ロールの詳細

ロール 表示名 許可される操作
roles/claude.viewer Claude Viewer ワークスペースリソースの参照 (読み取り専用)
roles/claude.user Claude User Viewer の権限に加え、メッセージ送信、トークンカウント、バッチ / ファイル / スキル / Claude Managed Agents リソースの管理
roles/claude.admin Claude Admin User の権限に加え、組織レベルの操作。Claude Console を開けるのはこのロールのみ

技術的な詳細

🔐 認証方式 — API キーは使用しない

各リクエストは Authorization: Bearer ヘッダーで Google OAuth 2.0 アクセストークン (cloud-platform スコープ) を送信します。SDK クライアントは Application Default Credentials (ADC) からトークンを取得するため、Compute Engine、GKE、Cloud Run 上ではワークロードにアタッチされたサービスアカウントが自動的に使われます。Workload Identity Federation やサービスアカウントの impersonation にも対応しています。

🔁 Claude API との差分は 3 点のみ

その他 (anthropic-version / anthropic-beta ヘッダー、リクエストボディ、ストリーミング、レスポンス) は Claude API と同一です。

1
ベース URL: https://api.anthropic.com の代わりにプロジェクトスコープの URL を使用
2
認証: x-api-key ヘッダーの代わりに Authorization: Bearer ヘッダーを使用
3
ワークスペース: anthropic-workspace-id ヘッダーの代わりに URL にワークスペース ID を含める

📦 SDK クライアント — AnthropicGoogleCloud (ベータ)

新しいクライアント AnthropicGoogleCloud (ベータ) が各言語の SDK で提供されます。環境変数 ANTHROPIC_GOOGLE_CLOUD_PROJECT と ANTHROPIC_GOOGLE_CLOUD_WORKSPACE_ID からプロジェクト ID とワークスペース ID を自動解決します。ant CLI も対応しています。

🏷️ モデル ID

Claude API と同じモデル ID (例: claude-opus-5-5) を使用します。Google managed で使われる @ 区切りのスナップショット表記 (例: claude-haiku-4-5@20251001) は、Claude 4.6 より前のモデルではハイフン区切り (claude-haiku-4-5-20251001) に置き換えます。

✅ サポートされる機能 / 🚫 されない機能

✅ Claude API と同様に動作

  • Fast mode
  • ツール使用 (Web 検索、Web フェッチ、コード実行、メモリツール、MCP コネクタなど)
  • Agent Skills / Files API
  • プロンプトキャッシュ / 拡張思考
  • ストリーミング / 構造化出力 / トークンカウント
  • Message Batches API
  • Claude Managed Agents
  • CMEK (Google Cloud KMS キー)
  • Compliance API

🚫 利用できない機能

  • API キー (認証は Google Cloud 認証情報のみ)
  • MCP トンネル
  • セルフホスト環境でのメモリストア
  • 事前構築されたセルフホストサンドボックスワーカー (ant CLI や SDK のワーカーは非対応のため、Environments Work エンドポイントを直接呼び出す独自ワーカーの実装が必要)

📋 監査ログ

Cloud Audit Logs が claude.googleapis.com サービスとして API アクティビティを記録します。Admin Activity ログ (暗号化キー、認証情報ボールトなど) は常に有効です。

⚠️
Data Access ログ (メッセージ、バッチ、ファイルなど大半のルート) はデフォルトで無効のため、リクエスト記録が必要な場合はプロジェクトの監査ログ設定で有効化が必要です。

🗄️ データ保持

Anthropic がデータ処理者となり、Claude API と同じデータ保持ポリシーに従います。Zero Data Retention (ZDR) はリクエストベースで利用可能ですが、他の Anthropic 組織の ZDR 契約は引き継がれません。トラスト & セーフティなど一部の支援サービスは Google Cloud 外でデータを処理します。

Google managed との比較

Google Cloud 経由の Claude 利用には 2 つの提供形態があります。Anthropic managed は Claude API ネイティブな開発体験が特徴です。

観点 🟢 Anthropic managed (新) 🔵 Google managed
API サーフェス Claude API エンドポイント /v1/{endpoint} Agent Platform の prediction エンドポイント
リクエスト形式 Claude API と同一 (model はボディ、anthropic-version ヘッダー) model は URL、anthropic_version はボディ
ストリーミング ボディの "stream": true 別エンドポイント :streamRawPredict
ロケーション global のみ (US 推論は inference_geo: "us" で指定) global / マルチリージョン / リージョナル
Anthropic 組織 プロジェクトごとに新規作成 なし
課金 Google Cloud Marketplace Agent Platform 使用量として Google Cloud
レート制限 Anthropic が管理 Google Cloud が管理

📝 必要なアクション (セットアップ 5 ステップ)

Marketplace でサブスクライブ

Google Cloud Marketplace で「Claude Models on Google Cloud (Anthropic managed)」のリスティングを購入

サービスの有効化

利用する各プロジェクトで 2 つのサービスを有効化

Bash gcloud でサービスを有効化 
gcloud services enable claude.googleapis.com \
  anthropic-managed-claude.cloudpartnerservices.goog \
  --project=my-project-id

Anthropic 組織のセットアップ

Google Cloud コンソールの Claude ページから Activate し、組織情報を登録 (既存の Anthropic 組織とは別の新しい組織が作成される点に注意)

IAM ロールの付与

API を呼び出す ID に roles/claude.user を付与

環境変数の設定

ANTHROPIC_GOOGLE_CLOUD_PROJECT と ANTHROPIC_GOOGLE_CLOUD_WORKSPACE_ID を設定 (ワークスペース ID は Claude Console の Settings > Workspaces で確認)

🚚 移行ガイド

Google managed からの移行

SDK クライアントを AnthropicVertex から AnthropicGoogleCloud に置き換えます。Messages API の呼び出し自体はほぼそのまま使えますが、Claude 4.6 より前のモデル ID は @ をハイフンに変更する必要があります。

既存の Anthropic 組織からの移行

既存組織を Anthropic managed の組織に変換することはできません。新組織を作成するカットオーバー方式となり、API キー、ワークスペース、Console 設定は引き継がれません。ファイル、スキル、バッチなどの保存リソースも既存組織に残ります。2 つの組織は並行稼働できるため、段階的な移行が可能です。

💡
既存の割引がある場合は、セットアップ前に Anthropic または Google Cloud の担当者への連絡が推奨されています。

コード例

Python AnthropicGoogleCloud クライアントでの呼び出し 
# pip install -U "anthropic[google_cloud]"
# 事前に以下を設定:
#   export ANTHROPIC_GOOGLE_CLOUD_PROJECT="my-project-id"
#   export ANTHROPIC_GOOGLE_CLOUD_WORKSPACE_ID="wrkspc_01AbCdEf23GhIj"
#   gcloud auth application-default login

from anthropic import AnthropicGoogleCloud

client = AnthropicGoogleCloud()

message = client.messages.create(
    model="claude-opus-5-5",
    max_tokens=1024,
    messages=[{"role": "user", "content": "Hello, Claude"}],
)
print(message)
Bash cURL での呼び出し例 
curl "https://claude.googleapis.com/v1/projects/$ANTHROPIC_GOOGLE_CLOUD_PROJECT/locations/global/workspaces/$ANTHROPIC_GOOGLE_CLOUD_WORKSPACE_ID/invoke/v1/messages" \
  -H "Authorization: Bearer $(gcloud auth application-default print-access-token)" \
  -H "content-type: application/json" \
  -H "anthropic-version: 2023-06-01" \
  -d '{
    "model": "claude-opus-5-5",
    "max_tokens": 1024,
    "messages": [{"role": "user", "content": "Hello, Claude"}]
  }'

ユースケース

🏦 エンタープライズのガバナンス統合

Google Cloud を標準基盤とする企業が、API キーの発行・管理を廃止し、既存の IAM ポリシーとサービスアカウントで Claude API へのアクセスを一元管理。Cloud Audit Logs による監査証跡と CMEK による暗号化で、コンプライアンス要件にも対応できます。

💰 請求とコスト管理の一本化

Claude の利用料金を Google Cloud の請求書に統合し、Anthropic からの個別請求を排除。Marketplace 経由の課金は Google Cloud の支出コミットメントにもカウントされるため、既存のクラウド契約を有効活用できます。

🚀 Google managed からの機能アップグレード

Agent Platform (Vertex AI) 経由で Claude を利用中のチームが、SDK クライアントの置き換えだけで Files API、Agent Skills、Claude Managed Agents、Fast mode などの Claude API ネイティブ機能を利用可能に。Compute Engine、GKE、Cloud Run 上ではサービスアカウントが自動的に使われます。

まとめ

Claude Models on Google Cloud (Anthropic managed) のローンチにより、Google Cloud ユーザーは API キーの管理なしに、IAM ベースのアクセス制御と Marketplace 経由の一元的な課金で Claude API のフル機能を利用できるようになりました。Claude API とのリクエスト互換性が高く (差分はベース URL、認証ヘッダー、ワークスペース指定の 3 点のみ)、Fast mode、Claude Managed Agents、CMEK などの最新機能にも対応しています。

Google managed (Agent Platform 経由) と比べて Claude API ネイティブな開発体験が得られる一方、既存の Anthropic 組織からの移行は新組織へのカットオーバーとなる点、API キーや MCP トンネルが使えない点には注意が必要です。なお、本サービスの料金単価 (Claude API 直接利用との価格差の有無) については公式ドキュメントに明記がなく、確認が必要です。
