Claude Opus 4.5 の非推奨化、Enterprise Frontier Safeguards ベータ提供開始、組織 Webhook のイベント追加

📅 2026-11-23 | ソース: Claude API Release Notes

概要

⚠️

Claude Opus 4.5 が非推奨化、提供終了は 2027-01-22

claude-opus-4-5-20251101 と日付なしの claude-opus-4-5 が 2026 年 11 月 23 日付で非推奨化された。Claude API での提供終了 (retirement) は 2027 年 1 月 22 日で、以降のリクエストは失敗する。推奨される移行先は Claude Opus 5.5。

🛡️

Enterprise Frontier Safeguards (EFS) がベータ提供開始

対象組織向けのゼロデータ保持 (ZDR)。Anthropic はプロンプトと応答を保持せず、暗号化されたコピーである Sealed Safety Data は顧客自身のクラウドアカウント内のバケットに保存される。EFS は無料で、モデルの挙動、API 料金、レート制限は変わらない。

🔔

組織 Webhook に external_storage イベントを追加

ベータ提供中の組織 Webhook に、顧客所有ストレージの健全性を通知する 2 つのイベントタイプ external_storage.failed と external_storage.recovered が追加され、バケットの日次チェック結果を自動で受け取れるようになった。

🧭

背景: 新モデルへの提供能力確保とデータガバナンス強化

Anthropic は新モデルのリリースに向けて古いモデルを定期的に非推奨化・提供終了しており、公開済みモデルは提供終了の少なくとも 60 日前に通知される。EFS と Webhook の更新は、エンタープライズ組織向けのデータガバナンス強化の流れに位置付けられる。

非推奨化スケジュール

2026 年 11 月 23 日

⚠️ Opus 4.5 の非推奨化を告知

claude-opus-4-5-20251101 と claude-opus-4-5 が非推奨 (Deprecated) になった。引き続き動作するが推奨されない。

2026 年 11 月 23 日 - 2027 年 1 月 21 日

🔧 移行期間 (約 2 か月)

Claude Console の Usage ページの CSV エクスポートで利用箇所を特定し、claude-opus-5-5 への移行作業を実施する。

2027 年 1 月 22 日

⛔ 提供終了 (Retired)

Opus 4.5 へのリクエストは失敗する。Anthropic 運営プラットフォーム (Claude API、Claude Platform on AWS、Google Cloud の Anthropic マネージド、Microsoft Foundry) に適用される。

💡 パートナー運営の Amazon Bedrock や Google マネージドの Google Cloud は独自の提供終了スケジュールを設定するため、状態と日付が異なる場合がある。Claude Code は Claude API を使用するため (Claude プランでのサインインを含む)、同じ日付が適用される。

Before / After: Opus 4.5 から Opus 5.5 へ

Before: Claude Opus 4.5

  • 🕐 claude-opus-4-5-20251101 / claude-opus-4-5 (2027-01-22 に提供終了)
  • 🧠 thinking: {"type": "enabled", "budget_tokens": N} で思考量を指定
  • 🎛️ temperature / top_p / top_k で挙動を調整
  • ✍️ アシスタントメッセージの prefill が使用可能
  • 🔧 tool_choice の any / tool で強制ツール呼び出し
  • 🏷️ effort-2025-11-24 などのベータヘッダーが必要
  • 📐 構造化出力は output_format={...}

After: Claude Opus 5.5

  • ⭐ claude-opus-5-5 (日付サフィックスのない固定 ID)
  • 🧠 アダプティブ思考が常時有効。思考量は effort パラメータで制御 (low / medium / high / xhigh / max、デフォルトは medium)
  • 💬 サンプリングパラメータは廃止。挙動はプロンプトで誘導
  • 📐 prefill は構造化出力またはシステムプロンプトで代替
  • 🔧 tool_choice は auto または none のみ
  • 🏷️ 不要になったベータヘッダーは削除。1M トークンのコンテキストウィンドウがデフォルト
  • 📐 構造化出力は output_config={"format": {...}}
🔢 Opus 4.7 以降の新しいトークナイザにより、テキスト処理で従来比約 1 倍から 1.35 倍のトークンを使用する場合がある。max_tokens の見直しと、クライアント側でトークンを見積もるコードの再テストが推奨される。

3 つの更新内容

⚠️ Opus 4.5 の非推奨化

2027 年 1 月 22 日に提供終了。移行先は claude-opus-5-5。移行時はアダプティブ思考への切り替え (必須)、サンプリングパラメータ・prefill・強制ツール呼び出しの削除、トークンカウントの再評価などが必要。Claude Console の Usage ページから CSV をエクスポートすると、API キーおよびモデル別に非推奨モデルの使用箇所を特定できる。

🛡️ EFS ベータ提供開始

Claude の最上位モデルを使用する対象組織向けのゼロデータ保持。Sealed Safety Data (プロンプト、応答、推論内容の暗号化コピー) は顧客所有バケットに書き込まれ、顧客チームも内容を読めない。Anthropic Human Review は常にオフとなり、自動安全モニタリングがフラグしたケースは顧客自身のチームがレビューする。Claude Platform、Claude Platform on AWS、Google Cloud の Anthropic マネージドで利用可能。

🔔 組織 Webhook のイベント追加

ベータヘッダー webhooks-2026-10-07、Admin API の /v1/organizations/webhooks で管理する組織 Webhook に、顧客所有ストレージの日次チェック結果を通知する external_storage.failed と external_storage.recovered が追加された。ペイロードの data.id は estrg_ で始まるバケットの ID。

EFS の適用範囲と注意点

  • 🏢EFS はワークスペース全体に適用される。有効になると、データ保持を必要としないモデルを含め、そのワークスペースのすべてのモデルへのすべてのリクエストが対象になる。一部のトラフィックのみに適用したい場合はワークスペースを分離する
  • 📨対象は EFS 設定済みワークスペースの Messages API リクエスト。コード実行コンテナ、Files API のアップロード、Batch API の結果、Claude Managed Agents のセッションなど、Claude Platform の機能が自身の用途で保存するデータは対象外
  • 🗄️自社バケットが必須。Anthropic マネージドストレージ上のワークスペースは、Anthropic が Sealed Safety Data を保存するため EFS の対象にならない
  • 💰EFS は無料で、モデルの挙動、API 料金、レート制限を変更しない。ただし、バケットへの読み書きやデータ転送などのストレージ費用はクラウドプロバイダーから通常どおり課金される
  • 🔐Claude Platform で EFS と Enterprise Data Controls の規約に同意すると両方が有効になり、顧客管理キー (CMEK) の使用や、Anthropic マネージドストレージでの Anthropic Human Review の無効化が可能になる。いずれかを使用すると組織で Access Transparency が有効になる

組織 Webhook の新イベントタイプ

イベント トリガー
external_storage.failed 顧客所有ストレージとして使用しているバケットが Anthropic の日次チェックに失敗したとき。通常、失敗したチェックの約 15 分後に届き、失敗が続いても再送はされない
external_storage.recovered external_storage.failed の送信後、バケットが再びチェックに合格したとき。通常、次に合格した日次チェックから数分以内に届く
JSON イベントペイロード例 (data.id は estrg_ で始まるバケットの ID) 
{
  "type": "event",
  "id": "whe_2b7e9d4c1a6f8035e2d9b6c3a0f51e84",
  "created_at": "2026-12-02T06:41:19.305127Z",
  "data": {
    "type": "external_storage.failed",
    "id": "estrg_01SDCCSbTxrXDpWc1phhtcfK",
    "organization_id": "org_011CZkZBj9RsYd3wNcHvKq6t"
  }
}

イベント受信時の対応

1

バケットの状態を確認

anthropic-beta: efs-2026-10-01 ヘッダー付きで GET /v1/organizations/external_storage/{external_storage_id} を呼び出し、status.healthy と status.last_checked_at を確認する。

2

異常時は直ちに連絡

status.healthy が false の場合は、バケットに届かない Sealed Safety Data が失われる可能性があるため、直ちに Anthropic アカウントチームへ連絡する。

3

定期的な状態確認を併用

2 回のチェックの間に失敗と回復が完結した場合など、どちらのイベントも届かないケースがある。イベントを唯一のシグナルにせず、リクエスト送信中にバケットへのオブジェクト到着を監視し、定期的に取りこぼしを確認する。

⏱️ チェックは 1 日 1 回のため、バケット側の変化からイベント到達まで 1 日以上かかることがある。バケットの失敗・回復時には、暗号化キーを管理できるロールを持つ組織メンバーへ通常メールも送信される。

開発者への影響と必要なアクション

対象: claude-opus-4-5-20251101 または claude-opus-4-5 を使用しているすべての開発者 (Claude Code で同モデルを指定している場合を含む)、Claude の最上位モデルを利用しつつプロンプトと応答のゼロデータ保持を必要とするエンタープライズ組織、EFS の顧客所有ストレージを運用する組織の管理者・プラットフォームチーム。

1

Opus 4.5 からの移行

2027 年 1 月 22 日の提供終了までに claude-opus-5-5 へ移行する。Usage ページの CSV エクスポートで非推奨モデルを使用している API キーを特定できる。budget_tokens 付き thinking、サンプリングパラメータ、prefill、強制ツール呼び出しの削除と、effort パラメータへの切り替えが必要。

2

トークン使用量の再評価

新しいトークナイザにより、テキスト処理のトークン数が最大約 35% 増える場合がある。max_tokens の調整と、クライアント側のトークン見積もりロジックの再テストを行う。

3

EFS の導入検討

Sealed Safety Data を自社クラウドアカウントに保持したい対象組織は、セットアップガイドに従ってアクセスを申請する。EFS はワークスペース全体に適用されるため、一部のトラフィックのみに適用する場合はワークスペースの分離が必要。コード実行コンテナや Files API など対象外のデータがある点にも注意する。

4

ストレージ監視の整備

顧客所有ストレージを使用する組織は、Webhook エンドポイントに external_storage.failed と external_storage.recovered を登録し、受信時にバケットの状態確認と Anthropic アカウントチームへの連絡を行うフローを整備する。イベントは取りこぼしの可能性があるため、定期的な状態確認も併用する。

📄 移行ガイドのページを先頭から順に適用する構成になっており、Opus 4.6 からの破壊的変更 (アダプティブ思考、サンプリングパラメータ削除、トークナイザ更新など) に加えて、Opus 4.5 以前に固有の変更 (prefill 削除、ツール引数の JSON エスケープの違い、不要になったベータヘッダーの削除、output_config.format への移行) が含まれる。Claude Code を使用している場合は、先に Claude Code 自体を更新してから、サブエージェント定義を含むすべてのモデル指定箇所を更新する。

ユースケース

🔄 本番システムの計画的なモデル移行

Opus 4.5 を本番利用している開発チームは、Usage ページの CSV エクスポートで対象の API キーを特定し、約 2 か月の移行期間内に claude-opus-5-5 への切り替えを計画的に実施できる。effort パラメータへの切り替えとトークン使用量の再評価を含めた移行計画を立てることで、提供終了日のリクエスト失敗を回避できる。

🏛️ 規制業界でのデータ主権と最上位モデルの両立

金融や医療などデータ主権の要件が厳しいエンタープライズ組織は、EFS により Anthropic 側にプロンプトと応答を保持させず、Sealed Safety Data を自社クラウドアカウント内のバケットに保持したまま Claude の最上位モデルを利用できる。安全モニタリングでフラグされたケースも自社チームでレビューできる。

📡 顧客所有ストレージの運用監視の自動化

EFS の顧客所有ストレージを運用するプラットフォームチームは、Webhook で external_storage.failed を受信したら状態確認 API を呼び出し、インシデント管理システムへの起票や Anthropic アカウントチームへの連絡につなげる監視フローを自動化できる。

まとめ

2026 年 11 月 23 日の Claude API リリースノートでは、Claude Opus 4.5 の非推奨化 (提供終了は 2027 年 1 月 22 日、移行先は Claude Opus 5.5)、エンタープライズ向けゼロデータ保持機能 Enterprise Frontier Safeguards のベータ提供開始、顧客所有ストレージの健全性を通知する組織 Webhook イベントの追加という 3 件の更新が発表された。Opus 4.5 の利用者は約 2 か月の移行期間内に、モデル ID の変更に加えてアダプティブ思考への移行やサンプリングパラメータの削除などの対応が必要になる。EFS は、最上位モデルの利用とデータ主権の両立を求めるエンタープライズ組織にとって重要な選択肢となり、Webhook のイベント追加により顧客所有ストレージの運用監視を自動化できるようになった。いずれもベータ機能を含むため、導入時は仕様変更の可能性に留意する必要がある。
