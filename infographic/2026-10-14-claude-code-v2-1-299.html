主要機能

🗜️ アイドルコンパクション

200K トークン以上の会話を約 54 分放置すると自動でコンパクトを実行。発動の最小トークン数は CLAUDE_CODE_IDLE_COMPACT_MIN_TOKENS で変更でき、settings.json の "idleCompaction": false で無効化できる。v2.1.290 以降が必要。

📎 CLAUDE_CODE_DISABLE_FILE_MENTIONS

@ メンション時にパスのみを Claude に渡す。Claude は必要に応じてファイルツールで読み込むため、メンション直後のコンテキスト消費を抑えられる。ファイルの一部だけ読めば足りるワークフローで有効。

🧩 Mod API 拡張

$.prompt.media で添付画像・ドキュメントのバイト列を読み取り (managed Mod)、$.session.identity() でサインイン方法や組織情報を取得。Text に size / weight / mono / tabular、Box に名前付きスペーシングが追加され、bold は非推奨に。

🛡️ セキュリティ修正

サンドボックス突破につながる --plugin-dir への書き込みを防止。ANTHROPIC_BASE_URL のゲートウェイ用 API キーが Anthropic へのリクエストに付いて送られる漏洩と、__proto__ キーによる tool.check ガード回避を修正。プランモードの書き込み防止も強化。

🔧 安定性の修正 (121 件)

デバッグログや stderr によるメモリリーク、MCP の HTTP 接続 30 秒ハングや OAuth ヘッダー欠落、Remote Control / クラウドセッションの大容量ファイル転送・二重実行、BOM 付き UTF-16LE の文字化けなどを修正。

技術詳細

⏱️ アイドルコンパクションの動作フロー

🔐 MCP allow ルールのスコープ厳格化

Before

mcp__a という allow ルールが a__b や a_ という名前のサーバーにまで一致していた。deny / ask ルールは正規化名に __ を含むサーバーに適用されないことがあった。

After

ルールは名前を指定したサーバーのみに適用。正規化名に __ を含むサーバーは mcp__<完全な正規化名>__* と記述する。エージェントの tools: リストも同様に厳密化された。

💻 コードサンプル

アイドルコンパクションの調整とファイルメンションの制御例。最小トークン数は環境変数で、無効化は settings.json で行う。

Bash 環境変数での調整 
# アイドルコンパクションの発動を 150K トークンからに変更
export CLAUDE_CODE_IDLE_COMPACT_MIN_TOKENS=150000

# @ ファイルメンションでパスのみを渡す
export CLAUDE_CODE_DISABLE_FILE_MENTIONS=1
JSON settings.json でアイドルコンパクションを無効化 
{
  "idleCompaction": false
}

セキュリティ関連の修正

  • 🚫サンドボックスから --plugin-dir への書き込み防止: このフォルダーのコードは Claude Code がサンドボックス外でリロード・実行するため、サンドボックス突破につながる経路だった。
  • 🔑サードパーティゲートウェイへの API キー漏洩の修正: feature flag、起動、fast mode、プロファイル、フィードバックの各リクエストが、ANTHROPIC_BASE_URL のゲートウェイ用 API キーを Anthropic へのリクエストに付けて送っていた問題を修正。
  • 🧬__proto__ キーによる tool.check ガード回避の修正: Mod の hook に渡される値から __proto__ キーが黙って除去され、別の Mod のツール呼び出しに対するガードを回避できる可能性があった。
  • 🔗macOS サンドボックスのシンボリックリンク対応: 拒否パスがシンボリックリンク経由で実体パスとして読み書きできていた問題や、グロブルール起点の再チェック漏れを修正。
  • 📝プランモードの書き込み防止: hook が許可した書き込み (MCP ツール、ファイル、シェルコマンド) をプランモードが実行してしまう問題を修正。
  • 🔒資格情報の露出防止: 説明なしで開始されたエージェントチームメイトが、プロンプト内の資格情報の一部をタスク説明に表示していた問題を修正。

その他の修正・変更 (抜粋)

  • 🧠メモリリーク: 大量のデバッグログ使用時のメモリ増加、stderr の読み手がいない場合の無制限な増加、サブエージェント多数実行後のセッション再開時の高メモリ使用などを修正。
  • 🔌MCP 接続: 通知応答を終了しないサーバーでの 30 秒ハング、OAuth で headers / headersHelper が送られない問題、バックグラウンド再接続中のツール呼び出し失敗・二重実行、constructor / prototype という名前のサーバーが接続されない問題を修正。
  • 📡Remote Control / クラウドセッション: 30〜35 MiB のファイルが届かない問題、低速回線での claude.ai 表示フリーズ、ワーカー交代直後の未応答・二重応答、承認済みツール呼び出しの二重実行 (v2.1.296 リグレッション) を修正。
  • 🔤ファイルエンコーディング: BOM 付き UTF-16LE の Read 文字化けと、Write が Windows-1252 / Shift-JIS / GBK / UTF-16BE を黙って UTF-8 に変換する問題を修正 (現在は拒否)。
  • 🪟Windows: 孤児 PowerShell プロセスによるメモリ枯渇と、Git for Windows 不在時に hook がフェイルオープンする問題を修正 (失敗したガードは呼び出しをブロック)。
  • 🔄動作変更: UserPromptSubmit hook がスキル / カスタムコマンド展開前に実行されるように。プラグイン hook が処理できないブロック可能アクションは通過ではなく拒否に。終了時の resume コマンドはセッション名ではなく ID で表示。
  • ➕その他の追加: --shutdown-drain-sec (セルフホストランナー)、エージェントビューの /effort と /fast、claude plugin eval の --disallow-tools、帰属ブロック制御の CLAUDE_CODE_ATTRIBUTION_HEADER=0、/usage の警告追加。
  • 🧰VSCode / Cloud sessions / Claude Tag / Code Review: 未送信プロンプトがセッション切り替えで失われる問題の修正、Python 拡張と並行起動による起動時間改善、ルーティンの環境移動の修正、Claude in Slack のキャンバス削除対応と 100 人超チャンネルへの静かな参加など計 20 件。

ユースケース

💬 長時間セッションの利用者: 離席後のコストと待ち時間を削減

200K トークンを超える会話を開いたまま離席しても、アイドルコンパクションがキャッシュ失効前に自動でコンパクトするため、復帰後の最初のメッセージにかかる時間とコストが改善される。発動条件は CLAUDE_CODE_IDLE_COMPACT_MIN_TOKENS で調整でき、不要なら "idleCompaction": false で無効化できる。

🏢 サードパーティゲートウェイの利用組織: 更新とキーローテーションの検討

ANTHROPIC_BASE_URL でゲートウェイを利用する組織は、API キー漏洩が修正された v2.1.299 への更新を推奨。過去のバージョンで漏洩の懸念がある場合はキーのローテーションを検討する。mcp__<server> 形式のルールを運用するチームは、スコープ厳格化に合わせてルールの書き換えを確認する。

🧩 Mod / プラグイン開発者: 新 API への移行と hook の見直し

bold から weight への移行、turn.start がサブエージェントのターンも受け取るようになったことへの e.agentId による分岐、UserPromptSubmit hook の実行タイミング変更 (展開前) の確認が必要。$.prompt.media や $.session.identity() で managed Mod の機能を拡張できる。
