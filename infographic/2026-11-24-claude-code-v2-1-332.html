Claude Code v2.1.332

MCP サーバー由来のスキル (ベータ) と大規模なフリーズ修正を含む 150 項目のアップデート

📅 2026-11-24 | ソース: Claude Code Changelog

概要 - キーポイント

🔌

MCP サーバー由来のスキル (ベータ、新機能)

MCP サーバーが提供するスキルを利用できるようになった。これらのスキルはスラッシュメニューに server:skill 形式で表示され、MCP サーバーがツールだけでなくパッケージ化された手順 (スキル) も配布できるようになった

🪝

PreSkillShellCommand フックイベント (新機能)

スキルやコマンドの読み込み時に実行されるインラインシェルコマンドを、読み込みの時点で拒否できる。組織でのスキル利用のガバナンスが強化される

🧊

フリーズ・ハング関連の大規模な修正 (重要)

名前付きパイプの読み取り、フックの暴走出力、MCP サーバーの標準出力フラッド、長い未分割文字列などに起因する多数のフリーズ・ハングが解消された

☁️

クラウドプロバイダーのモデルエイリアスとフォールバックの見直し (重要)

Microsoft Foundry のデフォルトモデルが Sonnet 5.5 に変更され、Foundry と Google Cloud の Agent Platform では sonnet / opus エイリアスの指す先が更新された。Amazon Bedrock の sonnet は Sonnet 4.5 のまま

📊

OpenTelemetry の assistant_response イベント (新機能)

レスポンスロギングが有効な場合、SendUserMessage や Cowork のメッセージツールを通じて Claude が送るテキストに対してイベントが記録される。デスクトップ Code タブの service.name は claude-code-desktop に変更された

主要な変更点

🔌 MCP サーバー由来のスキル (ベータ)

  • MCP サーバーが提供するスキルがスラッシュメニューに server:skill 形式で表示される。それ以外のスキルは従来どおりの名前を保つ
  • MCP サーバーがツールだけでなく、パッケージ化された手順 (スキル) も配布できるようになり、エコシステムの拡張点が増えた
  • Mac で computer use を有効にしている場合、computer-use が予約スキル名となり、同名の自作スキル・コマンドは読み込まれなくなった

🪝 PreSkillShellCommand フック

  • スキル・コマンド読み込み時のインラインシェルコマンドを、読み込みの時点でポリシーにより拒否できる
  • 組織でのスキル利用のガバナンスが強化される
  • 注意: v2.1.331 以前では、このイベントを記述した設定ファイルがあると起動時にダイアログが開く

🧊 フリーズ・ハングの修正

  • 書き込み側のいない名前付きパイプで Read・@ メンション・コンパクションがハングする問題を修正 (読み取りは 20 秒後に失敗)
  • フックの際限ない出力によるフリーズとメモリの暴走をほとんどのケースで修正。約 50,000 文字を超えるテキストは短縮される
  • 複数のワイルドカードを含む権限ルール・フック条件の照合によるフリーズを修正
  • ローカル MCP サーバーの標準出力フラッドで Ctrl+C も効かなくなる問題を修正
  • 巻き戻し・セッション再開・/stats のフリーズ、自動コンパクションの連続失敗も修正

☁️ モデルエイリアスとフォールバック

  • Google Cloud の Agent Platform と Microsoft Foundry で sonnet が Sonnet 5.5 を指すように。Foundry の opus は Opus 5.5 を指す
  • Foundry のデフォルトモデルが Sonnet 5.5 に変更。Claude Sonnet 4、Opus 4、Opus 4.1 は引退扱いに
  • Bedrock Mantle では sonnet が Sonnet 5 を意味するようになった (Sonnet 5.5 ではない)
  • ゲートウェイが独自の文言でモデルを拒否した場合でも、応答する古いモデルへステップダウンするようになった
  • --model default はモデルが利用できない場合にエラーで停止せず、古いモデルへ移動する

📊 OpenTelemetry と監視

  • assistant_response イベントを追加 (レスポンスロギング有効時)
  • レスポンスロギング無効時、SendUserMessage / Cowork の送信テキストは長さのみが tool_input に記録される
  • デスクトップ Code タブの service.name が claude-code-desktop に変更。旧名維持は OTEL_SERVICE_NAME で設定
  • 未有効の組み込みサーバーで失敗した mcp_server_connection イベントが毎回報告される問題を修正

🔧 MCP サーバーと Code Mode の修正

  • SSE MCP サーバーのストリーム切断後のハング・全ツール呼び出し拒否を修正
  • タスク ID が 128 文字超で失敗する問題を修正 (1,024 文字まで対応)
  • Code Mode: 4,096 項目超のリスト入力が黙ってスキップされる問題と、10 分超のスクリプトで "Agent stalled" になる問題を修正
  • MCP サーバーが多数のツールをリストする場合の起動時メモリ使用量を改善

🎙️ 音声入力 (タップモード) の挙動変更

  • 認識できる音声なしで 60 秒、上限 10 分までマイクを維持 (従来は 15 秒と 2 分)。VS Code 拡張も同様に延長
  • 停止後もテキストは未送信のまま保持され、次のタップで追記できる
  • 10,000 文字を超える音声入力テキストが失われる問題も修正

💻 VS Code 拡張の更新 (30 項目)

  • Windows 11 24H2 以降の VS Code 1.101 / 1.102 で、NTFS ドライブ上の会話のフォークやメモリの保存が失敗する問題を修正
  • コンパクション要約が自分のプロンプトとして表示される問題を修正
  • 長い返信のストリーミング中のパフォーマンスとパネルを開く時間を改善
  • スクリーンリーダーの読み上げや IME・ヘブライ語・アラビア語など国際化関連を修正
  • Manage plugins の各行にインストール済みバージョンを表示

✨ そのほかの注目点

  • claude auth login がログイン保存失敗時に Login successful. と報告する問題を修正 (終了コード 1 で確認点を表示)
  • PreToolUse フックが確認を求める理由を Read・Grep・Glob・Edit・Write プロンプトに表示
  • OAuth トークンのプレフィックスに oat02- が追加 (Self-hosted runner)
  • EnterWorktree 後の CLAUDE.md の二重送信をほとんどのケースで修正
  • macOS の computer use が新しい安全ルールに更新された

🏭 Microsoft Foundry のデフォルトモデル変更への対応

Foundry のデフォルトモデルが Sonnet 5.5 になったため、未デプロイの場合は次のいずれかの対応が必要になる。

Bash Foundry のデフォルトモデル変更への対応 
# 方法 1: claude-sonnet-5-5 を Foundry にデプロイする

# 方法 2: デプロイ済みのモデルを環境変数で指定する
export ANTHROPIC_DEFAULT_SONNET_MODEL=<デプロイ済みのモデル名>

🌏 Agent Platform のリージョン変数

Google Cloud の Agent Platform では、sonnet とバックグラウンドリクエストが新しいリージョン変数を参照する。

Bash Sonnet 5.5 用のリージョン変数 
# Sonnet 5.5 用のリージョン変数を設定する
export VERTEX_REGION_CLAUDE_5_5_SONNET=us-east5

# 4_5 変数のみ設定されている場合、リクエストは
# CLOUD_ML_REGION または us-east5 に送られる

⚙️ 自動モード開始のオプトアウト

Bedrock Mantle・Agent Platform・Foundry で Sonnet 5 / 5.5 に移行したセッションは、モードが未設定なら auto モードで開始するようになった。従来の動作を維持する場合は設定を追加する。

JSON settings - auto モード開始の無効化 
{
  "disableAutoMode": "disable"
}
注意 (PreSkillShellCommand の導入): PreSkillShellCommand は v2.1.332 で追加されたフックイベントである。v2.1.331 以前のバージョンでは、このイベントを記述した設定ファイルがあると起動時にダイアログが開くため、バージョンを混在させて運用している組織では展開順序に注意する

カテゴリ別の修正・変更の要約

☁️ フォールバック動作の修正

  • --fallback-model に sonnet などのファミリー名を指定した際、availableModels が古いバージョンしか許可していないと指定が失われる問題を修正
  • 強制される古いモデルのリストが Agent Platform と Foundry で先頭を拒否された際に失敗する問題を修正。新しい順に並んでいれば同ファミリーの次のモデルへ下がる
  • Bedrock のサブエージェントが、親のリージョンにモデルのプロファイルがない場合に失敗する問題を修正。モデル自身のプロファイル (リージョン外も可) を使うようになった
  • Bedrock Mantle で sonnet エイリアスが Haiku 4.5 に解決される問題を修正。Sonnet 5 が無効なアカウントではエラーになるため、先に有効化が必要

🧠 コンテキスト管理の修正

  • 自動コンパクションの連続失敗後にターンが "Prompt is too long" で終了する問題を修正
  • 要約が出力上限を超え続けてコンパクションが失敗する問題を修正 (3 回の切断後に短い要約を要求)
  • リクエストサイズ制限のあるプロキシの背後で、すべてのメッセージと /compact が 413 で失敗する長い会話の回復を改善

🔧 そのほかの運用関連の修正

  • /permissions がツール名のない rm -rf のような、次回起動時にスキップされるルールを理由とともに拒否するようになった
  • リセット済みの使用量上限が Remote Control・IDE・SDK クライアントに到達済みとして報告される問題を修正
  • Remote Control セッションのプロセス再起動後に、ローカル MCP サーバーが新しいセッション ID を見る問題を修正
  • 圧縮レスポンスが切断・破損した場合のエラーが、生の "ZlibError fetching" ではなく平易な文言になった

ユースケース - 開発者への影響

🔌 MCP サーバーの開発者・組織の管理者

MCP サーバーがスキルを配布できるようになった (ベータ)。利用側はスラッシュメニューの server:skill 形式の項目として確認できる。組織の管理者・セキュリティ担当者は、PreSkillShellCommand フックでスキル読み込み時のインラインシェルコマンドをポリシーで拒否できるようになり、スキル利用のガバナンスを強化できる

☁️ サードパーティクラウドプロバイダーの利用者

Microsoft Foundry ではデフォルトモデルが Sonnet 5.5 に変更され、Sonnet 4 / Opus 4 / Opus 4.1 が引退扱いになった。Google Cloud Agent Platform では sonnet エイリアスが Sonnet 5.5 を指し、VERTEX_REGION_CLAUDE_5_5_SONNET が参照される。Bedrock の sonnet は Sonnet 4.5 のまま変更なしだが、Bedrock Mantle では Sonnet 5 を意味するようになった

📊 監視・運用を担当する組織 (OpenTelemetry / Self-hosted runner)

デスクトップ Code タブの service.name が claude-code-desktop に変わるため、claude-code をキーにしたフィルターの更新が必要になる場合がある。Self-hosted runner の運用者は、OAuth トークンのプレフィックスに oat02- が追加されたため、プロキシルールやログスクラバーの更新が必要になる場合がある

必要なアクション

  1. アップデートの適用: フリーズ・ハング・メモリに関わる修正が非常に多いため、早期の更新を推奨する
  2. Foundry のモデルデプロイ確認: デフォルトモデルが Sonnet 5.5 になったため、claude-sonnet-5-5 のデプロイまたは ANTHROPIC_DEFAULT_SONNET_MODEL の設定を行う。Sonnet 4 / Opus 4 / Opus 4.1 へのピン止めは見直す
  3. Agent Platform のリージョン変数確認: VERTEX_REGION_CLAUDE_4_5_SONNET のみ設定している場合、VERTEX_REGION_CLAUDE_5_5_SONNET の追加を検討する
  4. OpenTelemetry フィルターの更新: service.name を claude-code で絞り込んでいる場合、claude-code-desktop を追加するか OTEL_SERVICE_NAME を設定する
  5. トークンマスキングルールの更新 (Self-hosted runner): oat01- 固定のマッチングを使っている場合、oat02- にも対応させ、値全体をマスクする
  6. computer-use という名前のスキル・コマンドの確認: Mac で computer use を使っている場合、同名の自作スキル・コマンドは読み込まれなくなるため、名前を変更する
移行ガイド (該当する場合): auto モードで開始させたくない場合、disableAutoMode を "disable" に設定して無効化できる。バージョン混在環境で PreSkillShellCommand を導入する場合はクライアントの更新を先行させる。SDK / claude -p でテキストを中継している場合、feature flags が取得されない環境では Opus 4.8 以降、ミッドターンのメッセージがユーザーのものとして扱われるため、中継テキストには isSynthetic: true を付ける

まとめ

Claude Code v2.1.332 は、MCP サーバー由来のスキル (ベータ) と PreSkillShellCommand フックによってスキルエコシステムを拡張し、名前付きパイプ・フックの暴走出力・MCP サーバーの出力フラッドなどに起因する多数のフリーズ・ハングを解消した安定性重視のリリースである。Sonnet 5.5 / Opus 5.5 世代への移行を反映し、Microsoft Foundry のデフォルトモデル変更と旧モデルの引退、Google Cloud Agent Platform のエイリアス更新、Bedrock のフォールバック改善など、サードパーティプロバイダーのモデル解決も大きく整理された。OpenTelemetry の service.name 変更や OAuth トークンプレフィックスの追加など、監視・運用設定の更新が必要になる変更も含まれるため、該当する組織は事前の確認を推奨する
