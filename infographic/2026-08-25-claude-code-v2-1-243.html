📅 発表日: 2026-08-25 | ソース: Claude Code Changelog

💰 コスト管理・可視化 🗄️ キャッシュ TTL 制御 🏢 組織向け機能の強化 ⚡ 起動・メモリ・サイズ改善

📋 概要 — 4 つのキーポイント

Claude Code v2.1.243 がリリースされた。約 60 項目におよぶ大規模なリリースであり、コスト管理とエンタープライズ運用に関わる新機能が多数追加された。v2.1.239 (8 月 21 日) の大規模リリース、v2.1.240 / v2.1.241 (8 月 22 日) のパッチリリースに続き、コスト可視化、キャッシュ戦略の制御、組織管理機能の強化という方向性が明確に表れている。

💰

コスト管理・可視化の強化

/usage に Loops 内訳が追加され、/loop タスクごとの実行回数・合計トークン数・実行あたりのトークン数・最終実行時刻を表示。暴走したループタスクを容易に発見できる。modelPricing 管理設定により、組織の契約単価とディスカウント率をコスト表示に反映できる。

🗄️

モデル・キャッシュ設定の柔軟化

modelPicker 設定で /model ピッカーの表示モデルをカスタマイズ可能に。promptCacheTtl / subagentPromptCacheTtl 設定により、メイン会話のプロンプトキャッシュを 1 時間に延長しつつサブエージェントは 5 分のまま維持するといった制御ができる。

🏢

認証・組織管理の強化

Anthropic Console アカウントでのキーレスサインインが追加され、API キーの発行を許可していない組織でもサインインできる。/status の Skipped sources 行、/mcp と /plugins の managed マーカーで管理状態の可視性が向上した。

⚡

大幅なパフォーマンス改善と信頼性修正

起動時のサンドボックスと MCP の初期化が初回描画をブロックしなくなり、バイナリは zstd 圧縮で約 340 MB から約 75 MB (Linux x64) に縮小、メモリは約 40〜70 MB 削減。リモート MCP サーバーの自動再接続、API 無応答時のタイムアウト処理など信頼性修正も多数含まれる。

⚡ パフォーマンス改善 — Before / After Improved

Before

  • サンドボックスと MCP の初期化が初回フレーム描画をブロック
  • ネイティブバイナリのダウンロードサイズは約 340 MB (Linux x64)
  • コードが起動時に一括読み込みされメモリを消費
  • 長時間セッションでヒープ増大時の GC が遅れがち

After

  • 初期化が初回描画をブロックせず、引数なし起動ではサブコマンド登録をスキップ
  • zstd 圧縮により約 75 MB に縮小 (約 78% 削減)
  • コードのオンデマンド読み込みでセッションあたり約 40〜70 MB のメモリ削減
  • ヒープ増大時により早くガベージコレクションが実行される
  • 🧰起動処理の軽量化: ワークフロー検出、設定、トラストストア処理も軽量化された
  • 🔐SSH 経由の /login を改善: サインイン URL が即座に表示され、c キーによるコピーの結果が正確に報告される
  • 🔁/loop の表示改善: Claude が何もすることのない連続起床を、ターミナル上で 1 行にまとめて表示

✨ 新機能 Added

💰 コスト管理・可視化

📊 /usage に Loops 内訳を追加

/loop タスクごとの実行回数、合計トークン数、実行あたりのトークン数、最終実行時刻を表示する。暴走したり無駄に会話の多いループタスクを容易に発見できる。

🏷️ modelPricing 管理設定

組織が契約しているモデル別単価とディスカウント率を設定でき、/cost、ステータスライン、テレメトリのコスト表示に定価ではなく契約価格が使用される。

🗄️ モデル・キャッシュ設定

🎛️ modelPicker 設定

/model ピッカーに表示するモデルを、順序付き・ラベル付きのリストでカスタマイズできる。Vertex / Bedrock 形式を含む任意のモデル ID 表記に対応し、組み込みリストへの追加または置き換えが可能。

⏱️ promptCacheTtl / subagentPromptCacheTtl 設定

API キーおよびクラウドプロバイダー経由のユーザーが、メイン会話のプロンプトキャッシュを 1 時間に延長しつつ、サブエージェントは 5 分のまま維持するといった制御ができる。

🏢 認証・組織管理

🔑 Console アカウントでのキーレスサインイン

/login → Anthropic Console に「Sign in with your Console account」(推奨) が追加された。API キーの発行を許可していない組織でもサインインできる。

📋 /status に Skipped sources 行を追加

より優先度の高い管理ソースが有効なために適用されなかった管理設定ソース (例: managed-settings.json) を一覧表示する。

🔖 /mcp と /plugins に managed マーカーを追加

組織が認証を管理している claude.ai コネクタを識別できる。

🧭 その他の新機能

  • 🤖サブエージェントのモデルと effort レベル表示: /tasks とエージェント詳細ダイアログに、各サブエージェントが実行されたモデルと effort レベルを表示
  • 🌐Claude Code on the web の接続状態表示: /status に Claude Code on the web (Pro/Max) の GitHub 接続状態を表示し、未接続の場合は /web-setup を案内

🔧 修正 Fixed

🔌 接続・信頼性

  • 🔁リモート MCP サーバーの再接続: 非対話モード (-p) および SDK セッションで、リモート MCP サーバーが切断後に復帰しない問題を修正。自動的に再接続するか、失敗として報告されるようになった
  • ⏲️API 無応答時のタイムアウト処理: Anthropic API が応答を開始しないままセッションが 10 分以上沈黙する問題を修正。約 3 分でタイムアウトして 1 回リトライし、それでも失敗した場合は API Error: No response from API を表示する
  • 🏗️CI でのワークロードアイデンティティフェデレーション: 同一ジョブ内のプロセスが交換済みトークンを共有するようになり、単回使用トークンの再交換による失敗がなくなった
  • 🚦過負荷時のツール呼び出し拒否: API が一時的に過負荷の際、auto モードのツール呼び出しが約 1 分の待機後に「temporarily unavailable」として拒否される問題を修正
  • 💤バックグラウンドサブエージェントの起床: バックグラウンドの Bash タスク完了時にバックグラウンドサブエージェントが起床しない問題を修正

⚙️ 設定・CLI

  • 🧩--agents のエラー処理: 不正な JSON やエージェント定義を黙って無視していた問題を修正。--mcp-config と同様に明確なエラーで終了する
  • 🪝hook の if 条件の誤発火: 条件 (例: Bash(cat *)) が、$() やバッククォートによるコマンド置換を含む無関係な Bash コマンドで発火する問題を修正
  • 🔄/resume の表示件数: 直近 50 セッションしか表示しなかった問題を修正。スクロールで追加読み込みされる
  • 🛜プロキシ設定の大文字・小文字対応: HTTPS_PROXY 環境で NO_PROXY の大文字表記しか設定していない場合に、ローカル IDE 接続がプロキシ経由になる問題を修正 (小文字表記 no_proxy との両対応)
  • ⌨️履歴検索の破損耐性: Ctrl+R 履歴検索と上矢印履歴が、~/.claude/history.jsonl の破損エントリで壊れる問題を修正
  • 🧱サンドボックス違反の詳細表示: ネットワーク違反の詳細が、ブロックされたコマンドの終了コードが 0 の場合に Bash ツール結果から欠落する問題を修正

🧩 VSCode 拡張

  • 🚩権限モードの初期化: 機能フラグ取得前に開始したセッション (インストール直後など) が、auto モードや設定済みのデフォルトモードではなくデフォルト権限モードで開く問題を修正
  • 🔍Focus ビューの折りたたみ: サブエージェントのツールアクティビティ中に、展開した Focus ビューのセクションが勝手に折りたたまれる問題を修正

🔄 変更 Changed

🌐 サンドボックスのネットワークホスト一覧を削除

サンドボックス化された Bash ツールのプロンプトから許可済みネットワークホストの一覧を削除。Claude が未掲載のホストをブロック済みと仮定せずリクエストを試行し、ユーザーが新しいホストを承認できるようになった。

💲 Sonnet 5 の価格表示を標準の定価に

/model ピッカーと同梱の claude-api スキルで、Sonnet 5 の $2/$10 per Mtok 価格を期間限定プロモーションではなく標準の定価として表示。

⚡ /model・/fast・/effort の即時実行

Bedrock / Vertex / Foundry 環境およびテレメトリ無効時も、ターン終了を待たず即座に実行されるようになった。

🖥️ macOS computer use の Finder 権限

デスクトップ・Dock・Finder ウィンドウのクリックには、他のアプリと同様に Finder へのアクセス許可が必要になった。

🔬 技術的な詳細 — 新しい設定項目

新しい設定項目の位置付けは以下のとおりである。

設定 種別 用途
modelPicker ユーザー / 組織設定 /model ピッカーの表示モデルをカスタマイズ
promptCacheTtl ユーザー設定 メイン会話のプロンプトキャッシュ TTL (例: 1 時間)
subagentPromptCacheTtl ユーザー設定 サブエージェントのキャッシュ TTL (デフォルト 5 分相当)
modelPricing 管理設定 (managed) 組織の契約単価・ディスカウント率をコスト表示に反映

⏱️ プロンプトキャッシュ TTL の使い分け

プロンプトキャッシュの TTL 制御は、API キーおよび Bedrock / Vertex などのクラウドプロバイダー経由の利用者が対象である。長時間の作業ではメイン会話のキャッシュを 1 時間に延長することでキャッシュミスによる再課金を抑えられる一方、短命なサブエージェントは 5 分のままにしてキャッシュ書き込みコストを抑える、といった使い分けができる。

💼 ユースケース / 開発者への影響

対象: Claude Code を利用しているすべてのユーザー (起動時間・メモリ・ダウンロードサイズの改善)、/loop を活用しているユーザー、API キーや Bedrock / Vertex 経由でキャッシュコストを最適化したいユーザー、契約単価でコストを管理したい組織や API キー発行を許可していない組織の管理者、非対話モードや SDK でリモート MCP サーバーを利用しているユーザー、CI でワークロードアイデンティティフェデレーションを利用しているチーム。

💰 キャッシュコストを最適化したい API キー / Bedrock / Vertex 利用者

promptCacheTtl でメイン会話のキャッシュを 1 時間に延長すれば、長時間の作業でキャッシュミスによる再課金を抑えられる。subagentPromptCacheTtl により短命なサブエージェントは 5 分のままにしてキャッシュ書き込みコストを抑える、という使い分けができる。/usage の Loops 内訳とあわせて、トークン消費の多いループタスクの発見とコスト最適化のサイクルを回せる。

🏢 契約単価でコストを管理したい組織・API キー発行を制限している組織

modelPricing 管理設定により、/cost、ステータスライン、テレメトリのコスト表示が定価ではなく組織の契約価格を反映するようになり、実際の請求額に即したコスト管理ができる。Console アカウントのキーレスサインインにより、API キーの発行を許可していない組織のメンバーもサインイン可能に。Skipped sources 行と managed マーカーで、管理設定の適用状況と組織管理のコネクタを可視化できる。

🤖 SDK・CI・自動化パイプラインで Claude Code を利用するチーム

非対話モード (-p) および SDK セッションでのリモート MCP サーバーの自動再接続、API 無応答時の約 3 分でのタイムアウトとリトライ、CI でのワークロードアイデンティティフェデレーションのトークン共有修正など、長時間運用や自動化パイプラインでの信頼性に直結する修正が多く、特に恩恵が大きい。

📝 まとめ

Claude Code v2.1.243 は、以下の 3 つの軸で大きく前進したリリースである。

1

コスト管理 — Loops 内訳・契約単価反映・キャッシュ TTL 制御

/usage の Loops 内訳でループタスクごとのトークン消費を可視化し、modelPricing で組織の契約価格をコスト表示に反映。promptCacheTtl / subagentPromptCacheTtl によりプロンプトキャッシュのコスト戦略を制御できるようになった。

2

組織向け機能 — キーレスサインイン・managed マーカー・Skipped sources 表示

Console アカウントでのキーレスサインインにより API キー発行を制限している組織でも利用しやすくなり、/status の Skipped sources 行と /mcp / /plugins の managed マーカーで管理状態の透明性が向上した。

3

パフォーマンス — 起動高速化・バイナリ約 75 MB への縮小・メモリ約 40〜70 MB 削減

起動時の初期化が初回描画をブロックしなくなり、バイナリは zstd 圧縮で約 340 MB から約 75 MB (Linux x64) へ縮小、メモリはセッションあたり約 40〜70 MB 削減された。

💡 アップデート推奨

リモート MCP サーバーの自動再接続や API 無応答時のタイムアウト処理など、長時間運用や自動化パイプラインでの信頼性に直結する修正も多く、SDK や CI で Claude Code を利用しているチームには特に恩恵が大きい。破壊的変更はないため、速やかなアップデートを推奨する。
