Claude Code v2.1.283

モデル統制の managed 設定強化、/doctor prompt-audit の追加、MCP・プラグイン管理の広範な信頼性改善

📅 2026-09-25 ｜ ソース: Claude Code Changelog

概要

Claude Code v2.1.283 がリリースされました。約 94 項目の変更を含むリリースで、エンタープライズ向けのモデル統制機能の強化と、MCP・プラグイン管理を中心とした広範な信頼性改善が特徴です。約 176 項目の変更を含んだ 2026-09-23 の v2.1.281 に続く大型のメンテナンスリリースです。

🏢

モデル統制の managed 設定 (エンタープライズ向け)

組織管理者向けに、許可リストの厳密一致を実現する availableModelsMatch と、明示的な拒否リストである deniedModels の 2 つの managed 設定が追加されました。

🩺

/doctor prompt-audit の追加

CLAUDE.md ファイル、スキル、エージェント、コマンドを監査し、古いモデル向けに書かれたプロンプトパターンを検出します。プロンプト資産をモデルの進化に追随させる実用的なツールです。

🛡️

セキュリティ・データ保全の修正

Windows の PowerShell ツールがドライブルートなどの削除を許してしまう問題や、大文字小文字のみが異なるプラグイン ID の誤削除といった、安全性に関わる修正が行われました。

🔌

MCP・プラグイン管理の広範な信頼性改善

MCP サーバーの接続・進捗通知・サインイン、プラグインの検証・キャッシュ・installed_plugins.json に関する多数の修正が含まれています。

🔄

デフォルトパーミッションモードの変更

サードパーティプロバイダー上、またはテレメトリ無効の対話型セッションは、パーミッションモード未設定の場合 auto mode で開始されるようになりました。v2.1.282 で導入された claude-ai 名の予約の取り消しも含まれます。

主要機能

📋 availableModelsMatch

"exact" を指定すると、availableModels のエントリはそこに記載されたモデルバージョンのみを許可します。新しいモデルがリリースされても、リストに追加されるまでブロックされたままになります。

🚫 deniedModels

特定のモデルをブロックする managed 設定です。availableModels が許可しているモデルであってもブロックでき、許可リストと拒否リストの組み合わせで利用可能なモデルを厳密に統制できます。

🩺 /doctor prompt-audit

CLAUDE.md ファイル、スキル、エージェント、コマンドを監査し、古いモデル向けのプロンプトパターンを検出します (/checkup prompt-audit も可)。古いパス・古いコマンド・矛盾する指示ファイルがレポートの先頭に表示されます。

🔗 x-claude-code-prompt-id ヘッダー

LLM ゲートウェイが 1 つのユーザープロンプトに対応するリクエスト群をグループ化できるヒントヘッダーです。CLAUDE_CODE_GATEWAY_HINT_HEADERS=1 でオプトインします。

🧪 gateway の load_test_mode / mantle

load_test_mode ではリクエストは構築・署名されますが upstream には送信されず、定型の応答が返るため、デプロイメントの負荷テストに利用できます。Amazon Bedrock の Mantle エンドポイント向けの mantle upstream プロバイダーも追加されました。

1. モデル統制の managed 設定 (エンタープライズ向け)

組織管理者向けに、モデル利用を制御する 2 つの managed 設定が追加されました。これにより、組織は「許可リストの厳密一致」と「明示的な拒否リスト」を組み合わせて、利用可能なモデルを厳密に統制できるようになりました。

  • 📋 availableModelsMatch "exact" を指定すると、availableModels のエントリはそこに記載されたモデルバージョンのみを許可します。新しいモデルがリリースされても、リストに追加されるまでブロックされたままになります。
  • 🚫 deniedModels 特定のモデルをブロックする設定です。availableModels が許可しているモデルであってもブロックできます。

2. 新機能

  • 🩺 /doctor prompt-audit (/checkup prompt-audit も可) CLAUDE.md ファイル、スキル、エージェント、コマンドを監査し、古いモデル向けに書かれたプロンプトパターンを検出します。あわせて、Claude Code の設定に対する prompt-audit も改善され、古いパス・古いコマンド・矛盾する指示ファイルがレポートの先頭に表示され、Claude Code がドキュメント化している thinking キーワードは保持されるようになりました。
  • 🔗 x-claude-code-prompt-id ゲートウェイヒントヘッダー LLM ゲートウェイが 1 つのユーザープロンプトに対応するリクエスト群をグループ化できるようになりました。CLAUDE_CODE_GATEWAY_HINT_HEADERS=1 でオプトインします。
  • 📊 OpenTelemetry の tool.output 拡張 OTEL_LOG_TOOL_CONTENT=1 のとき、MCP ツール、WebFetch、WebSearch の出力も tool.output スパンイベントに含まれるようになりました。
  • 🧪 Claude apps gateway の load_test_mode オプトインの設定ブロックで、リクエストは構築・署名されますが upstream には送信されず、クライアントには定型の応答が返ります。デプロイメントの負荷テストに利用できます。
  • ☁️ Claude apps gateway の mantle upstream プロバイダー Amazon Bedrock の Mantle エンドポイント向けプロバイダーが追加されました。
  • 📄 stream-json の plugin_errors に path を追加 --plugin-dir のロード失敗エントリに、ロードできなかったディレクトリを示す path が含まれるようになりました。
  • 🖱️ フルスクリーンモードの click-to-expand 他のセッションからの切り詰められたメッセージをクリックで展開できるようになりました。

3. セキュリティ・データ保全に関わる修正

  • 🪟 Windows の PowerShell ツールの削除保護 cmd /c rd、rmdir、del、erase により、Remove-Item が拒否するドライブルート、ホームフォルダーなどの削除が可能になっていた問題を修正しました。
  • 🧩 プラグインの誤削除の修正 大文字小文字のみが異なる ID を持つ 2 つのプラグインがインストールされている場合に、claude plugin uninstall が指定していない側のプラグインをオプションやシークレットごと削除してしまうことがある問題を修正しました (指定した側にそのスコープの enabledPlugins エントリがない場合に発生)。
  • 🔒 managed sandbox 設定の fail-closed 化 ネストされた値が 1 つ無効なだけで managed sandbox 設定全体が無視されていた問題を修正しました。無効な値は fail-closed となり、ブロックの残りの部分は引き続き適用されます。
  • 🔑 サンドボックス内 git の認証情報 サンドボックス化された git が credential helper にサンドボックスプロキシのログイン情報の保存を要求し、「failed to store」が表示される問題を修正しました。

4. MCP 関連の修正・改善

MCP サーバーの利用に関する修正が多数含まれています。

  • 📶 バックグラウンド移動後の進捗通知 長時間実行のツールコールがバックグラウンドに移動した後、MCP の進捗通知が破棄されていた問題を修正しました。バックグラウンドタスクに最新の進捗が表示されるようになりました。
  • 🛑 stdio MCP サーバーの残留を修正 セッション終了時に起動中だった stdio MCP サーバーが実行されたまま残る問題を修正しました。
  • 🌐 一時的な HTTP 404 からの回復 ステートレスなリモート MCP サーバー (再デプロイ中のプロキシなど) からの一時的な HTTP 404 により、接続中と表示されたままそのサーバーがセッションの残りの間使用不能になる問題を修正しました。
  • 🔐 サインインの改善 有効な URL を持たないサーバーへの MCP サインインが不明瞭な SDK エラーで失敗していた問題を修正し、/mcp はそのようなサーバーに Authenticate を表示しなくなりました。サインイン後に表示されるブラウザページも改善されました (中央揃えレイアウト、ダークモード、新しいアートワーク)。
  • 🧮 /context での instructions のカウント /context が MCP サーバーの instructions をカウントしていなかった問題を修正しました。専用の行として表示され、合計にも含まれるようになりました。
  • 📜 /mcp のツールリスト改善 一度により多くのツールを表示し、ページキーとマウスでスクロールでき、組織がブロックしたツールには警告アイコンが付くようになりました。
  • 🖼️ MCP ツールの画像のファイル保存 MCP ツールが返す画像がファイルにも保存されるようになり、Bash や Read などのツールから開けるようになりました。

5. プラグイン管理の修正・改善

  • 🔍 claude plugin validate の検証強化 Claude Code がインストールできないプラグイン名・マーケットプレイス名を許容していた問題を修正し、marketplace.json 内のそのような名前は検証エラーになります。また、outputStyles、themes、monitors、lspServers のパスが存在しない、またはプラグインディレクトリ外を指すプラグインを合格させていた問題も修正されました。
  • 📊 claude plugin details の表示修正 plugin.json で MCP サーバーを宣言しているプラグインに対して 0 servers と表示していた問題を修正しました。
  • 🗂️ claude plugin marketplace remove の改善 マーケットプレイスとともにアンインストールしたプラグインを列挙するようになりました。
  • 💾 キャッシュ復元の修正 バージョンを宣言していないプラグインのキャッシュファイルが失われた場合に、インストール済みのコミットではなくソースの最新コミットで暗黙に復元されていた問題を修正しました。ホームディレクトリや設定ディレクトリの移動後 (bind マウントされた devcontainer など) に「cache-miss」でロードに失敗する問題も修正されました。
  • 🧾 installed_plugins.json の保全 無効なプラグイン ID のレコードを含むファイルが再びロードできるようになり、読み取れないレコードを含む場合もファイルが書き換えられてレコードが失われることはなくなりました。まったく読み取れない場合は、再構築前に内容が隣のファイルに保全され、claude plugin list がそのファイル名を案内します。
  • 💬 Skill ツールのエラーメッセージ改善 プラグインのロードに失敗した場合、Skill ツールはスキルを「未インストール」と呼ぶ代わりに、プラグインがロードできなかったことを伝えるようになりました。

  • 🔁 フォールバック中の dynamic workflows モデルフォールバック中に開始された dynamic workflows が、設定されたモデルを再試行せず、すべてのエージェントをフォールバックモデルで実行していた問題を修正しました。

9. 動作変更

⚠️ デフォルトパーミッションモードの変更

サードパーティプロバイダー上、またはテレメトリ無効の対話型セッションは、パーミッションモードが未設定の場合 auto mode で開始されるようになりました。permissions.defaultMode の設定は引き続き優先されます。

  • ↩️ claude-ai 名の予約の取り消し v2.1.282 での予約が取り消され、この名前を持つスキル・コマンド・ワークフロー・MCP サーバーのスキルとプロンプトが再びロードされるようになりました。Skill(claude-ai:*) ルールは通常のプレフィックスルールに戻りました。
  • 🚷 Skill の deny ルールの拡張 Skill(anthropic-skills:<name>) の deny ルールは、Claude Desktop がプラグインとして配信するスキルもブロックし、Skill(skill:<name>) の deny はスキルのエイリアスと表示名にもマッチするようになりました。
  • 📝 --system-prompt / --append-system-prompt の併用 テキスト形式と -file 形式を同時に指定できるようになりました。ファイルのテキストが先に配置されます。
  • 🔧 claude plugin eval の git 要件 git がインストールされている場合、git 2.31 以降が必須になりました。古い git での実行はバージョンを明示したメッセージとともに拒否されます。
  • 🔎 /ultrareview の起動ダイアログ ローカルブランチのレビューでは、追跡ファイルの未コミット変更がアップロードされる可能性がある旨を表示するようになりました。
  • 🖥️ /model ピッカーの表示 Opus がすでに 1M コンテキストウィンドウを持つ環境では、Opus の行とデフォルトモデル名から「(1M context)」表記が削除されました。ウィンドウ自体は変更されていません。
  • 💡 プロンプト候補の頻度調整 ターミナルのプロンプト候補は、20 回連続で未使用の場合に表示頻度が下がります。候補を使用すると元に戻ります。
  • 👁️ Artifact の自動 watch 自動的に開始された watch は、アクティビティのない状態が 3.5 時間続くと終了します。公開または再度の watch で再開されます。
  • 🌲 worktree のチェックアウト CA 証明書が GIT_CONFIG_COUNT 環境変数ペアとして git に渡されている場合に、証明書検証 (Git LFS ダウンロードなど) が失敗する問題を修正しました。
  • 🧠 auto-memory の修正 git リポジトリのサブディレクトリで Claude Code を起動した場合に、Claude 自身の auto-memory ノートへの編集が機密ファイル書き込みとしてブロックされていた問題を修正しました。
  • 🏃 セルフホストランナーの git の変更 ライフサイクルフックの git はリポジトリの Git LFS pre-push フックをスキップし、書き込み可能なシステム core.hooksPath を無視し、--configure-git なしではコミットに署名しなくなりました。また、Anthropic 管理の git では GIT_SSL_CAINFO と GIT_SSL_NO_VERIFY の扱いが変わり、ランナー自身の git は Anthropic の git ルートを常に検証します。

10. VS Code / Cloud sessions / Claude Tag / Code Review の修正 (抜粋)

  • 🧰 VS Code auto mode や bypass mode からの自動切り替えが失敗した後も、パーミッションモードインジケーターが Default と表示され続ける問題を修正しました (切り替えは成功するまで再試行されます)。Web からテレポートしたセッションが作業中に送信されたメッセージを失う問題、空のローカルコピーが原因で Web セッションがリストから隠れる問題、再オープンしたセッションのターン分割や巻き戻し済みターンの表示に関する問題なども修正されました。
  • ☁️ Cloud sessions GitHub アカウントで読み取り可能だがプッシュ権限のないプライベートリポジトリを、実行中のセッションに読み取り用として追加できるようになりました。サーバー側の再起動からの復旧後に、完了済みのステップ (コメントやプッシュの重複投稿など) を再実行することがある問題も修正されました。新しいルーチンスケジュールは毎時数分過ぎがデフォルトとなり、正時ちょうどのルーチンは数分遅れて開始される可能性がある旨の注記が追加されました。
  • 💬 Claude Tag (Slack) Claude の Slack 検索を、追加済みのパブリックチャンネルに制限する「Channels Claude can search」管理者設定が追加されました (組織・ワークスペース・チャンネル単位で設定可能)。Claude アカウント接続後のページに Back to Slack ボタンが追加されたほか、attach ルール経由のアクセスバンドル表示、大量の選択リポジトリを持つ GitHub App インストールでのリポジトリ検索、返信の重複投稿、Slack Connect 共有後のチャンネル ID 変更によるルーチン停止などの問題を修正しました。
  • 🔍 Code Review GitHub が pull request を返せなかった場合に「@claude review」が沈黙する問題を修正しました (1 回再試行され、それでも失敗した場合はコメントで説明されます)。何も検証できないまま時間制限で停止したレビューは incomplete と表示され、課金されず、1 回再試行されるようになりました。

ユースケース

🏢 エンタープライズでのモデルガバナンス

managed 設定の availableModelsMatch: "exact" により、availableModels に記載されたモデルバージョンのみを許可し、新しいモデルがリリースされてもリストに追加されるまでブロックできます。さらに deniedModels を組み合わせることで、許可リストが許容しているモデルであっても明示的にブロックでき、組織のコンプライアンス要件に沿った厳密なモデル統制を実現できます。

🩺 プロンプト資産のメンテナンス

CLAUDE.md、スキル、エージェント、コマンドといったプロンプト資産を運用しているチームは、/doctor prompt-audit を実行することで、古いモデル向けに書かれたプロンプトパターン、古いパス・コマンド、矛盾する指示ファイルを一括で洗い出し、モデルの進化に合わせてプロンプト資産を最新の状態に保てます。

🔗 LLM ゲートウェイでのリクエスト追跡と負荷テスト

CLAUDE_CODE_GATEWAY_HINT_HEADERS=1 をオプトインすると、ゲートウェイは x-claude-code-prompt-id ヘッダーで 1 つのユーザープロンプトに対応するリクエスト群をグループ化できます。また、Claude apps gateway の load_test_mode を使用すると、upstream にリクエストを送信せずにデプロイメントの負荷テストを実施できます。

まとめ

Claude Code v2.1.283 は、約 94 項目の変更を含むメンテナンスリリースです。availableModelsMatch と deniedModels によるモデル統制の強化はエンタープライズ環境でのガバナンスを前進させ、/doctor prompt-audit はプロンプト資産をモデルの進化に追随させる実用的なツールとなります。Windows の PowerShell ツールの削除保護やプラグインの誤削除防止といった安全性の修正に加え、MCP サーバーの接続・進捗通知、プラグイン管理、リスト UI、初回レスポンスのレイテンシなど、日常的な利用体験に直結する改善が広範囲に行われています。サードパーティプロバイダーやテレメトリ無効環境でのデフォルトパーミッションモードの変更には注意が必要です。
