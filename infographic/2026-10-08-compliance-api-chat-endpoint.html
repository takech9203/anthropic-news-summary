Compliance API ベータ

Compliance API のチャットエンドポイントが
統合 Claude 体験のチャットに対応

📅 2026-10-08 | Claude Developer Platform Release Notes

概要

💬

統合 Claude 体験のチャットが監査カバレッジに追加

Compliance API のチャットエンドポイントが、統合 Claude 体験 (unified Claude experience) のチャットも返すようになった。クラウド上のセッションに続くチャットも、分割されずに 1 つのチャットとして取得できる。

🏢

Claude Enterprise 組織向けベータ

このカバレッジは Claude Enterprise 組織向けのベータとして提供される。本番の監査要件に組み込む場合は、仕様が変わる可能性を考慮する必要がある。

🔑

既存の Compliance Access Key でそのまま利用可能

新しいキー、スコープ、設定は一切不要。既存の Compliance Access Key と read:compliance_user_data スコープのインテグレーションに、統合 Claude 体験のチャットが自動的に現れる。

🧩

クラウドセッションの作業はツールブロックで表現

クラウドセッションで Claude が実行した作業は、各メッセージの content 内の tool_use ブロック (name と input) と tool_result ブロック (tool_use_id で対応付けられた出力) として現れる。

📈

チャットとセッションの両系統でカバレッジ拡大が継続

セッションエンドポイント側は 2026 年 8 月以降 Cowork、Claude Code、Claude Science、Claude for Microsoft 365、Claude in Chrome へと拡大。今回はチャットエンドポイント側の拡張である。

主な機能

📋 チャット一覧 / メッセージ取得 / 削除

既存の 3 つのチャットエンドポイント (一覧、メッセージ取得、ハード削除) がそのまま統合 Claude 体験のチャットに対応。エンドポイント URL、認証、フィルター、ページング、レスポンス形式に破壊的変更はない。

🧰 tool_use / tool_result ブロック

クラウドセッションでの作業内容は、メッセージの content 内のツールブロックとして記録される。tool_use はツールの name と input を、tool_result は tool_use_id で紐づく出力を保持する。

🔄 既存パイプラインへの自動流入

order_by=updated_at の組織全体ページネーションループなど、従来のエクスポートベストプラクティスは変更なし。統合 Claude 体験のチャットは既存のエクスポートループに自動的に流入する。

🗑️ 削除時のクラウドセッション連動

Delete chat で統合 Claude 体験のチャットを削除すると、そのチャットのために開始されたクラウド上のセッションも削除される。削除は即時かつ永久で、復元はできない。

📎 ファイル / アーティファクトの取得

各メッセージには files (添付ファイル)、generated_files (Claude が生成したファイル)、artifacts (バージョン管理付きドキュメント) が含まれ得る。実体は id をコンテンツエンドポイントに渡してダウンロードする。

技術詳細

🔌 対象エンドポイント

エンドポイント 役割
GET /v1/compliance/apps/chats チャットメタデータの一覧
GET /v1/compliance/apps/chats/{chat_id}/messages 単一チャットの全メッセージ取得
DELETE /v1/compliance/apps/chats/{chat_id} チャットのハード削除

🔐 認証とスコープ

🔑 read:compliance_user_data — 取得に必要 🗝️ delete:compliance_user_data — 削除に追加で必要

チャット、ファイル、プロジェクト系のエンドポイントは Compliance Access Key (sk-ant-api01-...) 専用。Admin API キー (sk-ant-admin01-...) では 403 Forbidden が返る。

🗂️ チャットオブジェクトの形式

統合 Claude 体験のチャットは、他のチャットと同じ claude_chat_ 接頭辞のオブジェクトとして返る。メッセージ取得エンドポイントは、チャットのメタデータと created_at でソートされた chat_messages 配列を返す。ユーザーが claude.ai で削除したチャットは deleted_at が設定された状態で一覧に返り、メッセージは内容なしで返る (従来どおり)。

コードサンプル

Bash チャット一覧の増分エクスポート (組織全体、更新日時順) 
# 組織全体のチャットを updated_at 順で取得する。統合 Claude 体験の
# チャットも同じ一覧に自動的に含まれる
curl --fail-with-body -sS -G \
  "https://api.anthropic.com/v1/compliance/apps/chats" \
  --header "x-api-key: $ANTHROPIC_COMPLIANCE_ACCESS_KEY" \
  --header "anthropic-version: 2023-06-01" \
  --data-urlencode "order_by=updated_at" \
  --data-urlencode "updated_at.gte=2026-10-08T00:00:00Z" \
  --data-urlencode "limit=100"
Bash チャットメッセージの取得 (ツールブロックを含む) 
# 統合 Claude 体験のチャットでは、クラウドセッションでの作業が
# content 内の tool_use / tool_result ブロックとして返る
chat_id="claude_chat_01H5CWunD7RpVJ5bHa8RCkja"

curl --fail-with-body -sS \
  "https://api.anthropic.com/v1/compliance/apps/chats/$chat_id/messages" \
  --header "x-api-key: $ANTHROPIC_COMPLIANCE_ACCESS_KEY" \
  --header "anthropic-version: 2023-06-01"
Python ツールブロックの処理例 (前方互換) 
# メッセージの content からテキストとツールの作業内容を振り分ける。
# 未知のブロックタイプは落とさずに通過させる (前方互換)
def extract_blocks(message: dict) -> dict:
    texts, tool_uses, tool_results, unknown = [], [], [], []
    for block in message.get("content", []):
        block_type = block.get("type")
        if block_type == "text":
            texts.append(block["text"])
        elif block_type == "tool_use":
            # クラウドセッションで実行されたツール呼び出し (name と input)
            tool_uses.append({"name": block.get("name"), "input": block.get("input")})
        elif block_type == "tool_result":
            # tool_use_id で対応するツール呼び出しに紐づく出力
            tool_results.append({"tool_use_id": block.get("tool_use_id")})
        else:
            unknown.append(block_type)
    return {
        "texts": texts,
        "tool_uses": tool_uses,
        "tool_results": tool_results,
        "unknown": unknown,
    }

注意点

⚠️ Delete chat はクラウドセッションも削除する

統合 Claude 体験のチャットを Delete chat で削除すると、そのチャットのために開始されたクラウド上のセッションも削除される。削除運用では以下の境界を把握しておく必要がある。

  • 削除されるのは「そのチャットのために開始されたセッション」まで。それらのセッションがさらに開始したセッションは削除されない
  • 削除は即時かつ永久であり、復元はできない
  • 削除には delete:compliance_user_data スコープが別途必要

🧪 ベータ提供であることの考慮

統合 Claude 体験のチャットカバレッジはベータであり、仕様が変わる可能性がある。本番の監査要件に組み込む場合は、この前提を関係者に明示する。また、クラウドセッションでの作業はツールブロックを通じて見える範囲に限られるため、何がトランスクリプトに現れ、何が現れないかを監査要件の関係者と確認する。

ユースケース

🛡️ 監査 / セキュリティ監視

セキュリティチームは SIEM や DLP にチャット内容を取り込み、機微情報を扱うやり取りを監視できる。統合 Claude 体験のチャットが加わることで、チャットから始まりクラウドセッションに続く作業も、ツールブロックを通じて監視対象に含められる。

⚖️ eDiscovery (電子証拠開示)

コンプライアンス / eDiscovery 担当者は、統合 Claude 体験でのやり取り (チャットとクラウドセッションでの作業) を 1 つのチャットとして証跡取得できる。クラウドセッションでの作業内容も tool_use / tool_result ブロックとしてエクスポートに含まれる。

🗄️ データガバナンス / アカウント削除対応

データガバナンス担当者は、Delete chat によるハード削除で統合 Claude 体験のチャットと、そのチャットのために開始されたクラウドセッションをまとめて削除できる。アカウント削除要求や保持ポリシーの運用に組み込める。

必要なアクション

既存インテグレーションの確認

追加設定は不要だが、既存のチャットエクスポートに統合 Claude 体験のチャットが流入し始める。tool_use / tool_result ブロックを含むメッセージを正しく処理できるか、パーサーや表示系を確認する。

ツールブロックの監査上の位置づけの整理

クラウドセッションでの作業はツールブロックを通じて見える範囲に限られる。何がトランスクリプトに現れ、何が現れないかを監査要件の関係者と確認する。

削除運用の見直し

Delete chat がクラウドセッションも削除する一方、それらのセッションが開始したセッションは残る。削除手順書にこの挙動を反映する。

ベータであることの考慮

本番の監査要件に組み込む場合は、ベータ提供であり仕様が変わる可能性があるという前提を明示する。
