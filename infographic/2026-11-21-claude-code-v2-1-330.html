Claude Code v2.1.330

Enterprise Admin Console 管理組織へのサインイン対応とチャート描画 mod「easel」を含む 142 項目のアップデート

📅 2026-11-21 (npm 公開: 2026-11-20 UTC) | ソース: Claude Code Changelog

概要 - キーポイント

🏢

Enterprise Admin Console 管理組織へのサインイン対応 (重要)

claude auth login の後に組織の設定が適用され、組織のクラウドプロバイダーまたはゲートウェイが使用される。各開発者のローカル設定に頼らず、組織側で一元管理された設定・接続先を Claude Code に適用できるようになった

📊

チャート描画の組み込み mod「easel」を追加

チャートの作成を依頼したときと、MCP メトリクス結果の下にチャートを描画する。対象は Pro / Max (利用可能な場合は Team / Enterprise) の macOS / Linux。自動チャート描画は /config でオフにできる

🧊

フリーズ・データ消失の集中的な修正

非常に長い会話のコンパクト直後に数分間フリーズする問題、WebFetch がセッションを数分間フリーズさせる問題を修正。複数プロセスの同時保存によるユーザー設定・プラグインリスト・タスクメタデータの消失も解消

⏰

スケジュールタスクと /loop の実行期間を 30 日に延長

セッションが動き続けている間、従来の 7 日ではなく最大 30 日まで実行される。ただしこのリリースより前に作成されたタスクは 7 日のままのため、必要に応じて作成し直す

🔄

max_tokens 自動リトライの復活 (重要)

v2.1.329 で削除された、モデルやゲートウェイの上限を超えた場合の自動リトライが本バージョンで復活した。前リリースで CLAUDE_CODE_MAX_OUTPUT_TOKENS の設定を案内されていたユーザーは必要性を再確認する

主要な変更点

🏢 Enterprise Admin Console 対応とサインイン改善

  • claude auth login の後に組織の設定が適用され、組織のクラウドプロバイダーまたはゲートウェイを使用
  • /login、claude auth login、claude setup-token のサインインリンクが大幅に短縮
  • 短いリンクがエラーになる場合は CLAUDE_CODE_FULL_SIGN_IN_LINK=1 で完全なリンクを表示
  • forceLoginOrgUUID が一時的なサーバーエラー 1 回で起動を拒否する問題を修正

📊 easel: チャート描画の組み込み mod

  • チャート作成の依頼時と MCP メトリクス結果の下にチャートを描画
  • 対象: Pro / Max、利用可能な場合は Team / Enterprise (macOS / Linux)
  • 自動チャート描画は /config でオフにできる
  • Code Mode で組み込みチャートツールの呼び出しが失敗する問題と、許可リスト / 拒否リスト除外時の "MCP server blocked by enterprise policy: easel" 警告を修正

🧊 フリーズの修正

  • 非常に長い会話のコンパクト直後に最大数分間フリーズする問題を修正
  • WebFetch が一部ページでセッションを数分間フリーズさせる問題と空の結果を返す問題を修正
  • Linux / WSL で 2 分以上のスリープ後に切断済みコネクションを 3 分間待つ問題を修正
  • Linux の大きな ignore フォルダーによる Bash 遅延、Windows の Git Bash 起動後の Bash 遅延を修正

🛡️ 同時実行によるデータ消失の修正

  • 複数の Claude Code プロセスの同時保存でユーザー設定の変更が失われる問題を修正
  • 複数の claude plugin コマンドの同時実行でプラグインが消える問題を修正
  • 複数のタスク更新の同時実行でタスクの依存関係とメタデータが失われる問題を修正
  • ExitWorktree が別の実行中セッションの worktree を削除してしまう問題を修正

⏰ スケジュールタスク / /loop の 30 日化

  • セッションが動き続けている間、従来の 7 日ではなく最大 30 日まで実行
  • 終了時にはその旨が通知される
  • 注意: このリリースより前に作成されたタスクは引き続き 7 日で終了。30 日が必要な場合はタスクを作成し直す

⚙️ Code Mode の修正と改善

  • 数百のファイルを読むコードの後の長い停止と、Esc / /compact 後にファイルが復元されない問題を修正
  • auto / bypass permissions モードでの MCP ツールのターン終了要求の無視と、プロンプトキャッシュの書き直しを修正
  • /context のシステムツール過少カウントを修正。画像・PDF の見方が Claude に伝えられるように
  • Esc 後は赤いエラーではなく "Interrupted" と表示。サブエージェントの数千回のツール呼び出し後のフリーズ時間を大幅短縮

🏃 Self-hosted runner の更新 (20 項目超)

  • --start-dir / SELF_HOSTED_RUNNER_START_DIR でリポジトリ内の指定フォルダーから作業開始
  • /metrics に作業指示から登録受理・最初のセッション引き渡しまでの秒数メトリクスを追加
  • IP 許可リストなどの 403 が不正なシークレットとして記録される問題を修正 (旧文言のログアラートは更新が必要)
  • spawn-runner フックの並行実行化 (デフォルト 4)、不要な Bash diff の省略、終了コード 108 での即時停止

💻 VS Code 拡張の更新 (28 項目)

  • /fork (最後の応答の後で会話をフォーク) と /workflows (エージェントマップ) を追加
  • claudeCode.escapeStopsClaude、claudeCode.pinPrompt、claudeCode.contextUsageThreshold の設定を追加
  • Enter 長押しや Remove / Delete ダブルクリックによる誤操作が確認なしで実行される問題を修正
  • macOS のキー操作、diff の Accept / Reject ボタン、フォークの二重実行、コードブロックコピーの末尾改行を修正

✨ そのほかの新機能と改善

  • claude plugin install --json に commandPrinted と commandFailed を追加
  • /config 検索の改善 ("effort" で Model、"dark" や "light" で Theme が見つかる)
  • /resume に画面を開いて離れただけのセッションが表示されなくなった
  • Windows の Grep / Glob / ファイル diff を高速化。/ultrareview は月間支出上限の残額を表示

🏃 Self-hosted runner の開始フォルダー指定

リポジトリ内の特定フォルダー (モノレポのサブプロジェクトなど) から作業を開始させる場合は、--start-dir または環境変数を使用する。設定とフックの読み込みは指定なしの場合と同じである。

Bash 開始フォルダーの指定 
# コマンドラインオプションで指定
claude self-hosted-runner --start-dir packages/web-app

# 環境変数で指定
export SELF_HOSTED_RUNNER_START_DIR=packages/web-app

🔑 完全なサインインリンクの表示

短縮されたサインインリンクがエラーになる場合や、スクリプトがリンクから値を読み取る場合は、環境変数で完全なリンクを表示する。

Bash 完全なサインインリンクを表示 
CLAUDE_CODE_FULL_SIGN_IN_LINK=1 claude auth login

📝 Self-hosted runner のファイル diff を常に取得する - Before / After

Before (〜 v2.1.329)

Bash コマンドのファイル diff は常に取得され、トランスクリプトに含まれていた

After (v2.1.330 〜)

不要な場合は Bash コマンドのファイル diff が省略される。監査などですべての diff が必要な場合は managed settings で bashEditDiffEnabled を true に設定する

JSON managed settings - すべての Bash diff を取得 
{
  "bashEditDiffEnabled": true
}

カテゴリ別の修正・変更の要約

🐛 そのほかの重要な修正

  • 多数の MCP ツールが API に拒否される入力スキーマを持つ場合に、ターンが "JSON schema is invalid" で失敗し、セッションファイルが数メガバイト単位で肥大化する問題を修正
  • ディスク満杯時に ~/.claude.json の不完全なバックアップが正常なバックアップを押しのける問題を修正
  • 最後のメッセージのタイムスタンプが欠落・不正な場合に --continue / --resume が空のセッションを開くか失敗する問題を修正

🏃 Self-hosted runner の運用に関わる修正

  • 失敗レポートの喪失後やセッションが同じランナーに戻された後に、ランナーが終了までそのセッションを無視する問題を修正
  • 再起動で準備できなかったリポジトリのリストが変わると、プロンプトキャッシュと以前の思考が失われる問題を修正
  • テレメトリ無効のセッションで、プロンプト待ちのツール呼び出しが結果なしで消える問題を修正
  • --push-outcome-on-release 設定時に、大きなリポジトリで再開セッションがプッシュ済みの作業なしで開始される問題を修正
  • Linux で pkill -f が自分自身のシェルやランナー自体を終了させる問題を修正 (--ignore-ancestors 対応の pkill が必要)
  • ディスク満杯で起動したランナーがセッションを受け取って失敗させる問題を修正 (空き容量を待ち、作業指示からの起動でなければ 1 分後に終了コード 1 で終了)
  • リポジトリ設定の warn モードが最初の検出で停止する問題を修正 (セッションあたり最大 50 件まで継続)
  • プラグインマーケットプレイスのリポジトリを取得できない場合や、Anthropic 管理の git がプラグインのリポジトリを拒否した場合に通知を表示

🔍 注目のバグ修正 (抜粋)

  • /rewind の復元ミス: キューされた 2 つのプロンプトやスタックされたスキルの同時実行で古いバージョンのファイルが復元される問題を修正
  • サブエージェントの MCP サーバー: 1 つのサブエージェントの終了時に、他のサブエージェントやセッションが使用中でもシャットダウンされる問題を修正
  • Amazon Bedrock のモデル選択: モデル未選択のセッションがピン留めされた Opus モデルを無視し、利用できないデフォルトモデルを呼び続ける問題を修正
  • claude -p の終了コード: ディスク満杯でファイル出力が失敗した際にメッセージなしで 0 で終了する問題を修正 (エラーを表示して 1 で終了)
  • /stats のタイムゾーン: 新しいアクティビティが UTC の日付でカウントされる問題を修正 (ローカルタイムゾーンでカウント)
  • claude.ai コネクタ: サーバー URL を共有する別名のコネクタが削除される問題と、@ メンションされたコネクタの MCP リソースが添付されない問題を修正
  • Claude in Chrome: 一時的な接続問題の後に「未接続」のままになる問題を修正
  • /mcp の分類: プラグインの MCP サーバーが組み込みとして表示される問題を修正 ("Plugin MCPs" の下に表示)

🔄 そのほかの挙動変更と取り消し

  • rm コマンドの承認強化: ルート、ホーム、トップレベルフォルダー、作業フォルダーを対象とする、より多くの rm が承認を求める。誰も回答できない環境では拒否される
  • deniedMcpServers の変更: 名前エントリは指定された claude.ai コネクタのみを隠す。URL のすべてのコネクタをブロックするには正確な URL を拒否する
  • claude --teleport の変更: 一部の環境ではブランチ切り替えの git コマンドを実行する代わりに表示。-p では切り替えるまで終了コード 1 で終了
  • システムプロンプトの変更: "sonnet" や "haiku" を含む未認識のモデル名が短いシステムプロンプトを使用。CLAUDE_CODE_SIMPLE_SYSTEM_PROMPT=0 で完全なプロンプトを与えられる
  • スキルとモデルの関係: model 設定付きのスキル (context: fork を除く) は、サブエージェント・フォーク・コンパクション・/recap をセッションのモデルに残す
  • プロンプトフックの拡張: model フィールドで haiku や sonnet などのモデルエイリアスを受け付ける
  • トークン使用量の削減: Claude apps ゲートウェイのターミナルセッションで、サブエージェントの進捗サマリーが短いノートから書かれ、使用トークンが大幅に減少

ユースケース - 開発者への影響

🏢 Enterprise Admin Console で管理される組織のユーザー・管理者

claude auth login だけで組織の設定とクラウドプロバイダー / ゲートウェイが適用されるようになった。組織管理者は Admin Console 側の設定が開発者の Claude Code に反映されることを把握しておく

📊 Pro / Max / Team / Enterprise の macOS / Linux ユーザー

チャート描画 mod「easel」が利用可能になり、依頼時や MCP メトリクス結果の下にチャートが描画される。自動チャートが不要な場合は /config でオフにする。長い会話や WebFetch の利用者は、コンパクト後・WebFetch のフリーズ解消のため早期更新の恩恵が大きい

🏃 Self-hosted runner の運用者・スケジュールタスクの利用者

--start-dir の追加、新メトリクス、403 ログの文言変更、spawn-runner フックの並行実行化、ファイル diff の省略など、運用設定とログアラートの見直しが必要な変更が多い。スケジュールタスク / /loop は最大 30 日に延長されたが、旧バージョンで作成したタスクは 7 日のままのため作成し直す

🌐 ゲートウェイ利用者・VS Code 拡張の利用者

v2.1.329 で削除された max_tokens エラー時の自動リトライが復活した。VS Code 拡張は /fork・/workflows の追加、新しい設定 3 種、誤操作防止など日常操作に関わる更新が 28 項目含まれる

必要なアクション

  1. アップデートの適用: コンパクト後・WebFetch のフリーズ修正、同時実行によるデータ消失の修正など、安定性に関わる修正が多いため早期の更新を推奨する
  2. スケジュールタスクの再作成: 30 日の実行期間が必要な既存タスクは、このリリース以降に作成し直す
  3. Self-hosted runner のログアラートの更新: 403 エラーのログ行がサーバー側の理由から始まるようになったため、旧文言にマッチするアラートを更新する
  4. Self-hosted runner のフック・diff 設定の確認: 並行実行できない spawn-runner フックには --hook-concurrency 1 を設定する。すべての Bash diff が必要な場合は managed settings で bashEditDiffEnabled を true にする
  5. ゲートウェイ利用者の設定確認: max_tokens の自動リトライが復活したため、v2.1.329 対応として CLAUDE_CODE_MAX_OUTPUT_TOKENS を設定した場合は必要性を再確認する
  6. deniedMcpServers の確認: 名前指定が同一 URL の他コネクタを隠さなくなったため、URL 単位でブロックしたい場合は正確な URL を拒否するよう設定を見直す
移行ガイド (該当する場合): 未認識モデル名で "sonnet" / "haiku" を含む名前を使っている場合は短いシステムプロンプトが使われるようになったため、完全なシステムプロンプトが必要な場合は CLAUDE_CODE_SIMPLE_SYSTEM_PROMPT=0 を設定する。スキルの model 設定に依存した運用をしている場合は、context: fork 以外のスキルでサブエージェント・フォーク・コンパクション・/recap がセッションのモデルで実行されるようになったため、モデルの使い分けを確認する

まとめ

Claude Code v2.1.330 は、Enterprise Admin Console 管理組織へのサインイン対応によりエンタープライズでの一元管理を前進させ、チャート描画 mod「easel」で可視化機能を組み込みで提供するリリースである。コンパクト後や WebFetch のフリーズ、複数プロセスの同時保存によるデータ消失といった日常利用の安定性問題を集中的に解消し、スケジュールタスクと /loop の実行期間を 30 日に延長した。Self-hosted runner は --start-dir や新メトリクスの追加に加え、ログ文言やフックの並行実行など運用に関わる変更が多いため、運用者は設定とアラートの見直しを推奨する。また、v2.1.329 で削除された max_tokens エラー時の自動リトライが復活している点にも留意が必要である
