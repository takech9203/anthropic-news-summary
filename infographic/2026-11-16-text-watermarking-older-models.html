Claude API / モデル

テキスト透かしの対象モデル拡大: Claude Opus 4.6 / Opus 4.5 / Sonnet 4.5 / Haiku 4.5 に適用

📅 2026-11-16 | ソース: Claude API Release Notes

概要

💧

旧世代 4 モデルへ透かしを拡大

Claude Opus 4.6、Claude Opus 4.5、Claude Sonnet 4.5、Claude Haiku 4.5 が生成するテキストに、対応プラットフォーム上で Anthropic のテキスト透かし (text watermark) が付与される。

📅

段階的な展開の第 2 弾

2026 年 11 月 3 日に最新世代 (Claude Mythos 5、Opus 4.7、Sonnet 4.6) へ導入された透かしを、より古い世代のモデルへ拡大するもの。

✨

出力の品質・可読性は変わらない

透かしは出力の意味、品質、可読性を変えず、トークンや隠し文字を追加しない。ユーザーや組織に関する情報も含まれないため、開発者側の対応は基本的に不要。

⚠️

対象 4 モデルすべてにサンプリングパラメータの例外

temperature、top_p、top_k のいずれかを非デフォルト値に設定したリクエストでは、透かしが付与されないことがある。前回は Sonnet 4.6 のみだった例外が、今回の 4 モデルすべてに適用される。

🇪🇺

背景は EU AI 法への対応

2026 年 7 月に署名した EU AI 法第 50 条 (2) の「AI 生成コンテンツの透明性に関する行動規範」を受けた取り組み。地域を限定する永続的な方法がないため、すべての地域でグローバルに適用される。

Before / After: 導入の経緯

Before: 2026-11-03 導入時

  • 🌌 対象は最新世代の 3 モデルのみ (Claude Mythos 5、Opus 4.7、Sonnet 4.6)
  • ⚠️ サンプリングパラメータによる例外は Sonnet 4.6 のみ
  • 📄 旧世代モデルの出力には透かしなし

After: 2026-11-16 (今回)

  • 💧 Opus 4.6、Opus 4.5、Sonnet 4.5、Haiku 4.5 の 4 モデルへ対象を拡大
  • ⚠️ サンプリングパラメータによる例外は対象 4 モデルすべてに適用
  • 🛠️ 開発者側のリクエスト・レスポンス処理の変更は不要

主要機能

今回拡大された対象モデル。

⭐Claude Opus 4.6 ⭐Claude Opus 4.5 🎵Claude Sonnet 4.5 🐦Claude Haiku 4.5

💧 埋め込みテキスト透かし

生成テキスト自体に織り込まれる不可視のマーク。出力の意味、品質、可読性を変えず、トークンや隠し文字を追加しない。ユーザーや組織に関する情報も含まれない。

🌐 対象プラットフォーム

透かしはモデルレベルで適用される。対応プラットフォームの一覧はサポート記事「How Claude marks AI-generated content」に記載されている。

⚠️ サンプリングパラメータの例外

対象 4 モデルへのリクエストで temperature、top_p、top_k のいずれかを非デフォルト値に設定すると、透かしが付与されないことがある。透かしに依存する場合は 3 つすべてを省略する。

🛠️ 開発者側の対応は不要

透かしのためにリクエストやレスポンス処理を変更する必要はなく、既存のアプリケーションはそのまま動作する。

🔍 検出 API (プライベートプレビュー)

検出には Anthropic の透かしキーが必要で、結果は確率として返される。検出 API は適格な組織に限定提供されている。

技術詳細: 仕組み

公式ブログ「How Claude's text watermark works」によると、この透かしは Google DeepMind の SynthID-Text (2024 年に Nature 誌で発表) をベースにした方式である。意味に影響しない低リスクな単語選択の揺らぎを利用し、次の単語を選ぶ際のランダム性の由来として「透かしキーと直前の数単語」から導出した値を使用する。珍しい単語へ不自然に誘導するものではなく、出力品質への影響は確認されていない。

サンプリングパラメータの例外の適用範囲

公式ドキュメント「Text watermark」の「Sampling settings」セクションによると、temperature、top_p、top_k の非デフォルト設定で透かしが付与されないことがあるのは以下のモデルである。なお、Claude Mythos 5 と Claude Opus 4.7 はこの一覧に含まれておらず、例外の対象外である。

モデル 備考
⭐ Claude Opus 4.6 今回の拡大で透かし対象に追加
🎵 Claude Sonnet 4.6 前回 (2026-11-03) から例外の対象
⭐ Claude Opus 4.5 今回の拡大で透かし対象に追加
🎵 Claude Sonnet 4.5 今回の拡大で透かし対象に追加
🐦 Claude Haiku 4.5 今回の拡大で透かし対象に追加
⭐ Claude Opus 3 モデルアクセスはリクエスト制

検出と制限事項 (前回発表時点からの共通事項)

  • 🔑検出には Anthropic の透かしキーが必要で、結果は確率として返される。検出 API はプライベートプレビューとして適格な組織に限定提供されている
  • 📏短いテキストや、単語選択の自由度が低い事実記述・コードでは検出が難しくなる
  • ✏️軽微な編集では透かしは残存し得るが、全面的な書き直しでは消える
  • ⚖️透かしがないことは人間が書いたことの証明にはならない (旧モデル、非デフォルトのサンプリング設定などで透かしが欠落し得る)
💡 ドキュメントには「If you need your output to carry the watermark, omit temperature, top_p, and top_k from your requests.」と記載されており、透かしに依存する場合は 3 つのパラメータすべてをリクエストから省略することが推奨される。フレームワークやクライアントライブラリが自動的にこれらのパラメータを設定する場合があるため、送信されるリクエストボディの確認も推奨されている。

コードサンプル

Python 透かしに依存する場合のリクエスト例 (Haiku 4.5) 
import anthropic

client = anthropic.Anthropic()

# 透かしに依存する場合は temperature / top_p / top_k を
# 設定しない (デフォルト値のまま使用する)
message = client.messages.create(
    model="claude-haiku-4-5",
    max_tokens=1024,
    messages=[
        {"role": "user", "content": "製品発表のお知らせ文を書いてください。"}
    ],
    # temperature=0.7,  # 非デフォルト値を設定すると
    # top_p=0.9,        # 対象 4 モデルでは透かしが
    # top_k=40,         # 付与されないことがある
)

print(message.content[0].text)

開発者への影響と必要なアクション

対象: Claude API および対応プラットフォームで Claude Opus 4.6、Opus 4.5、Sonnet 4.5、Haiku 4.5 を利用するすべての開発者、EU AI 法第 50 条などの透明性対応が必要な組織、透かし付与に依存するワークフローを構築する開発者。既存のアプリケーションはそのまま動作するため、移行作業は不要。

1

基本的に対応不要

透かしは出力の品質や形式を変えないため、既存のリクエストやレスポンス処理の変更は不要。

2

透かしに依存する場合

対象モデルへのリクエストから temperature、top_p、top_k をすべて省略する。フレームワークやクライアントライブラリが暗黙的に設定する値にも注意し、実際に送信されるリクエストボディを確認する。

3

検出ロジックを持つ場合の注意

「透かしがない = 旧世代モデルの出力」という前提で判定している場合、今回の拡大により前提が変わるため、判定ロジックの見直しが必要。

4

コンプライアンス確認

Claude を組み込んだサービスを提供する事業者は、EU AI 法第 50 条に基づく自社の義務を独自に評価することが推奨されている。

ユースケース

🇪🇺 AI 生成コンテンツの透明性対応

EU AI 法第 50 条などへの対応が必要な組織は、旧世代モデルを含む幅広いモデルの生成テキストに自動で透かしが付与されるようになったため、追加実装なしで透明性要件への取り組みに活用できる。自社の義務の評価は独自に行うことが推奨される。

🛠️ 透かし付与に依存するワークフローの構築

生成テキストの透かし付与を前提とする処理を実装する場合、対象 4 モデルすべてにサンプリングパラメータの例外が適用される点を考慮し、temperature、top_p、top_k を省略したリクエスト設計にする。

🔍 モデル判定ロジックの見直し

これまで「透かしがない = 旧世代モデルの出力」という前提で判定していたワークフローは、Opus 4.6 / Opus 4.5 / Sonnet 4.5 / Haiku 4.5 にも透かしが付与されるようになったため、判定ロジックの前提を更新する。

まとめ

2026 年 11 月 3 日に最新世代モデル (Claude Mythos 5、Opus 4.7、Sonnet 4.6) へ導入された Anthropic のテキスト透かしが、旧世代の Claude Opus 4.6、Opus 4.5、Sonnet 4.5、Haiku 4.5 にも拡大された。EU AI 法の透明性要件への対応を背景とした段階的な展開であり、出力の品質や可読性への影響はなく、ほとんどの開発者にとって対応は不要である。一方、前回は Sonnet 4.6 のみだったサンプリングパラメータの例外が今回の対象 4 モデルすべてに適用されるため、透かしの付与に依存する場合は temperature、top_p、top_k をリクエストから省略する必要がある点に注意が必要となる。
