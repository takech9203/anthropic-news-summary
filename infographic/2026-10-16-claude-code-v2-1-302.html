概要: キーポイント

v2.1.302 は、auto モード (権限の自動判断) の制御性向上、プロンプトキャッシュ効率やプラグイン読み込みなどのパフォーマンス改善、各プラットフォームでの安定性修正が中心のリリースである。スタンドアロン版 Claude Design の終了日が明示された点は、同サービス利用者にとって重要な告知となる。

🤖

新環境変数 CLAUDE_CODE_AUTO_MODE_MODEL

クライアント側 auto モード分類器が使用するモデルを選択できるようになった (サーバー側 auto モードのモデルは変更されない)。

⚙️

/config に Idle compaction 設定を追加

アイドルコンパクションのオン / オフを切り替えられる行が追加され、アイドルコンパクション後の通知にも無効化方法が表示されるようになった。

📢

Claude Design の終了告知

/design-sync と /design-login に、スタンドアロン版 Claude Design (claude.ai/design) が 2026 年 12 月 14 日に終了する旨の通知が追加された。

⚡

プロンプトキャッシュミスの修正

セッション途中で追加されたツールが ToolSearch 経由またはコンパクション後に再読み込みされた際のキャッシュミスを修正。

🔌

MCP プロトコル 2026-07-28 対応の修正

サーバーが同プロトコルバージョンをネゴシエートしつつ resultType などを省略した場合に、ツールが表示されない・全ツール呼び出しが失敗する問題を修正。

💾

Windows exFAT/FAT32 の修正

exFAT または FAT32 ドライブ上のプロジェクトで、すべてのファイル書き込みが拒否または確認を求められる問題を修正。

主要機能: 新機能 (Added)

🤖 CLAUDE_CODE_AUTO_MODE_MODEL

クライアント側 auto モード分類器が使用するモデルを選択する環境変数を追加。サーバー側 auto モードのモデルは変更しない。

⚙️ /config の Idle compaction 行

アイドルコンパクションをオフまたはオンに戻す設定行を /config に追加。アイドルコンパクション後に表示される通知にも、無効化の方法が示されるようになった。

📢 Claude Design 終了の通知

/design-sync と /design-login に、スタンドアロン版 Claude Design (claude.ai/design) が 2026 年 12 月 14 日までに終了する旨の通知を追加。

☁️ クラウドセッションのバナー

ルーチンのページに、前回の実行が開始されなかった理由 (組織のクラウドセッション同時実行数の上限到達など) を示すバナーを追加。

  • 会話のコンパクション中にターンを停止すると「Prompt is too long」エラーが発生する問題を修正

技術詳細 1: auto モード分類器のモデル指定

auto モード (権限の自動判断) では、クライアント側の分類器がツール呼び出しの安全性を判定する。新しい環境変数により、この分類器が使用するモデルを選択できるようになった。changelog に明記されているとおり、この設定はサーバー側 auto モードのモデルには影響しない。

Bash クライアント側 auto モード分類器のモデル指定 
# クライアント側 auto モード分類器のモデルを指定する例
export CLAUDE_CODE_AUTO_MODE_MODEL=claude-haiku-4-5

技術詳細 2: サーバー側 auto モードと長い会話の処理

サーバー側分類器を使う auto モードでは、従来、会話が安全性チェックの上限を超えると、チェック対象のツール呼び出しがすべて拒否されていた。v2.1.302 では、長すぎる会話を先にコンパクトする動作に改善された。

技術詳細 4: Claude Design の終了スケジュール

⚠️
2026 年 12 月 14 日 終了

/design-sync と /design-login に追加された通知によると、スタンドアロン版 Claude Design (claude.ai/design) は 2026 年 12 月 14 日に終了する。同サービスを利用中の場合は、終了日までに移行の検討が必要となる。

コード例

auto モード分類器のモデル指定、フォークサブエージェントの無効化、サードパーティプロバイダーでの auto モード維持の設定例。

Bash 環境変数の設定と実行例 
# クライアント側 auto モード分類器のモデルを指定する例
export CLAUDE_CODE_AUTO_MODE_MODEL=claude-haiku-4-5

# フォークサブエージェントを無効化する例
export CLAUDE_CODE_FORK_SUBAGENT=0

# サードパーティプロバイダーで auto モードを維持する例
claude -p --permission-mode auto "リポジトリのテストを実行して結果を報告してください"

ユースケース

🤖 auto モードの制御性向上

CLAUDE_CODE_AUTO_MODE_MODEL でクライアント側分類器のモデルを選択できる。また、サーバー側分類器では長い会話が全拒否ではなくコンパクションで処理されるようになり、長時間セッションでも auto モードを継続利用しやすくなった。

⚡ プロンプトキャッシュ効率化によるコスト・レイテンシー改善

ツール再読み込み時のキャッシュミス修正と Claude in Chrome 指示の配置換えにより、キャッシュヒット率が向上する。レイテンシーとコストの両面でメリットがある。

🏢 自動化パイプライン・SDK 利用コードの運用

サードパーティプロバイダー上の claude -p / Agent SDK で auto モードを前提にしている場合は、--permission-mode auto を明示する。フォークサブエージェントのデフォルト有効化やサブエージェントの実行方式変更もあわせて確認することが推奨される。

開発者への影響: 対象

  • auto モードを使用する開発者: CLAUDE_CODE_AUTO_MODE_MODEL によるクライアント側分類器のモデル選択と、長い会話での全拒否からコンパクションへの挙動改善
  • Claude Design (claude.ai/design) のユーザー: 2026 年 12 月 14 日のサービス終了に向けた対応が必要
  • claude -p / Agent SDK をサードパーティプロバイダーで使用する開発者: 権限モード未指定時のデフォルトが default モードに変更された (テレメトリーオフまたは新規インストール時)。auto を維持するには --permission-mode auto の明示が必要
  • デスクトップアプリ / VS Code のユーザー: フォークサブエージェントのデフォルト有効化と、メイン会話のサブエージェントの常時バックグラウンド実行
  • Vertex / Bedrock や LLM ゲートウェイのユーザー: プロバイダー切り替え時のエラー修正、プレフィックス付きモデル名での設定保存先の修正
  • Windows ユーザー: exFAT/FAT32 ドライブでのファイル書き込み修正と、プラグイン読み込みの高速化
  • MCP サーバーの開発者・利用者: プロトコルバージョン 2026-07-28 で一部フィールドを省略するサーバーとの互換性修正
  • Slack で Claude Tag を使用する組織: 画像形式対応、DM の安定性、管理設定の 4 タブ化など多数の改善

開発者への影響: 必要なアクション

通常の利用では自動更新により適用されるため、特別な対応は不要。手動更新する場合は claude update を実行する。

  • Claude Design を利用している場合は、2026 年 12 月 14 日の終了までに移行を計画する
  • サードパーティプロバイダー上の claude -p / Agent SDK で auto モードを前提にしている場合は、--permission-mode auto を明示的に指定する
  • フォークサブエージェントを無効にしたい場合は、CLAUDE_CODE_FORK_SUBAGENT=0 を設定する
  • アイドルコンパクションを無効化したい場合は、/config の Idle compaction 行から設定する
Bash 手動更新コマンド 
claude update

移行ガイド: デフォルト挙動の変更 3 点

破壊的変更ではないが、デフォルト挙動の変更が 3 点あるため、自動化パイプラインや SDK 利用コードでは以下を確認することが推奨される。

  • 権限モードのデフォルト変更: サードパーティプロバイダーでテレメトリーオフまたは新規インストールの場合、権限モード未指定の claude -p と Agent SDK セッションは default モードで開始する
  • フォークサブエージェントのデフォルト有効化: claude -p、Agent SDK、デスクトップアプリ、VS Code で有効になった
  • サブエージェントの実行方式: デスクトップアプリと VS Code ではメイン会話のサブエージェントが常にバックグラウンド実行となり、サブエージェント自身の Agent 呼び出しはフォアグラウンドがデフォルトになった

まとめ

Claude Code v2.1.302 は、auto モードの制御性 (分類器モデルの指定、長い会話のコンパクション)、設定の柔軟性 (Idle compaction のオン / オフ)、パフォーマンス (プロンプトキャッシュ効率化、プラグイン読み込み高速化)、プラットフォーム互換性 (MCP プロトコル 2026-07-28、Windows exFAT/FAT32、reftable 形式の git) を幅広く強化したリリースである。

また、スタンドアロン版 Claude Design の 2026 年 12 月 14 日終了が告知されており、該当ユーザーは移行計画の検討が必要となる。claude -p や Agent SDK を自動化に組み込んでいる場合は、権限モードとサブエージェントのデフォルト挙動の変更を確認することが推奨される。
