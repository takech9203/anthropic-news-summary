Claude Code v2.1.316

新しい環境変数と Claude apps gateway のエンタープライズ機能拡充。シェル・ネットワーク関連の多数の不具合を修正

📅 2026-10-31 | ソース: Claude Code Changelog

概要

🧠

ultrathink とサブエージェント effort の制御用環境変数

CLAUDE_CODE_DISABLE_ULTRATHINK で ultrathink キーワードを無効化でき、CLAUDE_CODE_SUBAGENT_EFFORT でサブエージェントの effort レベルを独立して設定できるようになった。

🏢

Claude apps gateway のエンタープライズ機能拡充

グループ共有の月次予算 pooled_budget、マッチした全ポリシーをマージ適用する managed.policy_mode: layered、Bedrock ガードレール向けの guardrail.input_tagging が追加された。

🔧

シェル・プロセス関連の不具合を多数修正

自己終了時のシェルコマンド残留、改行を含む bash エイリアスの破損、SHELLOPTS による bash スクリプトの停止、PowerShell フックが終了コード 2 でブロックしない問題などを解消。

🌐

ネットワーク・プラットフォームの信頼性向上

破損した圧縮レスポンスでのハング、Vertex AI / Bedrock で最新モデル未提供時に旧モデルへ切り替わらない問題を修正。SSL 証明書エラーは考えられる原因と対処法を表示するようになった。

💻

VSCode、Cloud sessions、Claude Tag、Code Review も改善

VSCode のチャットパネルからの gateway サインイン、Cloud sessions の MCP フォームカード、Code Review 分析ページの重要度別 findings カードなど、各コンポーネントに改善が入った。

⚠️

Opus 4.8 fast mode の非推奨化

2026 年 10 月 30 日付で非推奨となり、2026 年 11 月 30 日に削除される。削除後、Opus 4.8 への fast mode リクエストはエラーを返し、標準の Opus 4.8 にはフォールバックしない。速度向上を維持するには Opus 5.5 への移行が必要 (詳細は別レポートを参照)。

主要機能

🚫 CLAUDE_CODE_DISABLE_ULTRATHINK

ultrathink キーワードを無効化できる環境変数。キーワードの誤発動による高 effort 実行を避けたい環境で有用。

🎚️ CLAUDE_CODE_SUBAGENT_EFFORT

他に指定がない場合にサブエージェントが実行される effort レベルを設定できる。従来はセッションの effort を継承していたため、サブエージェントのコストと速度を独立して制御できるようになった。

💰 プールドグループ予算

Claude apps gateway の支出上限管理 API の pooled_budget で、グループのメンバーが共有する月次予算を、各メンバー個別の上限に加えて設定できる。

🧩 managed.policy_mode: layered

開発者にマッチするすべてのポリシーが適用されるモード。各ポリシーは下に列挙されたものの上にマージされる。従来は最初にマッチしたポリシーのみが適用されていた。

🛡️ guardrail.input_tagging

Bedrock アップストリームで、Amazon Bedrock ガードレールのプロンプト攻撃フィルターが必要とする入力タグでプロンプトをラップする。all_messages_and_system でシステムプロンプトも対象になる。

🔐 CLAUDE_CODE_DISABLE_LOOPED_CROSS_CERT_DROP

ループ状に相互認証するシステムクロス証明書を保持する環境変数。プライベート CA がそれを必要とするサーバー向け。

layered policy mode の動作

Before

Claude apps gateway は、開発者にマッチした最初のポリシーのみを適用。組織全体の基本ポリシーとチーム固有の設定を両立させることが難しかった。

After

managed.policy_mode: layered により、マッチしたすべてのポリシーが下位のものの上にマージされる。基本ポリシーにチーム固有の設定を重ねる運用が可能になった。

変更カテゴリ別の詳細

🔧 Fixed (修正)

🐚 シェル・プロセス関連

🧹 シェルコマンドの残留

macOS と Linux で、Claude Code が自己終了した際 (認証情報の拒否やクラウドセッションのアーカイブなど) にシェルコマンドが実行されたまま残る問題を修正。

🔤 bash エイリアスの破損

値に改行を含む bash エイリアス (Git Bash を除く) と、名前がダッシュで始まる関数が、Bash ツールのシェルで破損または消失する問題を修正。

⏸️ SHELLOPTS による停止

SHELLOPTS がエクスポートされている場合に、Bash ツールから起動した bash スクリプトが最初のコマンドで停止する問題を修正。

🪟 PowerShell フックと Git Bash

PowerShell フックが型キャスト、param、using、属性で始まるコマンドで終了コード 2 でブロックしない問題と、Windows の Git Bash でエイリアスと関数が失われる問題を修正。

🌐 ネットワーク・プラットフォーム関連

📡 圧縮レスポンスでのハング

圧縮レスポンスが途中で切れた場合や破損した場合に、一部のネットワークリクエストがハングする問題を修正。

🔄 Vertex AI / Bedrock のフォールバック

最新モデルがアカウントやリージョンで未提供の場合に、sonnet / opus / haiku が旧モデルへ切り替わらずセッション途中でエラーを表示する問題を修正。

🚧 gateway のモデルチェック

リクエストに含まれるすべてのモデルを availableModels、deniedModels、models に対してチェックするよう修正。ブロックされたモデルを含むリクエストは 400 エラーを返す。

🔑 claude auth login の拒否

managed settings が Claude apps gateway を必須とする環境で claude auth login が実行を拒否する問題を修正。ターミナルではゲートウェイのサインインを表示する。

🔒 権限・セキュリティ・設定関連

📁 --restricted セッション

Read の許可ルールの対象であれば作業ディレクトリ外のファイルをアップロードしていた問題を修正。

🛂 autoMode.allow の組み込み例外

"$defaults" を含まない managed の autoMode.allow リストに、--settings や /permissions の操作で組み込み例外が復活する問題を修正。

☁️ auto モードのターン停止

サーバーの安全性判定を得られずターンを停止した際にクラウドセッションが失敗としてマークされない問題と、claude -p が停止理由を表示しないことがある問題を修正。

🔀 プロキシ経由の auto モード設定

プロキシや LLM ゲートウェイの背後でホストアプリから開始したセッションで、experimental betas 無効時に CLAUDE_CODE_AUTO_MODE_SERVER=1 が無視される問題を修正。

💬 セッション・UI 関連

⌨️ 不可視文字を含むプロンプト

送信に Enter が 2 回必要だった問題を修正。プレーンなプロンプトはクリーニング後 1 回の Enter で送信され、コマンドは引き続きレビューを待つ。

🤖 サブエージェントのモデル継承

親サブエージェントのモデルを継承したサブエージェントが、バックグラウンドジョブやメッセージで再開した際にメインモデルへ移動する問題を修正。

🔍 Grep / Glob の無応答

検索プロセスがタイムアウトで強制終了されても終了しない場合に、Grep と Glob が応答を返さない問題を修正 (Windows で確認)。

📝 プラン復元と /model の警告

保存中の /clear / /resume でプランが復元されない問題と、/model <id> が未認識モデルで auto-compact の 200K 前提を警告しない問題を修正。

ほか、プラグイン MCP の headersHelper、SDK の register_repo_root、Artifact ツールのアクセスルール表示、ターミナル UI、セルフホストランナーなど多数の修正あり

⤴️ Improved (改善)

🗂️ /code-review の findings カード

Claude Desktop や Web の Code タブから開始した /code-review で、クラウドセッションと claude remote-control セッションがプレーンテキストではなく findings カードを表示する。

⚡ 大規模リポジトリでの /diff

リフレッシュごとのリポジトリ全体に対する git コマンドが通常 1 回減り、git が遅い場合はリフレッシュの間隔が空けられる。

🔗 GitHub リモート未検出時の案内

/ultrareview、クラウドセッション、クラウドエージェントがリポジトリ作成ページを案内し、/ultrareview は gh が拒否するコマンドを提案しなくなった。

🔐 SSL 証明書エラーの説明

中間証明書を省略しているサーバーなどの考えられる原因と、それぞれの対処法を示すようになった。

🔄 Changed (動作変更)

📋 autoMode.allow の組み込みルール

"$defaults" を含まない autoMode.allow リストが、スケジュールタスクのプロンプトに関する組み込みルールを削除しないように変更。

🏢 サーバー管理設定の適用方法

Team / Enterprise ログインで、Anthropic の API から取得した設定は承認プロンプトなしで適用され、検証に失敗した保存済みコピーは拒否される。

コンポーネント別の変更

💻 VSCode

チャットパネルから Claude apps gateway へサインイン可能になった (ターミナル不要)。ultrathink がターンを xhigh effort で実行しチャットボックスでレインボー表示されるよう変更。[1m] タグ付きモデル設定で Effort スライダーなどが表示されない問題、/btw サイド質問履歴の早期削除、プラン承認後の Auto モード復帰を修正。

☁️ Cloud sessions

MCP サーバーが要求するフォームに入力・拒否できるフォームカードを追加。切り替えて戻ったセッションに「Catching up…」行を表示。Enterprise メンバーが自身のクラウド環境でネットワークシークレットを追加・削除可能に変更。Changes ペインの注記をバッジ化し、Files ペインのファイル検索パス表示を修正。

🏷️ Claude Tag

複数チャンネルに共有された canvas の編集拒否、Slack Connect スレッドでのタグなし返信への無応答、クラウドスケジュールタスクのライブステータス停止を修正。「Respond automatically」スイッチは「How Claude participates」の選択に変更された。

📊 Code Review

分析ページに重要度別の findings カードを追加。期間内の合計 findings 数、重要度別に積み上げた日次チャート、各重要度の件数を表示する。

技術詳細

🎚️ サブエージェントの effort 制御

CLAUDE_CODE_SUBAGENT_EFFORT は、エージェント定義などで effort が明示されていない場合にのみ適用される。多数のサブエージェントを起動するワークフローで、セッション全体を高 effort にしたままサブエージェントのコストを抑える、といった使い分けが可能になる。

Bash 新しい環境変数の設定例 
# ultrathink キーワードを無効化
export CLAUDE_CODE_DISABLE_ULTRATHINK=1

# サブエージェントのデフォルト effort を指定
export CLAUDE_CODE_SUBAGENT_EFFORT=medium

# ループ状に相互認証するクロス証明書を保持 (プライベート CA 向け)
export CLAUDE_CODE_DISABLE_LOOPED_CROSS_CERT_DROP=1

🛡️ Bedrock ガードレールの入力タグ

Amazon Bedrock ガードレールのプロンプト攻撃フィルターは、評価対象の入力を特定のタグで囲む必要がある。guardrail.input_tagging はこのタグ付けをゲートウェイ側で行い、all_messages_and_system ではシステムプロンプトも対象に含める。

🔄 モデルフォールバックの改善

Vertex AI / Bedrock でエイリアス (sonnet など) が指す最新モデルが未提供のリージョンやアカウントでも、セッションがエラーで中断せず旧モデルへ切り替わるようになった。

💰 プールドグループ予算の位置づけ

pooled_budget はグループのメンバーが共有する月次予算で、各メンバー個別の上限に加えて設定できる。個別上限とグループ全体の支出管理を組み合わせた柔軟な予算運用が可能になる。

ユースケース

🎚️ 多数のサブエージェントを起動するワークフローのコスト最適化

CLAUDE_CODE_SUBAGENT_EFFORT を設定することで、セッション本体は高 effort のまま、サブエージェントのコストと速度を独立して制御できる。ultrathink の誤発動を避けたい環境では CLAUDE_CODE_DISABLE_ULTRATHINK を併用する。

🏢 Claude apps gateway を運用するエンタープライズ管理者

グループ共有予算が必要な組織は pooled_budget を、組織全体の基本ポリシーにチーム固有の設定を重ねたい組織は managed.policy_mode: layered を、Bedrock ガードレールのプロンプト攻撃フィルターを使う組織は guardrail.input_tagging の活用を検討する。

⚠️ Opus 4.8 fast mode を利用しているユーザー

2026 年 11 月 30 日の削除までに Opus 5.5 へ移行する。削除後はリクエストがエラーになり、標準の Opus 4.8 へのフォールバックは行われないため、期限前の移行計画が必須となる。
