主要な変更点

🤖 auto mode の対応プラットフォーム拡大

  • Opus 4.6 / Sonnet 4.6 の auto mode が Amazon Bedrock、Google Cloud の Agent Platform、Microsoft Foundry、Claude apps ゲートウェイで利用可能に
  • permission mode 未指定の対話セッションは auto mode で開始
  • plan mode と Bash プロンプトもサードパーティ上の両モデルで auto mode を使用・提案
  • 無効化は disableAutoMode で可能
  • CLAUDE_CODE_DISABLE_EXPERIMENTAL_BETAS 設定時に beta を拒否するゲートウェイの背後で auto mode が毎ターン失敗する問題も修正

🪝 mcp_tool フックの onFailure: block

  • フックの呼び出し自体が失敗した場合に対象のアクションをブロック
  • command フック・HTTP フックに続く対応
  • MCP ツール経由のセキュリティチェック・ポリシー適用で、フック障害時に処理を通過させないフェイルクローズド構成が可能に

🏃 Self-hosted runner の新機能

  • --repository-folder: --capacity 1 のときセッションがリポジトリに使うフォルダー名を指定 (シンボリックリンク不可)
  • --hook-label: orchestrator で選択したセッションラベルを spawn-runner フックに渡す
  • --metadata key=value: claude --environment でセッションにラベルを付与
  • 新メトリクス: 待機時間を理由別に区別する session_queue_wait_by_reason_seconds と、起動断念を原因別に数える sessions_given_up_total
  • ホストの settings.json がセッションに無視されるデフォルト permission mode を設定している場合の起動時警告

⚙️ Code Mode の安定化

  • 権限プロンプト・プラン承認・質問が 10 分間開いたままのときのスクリプト停止を修正
  • 前の実行中に接続した MCP サーバーを呼び出せない問題、--resume ピッカー経由のバックグラウンド実行不可を修正
  • 再開時のロード済みスキル・フックコンテキスト・承認メモの消失を修正
  • { で始まるスクリプトやトップレベル await + return の拒否を修正
  • 0.75 秒の待機を削除し高速化、ツール説明の短縮でトークン削減

✨ そのほかの新機能

  • メッセージ保留の警告: クラウドセッションで保留・破棄され得るメッセージを警告し、claude -p では stderr で通知
  • OpenTelemetry の診断: エンドポイントのない exporter を /status と claude doctor に通知
  • CLAUDE_CODE_DISABLE_DEFERRED_TOOL_RESUME: フックが保留したツール呼び出しの再開を停止
  • allowManagedModsOnly: policy プラグインで組み込みアプリが有効化可能
  • policy の maxEffortLevel が無効な値のとき Claude apps ゲートウェイに起動時警告

💻 VS Code 拡張の更新

  • 別セッションからのメッセージ保留時の通知を追加 (許可できる設定ファイルへのリンク付き)
  • パネルが低い・テキストが長い場合に権限プロンプトの No ボタン・返信フィールド・タイトルが切れる問題を修正
  • 失敗・ブロックされたツール呼び出しの理由の非表示・途切れと、Glob / Grep がエラーを結果として数える問題を修正

🪝 mcp_tool フックの onFailure: block 設定

フック呼び出しの失敗時にアクションをブロックする設定は、settings.json のフック定義で指定する。

JSON settings.json - フェイルクローズドなフック定義 
{
  "hooks": {
    "PreToolUse": [
      {
        "matcher": "Bash",
        "hooks": [
          {
            "type": "mcp_tool",
            "tool": "mcp__security__check_command",
            "onFailure": "block"
          }
        ]
      }
    ]
  }
}

🏃 Self-hosted runner のセッションラベル付け

spawn-runner フックにセッションのメタデータを渡せるようになり、runner の割り当てロジックをセッション属性に基づいて制御できる。

Bash セッションラベルの付与と orchestrator への指定 
# セッションにメタデータを付与して環境を作成
claude --environment --metadata team=platform --metadata priority=high

# orchestrator 側で選択したラベルを spawn-runner フックに渡す
claude self-hosted-runner orchestrator --hook-label team --hook-label priority

⚙️ Code Mode の出力秘匿化 - Before / After

Before (〜 v2.1.327)

Code Mode はスクリプトの出力に対して UserPromptSubmit フック (管理対象含む) を実行していた。出力の秘匿化を UserPromptSubmit フックで行う構成が可能だった

After (v2.1.328 〜)

Code Mode はスクリプト出力に対して UserPromptSubmit フックを実行しない。出力の秘匿化が必要な場合は、updatedToolOutput を使う PostToolUse フックを使用する

カテゴリ別の修正・変更の要約

🏃 Self-hosted runner の主な修正・挙動変更

  • プロキシや Web フィルターがポーリングに HTTP 200 と {} のようなボディで応答した際、実行中の全セッションが停止する問題を修正 (再試行するようになった)
  • 一時的なディスクエラー後に、保持していたクローンのオブジェクト・参照や、そこにしか存在しないコミットが削除される問題を修正 (起動が失敗するようになった)
  • ホストの時計が遅れている・巻き戻された環境で、トークン失効により runner が停止する問題を修正
  • Anthropic 管理の git を使うセッションで、スクリプトやフックが claude を再実行した後に GitHub への git アクセスを失う問題を修正
  • 破損した .claude.json を持つセッションが --trust-workspace false 下で以後の起動に失敗し続ける問題を修正 (デフォルト設定で起動し、MCP サーバーは無効化)
  • 登録後にセットアップが失敗した runner がサーバーに通知せず終了する問題を修正 (理由付きで登録解除し、オンデマンド runner は起動失敗を報告)
  • 挙動変更: settings が GitHub ツールを名前でガードしている場合、組み込みの gh api がデフォルト無効に (--use-anthropic-gh true で有効化)
  • 挙動変更: CLAUDE_RUNNER_SESSION_UUID と CLAUDE_CODE_REMOTE_SESSION_UUID の両方がセッションと checkout / post-session / spawn-runner フックに設定される
  • 挙動変更: --capacity 1 のとき、プッシュ先リポジトリのパスがシンボリックリンクの場合はより早い段階でセッションを拒否

⚙️ Code Mode の修正・改善

  • 1 つの返信で複数スクリプトを実行したセッションの再開時に、ロード済みスキル・フックコンテキスト・権限承認時のメモが失われる問題を修正
  • 先に失敗したスクリプトが設定しなかったトップレベル変数に、暗黙に undefined が使われる問題を修正
  • 読み取り専用サブエージェントに、呼び出せない write() と edit() が提示される問題を修正
  • MCP サーバーがある新規 Code Mode セッションのプロンプトキャッシュを改善
  • スクリプトが実行中のコマンドとその出力を実行中に表示するようになった
  • 何も変更しない編集がスクリプトを停止しなくなり、失敗した編集については一致箇所・最も近い箇所が Claude に伝えられる

🐛 注目のバグ修正

  • zsh の Bash コマンド: echo ==== や [ a == b ] のように = で始まる語で "not found" エラーになる問題を修正 (=cmd がコマンドパスに展開されなくなった)
  • 自動コンパクション: /compact と同様にシステムプロンプトを再構築するのではなく、古いシステムプロンプトを再利用していた問題を修正
  • スケジュールタスクの保護: タスクファイルが読めないときの保存で他のタスクが消える問題、タイポのあるタスクが次回保存時に削除される問題を修正
  • トークンカウント: 再試行された応答の二重カウント、ストリーミングされない応答の見逃し、思考中の停止を修正
  • MCP スキーマ: anyOf / oneOf / allOf で始まるツールが消える問題、無効なスキーマがリクエストを失敗させる問題を修正 (無効なツールは除外され、理由が Claude に伝えられる)
  • ストリーム接続: CLAUDE_STREAM_IDLE_TIMEOUT_MS がゲートウェイ・カスタムベース URL・クラウドプロバイダーで 5 分の接続制限を延長できない問題を修正
  • "Prompt is too long" の恒久停止: サードパーティプロバイダー上の一部 Claude Desktop セッションが大きなツール結果の後に終了する問題を修正 (最大の結果が除外される)
  • effort の退行修正: Bedrock / Agent Platform / Foundry がサブエージェントの進捗サマリーの effort 設定を拒否した場合に、effort がセッション全体で無効になる問題を修正 (v2.1.327 の退行)
  • Remote Control / クラウドセッション: 切断メッセージの重複、rewind と /clear 後の会話復活、runner 喪失時のツール呼び出し・結果の消失、/diff の表示漏れなどを修正
  • ターミナル関連: Esc 直後のキー喪失、低速接続でのペースト分断、GNU screen の色異常、Linux の Ctrl+V 画像取りこぼし、Ctrl+Z サスペンド中のフリーズなどを修正
  • クラッシュ対策: FORCE_COLOR が負の数のときの起動時クラッシュ、メモリ逼迫時のシークレットマスキングのクラッシュを修正

🔄 挙動変更 (抜粋)

  • /code-review の整理: ほとんどのモデルでバグと CLAUDE.md 違反のみを報告。クリーンアップは /simplify へ。各指摘に Important / Pre-existing / Nit のマークが付き、サマリー末尾に修正案が提示される
  • managed PostToolUse フック: 実行前に拒否された呼び出しには発火しない (ログ・書き換え・ブロック・停止なし)。PostToolBatch はほとんどを受け取るが、拒否のマークは付かない
  • deniedMcpServers: claude.ai <name> 形式のエントリが、クラウドセッションと self-hosted runner セッションのコネクタにも適用される
  • サブエージェントの待機: CLAUDE_CODE_FORK_SUBAGENT=0 設定時、claude -p / Agent SDK / デスクトップ / VS Code のサブエージェントはデフォルトで自身のサブエージェントを待つ。待機は 1 つの 10 分制限にまとめてカウント (CLAUDE_CODE_PRINT_BG_WAIT_CEILING_MS で延長可能)
  • サンドボックス: PermissionRequest フックがサンドボックス除外コマンドに書き換えたシェルコマンドはサンドボックス外で実行。起動できないサンドボックスは次のサンドボックス対象 Bash コマンドを拒否し、セッション中のサンドボックス無効を通知 (sandbox.failIfUnavailable 未設定時)
  • /bug の確認: 送信前に Yes / No を確認するようになり、Enter の連打でレポート送信や GitHub が開くことがなくなった
  • ペーストの明示: サードパーティプロバイダー、またはテレメトリ・機能フラグ無効時に、ペーストされたテキストがペーストとして Claude にマークされる

🚀 改善 (抜粋)

  • 大きなセッションの再開時間、多数の画像を含むセッション再開時のメモリ使用量を改善
  • 遅いコマンドやツールを実行する長時間の SDK / デスクトップセッションのメモリ使用量と応答時間を改善
  • 複数の in-process チームメイトの同時起動時に "Lock file is already being held" で失敗するケースを大幅に削減
  • Anthropic API 上のターミナルセッションで、サブエージェントの進捗サマリーがデフォルトの小型高速モデルにより短いメモから生成され、トークン消費が大幅に減少 (テレメトリ無効時も適用)
  • computer use の承認ダイアログが、各アプリのアクセスレベルとより平易な警告を表示

ユースケース - 開発者への影響

☁️ Bedrock / Agent Platform / Foundry / Claude apps ゲートウェイの利用者

Opus 4.6 / Sonnet 4.6 で auto mode が利用可能になり、permission mode 未指定の対話セッションは auto mode で開始される。従来の挙動を維持したい場合は disableAutoMode を設定する

🛡️ フックでポリシーを適用する組織

mcp_tool フックの "onFailure": "block" でフェイルクローズドな構成が可能になった。一方、Code Mode のスクリプト出力には UserPromptSubmit フックが実行されなくなったため、出力の秘匿化は updatedToolOutput を使う PostToolUse フックへ移行が必要

🏃 Self-hosted runner の運用者

プロキシ応答による全セッション停止、クローンデータの消失、トークン失効による停止など運用に関わる修正が多いため、早期の更新を推奨。新メトリクスによる監視強化も可能

⚙️ Code Mode の利用者

スクリプトの停止・拒否・状態消失に関する多数の修正と、速度・トークン使用量の改善が含まれる

🔍 /code-review の利用者

レビューの対象がバグと CLAUDE.md 違反に絞られた。品質面のクリーンアップには /simplify を使用する

必要なアクション

  1. アップデートの適用: Code Mode・Self-hosted runner・Remote Control の信頼性に関わる修正が多いため、これらの機能を使う環境では早期の更新を推奨する
  2. auto mode の方針確認: サードパーティプロバイダーで permission mode を指定していない場合、セッションが auto mode で開始されるようになる。組織のポリシーに合わない場合は disableAutoMode または明示的な permission mode の指定を検討する
  3. Code Mode の出力秘匿化の移行: スクリプト出力の秘匿化を UserPromptSubmit フックに依存している場合は、updatedToolOutput を使う PostToolUse フックへ書き換える
  4. Self-hosted runner の GitHub ツール設定の確認: settings で GitHub ツールを名前でガードしている場合、組み込みの gh api がデフォルトで無効になった。必要であれば --use-anthropic-gh true を指定する
  5. OpenTelemetry 設定の確認: 更新後に /status または claude doctor を実行し、エンドポイント未設定の exporter が報告されないか確認する
移行ガイド (該当する場合): CLAUDE_CODE_FORK_SUBAGENT=0 を使う SDK / headless 環境では、サブエージェントが自身のサブエージェントをデフォルトで待つようになり、待機は 1 つの 10 分制限にまとめられる。長いチェーンには CLAUDE_CODE_PRINT_BG_WAIT_CEILING_MS を引き上げる。フックが保留したツール呼び出しの再開を制御したいホストは CLAUDE_CODE_DISABLE_DEFERRED_TOOL_RESUME を設定すると、claude -p --resume / --continue での実行を止められる。managed PostToolUse フックに依存する監査基盤は、実行前に拒否された呼び出しではフックが発火しなくなったため、拒否も含めて把握する必要がある場合は PostToolBatch の利用を検討する (拒否のマークは付かない点に注意)

まとめ

Claude Code v2.1.328 は、Opus 4.6 / Sonnet 4.6 の auto mode を Amazon Bedrock、Google Cloud の Agent Platform、Microsoft Foundry、Claude apps ゲートウェイへ拡大し、エンタープライズ環境での利用体験を Anthropic API に近づけるリリースである。mcp_tool フックの "onFailure": "block" によりフェイルクローズドなポリシー適用が可能になり、Self-hosted runner はメタデータによるセッションラベル付けや新メトリクスなど運用面の強化が進んだ。Code Mode はスクリプトの停止・拒否・状態消失に関する 20 項目超の修正・改善により大きく安定化しており、これらの機能を運用する環境では早期の更新を推奨する
