セルフホスト型 Claude Managed Agents の提供開始

📅 2026-11-12 | ソース: Claude API リリースノート

Managed Agents サービス全体 (API、エージェントループ、エージェント・セッション・セッション履歴の保存) を自社のクラウドアカウントやオンプレミスのデータセンターで実行可能に。推論プロバイダーも Claude API (デフォルト) のほか Amazon Bedrock、Google Cloud、Microsoft Foundry、自社ゲートウェイから選択できる

cma-server | PostgreSQL 16+ | ant beta:worker

概要

🏢

サービス全体を自社インフラでホスト可能に

これまでの「セルフホスト型サンドボックス」(ツール実行環境のみ自社ホスト) から拡張され、API、エージェントループ、エージェント・セッション・セッション履歴のストレージまで、Managed Agents サービス全体を自社のクラウドアカウントまたはオンプレミスで実行できる。

🤖

推論プロバイダーを選択可能

モデル呼び出しの送信先として、デフォルトの Claude API のほか、Amazon Bedrock、Claude Models on Google Cloud、Microsoft Foundry、自社のモデルゲートウェイを選択できる。

🔌

既存の API との互換性を維持

自社サーバーはホステッドサービスと同じ API を持つため、既存の SDK と ant CLI がそのまま利用できる。一部の機能差分は公式ドキュメントの「Differences from the hosted service」に記載されている。

📝

アクセス申請制

ダウンロードへのアクセスには Anthropic アカウントチームへの連絡が必要。サーバーソフトウェアは「Software License Agreement: Claude Managed Agents Server」に基づいてライセンスされる。

🛡️

運用とセキュリティは自社の責任範囲に

ホステッドサービスで Anthropic が担っていたサーバーの保護、メモリストアのホスティング、異常利用の検知などは自社の責任となる。データレジデンシーやコンプライアンス要件の厳しい組織に適した選択肢である。

Before / After: セルフホストの範囲

Before (セルフホスト型サンドボックス)

  • 自社ホストできるのはツール実行環境 (サンドボックス) のみ
  • API、エージェントループ、データ保存は Anthropic 側で実行
  • エージェント・セッション・履歴は Anthropic 側に保存
  • 推論先は Anthropic (Claude API) に固定

After (セルフホスト型 Managed Agents)

  • サービス全体 (API、エージェントループ、ストレージ) を自社インフラで実行
  • エージェント・セッション・履歴を自社のデータベースに保存
  • 推論プロバイダーを Claude API、Bedrock、Google Cloud、Foundry、自社ゲートウェイから選択
  • オンプレミスやデータレジデンシー要件に対応

主要機能

🏢 サービス全体の自社ホスト

API、エージェントループ、エージェント・セッション・セッション履歴のストレージを自社インフラ (クラウドアカウントまたはオンプレミスのデータセンター) で実行できる。

🤖 推論プロバイダーの選択

モデル呼び出しの送信先として、Claude API (デフォルト) のほか、Amazon Bedrock、Claude Models on Google Cloud、Microsoft Foundry、自社のモデルゲートウェイを選択できる。

🔌 既存の API との互換性

自社サーバーはホステッドサービスと同じ API を持つため、SDK と ant CLI がそのまま利用できる。既存コードは自社サーバーに対してもそのまま動作する。

🖥️ Web コンソール

サーバーのアドレスで Web ページが提供され、自社の ID プロバイダー経由でサインインし、エージェントの作成やセッションの実行ができる。

📝 アクセス申請制

ダウンロードへのアクセスには Anthropic アカウントチームへの連絡が必要。各リリースのアーカイブにはオペレーターガイド (operator-guide.md) が含まれ、設定・運用に Claude を活用できる。

技術詳細

🧩 デプロイメントの主要コンポーネント

コンポーネント 役割
サーバー cma-server API の提供、エージェントループの実行、エージェント・セッション・履歴の保存を担う。エージェントがモデルを必要とするたびに、設定された推論プロバイダーを呼び出す。サーバー自体はエージェントのシェルツールやファイルツールを実行しない
データベース PostgreSQL 16 以降。データベースなしの場合、サーバーはデータをメモリ上に保持し、再起動でデータは消去される
ワーカー サーバーから作業を取得し、エージェントのシェルツールとファイルツールを自社サンドボックス内で実行するプログラム。ant beta:worker コマンドまたは SDK ワーカーとして動作する
コンソール サーバーのアドレスで提供される Web ページ。自社の ID プロバイダー経由でサインインし、エージェントの作成やセッションの実行ができる
管理 CLI cma-server-admin 環境と環境キーを作成する。Linux (x86-64 および Arm) と Apple シリコン搭載 macOS で動作する

🔐 3 種類のクレデンシャル

クレデンシャル 保持者 認証対象
サーバー API キー 自社アプリケーション、ant CLI、管理 CLI 自社サーバーへのリクエスト
推論クレデンシャル サーバー 推論プロバイダーへのモデル呼び出し
環境キー サーバーをポーリングするワーカー 環境の作業キューとセッション

🌐 ネットワーク外に出るデータ

モデル呼び出しごとに、サーバーはツール入力・ツール結果を含むそれまでの会話を推論プロバイダーに送信する。Claude API への呼び出しには、セッション、エージェント、環境の ID も含まれる。

⚠️ セキュリティ上の注意

  • エージェントの bash ツールはワーカープロセスの権限とネットワークアクセスを持つ実際のシェルであり、ワーカー自体はシェルを分離しない。分離は実行環境 (コンテナや VM) に依存する
  • ホステッドサービスで Anthropic が担っていたサーバーの保護、メモリストアのホスティング、異常利用の検知などは、自社の責任範囲となる
  • データベースを構成しない場合、データはメモリ上に保持され、サーバーの再起動で消去される

3

運用体制の整備: サーバー、データベース (PostgreSQL 16 以降)、サンドボックスの運用とセキュリティ確保、各リリースのインストールを自社で行う

4

機能差分の確認: 一部の機能はホステッドサービスのみで提供されるため、導入前に「Differences from the hosted service」を確認する

ライセンスの確認: サーバーソフトウェアは「Software License Agreement: Claude Managed Agents Server」に基づいてライセンスされる

🔁 移行ガイド

自社サーバーはホステッドサービスと同じ API を持つため、既存の SDK や ant CLI を使用するコードは自社サーバーに対してもそのまま動作する。各リリースのアーカイブにはそのバージョンのオペレーターガイド (operator-guide.md) が含まれており、サーバーの設定・運用や接続コードの作成に Claude を活用できる。

ユースケース

🏛️ データレジデンシー要件への対応

エージェント、セッション、セッション履歴を自社のクラウドアカウントやオンプレミスのデータセンターに保存できるため、データの保管場所に関する規制やコンプライアンス要件の厳しいエンタープライズでも Managed Agents を採用できる。

☁️ 既存のクラウド契約を活用した推論

モデル呼び出しを Amazon Bedrock、Claude Models on Google Cloud、Microsoft Foundry に送信できるため、既存のクラウド契約や調達ルートを活用しながらエージェントを運用できる。自社のモデルゲートウェイを経由させることで、組織の統制ポリシーも適用できる。

🔌 既存コードを変えないセルフホスト移行

自社サーバーはホステッドサービスと同じ API を持つため、SDK や ant CLI を使用する既存のアプリケーションは、接続先を変えるだけでセルフホスト環境でもそのまま動作する。段階的な移行や検証がしやすい。

まとめ

セルフホスト型 Claude Managed Agents の提供開始により、Managed Agents のホスティング選択肢は「クラウドサンドボックス」「セルフホスト型サンドボックス」に加えて「サービス全体のセルフホスト」まで拡大した。エージェントデータの自社保存や推論プロバイダーの選択 (Amazon Bedrock、Google Cloud、Microsoft Foundry、自社ゲートウェイ) が可能になり、データレジデンシーやコンプライアンス要件の厳しいエンタープライズでも Managed Agents を採用しやすくなった。一方で、サーバー・データベース・サンドボックスの運用とセキュリティは自社の責任となるため、導入時にはホステッドサービスとの機能差分と運用体制の確認が重要である。利用を希望する場合は、Anthropic アカウントチームへの連絡が必要となる。
