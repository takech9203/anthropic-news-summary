🛡️ アカウントメール送信前の確認チェック

Web ツールまたはシェルツールの呼び出しがアカウントのメールアドレスをネットワークへ送信しようとする際、事前に確認を求めるようになった。プロンプトインジェクションなどによる意図しない個人情報の流出を防ぐセキュリティ強化

⚠️ /schedule のコネクタ警告

新しいクラウドスケジュールタスクに、ユーザーが要求していないコネクタが付与された場合に警告を表示し、削除方法を案内する

🔒 Agent SDK フックの onFailure: "block"

フックコールバックが失敗した場合に、アクションを実行させるのではなくブロックできるようになった。フックをセキュリティゲートとして利用する場合のフェイルセーフ (fail-closed) 動作を実現できる

📊 OTel テレメトリの属性追加

anthropic.plan、anthropic.seat_type、anthropic.provider、anthropic.custom_base_url がメトリクス、イベント、スパンに追加された。プランやプロバイダー別の利用分析が可能になる

💰 Claude apps gateway のコストレポート API

管理 API に GET /v1/organizations/analytics/cost が追加され、期間を指定して過去の支出を合計、開発者別、日別、IdP グループ別に取得できる。あわせて、admin: を設定したゲートウェイでは各開発者の IdP グループが日次で記録され (admin.identity_retention_days の期間保持)、コストレポートのグループ集計に利用される

🪆 CLAUDE_CODE_DISABLE_NESTED_SESSION_ID の追加

セルフホストランナーで 1 に設定すると、セッション内で実行した claude -p が以前のバージョンと同様にそのセッションの ID とトランスクリプトを使用する。既定ではネストした claude -p が独自のセッション ID を持つ新動作となる

🔒 onFailure: "block" のセマンティクス

従来、Agent SDK のフックコールバックが失敗 (例外やタイムアウトなど) した場合、対象のアクションはそのまま実行されていた (fail-open)。onFailure: "block" を指定すると、コールバックの失敗時にアクションがブロックされる (fail-closed)。権限チェックや監査をフックで実装している場合に重要な選択肢となる

Before — fail-open

フックコールバックが失敗 (例外やタイムアウト) しても、対象のアクションはそのまま実行されていた。セキュリティゲートとしてのフックに抜け道が残る

After — fail-closed

onFailure: "block" を指定すると、コールバックの失敗時にアクションがブロックされる。権限チェックや監査のフェイルセーフ動作を実現

💰 コストレポート API と IdP グループ記録

GET /v1/organizations/analytics/cost は日付範囲を指定して支出を取得でき、集計軸は合計、開発者別、日別、IdP グループ別の 4 種類。IdP グループ別の集計は、admin: を設定したゲートウェイが日次で記録する各開発者の IdP グループ情報に基づき、保持期間は admin.identity_retention_days で制御する

🪆 ネストした claude -p のセッション分離

セッション内で実行された claude -p は独自のセッション ID とトランスクリプトを持つようになり、親セッションのトランスクリプト汚染や誤った会話の再開を防ぐ。旧動作が必要な場合は CLAUDE_CODE_DISABLE_NESTED_SESSION_ID=1 を設定する

📖 Read ツールのスタブ削除

変更のないファイルの再読み込みで「file unchanged」のスタブではなく実際の内容が返るようになったため、長い会話でコンテキストから内容が失われた場合でも再読み込みで確実に取得できる

  • CI などでセッション内から claude -p をネストして実行しているユーザー

ユースケースと必要なアクション

🔒 フックをセキュリティゲートとして運用するチーム

Agent SDK のフックで失敗時にアクションを確実にブロックしたい場合は、onFailure: "block" の設定を検討する。権限チェックや監査フックのフェイルセーフ (fail-closed) 化により、コールバック失敗時の抜け道を塞げる

📊 OTel と gateway で利用状況・コストを管理する組織

OTel でプランやプロバイダー別の分析を行いたい場合は、追加された anthropic.plan などの属性をダッシュボードやアラートに取り込む。Claude apps gateway の管理者は、コストレポート API による支出分析と、IdP グループ記録の保持期間 (admin.identity_retention_days) の設定を確認する

🏃 CI やセルフホストランナーで claude -p をネスト実行する環境

セッション内の claude -p が親セッションの ID とトランスクリプトを共有する旧動作に依存している場合は、CLAUDE_CODE_DISABLE_NESTED_SESSION_ID=1 を設定する。また、Read ツールの「file unchanged」スタブ削除により再読み込みの挙動が変わるため、自動化やフックでスタブ文字列に依存している場合は見直しが必要

※ 通常のアップデートで新機能と修正が適用される。特別な移行作業は原則不要

まとめ

Claude Code v2.1.317 は 87 件の変更を含む大規模リリース。アカウントメール送信前の確認チェックや Agent SDK フックの onFailure: "block" といったセキュリティ強化、OTel 属性の拡充と Claude apps gateway のコストレポート API によるエンタープライズ可観測性の向上が柱となる。MCP サーバーの切断、auto モードの失敗、セッション復元時の会話消失、プロキシ環境での OpenTelemetry エクスポート停止など、運用に影響する不具合も幅広く修正されており、特にゲートウェイやプロキシ環境、セルフホストランナーを利用する組織にとって安定性が大きく向上するアップデートである。
