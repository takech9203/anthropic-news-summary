Claude API / モデル

Claude Mythos 5 / Opus 4.7 / Sonnet 4.6 の生成テキストに Anthropic のテキスト透かしを付与

📅 2026-11-03 | ソース: Claude API Release Notes

概要

💧

対象モデルの拡大

Claude Mythos 5、Claude Opus 4.7、Claude Sonnet 4.6 が生成するテキストに、Anthropic の不可視なテキスト透かし (text watermark) が付与される。

✨

出力の品質・可読性は変わらない

透かしは出力の意味、品質、可読性を変えず、トークンや隠し文字を追加しない。ユーザーや組織に関する情報も一切含まれない。

🛠️

開発者側の対応は基本的に不要

透かしのためにリクエストやレスポンス処理を変更する必要はなく、既存のアプリケーションはそのまま動作する。

⚠️

Sonnet 4.6 のサンプリングパラメータ例外

Claude Sonnet 4.6 では、temperature、top_p、top_k を非デフォルト値に設定したリクエストで透かしが付与されないことがある。

🇪🇺

背景は EU AI 法への対応

2026 年 7 月に署名した EU AI 法第 50 条 (2) の「AI 生成コンテンツの透明性に関する行動規範」を受けた取り組み。地域を限定する永続的な方法がないため、すべての地域でグローバルに適用される。

主要機能

対象モデル。

🌌Claude Mythos 5 ⭐Claude Opus 4.7 🎵Claude Sonnet 4.6

🌐 対象プラットフォーム

透かしはモデルレベルで適用され、Claude Platform (API)、Claude アプリ、Claude Code などが対象。AWS、Google Cloud、Microsoft Foundry 経由のアクセスでも付与される。詳細はサポート記事に記載。

💧 埋め込みテキスト透かし

生成テキスト自体に織り込まれる不可視のマーク。コピー & ペーストしても一緒に移動し、ある程度の編集後も残存する場合がある。

📜 Content Credentials C2PA

生成ファイル (PNG、JPEG など) に付与される署名付き来歴メタデータ。こちらは透かしではなくラベルであり、テキスト透かしとは別の仕組み。

⚠️ Sonnet 4.6 の例外

temperature、top_p、top_k のいずれかを非デフォルト値に設定すると透かしが付与されないことがある。透かしに依存する場合は 3 つすべてをリクエストから省略することが推奨 (Mythos 5 と Opus 4.7 にはこの例外の記載なし)。

🔍 検出 API (プライベートプレビュー)

検出には Anthropic の透かしキーが必要で、結果は確率として返される。適格な組織 (規制当局、法執行機関、報道機関、ファクトチェッカー、研究者、教育機関、EU 市民社会組織) と、コンプライアンス上の必要がある企業に限定提供。アクセスはフォーム経由で申請。ファイルの Content Credentials は無料の Claude Content Checker で誰でも検証できる。

技術詳細: 仕組み

公式ブログ「How Claude's text watermark works」によると、この透かしは Google DeepMind の SynthID-Text (2024 年に Nature 誌で発表) をベースにした方式で、系譜は Scott Aaronson 氏による 2022 年の提案にさかのぼる。意味に影響しない低リスクな単語選択の揺らぎを利用し、次の単語を選ぶ際のランダム性の由来を「透かしキーと直前の数単語」から導出した値に置き換える。珍しい単語へ不自然に誘導するものではなく、Claude が通常使わない語彙を押し付けることはない。

出力品質への影響

  • ✅読者にとって、透かし入りの応答と透かしなしの応答は区別できない
  • ✅社内テストで内容、創造性、可読性への影響は確認されていない
  • ✅隠し文字や追加トークンはなく、追加コストや意味のある速度低下もない
  • ✅透かしにはユーザー、組織、特定のチャットをたどれる情報は一切含まれない

制限事項

項目 内容
📏 短いテキスト 検出が難しく、テキストが長いほど検出の信頼度が上がる
💻 事実記述やコード 正確な出力が求められ単語選択の自由度が低いため、透かしが疎になる。コードでは主にコメント部分に乗る
✏️ 編集 軽微な編集では完全には消えない可能性が高いが、すべての単語を置き換える全面的な書き直しでは消える
🌍 翻訳 すべての単語を Claude が選択するため、翻訳結果には透かしが付与される
⚖️ 判定の限界 「Claude が書いた」と「Claude が大幅に編集した」は区別できない。透かしがないことは人間が書いたことの証明にはならない (旧モデル、大幅な編集、ごく短い文章、非デフォルトのサンプリング設定などで欠落し得る)
🚪 オプトアウト 公式ドキュメントにオプトアウトの記載はない。マーキングはモデルレベルで全サーフェスに適用される
💡 透かしに依存する場合、Claude Sonnet 4.6 では temperature、top_p、top_k の 3 つすべてをリクエストから省略することが推奨される。フレームワークやクライアントライブラリが自動設定する値にも注意。

コードサンプル

Python 透かしに依存する場合のリクエスト例 (Sonnet 4.6) 
import anthropic

client = anthropic.Anthropic()

# 透かしに依存する場合は temperature / top_p / top_k を
# 設定しない (デフォルト値のまま使用する)
message = client.messages.create(
    model="claude-sonnet-4-6",
    max_tokens=1024,
    messages=[
        {"role": "user", "content": "製品発表のお知らせ文を書いてください。"}
    ],
    # temperature=0.7,  # 非デフォルト値を設定すると
    # top_p=0.9,        # Sonnet 4.6 では透かしが
    # top_k=40,         # 付与されないことがある
)

print(message.content[0].text)

開発者への影響と必要なアクション

対象: Claude API (および AWS、Google Cloud、Microsoft Foundry) で対象モデルを利用するすべての開発者、EU AI 法第 50 条などの透明性対応が必要な組織、透かし付与に依存するワークフローを構築する開発者。既存のアプリケーションはそのまま動作するため、移行作業は不要。

1

基本的に対応不要

透かしは出力の品質や形式を変えないため、既存のリクエストやレスポンス処理の変更は不要。

2

透かしに依存する場合

Claude Sonnet 4.6 を使用するリクエストから temperature、top_p、top_k をすべて省略する。フレームワークやクライアントライブラリが暗黙的に設定する値にも注意する。

3

コンプライアンス確認

Claude を組み込んだサービスを提供する事業者は、EU AI 法第 50 条に基づく自社の義務を独自に評価することが推奨されている (Anthropic は今後、追加の技術ガイダンスを公開予定)。

4

検出が必要な組織

テキスト透かしの検出 API はプライベートプレビューのため、適格な組織はフォームからアクセスを申請する。

ユースケース

🇪🇺 AI 生成コンテンツの透明性対応

EU AI 法第 50 条などへの対応が必要な組織は、対象モデルの生成テキストに自動で透かしが付与されるため、追加実装なしで透明性要件への取り組みに活用できる。自社の義務の評価は独自に行うことが推奨される。

🔍 適格な組織によるコンテンツ検証

規制当局、法執行機関、報道機関、ファクトチェッカー、研究者、教育機関、EU 市民社会組織などは、プライベートプレビューの検出 API を申請し、テキストが Claude 由来かを確率として確認できる。今後対象の拡大が予定されている。

🛠️ 透かし付与に依存するワークフローの構築

生成テキストの透かし付与を前提とする処理を新規に実装する場合、Sonnet 4.6 のサンプリングパラメータに関する例外を考慮し、3 つのパラメータを省略したリクエスト設計にする。

まとめ

Claude Mythos 5、Claude Opus 4.7、Claude Sonnet 4.6 の生成テキストに Anthropic のテキスト透かしが付与されるようになった。EU AI 法の透明性要件への対応を背景とした取り組みで、SynthID-Text ベースの方式により、出力の品質や可読性を変えず、追加トークンやコストも発生しないため、ほとんどの開発者にとって対応は不要である。一方、透かしの付与に依存する場合は、Sonnet 4.6 で temperature、top_p、top_k を非デフォルト値に設定すると透かしが付かないことがある点に注意が必要となる。検出 API は現時点でプライベートプレビューであり、一般の開発者が透かしを直接検証する手段は提供されていない。
